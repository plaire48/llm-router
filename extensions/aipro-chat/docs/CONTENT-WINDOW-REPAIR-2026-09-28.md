# 첫 본문 읽기 개선과 날씨 재측정

후속 5개 실측에서는 E-07이 다시 미통과했다. 첫 5,000자 원문에는 오늘 날짜와 정확한 값이 들어왔지만 모델/검토 과정이 이를 답변에 정확히 연결하지 못했다. 아래 단일 성공을 안정적 성공으로 확대하지 않으며 [최신 결과](../verification/naver-sso-luna-2026-09-28T03-25-57-335Z-evidence/FINDINGS.md)를 따른다.

2026-09-28. 이전 5개 실측의 E-07 실패를 출발점으로 첫 개선을 완료했다. **제목만 반환하던 일반 본문 읽기를 수정했고, GPT-5.6 Luna의 같은 날씨 과제 1회 재측정은 독립 채점 3/3 통과다.** 규칙 설명의 예외 누락과 부분 근거의 모든 잘못된 완료 판정을 해결한 것은 아니다.

## 원인 재현과 선택

[이전 5개 실측](../verification/naver-sso-luna-2026-09-27T22-28-12-862Z-evidence/FINDINGS.md)에서 자동 본문 조회가 전체 26,627자 중 23자만 반환했다. 당시 모델에 전달된 관찰 원문은 미수집이어서 그 23자의 정확한 내용은 확정할 수 없다.

현재 `browser-content.js`와 설치된 `@langchain/textsplitters` 1.0.1의 실제 `_splitText`를 읽고 별도 입력으로 재현했다. Markdown 제목 다음에 큰 구간이 있으면 분할기가 작은 앞 구간을 먼저 내보낸다. 누비가 그중 첫 구간 하나만 반환하므로 7자 제목으로 첫 조회가 끝날 수 있었다. 분할기는 검색용 구간 생성 계약을 따랐지만 누비의 순차 읽기 요구와 맞지 않았다.

[LangChain 공식 분할기 문서](https://docs.langchain.com/oss/javascript/integrations/splitters/index)는 구조별 분할과 길이별 분할을 구분한다. 기존 MIT 라이선스 라이브러리의 구조별 분할은 집중 검색에 유지하고, 일반 순차 읽기는 정확한 원문 문자 범위로 분리했다. 새 패키지/런타임이나 모델 검토 계층을 추가하지 않았다. 이전 [agent-browser 문서 식별 참고](AGENT-BROWSER-REFERENCE-2026-09-28.md)와 Claude/Codex 기반 관찰→실행→검증, 실제 영수증/독립 채점의 방법을 유지한다.

## 실제 변경

- 일반 본문 읽기는 offset부터 최대 5,000자의 연속 원문을 반환한다. 제목과 본문 사이의 분할 경계 때문에 짧게 끝나지 않는다.
- next_offset은 실제 반환 끝이며 공백이나 반복 문장을 건너뛰지 않는다. UTF-16 surrogate pair의 중간에서 창을 끝내지 않는다.
- query 조회는 기존 LangChain/MiniSearch 검색과 검색 결과 순번 offset을 유지한다. 두 offset 계약을 섞지 않는다.
- 범위 밖 문자가 있거나 검색으로 제한된 결과는 partial로 표시한다. 실제 DOM 추출의 숨은 내용/iframe/shadow 제외 상태도 유지한다.
- 동일 content_hash 검사, 문서 교체 거절, PDF 페이지/문자 범위와 탭/프레임/승인/미확정 쓰기 경계는 유지한다.

길이별 창은 표/문장/예외 조항 중간에서 끝날 수 있다. 반환 안내에 다음 구간을 읽어 문맥을 확인하도록 명시했다. 첫 5,000자가 모든 요구를 포함한다는 보장이 아니며, 화면 관찰/추가 집중 읽기/최종 검토는 계속 필요하다.

## 기록 보완과 창 닫힘 진단

`NUBI_EVAL_CAPTURE_PUBLIC_READS=1`을 선택한 공개 읽기 과제에서만 계획에 고정된 시작 페이지의 origin/path에 대해 정제된 도구 반환 원문을 제한 수집한다. 인증 경로, credential query, 다른 페이지는 제외하며 프레임/문서 ID와 잘림 여부를 기록한다. 정확한 전체 모델 입력을 수집한 것은 아니다. 제품 로거에는 적용하지 않고 기존 값 없는 진단 기본값을 유지한다.

사용자가 창이 오류로 닫혔다고 알린 시점에 원자료를 확인했다. 프로세스 종료 코드는 0, report는 trials_recorded, agentError=null, 답변 표시/계획 완료 확인 후였다. 평가기의 finally가 브라우저를 닫은 것이며 해당 실행의 오류 종료 근거는 없다. 같은 격리 프로필/후보를 다시 열어 저장된 답변과 계획 2/2가 복원됨을 확인했다. **모델 요청이나 브라우저 작업을 재전송하지 않았다.** Chrome 종료 후 세션 인증이 사라져 연결 필요가 보이는 것은 답변 저장 실패와 구분한다.

이 대화에서 다음 대화형 평가는 `NUBI_EVAL_KEEP_BROWSER=1`로 실행해 사용자가 결과를 확인할 때까지 창을 유지한다. 기존 자동화의 기본 종료 정책을 일괄 바꾸지 않았다.
