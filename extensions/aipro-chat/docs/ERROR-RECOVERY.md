# 오류 복구

2026-09-22. `nubi@1.0.0-beta.12` / Chrome `1.4.15` 로컬 후보에 적용했다. 공개 beta11과 실제 Qwen 성능 평가는 구분한다.

## 선택한 방법

오류를 없애는 단일 프레임워크보다 **실패 원인과 실행 여부에 따라 복구 주체를 나누는 방식**이 현재 확장에 적합하다. 설치된 MIT Pi `0.86.1`과 MIT p-retry `8.0.1`을 사용한다. 별도 서버나 로컬 런타임을 추가하지 않았다.

| 근거 | 채택한 방법 | 적용 범위 |
| --- | --- | --- |
| [LangGraph의 오류 처리](https://docs.langchain.com/oss/javascript/langgraph/thinking-in-langgraph#handle-errors-appropriately) | 통신 오류는 시스템, 도구/파싱 오류는 모델, 모호한 요구는 사용자에게 넘긴다. | 기존 Pi 도구 결과와 질문 경로에 적용. LangGraph 런타임은 중복 도입하지 않음. |
| [Pi 실제 agent loop](https://github.com/earendil-works/pi/blob/main/packages/agent/src/agent-loop.ts) | 미등록 도구와 잘못된 인자를 오류 결과로 돌려주고 다음 모델 판단을 받는다. | Nubi가 먼저 종료하던 미등록 도구 검사 제거. 실제 실행 권한은 기존 등록 도구에 한정. |
| [p-retry](https://github.com/sindresorhus/p-retry) | 선택적 재시도, 지수 지연, 무작위 편차, AbortSignal. | 추론 요청에만 사용. SDK 내부 재시도는 끄고 이 계층이 횟수를 관리. |
| [AWS backoff와 jitter](https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/) | 동시에 실패한 요청의 재시도 시점을 분산한다. | p-retry의 randomize 사용. AWS 글의 Full Jitter 구현 자체를 복사한 것은 아님. |
| [Playwright actionability](https://playwright.dev/docs/actionability) | 현재 요소의 가시성, 활성 상태, 이벤트 수신과 안정성을 확인한다. | 기존 정상 대기와 최신 관찰 유지. 실패했다고 force/DOM 클릭으로 우회하지 않음. |
| [LangGraph 상태 보존](https://docs.langchain.com/oss/javascript/langgraph/persistence) | 완료 단계와 실행 결과를 보존하고 필요한 부분부터 이어간다. | 기존 작업 체크포인트와 실행 기록 사용. 새 영속 실행 엔진을 도입한 것은 아님. |

선택 기준은 MV3 호환성, 기존 제공자 계약 유지, 실제 실행 여부 확인, 취소 전파와 유지보수 비용이다. 다른 하네스보다 Qwen 성능이 높다는 비교 결과는 아직 없다.

## 복구 정책

| 실패 | 처리 | 자동으로 반복하지 않는 것 |
| --- | --- | --- |
| 네트워크, 무응답, 408/429/500/502/503/504 | 모델 요청 최대 3회 재시도. 1초 기준 지수 지연과 편차, 최대 8초. 무응답 감시는 실제 응답 활동 때 갱신. | 완료한 페이지 동작 |
| 429/503의 Retry-After | 초 또는 HTTP 날짜를 해석. 같은 작업의 주 Agent와 분석 담당이 대기 상태 공유. | 서버가 정한 시간 이전 재요청 |
| 60초보다 긴 서버 대기 | 이 요청의 자동 재시도를 종료하고 기존 중단/이어가기 경로로 전달. | 짧게 잘라 조기 재요청하거나 무기한 대기 |
| 완료 신호 전 SSE 단절 | 불완전한 도구 호출을 모두 버리고 추론만 재요청. | 도구 이름/인자가 그럴듯해도 부분 호출 실행 |
| 인증, 접근 거절, 잘못된 모델/요청 | 해당 오류를 유지하고 연결 또는 요청 수정 필요를 표시. | 맹목적 재시도, 다른 계정으로 자동 전송 |
| 미등록 도구, 인자 스키마 오류 | 실행하지 않은 이유를 Pi 도구 결과로 전달. 모델이 허용 도구와 최신 대상에 맞춰 수정. | 해당 응답의 뒤쪽 의존 작업 |
| 도구 호스트 예외 | 알려진 오류 코드와 HTTP 상태만 전달. 코드 문법/대상/권한/취소를 구분. | 예외 원문, 토큰, 입력값을 진단에 저장 |
| 쓰기를 시도한 뒤 응답 유실 | 실행 여부를 unknown으로 표시. 읽기/관찰 전 추가 쓰기와 승인 요청을 차단. 잠정 완료 답변도 보류. | 입력, 클릭, 전체 스크립트 재실행 |
| 부분 실행 또는 대상 변경 | 기존 명령 기록과 최신 화면을 보고 모델이 남은 작업만 선택. 필요하면 격리된 실패 분석 담당 사용. | 성공한 단계와 불확실한 최종 트랜잭션 |
| 검토 JSON/근거 ID 오류 | 동일한 실제 근거로 검토 요청 한 번 교정. 두 번 실패하면 미검증 상태 유지. | 교정을 위해 브라우저 작업을 다시 실행하거나 근거를 만들어 완료 처리 |
| 반복된 잘못된 도구 호출 | 세 번 연속 수정되지 않으면 기존 질문 폼으로 필요한 대상/결과 확인. 도구가 없는 하위 담당은 실패 요약 반환. | 이름만 바꿔 계속 실행하거나 권한 확대 |
| 사용자 중지 | 대기, 모델 요청과 분석 담당 취소. 뒤늦은 결과 무시. | 자동 재시작 |

횟수 제한은 실패한 한 요청 또는 진전 없는 복구에 적용한다. 계속 진전하는 전체 브라우저 작업을 고정 횟수로 끊지 않는다. 질문은 부족한 선택/정보를 받는 용도이며 최종 발송/등록 승인은 별도 HITL을 유지한다.

## 구현 경계

- 모델 재시도와 브라우저 실행은 다른 경로다. `recoverModel`은 도구 실행기를 호출하지 않는다.
- HTTP 오류와 대기 시간은 AI Pro, ChatGPT, FabriX 어댑터에서 유지한다. FabriX의 프로토콜 교정과 실제 HTTP 장애는 구분한다.
- MV3 worker가 읽는 HTTP 대기 파서는 의존성 없는 `http-retry.js`로 배포한다. p-retry와 Pi는 기존 UI 번들에 남긴다.
- UI의 RPC 실패를 무조건 `page_changed`로 바꾸던 경로를 제거했다. 실행기가 실패의 분류와 불확실한 쓰기를 판단한다.
- 모델 답변이 손상됐다고 임의로 JavaScript 예외까지 network로 분류하지 않는다.
- 진행 내역은 실제 복구 상태를 표시하고 Markdown과 CX 토큰을 공유한다. 복구를 위한 설정이나 모달을 추가하지 않았다.
- 새 역할별 분석은 하나의 작업 안에서 같은 연결의 대기를 공유한다. 다른 탭, 다른 대화, 브라우저 재시작까지 공유하는 전역 circuit breaker는 아니다.
- 한 번 실행됐는지 서버에서 보장할 수 없는 사이트의 exactly-once를 주장하지 않는다. 최신 DOM 관찰은 서버 저장 증명의 대체물이 아니다. 보이는 저장 결과와 기존 검증/HITL을 유지한다.

## 검증

브라우저의 반복 실패와 실제 화면 변화 구분은 [실행 결과 기반 복구](BROWSER-OUTCOME-RECOVERY.md)에 정리했다. 같은 화면 재조회나 새 참조 ID가 실패를 지우지 않으며, 실제 결과 변화가 있으면 정상 작업의 반복 횟수를 초기화한다.

오류를 주입하고 실제 결과를 확인한다. 단위 검사는 대기/취소/횟수, 병렬 담당 대기 공유, 예외 원문 제거, 미등록 도구 복구, 불확실한 쓰기 차단과 검토 교정을 검사한다.

`tests/error-recovery-browser.mjs`는 새 Chrome 프로필에서 합성 Qwen 응답과 실제 버튼을 사용한다. 클릭한 뒤 RPC 응답만 잃어버리게 하고 잘못된 재클릭, 429, 완료되지 않은 SSE와 잘못된 검토 JSON을 연속 주입한다. 최종 클릭 수 1, 실제 토글 상태, 결과 검증, 요청별 사용량, 새로고침 보존과 대기 중 취소를 확인한다. `verify:browser`에서 3회 반복한다.

실제 회사망의 Qwen 정확도, 장애율, 지연과 토큰 비용 변화는 별도 실계정 평가가 필요하다. 현재 환경에는 평가용 `NUBI_EVAL_TOKEN`이 없어 실모델 비교는 미실행이다. 검사 결과는 `verification/pre-release-*/report.json`의 선택한 스위트와 빌드/ZIP 해시에 묶는다. 이 문서 작성만으로 공개 릴리스를 교체하지 않는다.
