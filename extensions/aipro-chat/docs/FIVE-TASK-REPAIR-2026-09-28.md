사용자 요청: 코드와 방법론을 함께 개선하고 GPT-5.6 Luna로 E-01/E-03/E-04/E-07/E-08을 모두 통과시킨다. 원래 사용자 요청, 독립 채점 기준과 실모델은 유지한다. 개별 재시험을 전체 성공률에 합치지 않는다. 완료 선언이 아니라 저장된 최종 답변, 표시 화면과 실제 출처를 대조한다.

## 참고와 선택

- [OpenAI harness engineering](https://openai.com/index/harness-engineering/), [agent evals](https://developers.openai.com/api/docs/guides/agent-evals): 관찰 가능한 상태와 재현 가능한 검사로 피드백한다. 실패 기록을 수정 근거로 사용하고 단위 검사와 과제 성과를 구분한다. 별도 API/CLI 제공자로 모델을 바꾸지 않는다.
- [Anthropic tools](https://www.anthropic.com/engineering/writing-tools-for-agents), [agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents): 모델이 필요한 근거를 구별할 수 있게 도구 결과를 개선하고 정상 대조군도 검사한다. 지난 검토 프롬프트 강화 실험은 정상 답변을 거절했으므로 이번에도 채택하지 않는다.
- [browser-use](https://github.com/browser-use/browser-use) `4cbe921673b48a488f5415d9159249afd12a625b`, MIT: 실제 `tools/service.py`의 `extract`/구조화 출력과 `done` 경로를 확인했다. 요구 필드와 원문/URL을 분리해 추출하고 누락/절단을 표시하는 패턴을 실행 안내에 반영했다. 추출 모델의 생성물을 독립 관찰로 취급하지 않는다. Python 런타임/원문 코드/프롬프트는 제품에 복사하지 않았다.
- [Vercel agent-browser](https://github.com/vercel-labs/agent-browser) `d01253d9db28d75080e36da3c1c31ef89454731e`, Apache-2.0: 이전 고정 소스와 현재 공식 저장소를 확인하고 실제 `RefMap.observe_document`와 읽기 경로를 재검토했다. 같은 문서의 관찰 범위 안에서만 링크 대응을 제공한다. CLI는 개발/검증 수단으로 사용할 수 있지만 이번 세 실패는 누비의 정보 표현/검토 문제여서 별도 브라우저 런타임 교체를 선택하지 않았다.
- [Claude Code Chrome](https://code.claude.com/docs/en/chrome): CLI 수정 → 실제 브라우저 관찰 → 보완 흐름을 참고한다. 기존 배포본 분석 기록의 탭/도구 관찰 계약을 재사용하며 최신 배포본 전체를 새로 분석했다고 주장하지 않는다. 재사용 라이선스가 확인되지 않은 배포 코드/프롬프트를 복사하지 않는다.

## 후보 D 변경

1. 검색 결과에는 사이트명·제목·요약이 같은 주소로 연결된 여러 링크가 있다. 기존의 각 요소 이름/목적지에 더해 같은 전체 href에 속하는 실제 이름 후보를 최대 4개 묶는다. 표시 URL이 같아도 서로 다른 query 문서는 합치지 않는다. 숨긴 글/인증 URL/실행 URL은 제외하고 제목 의미를 호스트가 임의 추정하지 않는다. 관찰을 다시 하면 다시 수집한다.

3. 관찰 시각만 달라졌을 때는 복구의 진전으로 세지 않는다. 처음 전체 회귀에서 이 부작용 1개를 발견했고 browser-recovery와 실행 진전 비교를 함께 수정했다. 실제 텍스트·문서/대상 바인딩 검사는 유지한다.
4. 실행 안내는 요청 필드 → 실제 원문과 URL 추출 → 조건/예외 및 날짜 의미 구분 → 최종 답변 항목 대조를 요구한다. 도해가 모호하면 명시 설명문을 확인하며 특정 펜싱 정답/인물/사이트를 하드코딩하지 않았다. 중복 이미지 안내를 줄여 상시 문맥 예산을 유지한다. 독립 검토 프롬프트, 과제와 채점 기준은 변경하지 않았다.
