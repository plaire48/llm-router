# OpenWiki 검색과 업무 스킬

현재 브라우저 조회는 [위키별 OpenWiki 에이전트 위임](OPENWIKI-AGENT-DELEGATION.md)으로 이어졌다. 아래는 호환 API로 유지하는 어휘 검색의 구현 기록이다. 서버가 모델을 실행한다는 뜻이 아니다.

## 이전 어휘 검색 구현 기록

누비가 질문과 관찰한 용어를 보내면 **OpenWiki 라이브러리가 관련 문서 구간을 찾아 근거 묶음을 반환**한다. 누비는 그 근거를 현재 화면과 비교하고 요청한 브라우저 작업을 수행한다. 부족한 문맥만 추가로 읽는다.

`사용자 요청 → 필요한 업무 스킬 → wiki_query → 근거 비교 → 페이지 초안/행동 → 검증 → 최종 행동 승인`

- 서버 연결: 이 저장소의 OpenWiki-SDS `openwiki visualize /path/to/project/openwiki --project-root /path/to/project`를 실행한 뒤 누비 설정의 **OpenWiki 폴더 → 서버 연결 → 프로젝트 연결**에서 연결한다. 프로젝트 경로는 서버 실행 시 고정한다. 기존 연결은 새 서버로 다시 연결해야 새 기능을 인식한다.
- 폴더 연결: 서버 없이 저장한 Markdown을 검색하고 읽는 기존 방식이다. `wiki_query`는 서버가 제공한다고 알린 경우에만 노출된다. 기존 서버는 `wiki_search`와 `wiki_read`를 계속 사용한다.
- 새 API: 인증된 `POST /api/nubi/v1/wiki/query`, JSON `{ "question": "CheckoutButton의 검토 흐름은?", "limit": 5 }`. 기존 페어링, 만료, Origin 검사, 프로젝트 접근 범위를 그대로 적용한다. 임의 폴더를 요청 인자로 받을 수 없다.
- 반환: 관련 발췌, 상대 경로, 줄 범위, 읽은 내용의 SHA-256, 검색 범위와 잘림 여부. 생성된 답변이나 화면 동작의 증명은 반환하지 않는다. 실제 소스는 기존 `source_search`/`read_source`, 실제 화면은 브라우저 관찰로 확인한다.

## 검색 방식과 근거

MiniSearch 7.2.0(MIT)의 BM25 검색에 문서 제목, 파일명, 섹션 제목을 함께 사용한다. 긴 문서는 섹션과 줄 경계를 보존해 나눈다. 한 문서의 결과 독점을 제한하고 최대 5개 발췌, 본문 합계 10,000자만 전달한다. 읽기마다 현재 파일과 제외 규칙을 확인한다. 문서 수, 읽기량, 시간 제한에 걸리거나 일부 문서를 읽지 못한 경우 범위가 불완전하다고 표시한다.

이 구현은 구조 정보를 활용한 로컬 어휘 검색이다. Anthropic의 LLM 생성 청크 설명, 벡터 검색, 모델 기반 재순위화 전체를 구현한 것은 아니다. 자연어에 원문과 다른 동의어만 있으면 놓칠 수 있다. 모델은 관찰된 파일명/심볼/페이지 용어로 질문을 보완하고, 결과가 없다고 대상 부재를 단정하지 않는다.

- [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval): 청크의 문맥 보존, 검색 결과 수 조절, 평가 후 재순위화 적용 원칙을 참고했다. 공개 성능 수치는 누비의 개선율로 사용하지 않는다.
- [MiniSearch](https://github.com/lucaong/minisearch): 브라우저와 Node에서 사용하는 가벼운 로컬 검색 라이브러리. 확장에서 쓰던 라이브러리를 OpenWiki에도 정확한 버전으로 도입했다.
- [DeepWiki-Open API](https://github.com/AsyncFuncAI/deepwiki-open/blob/main/api/README.md): 저장소 질문을 별도 검색 계층에서 처리하는 구성을 검토했다. 별도 Python 서버와 임베딩 구성을 요구하므로 이번에는 도입하지 않았다. OpenWiki와 동일한 프로젝트가 아니다.

## 스킬을 업무 단위로 제공하기

입력창의 스킬 메뉴에서 패키지 아이콘으로 `SKILL.md`가 있는 폴더를 가져온다. 설명에는 사용할 상황을 적는다. 자동 모드는 이름과 목적만 보고 스킬을 고르고, `read_skill`로 절차와 필요한 자료만 읽는다. 기존 스킬의 직접 선택도 유지한다.

등록 화면은 이름, 사용할 때, 지침만 받는다. 페이지 읽기/입력/저장 정보/자동화 체크박스는 제거했다. 화면에서 새로 등록하거나 수정한 스킬은 `toolMode: automatic`으로 저장해 일반 채팅과 같은 도구를 사용하며, 실제 페이지 도구가 필요할 때 연결한다. 이전에 저장한 스킬의 범위는 편집 저장 전까지 유지한다. 자동 연결과 스킬 선택은 별도로 기록해 중단 후에도 같은 지침을 이어 쓴다. 브라우저의 사이트 접근 허용, 탭 소유권, 민감한 저장 정보 차단과 최종 등록/발송 승인은 기존 호스트가 검사한다.

지원하는 폴더는 `SKILL.md`와 `references/`, `scripts/`, `assets/` 아래의 텍스트 자료다. 최대 24개 자료, 개별 48KB, 패키지 200KB이며 바이너리 자료와 ZIP 직접 가져오기는 이번 범위에 포함하지 않는다. 가져온 파일은 현재 시점의 사본이다. 다시 가져오기 전까지 PC 폴더 변경을 추적하지 않는다. Python/Node 스크립트는 참고 자료이며 실행 권한을 부여하지 않는다. 브라우저 동작은 기존 누비 도구만 사용한다.

스킬 지침에는 업무 목표, 필요한 입력, 근거 수집, 단계별 결과, 실패 시 재관찰, 최종 검증과 승인 조건을 작성한다. 매 요청에 전체 참고 자료를 넣지 않는다. 실행 중 스킬 내용이 달라지면 해시를 비교해 읽기를 거절하고 다음 요청에서 다시 선택한다. 스킬의 설명과 절차는 작업 완료를 증명하는 근거에서 제외한다.

연결된 프로젝트에는 기본 `OpenWiki 업무 실행` 가이드가 자동 제공된다. 수정과 공유용 예시는 `examples/skills/openwiki-page-workflow/`에 있다. JSON 내보내기 v2는 설명과 자료를 함께 보존하며 기존 v1 가져오기도 지원한다.

[Agent Skills의 단계적 로딩](https://agentskills.io/client-implementation/adding-skills-support)과 [표준 폴더 구조](https://agentskills.io/specification)를 참고했다. YAML frontmatter는 `yaml` 2.9.0(ISC)로 파싱한다. 파일 안의 `allowed-tools`는 도구 권한을 늘리지 않는다.

## 다음 개선의 판단 기준

실제 업무 질문을 정답 근거와 함께 모아 Recall@5, 출처 정확성, 검색 지연, 전달 문자/토큰, 브라우저 결과 달성 여부를 각각 평가한다. 현재 검사는 합성 문서와 합성 모델 응답을 사용한다. Qwen 실계정의 요구사항 해석 능력이나 실사내 사이트 성공률을 증명하지 않는다.

어휘 검색이 놓치는 동의어 질문이 반복되면 임베딩과 BM25를 결합하고 재순위화를 비교한다. 사용할 사내 임베딩/재순위화 API와 데이터 범위를 확인한 뒤 도입한다. 근거가 없는 자연어 요약만 돌려주는 별도 LLM 호출은 현재 추가하지 않았다. 비용과 지연을 늘리기 전에 근거 검색의 정확도를 측정한다.
