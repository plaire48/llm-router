## 우선 개선할 항목

### P1. 아무 작업 없이 완료하는 경로 차단

`현재 페이지 본문에 평가용 초안을 입력해줘. 등록하지 마.`에 대해 모델이 도구 호출 없이 완료 문장만 반환하도록 했다. **실제 입력 0회, 본문 빈 값, 검토 호출 0회인데 메시지는 done**이었다.

원인은 [agent-runtime.js:493](../agent-runtime.js#L493)의 근거가 없으면 최종 검토를 건너뛰는 경로다. 일반 텍스트 응답을 빠르게 처리하려는 조건이 브라우저 작업 요구에도 적용된다.

개선: 요청의 완료 조건과 브라우저 근거 필요 여부를 실행 전에 기록한다. 브라우저 상태가 필요한 작업은 근거가 없으면 완료로 확정하지 않고, 관찰 또는 필요한 질문으로 돌린다. 인사·글 초안 제안 같은 순수 텍스트 요청에는 불필요한 브라우저 호출을 강제하지 않는다. 단순 키워드나 완료 문장 감지만으로 처리하지 않는다.

완료 기준: 도구 없음, select_tools만 실행, 계획만 완료, 잘못된 페이지 관찰, 오래된 근거를 각각 주어도 실행 완료를 주장하지 않는다. 순수 대화에서는 페이지 접근 0회를 유지한다.

### P1. 실모델 평가기의 채점 대상 수정

[evaluate-agent.mjs:77](../scripts/evaluate-agent.mjs#L77)은 고정된 원래 `target`에서 값을 읽는다. 현재 기본 동작은 누비 전용 창이다. 반례에서는 **작업 창 본문은 정상 입력되고 원본은 보존됐지만, 기존 평가 방식은 빈 원본을 채점**하게 된다.

개선: 작업 소유권에 연결된 실제 탭을 식별해 채점하고, 원래 탭은 별도의 보존 조건으로 검사한다. 팝업/탭 이동에도 정답 검사 대상을 갱신한다. 가능한 업무는 페이지 표시와 별도로 테스트 앱의 저장 상태 및 재열기를 검사한다. 현재 탭 모드만 강제하는 우회로 기본 작업 창의 검증을 대신하지 않는다.

완료 기준: 동일 과제를 현재 탭/전용 창/팝업에서 각각 실행해 정상 결과를 같은 방식으로 채점하고, 사용자 원본 변경은 별도 실패로 처리한다.

### P1. 회귀 검사 계약 동기화

| 실패 스위트 | 관찰한 원인 | 판단 |
| --- | --- | --- |
| browser-workflows-browser | 토글 expanded가 boolean `true`인데 문자열 `'true'`를 기대 | 오래된 자료형 기대값. 이 지점 이후 업무 검사는 실행되지 않음 |
| clarification-browser | 마지막 텍스트 스킬 검사에서 ask_user만 기대하지만 find_skills/read_skill도 제공 | 앞선 질문·재개 6개 검사는 통과. 새 도구 계약을 반영할 필요 |

원본 실패를 성공으로 바꾸거나 삭제하지 않았다. 마지막 진단은 테스트 모드 불일치를 분리한 증거이며, 원본 기본 창 시나리오의 성공을 뜻하지 않는다. 테스트를 고칠 때 의미 조건·쓰기 횟수·부작용 검사를 약하게 만들지 않아야 한다. 별도 창 시나리오는 실제 로컬 HTTP 픽스처와 소유 탭 기준으로 유지한다.

### P1. 실제 Qwen 기준선 확보

현재 실모델 실행기에는 8개 과제가 있지만, 실제 토큰 합산·반복 시도·비교용 홀드아웃이 없다. 합성 응답을 정해 둔 테스트는 Qwen의 도구 선택 능력을 측정하지 않는다.

다음 평가는 **24개 과제 × 3회**를 제안한다. 16개는 개발용, 8개는 프롬프트와 예제 개선에서 제외한 비교용으로 고정한다. 읽기, 새 탭 메일 초안, 중복 이름, 동적 폼, 호버/토글, 모호한 요청, 실패 복구, 긴 대화, Wiki 근거 적용, 이미지 선택을 포함한다.

같은 Qwen 모델 ID와 후보 해시로 최종 업무 성공률, 3회 모두 성공한 과제 비율, 거짓 완료, 중복 쓰기, 불필요한 질문, 첫 유효 행동까지 시간, 전체 지연, 주/하위/검토/요약의 총 usage를 기록한다. 미완료·환경 오류·모델 실패를 분리하고 신뢰구간을 함께 제공한다. 단일 Agent와 역할별 분석은 같은 과제에서 비교한다. 더 많은 호출을 성능 향상으로 간주하지 않는다.

### P2. 작업 수명과 긴 문맥 개선

Pi 실행은 채팅 문서에 있고 [background.js:224](../public/background.js#L224)는 소유자가 사라지면 정리하고 작업을 일시 중지한다. 상태 보존과 수동 이어가기는 지원하지만 닫힌 뒤 자동 지속은 지원하지 않는다. 별도 장수 실행 문서/실행 소유권 구조를 검토하고, 적용 전 종료·재시작·네트워크 유실을 주입해 중복 쓰기 없이 복구되는지 평가해야 한다. 사용자 취소는 자동 재개하지 않는다.

컨텍스트는 최근 조건과 실행 기록을 보존하지만, 오래된 조건의 의미는 요약 품질에 영향을 받는다. 요약과 별도로 요구사항/수정/완료 근거를 연결한 조건 목록을 유지하고, 긴 대화에 숨겨 둔 제한을 끝까지 지키는지를 검증한다. 현재 같은 모델의 별도 검토는 실행기와 오류가 상관될 수 있으므로, 실제 앱 상태와 사람의 표본 검토를 함께 사용한다.

## 방법론과 오픈소스 판단

[Anthropic의 Agent 평가 방법](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)을 참고해 회귀 검사와 실제 능력 평가를 분리하고, 완료 문장이 아닌 환경의 실제 결과를 채점했다. 반례와 독립 상태 검사는 이번 감사에 적용했다. 자체 검토 모델의 통과를 성능 정답으로 사용하지 않았다.

[BrowserGym](https://github.com/ServiceNow/BrowserGym)과 [AgentLab](https://github.com/ServiceNow/AgentLab)은 외부 개발용 벤치마크 후보로 적합하다. 둘 다 공식 저장소에서 Apache-2.0 라이선스를 확인했다. Python/브라우저 실행 환경이 필요하므로 확장에 그대로 포함하지 않고, 별도 평가 환경에서 과제와 정답 판정을 연결하는 방향을 권한다. 이번에는 설치하거나 점수를 측정하지 않았다. 기존 Pi/Playwright 실행기를 교체할 근거는 확보하지 못했다.

평가 증거와 재현 스크립트만 추가했다. 제품 로직을 수정하거나 공개 배포하지 않았다. 우선순위는 **거짓 완료 차단 → 채점/회귀 정비 → Qwen 기준선 → 지속 실행과 문맥 개선**이다.
