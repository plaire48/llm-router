# 누비 Playwright 작업 품질 개선안

최초 검토: 2026-09-21, 누비 0.16.2 기준. 현재 배포 후보: 1.4.17 (Beta 1.0.0 beta14).

**상태: 사전 검사와 실패 유형별 복구, 지연 호버 메뉴와 가상 포인터까지 구현.** 최신 검증 범위는 [beta13 기록](RELEASE-BETA13.md)을 따른다. 1.4.0의 변경 범위와 검증은 [1.4.0 기록](VERIFICATION-1.4.0.md)을 따른다. 1.0.0의 전체 기능과 디자인 검사 결과는 [1.0.0 검증](VERIFICATION-1.0.0.md)을 따른다. 앞선 22개 스위트 검사는 [배포 전 검증 이력](VERIFICATION-2026-09-21-PRE-RELEASE.md)에 남긴다. 실제 AI Pro 모델이 자율적으로 과제를 해결하는 성공률과 절차 재사용은 아직 검증/구현하지 않았다.

| 검증된 절차 재사용 | 미구현. 실제 모델 기준선과 개선 효과를 확보한 뒤 적용 |

## 배포 전 검증

`npm run verify:browser`는 단위/디자인 검사와 후보 빌드 뒤 핵심 실행/인증/폼 스위트를 새 프로필로 각각 3회, 나머지 기능/디자인 회귀 스위트를 1회 실행한다. 목록은 `scripts/verify-browser.mjs`를 따른다. 실패 시 즉시 중단하고 실패 로그를 남긴다. 반복 횟수를 줄인 점검을 정식 반복 검증으로 대신하지 않는다.

검사한 ZIP과 빌드 해시를 결과에 묶고, 실행 중 빌드가 바뀌면 결과를 인정하지 않는다. 후보 ZIP은 기존 배포 파일과 분리하며 이 명령은 업로드하지 않는다. 실행 명령과 증거의 한계는 [TESTING.md](../TESTING.md)를 따른다.

배포 판단에서는 아래 결과를 구분한다.

1. **실행기 회귀:** 실제 Chrome에서 입력값, 요청 payload, 동작 횟수, 팝업 전환과 승인 경계를 검사한다.
2. **모델 품질:** 같은 실제 모델/설정으로 아래 과제를 반복하고 자율 선택/복구/완료 판단을 측정한다. 도구 호출을 미리 정한 테스트는 이 결과에 포함하지 않는다.
3. **실사용 연결:** 회사망 SSO/API와 대상 사이트에서 로그인, 권한 요청, 저장/조회 결과를 확인한다.

실행기 회귀만 통과한 후보를 실제 모델 품질까지 검증된 배포로 설명하지 않는다.

## 권장 방향

기존 Pi + Playwright CRX + QuickJS 실행 기반을 유지하면서 **정확한 관찰 → 작은 스크립트 → 구체적인 실행 피드백 → 요구사항 검증**을 강화한다. 개선 여부는 같은 AI Pro 모델에 같은 과제를 주어 측정한다.

오픈소스는 관찰·복구·재사용 기능 단위로 활용한다. 브라우저 확장만 설치하면 동작하는 조건과 기존 AI Pro/ChatGPT/FabriX 연결은 유지한다. MCP는 선택적인 도구 연결 방식이며 스크립트 작성 능력 자체의 해결책은 아니다.

### 최초 조사에서 직접 재현한 관찰 불일치

0.16.2의 `collectSnapshot`을 Chromium의 작은 합성 페이지에서 실행했다. 아래 두 문제는 0.17.0에서 수정하고 회귀 검사로 전환했다.

| 실제 요소 | 누비 관찰 결과 | 실제 Playwright 조회 |
| --- | --- | --- |
| `label` 안의 단일 선택 목록 | 이름 `분류업무`, 역할 `select` | `getByRole('combobox', {name: '분류'})`가 1개를 찾음 |
| `aria-labelledby`로 이름을 가진 입력란 | 이름 `textbox`, 역할 `textbox` | `getByRole('textbox', {name: '받는 사람'})`가 1개를 찾음 |

재현 결과: `verification/playwright-observation-gap.json`. 실제 회사 사이트의 장애를 재현한 것은 아니지만, 당시 모델에 잘못된 locator 근거를 줄 수 있는 구현 문제를 확인했다.

## 개선 순서

### 1. 관찰 정보와 locator를 일치시킨다

- 브라우저/Playwright의 accessible name과 role 계산을 우선 사용한다. 직접 계산한 `name`을 정확한 Playwright 이름처럼 전달하지 않는다.
- 현재 page/frame, 열린 dialog, 요소의 주변 제목/행, disabled/expanded 상태를 함께 제공한다. 같은 이름의 버튼은 어느 영역에 있는지 구분한다.
- 관찰 시 locator 후보가 해당 요소 1개를 실제로 가리키는지 확인한다. 유일하지 않으면 범위를 좁히거나 후보가 불명확하다고 표시한다.
- 관련 영역을 먼저 반환한다. 결과 제한에 걸리면 생략 여부와 더 볼 수 있는 범위를 알려준다. 화면 전체 덤프가 반복되어 중요한 근거가 잘리는 상황을 줄인다.
- 새 페이지/모달/화면 전환 시 관찰을 갱신한다. 좌표 동작은 최신 캡처와 viewport에 연결한다.

### 2. 스크립트 작성 계약을 정리한다

- 허용 API 명세 한 곳에서 QuickJS facade, 호스트 dispatch 검증, 모델용 안내와 예제를 생성한다. 지금은 여러 파일의 목록을 따로 유지한다.
- 실행 전 문법/명백한 미지원 API 검사를 한다. 정적 검사는 사전 피드백이고 격리 VM과 실행 시 검사를 대체하지 않는다.
- 폼 입력, 동명이인 버튼, iframe 편집기, 팝업, 동적 메뉴, 조건부 대기에 대한 짧은 예제를 필요한 시점에 제공한다.
- 보통 한 화면의 관찰된 입력/행동을 작은 단위로 묶는다. 페이지 전환 뒤 아직 보지 않은 UI까지 긴 스크립트로 추측하지 않는다. 같은 폼의 확실한 여러 입력은 한 번에 처리할 수 있다.
- 상태 대기와 검증 helper는 실제 호스트가 검사하도록 구현한다. `return {success:true}`는 완료 근거로 사용하지 않는다.

### 3. 실패를 고칠 수 있는 피드백을 제공한다

호스트가 각 명령의 실행 상태를 기록하고 다음 정보를 돌려준다.

```text
실패 명령: 3번째 클릭
대상: '임시 저장' 버튼
사유: 이름이 같은 버튼 2개
이전 명령: 받는 사람 입력 반환 / 제목 입력 반환
현재 상태: 작성 모달 유지
후보 범위: 본문 작성 모달 / 배경 목록
다음 조치: 작성 모달로 범위를 좁혀 현재 저장 상태 확인
```

- 명령을 요청함, 명령이 반환됨, 결과가 검증됨을 별도 상태로 기록한다. timeout이면 효과는 불명일 수 있다.
- 오류 코드는 미지원 API, 대상 없음, 다중 일치, 다른 요소에 가림, 노드 교체, 페이지 전환, 입력 불가, 시간 초과를 구분한다.
- 실행기의 검증된 짧은 오류만 모델에 전달한다. 인증값이나 불필요한 입력값이 포함된 원본 오류 전체를 저장하지 않는다.
- 수정은 실패 지점의 현재 상태에서 시작한다. 결과가 불명인 클릭/제출을 포함한 스크립트 전체를 자동 재실행하지 않는다.
- 재렌더링으로 분리된 대상은 명령이 아직 발행되지 않았다는 근거가 있을 때만 재관찰·재검사 후 재시도한다.
- 사용자 후속 요청에 따라 현재 모델/도구의 누적 횟수 제한은 없다. 사용자 중지, 실제 작업 시간/자원 제한과 진행 없는 반복만 구별해 처리한다.

### 4. 성공한 절차를 재사용한다

Stagehand의 관찰 결과/절차 재사용 방식을 참고한다. 저장 대상은 코드 전체와 당시의 입력값이 아니라 origin, 작업 종류, 화면 구조, 검증된 locator 전략, 매개변수, 완료 조건이다.

현재 구조와 대상의 유일성 확인 → 재사용 → 결과 재검증 순서다. 구조가 달라지면 다시 관찰하고 수정한다. 개인 입력값과 이전 작업의 권한을 새 작업에 재사용하지 않는다. 먼저 자동화 성공률을 확보한 뒤 추가한다.

## 실제 모델 평가

첫 평가판은 24개 과제를 제안한다. 16개는 개선 과정에 사용하고 8개는 프롬프트/예제에 노출하지 않은 비교용으로 남긴다. 각 과제를 동일한 모델·설정으로 3회 실행한다. 아래 숫자는 계획이며 아직 측정한 결과가 아니다.

| 과제군 | 포함할 변형 | 성공 판정 |
| --- | --- | --- |
| 메일 초안 | 포털→새 탭→iframe 편집기, 받는 사람 확인 | 실제 초안의 수신자/제목/본문 일치, 발송 횟수 0 |
| 입력 폼 | React 재렌더링, custom combobox, 자동 저장 | 앱의 저장 상태/값 확인 |
| 목록 업무 | 중복 이름, 페이지 이동, 가상 목록 | 요청한 행과 결과의 일치 |
| 메뉴/모달 | 가림 요소, 지연 등장, 같은 이름 버튼 | 올바른 대상의 상태 변화 |
| 이미지 작업 | 텍스트로 이미지 설명, 이름이 없는 아이콘 | 올바른 원본 파일과 다운로드 가능한 첨부 |
| 질문과 복구 | 필수 정보 누락, 작업 중 일부 실패 | 필요한 질문 또는 현재 상태에서 복구, 중복 실행 없음 |

모델 응답을 스크립트로 고정하지 않고 실제 선택한 AI Pro 모델에 요청한다. 실행 전 테스트 앱을 같은 상태로 되돌리며 앱 측의 저장 데이터/이벤트 카운터로 판정한다. LLM의 완료 문장이나 누비 자체 검사기의 판정만으로 합격시키지 않는다.

측정값은 최종 과제 성공률, 첫 스크립트 성공률, 실패 후 복구율, 잘못된 완료 선언, 중복 실행, API 오용, 소요 시간과 실측 토큰이다. 불필요한 질문과 필요한 질문도 구분한다.

현재 버전 → 관찰 수정 → 오류/실행 기록 → 작성 계약 → 재사용 순서로 같은 과제를 비교한다. GLM과 Qwen 중 어느 쪽이 더 낫다고 선결론을 내리지 않는다. 사용자가 선택한 모델을 유지하고 다른 제공자로 자동 전환하지 않는다. 이미지 입력은 제공자가 실제 지원하는 모델에서 별도로 평가한다.

## 구현 전달 범위

| 순서 | 주요 파일 | 완료 조건 |
| --- | --- | --- |
| P0 | `browser-agent.js`, 브라우저 fixture/평가 문서 | 위 두 관찰 불일치 재현을 회귀 검사로 전환. 이름·역할·유일한 locator가 실제 조회와 일치. 실제 모델 평가 기준선 확보. |
| P1 | `script-sandbox.js`, `browser-agent.js`, `skills.js` | API 계약 통합, 명령별 상태/구체적 오류 반환. 부분 실패 후 앞선 쓰기를 반복하지 않고 복구. |
| P2 | `agent-runtime.js`, `goal-review.js`, `context-manager.js` | 화면 전환에 따른 재관찰과 실패 유형별 복구. 전체 덤프 대신 필요한 현재 근거를 전달. 실제 모델 비교에서 효과 확인. |
| P3 | 검증된 절차 저장 모듈 | 재사용 시 사전조건과 최종결과 검증. 구조가 바뀌면 재관찰. 새 과제에서 성공률을 낮추지 않는지 비교. |

UI에 새 설정 화면이나 스크립트 편집기를 추가할 필요는 없다. 사용자는 평소처럼 요청하고, 누비는 기존 작업 표시에서 진행 상황과 필요한 질문만 보여준다. 상세 코드는 진단에 둔다.

구현자는 기존 세션/도구 권한/인증 저장 경계를 유지한다. 일반 Node Playwright, 새 로컬 서버, OpenCode 설치를 요구하지 않는다. 새 dependency를 채택할 때만 버전과 라이선스/고지 파일을 함께 기록한다.
