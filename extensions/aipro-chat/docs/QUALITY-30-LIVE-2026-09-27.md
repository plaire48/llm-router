## 평가기 수정과 판정 근거

새 과제의 시작 탭을 같은 URL의 이전 작업 탭과 혼동하지 않도록 생성 전후 탭 ID와 연결 결과를 확인한다. 결과 수집 오류 시 화면을 유지한다. 실행 도중 독립 사실 확인용 소유 탭의 DOM, 링크, 시각과 로컬 시험 상태를 기록한다. 임의 사용자 탭이나 인증 본문을 수집하지 않는다.

원본 보고서는 보존하며 `*.grades.json`, `*.delivery-adjudications.json`, `*.model-adjudications.json`에 독립 판정 근거를 둔다. E-07의 즉시 DOM 표본은 답변 미표시였지만 같은 회차 최종 스크린샷은 실제 답변을 표시한다. 뒤의 스크린샷으로 표시 여부만 정정했다. E-01과 H-05는 SSE 종료 본문 표본이 없지만 실제 제공자 요청과 Pi가 파싱해 실행한 도구 기록으로 최소 1개 모델 응답을 확인했다. 각각 fill_form의 실제 readback과 select_tools의 실행 기록을 별도 판정 파일에 남겼다. 이는 해당 과제의 성공 근거가 아니다.

모든 조건 확인이 필요하다는 통과 기준은 유지한다. 반대로 독립 증거로 필수 조건 하나가 틀렸으면 실패를 확정할 수 있으므로 미확인 나머지 조건을 임의 채점하지 않는다. 이 판정기 회귀 8개가 통과했다. 평가기 개선은 제품 성능 개선으로 계산하지 않는다.

Anthropic의 결과 중심 평가와 transcript/outcome 분리를 재사용했다. https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents
기존 Playwright, Chrome API, Node와 독립 로컬 fixture를 사용했다. 새로운 모델 심판 의존성이나 패키지는 추가하지 않았다. 실행 모델의 자체 complete와 표면상 3/3을 정답으로 채점하지 않는다.

## 현재 확인된 개선 우선순위

1. 출처 URL 식별 정보: `browser-agent.js`의 safeURL이 query를 없애 YouTube v, 뉴스 기사 ID 등을 검토 근거에서 잃을 수 있다. E-05는 실제 영상/길이를 읽고도 고유 출처 부족으로 반복했다. 민감 인증값을 보존하자는 뜻이 아니며 출처 식별과 비밀값 제거의 별도 계약이 필요하다.
2. 다중 페이지 근거와 검토 범위: M-09는 실제 방문 기록상 1~3쪽을 반복해서 읽고도 3쪽 이동 여부를 다시 물었다. M-05는 3/3 이후 최종 검토로 재계획했다. 과거 읽기 근거와 현재 조작 대상의 유효성을 구분해야 한다.
3. 승인 분류: M-08의 모달 열기가 차단됐고, 읽기 전용 M-06은 결제 질문으로 멈췄다. 모달/안내 열기와 실제 반영 경계를 실제 사이트에서 분리해 검증해야 한다.
4. 병합 표 읽기: M-04는 계획과 답변을 완료했지만 rowspan=3인 평일 운영시간을 잘못 적용했다. 독립 공식 HTML 대조로 실패 판정했다. 근거: `verification/browser-30/M-04-independent-table.json` 및 https://lib.seoul.go.kr/main/useInfo
5. 캡처 전달: E-06은 캡처 후 attach_images 오류를 반복했다. 캡처 생성과 최종 첨부 완료를 별도 검증해야 한다.
6. 불필요한 계획 확대/재질문: E-04는 검색 요약 범위도 허용된 과제에 공식 규정 원문 확인을 추가했고, M-02는 이미 지정된 정렬을 다시 물었다.
7. 탭 수명 관리: H-04 실행 중 과거 과제를 포함한 소유 탭 37개가 한 창의 한 그룹에 있었다. 그룹 통합은 확인했지만 종료 후 탭 정리가 해결됐다는 뜻은 아니다. 평가를 위한 근거 보존과 제품의 정상 종료 정책을 분리해 후속 검증한다.

H-03은 414초 동안 81회 모델 요청 후 평가기의 호출 예산을 넘겼다. `timeout`에는 시간 제한뿐 아니라 호출/무진전 제한도 포함될 수 있으므로 모든 실패를 8분 시간 초과로 설명하지 않는다. 이 실행에서 제품의 자발적인 종료와 평가기의 예산 종료를 구분한다.

H-04는 실제 `analysis_page` 하위 작업 6개를 실행하고 수집했다. 각 작업은 모델 호출 2회, 원문 읽기 1회, `delivered=true`를 기록했으며 첫 두 작업의 실행 구간은 겹친다. 다만 6개 모두 `outcome=partial`이었고 전체 작업은 최종 답변 없이 호출 예산을 초과했다. 하위 담당이 없어서 실패한 것이 아니라 부분 결과의 보완과 통합이 끝나지 않은 사례로 분류한다.

모든 개선은 이 후보의 평가 후 별도 후보에서 검증해야 한다. 위 항목은 원인/우선순위 기록이며 구현 완료를 의미하지 않는다.

## 질문과 외부 환경의 해석

H-05는 지역 확인 질문에서 멈췄다. 시작 검색어에는 서울이 있지만 목표 문장에는 지역이 명시되지 않았다. 정해진 실행에서 후보 3개를 전달하지 못해 미완수로 채점하되 질문 자체를 잘못된 행동으로 단정하지 않는다. 다음 평가 설계에서는 질문에 대한 운영자 답변을 사전에 고정하거나 목표에 지역을 명시한다. 현재 기준과 결과는 소급 변경하지 않는다.

H-06은 국립중앙도서관 공식 사이트의 접근 오류 뒤 계속할지 질문했다. 비교표가 없어 미완수이지만 외부 사이트 접근 제한과 하네스의 복구 문제를 분리한다. 무조건 재시도하거나 확인하지 못한 정보를 만들어 내는 것을 통과 조건으로 요구하지 않는다.

## 평가 중단 복구와 운영자 개입

H-08에서 제품이 `download_permission`을 반환한 뒤 평가기가 없는 `chrome.downloads.search`를 호출해 중단됐다. 제품은 이미 기술적 재시도 질문과 빈 답변, 계획 0/3을 기록했다. 원본의 `outcomeBeforeCollectionError`와 화면 상태로 중단 이전 상태만 별도 판정 파일에서 복원한다. 다운로드 완료나 파일 해시를 추정하지 않는다. 평가기는 API 부재를 명시적 수집 불가로 기록하도록 수정했다. 선택 권한이 켜진 환경의 다운로드 성능은 이번 실패로 판단할 수 없다.

H-09/H-10은 원래의 Chrome, SSO, 확장 후보와 로컬 시험 서버에서 이어 실행했다. 실행 중 모듈 해시를 다시 확인했으며 이전 28개를 재실행하거나 성공 결과로 교체하지 않았다. 추가 원본은 `verification/browser-30/continuation-H09-H10.json`이다.

H-09는 동일 대화에서 파일 선택 동의와 실제 파일/대상이 표시된 정식 승인에 각각 답했다. 그 뒤에도 원래 문서의 FileList는 비어 있었으며 또 다른 업로드 승인을 요구했다. `H09-operator-continuation.json`에 DOM 문서 ID, 승인 문구, 제출 횟수 0을 보존했다. 추가 승인 대기 뒤 실패한 상태이며 파일을 직접 주입해 통과시키지 않았다.

첫 H-10은 3분 대기 도중 17.742초에 평가기가 보내지 않은 ‘교육팀’ 답변이 들어왔다. 평가기 `answerSentAt`은 없고 실제 대화에 해당 선택 답변이 저장됐다. 입력 주체는 확인 전이지만 정해진 운영자 절차가 깨진 시도로 제외한다. 기록은 `H10-unexpected-answer.json`과 원래 continuation 보고서에 유지하고, 같은 후보에서 `H10-protocol-retest.json`으로 대기 절차를 다시 측정한다. 실패한 제품 결과를 성공 재시험으로 덮어쓰는 것과 구분한다.

유효 H-10은 180.050초 동안 같은 질문, 동일 입력값, 추가 모델 요청 없음을 확인했다. UI 답변 클릭 직후 이전 질문 메시지를 새 완료 응답으로 오인한 평가기 문제도 발견했다. 답변은 다시 보내지 않고 같은 대화의 실제 실행만 `H10-completion-continuation.json`에서 이어 관찰했다. 개발팀 반영과 완료 뒤 운영팀 정정을 한 번 전송했고, 동일 DOM 문서에서 제목 가을 교육, 팀 운영팀, 원본 메모 유지, 제출 0회를 확인했다. 최종 계획 3/3, 최종 검토 complete, busy=false와 실제 표시된 답변은 `H10-final.png`로 확인했다. 평가기는 이전 질문/답변 메시지와 다음 실행의 완료를 구분하도록 수정했다.

## 다음 후보의 완료 기준

1. 첫 단계 완료 검토가 전체 과제 조건을 요구하거나 이미 읽은 근거를 잃어 반복하는 원인을 수정한다. E-02/E-05/M-09/H-07의 재현을 먼저 통과시킨다.
2. URL 식별 정보와 출처별 읽기 근거를 보존하고 병합 표의 행/열 관계를 검증한다. M-04처럼 3/3이지만 오답인 경우를 차단한다.
3. 파일 권한 안내, 대상 검증, 실제 승인과 실행을 연결한다. H-08은 권한 설정 여부별로 나누고 H-09는 승인 한 번 뒤 실제 FileList/해시와 제출 0회를 확인한다.
4. 하위 담당의 부분 결과를 요구사항별로 보완하고 종합한다. 하위 호출 수 증가를 개선으로 계산하지 않는다.
5. 종료한 작업 탭의 보존/정리 정책을 검증한다. 한 그룹에 속해 있다는 사실만으로 탭 증가 문제가 해결됐다고 하지 않는다.

수정 후보의 같은 30개 전체 재검증에서 24개 이상 통과해야 80% 목표 달성을 주장한다. 이번 실패를 후속 성공과 섞지 않는다. 브라우저는 결과 확인을 위해 닫지 않았다.
