# 누비 1.2.0 첨부와 붙여넣기

2026-09-22. 설치 ZIP을 만들었으며 GitHub 게시나 웹 스토어 배포는 하지 않았다.

## 반영한 흐름

- 이미지, PDF, Word(docx), UTF-8 텍스트와 소스 파일을 입력창에 첨부한다. 선택, 끌어놓기와 붙여넣기는 같은 흐름이다.
- 짧은 글은 입력창에 붙여넣고 2,000자 또는 30줄 이상은 원문을 보존한 텍스트 카드로 표시한다.
- 모든 카드는 같은 높이, 아이콘 자리, 서체와 제거 버튼을 쓴다. 한 줄로 배치하며 좁은 창에서는 가로 스크롤과 Tab으로 뒤의 파일을 확인한다.
- 미리보기는 같은 CX 모달과 본문 틀을 사용한다. 일반 글과 문서는 본문 서체로, 소스는 구문 강조와 줄 번호로 읽는다. 복사와 다운로드는 오른쪽 하단에 둔다. 긴 코드 줄은 작은 창에서도 가로 스크롤로 읽을 수 있다.
- 파일 선택만으로 외부 요청을 하지 않는다. 전송할 때 선택한 모델로 텍스트/이미지를 전달한다. 이미지 미지원은 전송 전에 알리고 초안을 유지한다.
- 원본 파일은 확장 IndexedDB에 보관한다. 대화/초안과 함께 복원하며 제공자별로 분리하고 해당 대화 삭제 시 제거한다.

PDF/Word는 브라우저의 번들 파서로 텍스트만 읽는다. 그림, 도표, 배치와 OCR은 포함하지 않는다. PDF는 150쪽까지다. 메시지당 4개/8 MiB, 이미지당 4 MiB/20 MP, 원본 또는 추출 텍스트 128 KiB/4만 자를 허용한다. 원문을 임의로 자르지 않는다. 파일의 코드/HTML/매크로를 실행하거나 첨부 이미지에서 현재 페이지의 클릭 좌표를 추정하지 않는다.

## 검증

단위 테스트 277개, CX 디자인 검사, 빌드와 **Chrome 스위트 20개의 34회 실행이 최종 후보에서 통과했다.** 핵심 7개 스위트는 새 프로필로 3회 반복했다. [검증 기록](evidence/1.2.0-report.json)에 검사한 빌드와 ZIP 해시를 함께 기록했다. 변경 범위의 선택 회귀이며 전체 제품 전수 검사로 표현하지 않는다.

- 실제 Chrome의 파일 입력과 IndexedDB, 원본 다운로드 바이트, 새로고침/브라우저 종료 후 복원.
- 이미지/글/PDF/한글 DOCX 카드, 텍스트 추출, 비어 있거나 손상된 문서, 파일 개수/크기/형식 제한과 저장 실패 시 초안 보존.
- 320/360/1100px에서 카드의 높이/아이콘/글꼴 일치, 모달 제목 16px/본문 14px/단위 12px, 넘침, 초점 복귀, 가로로 숨은 카드의 Tab 접근과 긴 코드 줄 스크롤.
- Pi 도구 호출 후 이미지/텍스트 보존, AI Pro Chat Completions 이미지 입력, ChatGPT Responses input_image, FabriX 텍스트 요청, 대화 압축과 요구사항 검토의 자료 출처 구분.
- 로그인/제공자 전환, 브라우저 하네스/자동화, 사이드 패널, 대화 이력, 캡처, 이미지 선택과 다운로드, 코드 표시, OpenWiki 폴더 회귀.

초기 후보의 중단된 검사와 UI/긴 코드 줄 수정 과정의 이전 검사는 최종 통과 횟수에 합산하지 않았다. 자세한 제외 사유는 검증 기록에 남겼다.

## 확인하지 않은 범위

모델 응답과 로그인은 합성이다. 실제 AI Pro/ChatGPT/FabriX 계정이나 회사망, 모델의 판단 성능을 확인한 것은 아니다. 테스트 복사본의 사이트 권한은 미리 부여한다.

파일 입력은 Playwright의 파일 선택 API, 붙여넣기/끌어놓기는 합성 이벤트를 사용했다. 복사는 전달한 텍스트와 UI 피드백을 검사했다. 실제 OS 선택창과 운영체제 클립보드 사용을 검증한 것으로 표현하지 않는다. Word는 docx이며 HWP/HWPX, 구형 doc, OCR은 지원하지 않는다.
