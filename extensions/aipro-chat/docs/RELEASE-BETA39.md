# nubi Beta 1.0.0 — beta39

Chrome 업데이트 번호 **1.4.42**. 기존 `beta38`은 보존하고 이번 변경을 새 ZIP으로 배포한다.

## 변경

**페이지 관찰**
- 컨트롤이 많은 관찰은 행·항목·양식 단위로 묶어 조상을 한 번만 적고, 기본값(유효한 입력 검증, 역할과 같은 형식 등)은 적지 않는다. 컨트롤당 약 88토큰이 46토큰이 됐다. 컨트롤 80개 이하의 최신 관찰은 이전처럼 항목마다 모든 키를 적는다.
- 한 번에 담는 컨트롤을 180개 고정에서 크기 예산(약 1만 2천 토큰) 안의 최대 400개로 늘렸다. 30행×7일 공수 표(컨트롤 236개)가 첫 관찰에 모두 들어간다.
- 다 담지 못할 때는 대화상자, 포커스, 사용자 요청과 맞는 컨트롤을 먼저 담는다. 요청 문장은 페이지 스크립트가 볼 수 없는 격리된 실행 환경에만 전달한다.
- 표의 입력칸에 열 제목(날짜)을 붙인다. 병합된 머리글도 반영한다. 체크박스나 별표로 시작하는 메일 목록 행, 반복되는 `div`·`li` 행도 행의 글자로 이름을 붙인다.
- 클래스 이름에 드러난 상태(starred, unread, on, active 등)를 행과 컨트롤에 싣는다. 상태 클래스가 붙은 행이 목록 행에서 빠져 이름을 잃던 결함을 고쳤다.
- 본문 추출이 데이터 표를 버리는 페이지에서는 표를 담은 영역을 읽는다.

**클릭**
- 다른 요소가 대상을 덮으면 대상을 화면 가운데로 옮겨 다시 찾는다. 대상의 모든 점을 같은 요소가 받고 그 요소가 대상을 대신할 때만(대상의 라벨, 안을 채운 컨트롤, 같은 행의 같은 목적지 링크, 행 자체) 그 요소를 누른다. 승인이 필요한 요소는 누르지 않는다.
- 누를 수 있는 점이 없으면 가운데를 누르지 않고, 무엇이 덮었는지(대화상자, 고정 막대, 같은 행의 다른 컨트롤) 알린다. 이전에는 가운데를 눌러 행 안의 삭제 버튼이 눌릴 수 있었다.
- 마우스를 올리면 나타나는 도구 때문에 행 이름이 바뀌어 "페이지 변경됨"으로 실패하던 문제를 고쳤다.
- 링크와 행은 20자 이하 문구가 동작 단어로 끝날 때만 최종 동작으로 본다. 제목이 "승인"으로 끝나는 메일을 열 때 승인을 요구해 "초안 검증 필요"가 반복되던 문제를 고쳤다. "반영, 승인, 확정, 결재, 상신"으로 끝나는 버튼은 최종 동작으로 본다.

**검증**
- 검증 결과 항목마다 칸의 이름·행·열을 적는다. 값은 적지 않는다.
- `fields_unchanged`: 이번 작업이 쓴 칸을 뺀 페이지의 모든 칸이 처음 본 값 그대로인지 한 번에 확인한다. 칸을 쓴 뒤의 모든 검증에 이 결과를 함께 적는다.
- 최종 동작을 승인한 뒤 이어서 실행할 때도 처음 본 값과 쓴 칸의 기록을 이어 간다. 값은 페이지 밖으로 나가지 않고 한 방향 표식만 쓴다.

**검토**
- 최종 검토 횟수는 조건 대부분을 충족한 회차만 센다(전체 6회 상한).
- 입력칸 내용처럼 관찰할 수 없는 조건은 검토가 요구하지 않는다.
- 범위 감사가 한 실행에서 연속 2회 실패하면 그 뒤로는 건너뛴다. 범위 감사가 최종 동작 전 승인 단계를 문제 삼으면 그 지적은 버린다. 승인 절차 자체는 그대로다.

**화면 캡처**
- 긴 페이지는 구간별로 찍어 한 장으로 잇고, 크기 한도를 넘으면 전체를 유지한 채 축소한다. 상한은 2,400만 화소로, GPT-5.6이 거절하는 크기보다 작다.
- 찍힌 크기가 측정한 크기와 조금 달라도(32픽셀 또는 2% 이내) 캡처를 버리지 않는다.
- `capture_page`에 `ref`를 주면 요소 하나를 여백과 함께 찍고, 작으면 최대 3배로 확대한다. `marks=true`는 화면 캡처에 관찰된 컨트롤의 번호 상자를 그리고, 번호를 참조와 함께 목록으로 준다.

권한과 콘텐츠 보안 정책은 beta38과 같다. 새 필수 권한은 없다.

## 설치와 업데이트

ZIP을 풀고 `chrome://extensions`에서 개발자 모드의 **압축해제된 확장 프로그램 로드**를 선택한다. 기존 사용자는 **같은 설치 폴더**의 파일을 교체하고 확장을 새로고침한다. 폴더를 바꾸면 확장 ID와 저장된 대화가 달라질 수 있다. 웹 스토어 배포본은 아니다.

## 검증 범위

GATE_RESULT

UPGRADE_RESULT

단위 검사 UNIT_RESULT. 운영 의존성 점검에서 보고된 취약점은 AUDIT_RESULT개다.

실제 모델(GPT-5.6 Sol, ChatGPT 로그인) 실측은 과제별 1회 실행이다. 로컬 평가 페이지 과제는 페이지의 실제 상태로 채점했다. beta39는 개발 후보 38에 버전 번호만 바꾼 빌드다.

| 과제 | 후보 37 | beta39(후보 38) | 페이지 상태 채점 |
|---|---|---|---|
| 업무 시스템 공수 표(210칸, 두 칸 입력 후 승인·최종 반영) | 승인 단계 교착으로 멈춤 | 완료 97초 | 3/3 |
| 60행 메일함(한 통만 중요 표시, 열어서 답하기) | 완료 80초 | 완료 60초 | 3/3 |
| 프레임과 같은 이름 구분 | 완료 68초 | 완료 45초 | 3/3 |
| 조건부 모달 작성 | 완료 126초 | 완료 95초 | 4/4 |
| 뉴스 원문 읽기 | 완료 88초 | 완료 90초 | 공개 사이트 |
| 현재 화면 캡처 | 측정 안 함 | 완료 34초 | 공개 사이트 |

업무 시스템 공수 표 과제는 후보 32에서 179초, 후보 36에서 109초였다.

## 알려진 한계

- 요청 문장에 대상이 없고 현재 페이지에만 있으면(예: 검색 결과 페이지에서 "뉴스로 이동해 최근 1주를 적용해 줘") 페이지를 보기 전에 대상을 되묻는 경우가 있다. 일반 대화에서는 브라우저 도구를 쓰기 전까지 현재 탭의 제목과 주소를 모델에 보내지 않기 때문이다.
- 컨트롤이 400개를 넘는 페이지를 디버거로 관찰할 때는 요청 기반 순서를 쓰지 않는다. 잘렸다는 안내에 따라 행·열 이름으로 다시 관찰한다.
- 안쪽 스크롤 영역에 있는 목록은 전체 페이지 캡처에도 보이는 부분만 담긴다.
- 사내 모델로는 이번 변경을 실측하지 않았다.
