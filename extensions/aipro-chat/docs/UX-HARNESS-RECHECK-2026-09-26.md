# 누비 사용 흐름 7개 개선

사용자 요청을 아래 순서로 구현하고 실제 Chrome에서 검증한다. 배포 전 전체 gate와 실계정 모델 성능은 별도다.

| 번호 | 요청 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 1 | 기존 누비 탭 재사용 | 전체 화면 중복 생성 방지, 같은 소유 작업 탭 재연결 시 복제하지 않음 | 구현 및 합성 회귀 통과 |
| 2 | 첫 입력창 하단 | 빈 대화/입력 중/답변 뒤 모두 하단, 작은 화면 넘침 없음 | 구현 및 합성 회귀 통과 |
| 3 | 첨부파일 설정 문구 | 티켓 용어 제거, 짧은 첨부파일 설정 이름 | 구현 및 합성 회귀 통과 |
| 4 | 폼 글자를 눌러 수정 | 별도 연필/모달 없이 원문 재조회 후 인라인 편집, 반영 뒤 재검토/승인 유지 | 구현 및 합성 회귀 통과 |
| 5 | 실제 하위 분석과 문맥 관리 | 원 요청 보존, 실제 워커 호출과 인계/압축 근거 확인 | 구현 및 합성 회귀 통과 |
| 6 | 맨 아래 이동 | 위를 읽을 때 원형 버튼, 동적 크기 변경 대응, 읽는 위치 보존 | 구현 및 합성 회귀 통과 |
| 7 | 과도한 모델 대기 | 정상 스트림과 실제 응답 지연 구분, 근거 기록 유지 | 구현 및 합성 회귀 통과 |

## 적용 기준

기존 Pi, p-limit, DeepAgents, MiniSearch와 CX를 유지하고 실제 결함에 해당하는 방법론을 적용한다. 질문/승인과 쓰기 권한을 넓히지 않는다. 같은 이름의 탭을 소유권으로 취급하지 않는다. 단순히 모델 호출을 병렬화하거나 대기 기록을 지워 성능 개선으로 표현하지 않는다.

## 화면 스크롤 참고

[use-stick-to-bottom](https://github.com/stackblitz-labs/use-stick-to-bottom)의 MIT 공개 구현은 ResizeObserver로 콘텐츠 변경을 추적하고 사용자 스크롤 시 추적을 중단한다. 누비는 이미 스크롤 위치/대화 전환/하단 이동 제어를 갖고 있으므로 관찰 패턴을 기존 경로에 적용한다. spring 애니메이션과 두 번째 스크롤 상태 관리 라이브러리는 추가하지 않는다. 확대/축소, 펼침, 이미지 로딩과 입력창 높이 변화까지 확인한다.

## 수정 내용과 근거

1. `runtime.getContexts()`로 기존 누비 탭을 찾는다. `tabs.query()`만 사용하면 `tabs` 권한이 없는 정상 설치에서 자체 화면 URL도 숨겨져 중복 탭이 열렸다. 추가 권한 없이 현재 문서와 탭 ID를 확인한다. 같은 소유 작업 탭이나 원본의 재연결은 기존 작업 공간을 유지한다. [탭 조사](TAB-REUSE-2026-09-26.md).
2. 빈 대화에만 적용되던 중앙 배치를 제거했다. 첫 화면부터 입력창은 하단이며 캐릭터와 배경은 기존 토큰을 유지한다.
3. 저장 설정 제목은 **첨부파일 설정**이다. 불필요한 티켓 설명을 제거하고 저장 폴더 선택/변경의 접근성 이름은 유지한다.
4. 승인 미리보기의 글자를 누르면 같은 카드에 검증된 전체 원문을 가져와 해당 항목에 초점을 둔다. 축약 미리보기를 원문으로 사용하지 않는다. 수정 중 최종 등록 대신 **수정 반영**을 표시하며 수정 반영 뒤 페이지 재검증과 새 승인을 요구한다. 접어도 작성 중 값은 유지한다.
5. 질문 재개 시 내부 체크포인트를 원 목표로 오인하는 경로와 호스트의 ‘사용자 수정 요청’ 접두사가 비교 분석을 끄는 경로를 수정했다. 하위 호출이 리더 상태를 덮지 않는다. [OpenCode/Codex/Claude/OpenAI 비교와 실제 호출 검사](MODEL-WAIT-AND-DELEGATION-2026-09-26.md).
6. 위를 읽을 때 원형 아래 화살표를 표시한다. [use-stick-to-bottom 공개 훅](https://github.com/stackblitz-labs/use-stick-to-bottom/blob/main/src/useStickToBottom.ts)의 사용자 이탈/크기 관찰 패턴을 기존 ResizeObserver 기반 처리에 반영했다. 기존 하단 추적 상태를 재사용하며 별도 패키지는 추가하지 않았다. 버튼은 대화 아래의 일정한 조작 공간에 둬 폼을 가리지 않고, 표시 여부가 바뀌어도 클릭 대상 위치가 움직이지 않는다.
7. 정상 스트리밍 중에도 요청 시작 15초 뒤 나타나던 대기 안내를 실제 무응답 15초로 수정했다. 모델 활동이 재개되면 같은 대기 항목을 종료한다. 실제 지연은 숨기지 않으며 계획/검토/하위 분석/문맥 정리의 대기를 구분한다.

## 검증 경계

독립 회귀는 실제 Chrome에 후보 확장을 로드하고 합성 사이트/모델 응답을 사용한다. 두 하위 워커와 전송 경로가 동작하는 증거는 실제 모델의 응답 품질이나 시간 개선과 다르다. 문서 분할/근거 압축은 기존 회귀로 확인하며 모든 요청을 자동 병렬화하지 않는다. 공통 승인 UI의 브라우저 경로를 검사했으며 Office 호스트는 별도 검증 대상이다. 후보 ZIP만 생성하며 기존 배포 파일은 교체하지 않는다.
