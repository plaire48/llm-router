# OpenWiki 브라우저 직접 연결

2026-09-24: 모델 실행 구조는 [위키별 OpenWiki 위임](OPENWIKI-AGENT-DELEGATION.md)을 따른다. 내장/외부 실행기는 확장에 포함되며 문맥은 별도, LLM 연결은 현재 누비와 같다. 아래 서버 API 설명은 문서 수집과 선택 소스 조회에 관한 계약이다.

## 기본 흐름: 설정에서 폴더 선택

현재 설정의 **OpenWiki 폴더**에서 `openwiki` 폴더 또는 그 폴더를 포함한 프로젝트를 선택한다. 브라우저가 읽기 권한을 받은 뒤 폴더 핸들을 확장 IndexedDB에 보관한다. 폴더 경로 문자열 입력, 서버 실행, 매번 프로젝트 연결은 필요 없다. 프로젝트를 선택하면 하위 `openwiki` 폴더로 범위를 좁힌다.

사용자 요청 → `ask_openwiki(external)` → 같은 모델의 독립 OpenWiki 실행기 → 문서를 근거로 내용 작성 → 브라우저 입력/조작 → `verify_page`. 최종 등록/발행은 기존 승인 흐름을 유지한다. 문서 조회만 하고 사용자가 요청한 페이지 작업을 끝냈다고 답하지 않는다.

폴더에서는 Markdown 문서만 읽으며 원본 저장소 코드, 명령 실행, 파일 쓰기를 제공하지 않는다. 전체 폴더를 모델에 전송하지 않고 필요한 검색 결과와 줄 범위만 보낸다. 매 요청에서 현재 파일을 읽고 해시를 계산한다. 선택/변경은 UI의 사용자 제스처에서 시작하고, 임시 핸들은 실행 작업과 직렬화된 worker 검사를 거쳐 활성화한다. 실행 중에는 폴더 변경/해제를 막으며 도구는 해당 연결 ID에 묶인다.

폴더 설정은 새로고침과 브라우저 재시작 후에도 남는다. 읽기 권한은 브라우저 정책에 따라 다시 허용해야 할 수 있으며 설정에 복구 동작을 표시한다. 권한이 없을 때 다른 프로젝트나 서버로 조용히 전환하지 않는다. 사이드 패널에서 선택창을 지원하지 않으면 전체 화면 설정으로 이동해 선택한다.

근거: [Chrome의 폴더 선택과 핸들 저장/권한 문서](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access).

## 선택 기능: 로컬 서버 연결

아래는 1.1.0의 서버 방식이다. 현재 소스코드 조회가 필요할 때 설정에서 선택할 수 있으며 폴더 검색의 필수 조건이 아니다.

상태: 2026-09-22 누비 1.1.0 / OpenWiki-SDS 0.6.0에 읽기 연결 구현. 통합 검증 결과는 별도 검증 기록을 따른다.

## 방향

누비의 확장 service worker가 실행 중인 로컬 OpenWiki 서버에 HTTP 요청을 보낸다. 기존 OpenWiki 서버에 읽기 기능을 더하며, 별도 연결 프로그램이나 LLM Router를 필수로 만들지 않는다. OpenWiki는 지식 연결이며 AI Pro/ChatGPT/FabriX 모델 선택과 분리한다.

```text
사용자 요청 → 누비의 도구 선택 → 확장 worker → OpenWiki HTTP API
                          ↓
                 필요한 문서/소스 발췌
                          ↓
              기존 모델이 DOM/화면과 함께 판단
```

OpenWiki 탭을 계속 열어둘 필요는 없지만 로컬 OpenWiki 서버는 실행 중이어야 한다. 확장이 로컬 프로그램을 자동 실행한다고 안내하지 않는다. 일반 브라우저 자동화는 OpenWiki 없이도 유지한다.

## 이미 있는 기능과 추가할 기능

| 범위 | 현재 상태 | 연결 방식 |
| --- | --- | --- |
| Wiki 본문과 문서 관계 | `GET /api/graph`에 `nodes[].body`, `links`, `backlinks` 제공 | 작은 Wiki는 한 번 읽고 확장에서 검색/발췌 |
| 정적 Wiki | 정적 내보내기의 `graph.json` 제공 | 문서 조회만 지원하는 별도 연결 모드로 후속 지원 가능 |
| 문서 검색/부분 조회 | 인증된 검색/줄 범위 API 구현 | 필요한 발췌만 조회 |
| 최신 프로젝트 소스 | 명시한 project-root 안에서 읽기 구현 | 파일 검색/줄 범위/현재 해시 조회 |
| 수정/명령 실행/빌드 | API 없음 | 이번 읽기 연결에 포함하지 않음 |

근거: OpenWiki의 `src/visualize/server.ts`, `graph.ts`, `static-export.ts`. 기존 `/api/graph`는 Wiki 문서이며 프로젝트 소스 전체가 아니다. `generatedAt`은 그래프 구성 시각이므로 코드 최신성/문서 검증 시각으로 사용하지 않는다. 현재 그래프에는 상세 source Claims와 파일 버전이 빠져 있다.

## 사용자 흐름

1. 로컬 OpenWiki 페이지에서 누비의 **프로젝트 연결**을 선택한다. 현재 탭의 주소를 후보로 사용하고 서버 식별 응답을 확인한다. 포트 전체를 검색하지 않는다.
2. 첫 연결에서 사이트 접근과 프로젝트 읽기를 허용한다. 서버와 일회 연결 후 세션 토큰을 확장에 보관한다.
3. 채팅에는 프로젝트 이름만 표시한다. 주소와 상세 진단은 연결 화면에만 둔다.
4. “이 화면의 저장 버튼은 어디에서 처리해?”처럼 요청하면 Wiki 검색 → 관련 소스 읽기 → 현재 화면 확인으로 진행한다.
5. 파일/줄과 Wiki 출처를 답변에 붙인다. 화면과 코드의 직접 매핑이 없으면 후보로 설명한다. 서버가 종료되면 재연결을 안내하며 대화는 보존한다.

첫 버전은 현재 OpenWiki 서버가 연 프로젝트 하나를 연결한다. 프로젝트 목록 관리나 추가 툴바를 먼저 만들지 않는다. 주소를 자동 인식하지 못한 경우에만 연결 주소를 입력받는다.

## UI와 CX 기준

사용자 제공 `agentfactorysdkdeck.html`, [시각 기준](VISUAL-STANDARD.md), [CX UI 스킬](../.agents/skills/cx-ui/SKILL.md)을 구현 기준으로 사용한다. HTML의 분위기/색감/움직임을 `design/agent-deck.css` 토큰으로 적용하고 설치된 CX의 공개 컴포넌트와 키보드/초점 동작을 재사용한다.

- 기존 채팅 안에서 연결하고, 연결 후에는 프로젝트 이름이 담긴 작은 칩을 표시한다. 포트와 로컬 경로를 상시 노출하지 않는다.
- 연결 화면은 기존 `deck-dialog`를 사용한다. 자동으로 찾은 프로젝트와 지금 필요한 입력/동작만 보여준다. 문구는 핵심 문장과 필요한 설명만 남긴다.
- Noto Sans KR, 제목 16px, 본문/입력/버튼 14px를 유지한다. 직관적인 조작은 아이콘과 툴팁을 사용하고, 프로젝트 이름과 모호한 동작에는 짧은 텍스트를 남긴다.
- 옅은 블루/보라/민트, 흰 모달, 기존 누비 캐릭터와 부드러운 전환을 유지한다. 모달은 처음부터 불투명하게 표시하고 모션 감소 설정을 따른다.
- 연결 중/성공/실패는 실제 요청 결과와 일치시킨다. 성공 토스트는 상단, 재시도가 필요한 오류는 연결 화면에 남긴다. 연결되지 않은 상태를 성공 아이콘으로 표시하지 않는다.
- 320px/360px/큰 창에서 입력, 오류, 연결 완료, 재연결과 펼친 진단까지 시각 확인한다. `design:check`, 빌드와 실제 확장 브라우저 검사를 완료한다.

## 구현 계약

아래 API와 도구를 구현했다. `/api/nubi/v1/info`는 자료 없이 프로토콜을 확인한다. 시각화 HTML의 일회 코드는 5분, 연결 세션은 8시간 유효하다. 서버 재시작과 브라우저 종료 후에는 다시 연결한다.

| API | 역할 |
| --- | --- |
| `GET /api/nubi/v1/info` | 프로토콜 버전과 지원 기능만 반환. 인증 전 파일/프로젝트 경로는 노출하지 않음 |
| `POST /api/nubi/v1/pair` | 일회 연결 코드 교환. 코드 만료/일회 사용, 프로젝트 범위의 세션 발급 |
| `POST /api/nubi/v1/wiki/search` | 검색어와 limit으로 관련 Wiki 발췌 조회 |
| `GET /api/nubi/v1/wiki/page?id=...` | Wiki 원문과 출처/버전 조회 |
| `POST /api/nubi/v1/source/search` | 허용 프로젝트 안에서 코드 위치 검색 |
| `GET /api/nubi/v1/source?path=...&start=...&end=...` | 상대 경로, 줄 범위, 현재 파일 해시와 실제 읽은 범위 반환 |

큰 Wiki에서 `/api/graph` 전체를 매번 다운로드하거나 모델에 보내지 않는다. 검색은 상위 5개, 소스는 기본 200줄 이내로 발췌하며 더 필요한 범위만 추가 요청한다. Wiki만 연결된 경우에는 소스 도구를 노출하지 않는다.

누비는 `wiki_search`, `wiki_read`, `source_search`, `read_source`를 기존 Pi 루프에 등록한다. 프로젝트 도구는 `RUN_TOOL`의 작업 소유권/허용 도구 검사 이후, 브라우저 페이지 연결 검사 이전에 처리한다. 코드 질문에 페이지 연결이나 debugger를 요구하지 않는다. 조회 자체는 HTTP 요청이며 브라우저 조작 도구와 구분한다.

## 통신과 프로젝트 범위

- `public/manifest.json`의 HTTP connect-src는 `localhost`와 `127.0.0.1`만 허용한다. CSP 문법에서 지원하지 않는 IPv6 리터럴을 직접 연결 주소로 받지 않는다. 로그인 콜백의 IPv6 탐색 규칙과는 별개다. 연결 버튼에서 해당 origin의 사이트 권한을 요청한다. 기존 로그인 수신을 위해 이미 허용된 loopback 사이트는 권한 창이 생략될 수 있다. 읽기 권한은 별도로 페어링한 프로젝트에 묶는다.
- 로컬 서버는 `127.0.0.1`에만 바인딩한다. 주소의 host/port와 서버 식별을 확인하고 다른 목적지로의 redirect를 따르지 않는다.
- 자료 API는 연결 토큰을 검사한다. 토큰은 trusted extension session storage에 두며 모델, 진단, 페이지에는 전달하지 않는다. 현재 `/api/graph`의 인증 없는 시각화 경로를 그대로 최신 소스 공개 API로 확대하지 않는다.
- 프로젝트 root는 서버가 선택/고정한다. 소스 API는 realpath 범위, 외부 symlink, 제외 파일, 비밀 파일, 크기와 줄 제한을 검사한다. 원격 URL 프록시와 쉘 명령 API를 추가하지 않는다.
- 일반 웹페이지/content script가 임의 URL이나 경로를 지정해 worker에게 조회를 시키지 못하게 한다.
- 읽은 문서와 코드는 참고 데이터다. 내부 문장을 새 사용자 지시로 실행하지 않는다. 필요한 발췌가 현재 선택한 모델로 전달된다는 점은 첫 연결에서 짧게 안내한다.

Chrome 공식 근거: [확장 HTTP 요청과 CSP](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests), [선택적 사이트 권한](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions).

## 실행하기

OpenWiki-SDS 0.6.0으로 Wiki 서버를 시작한다. Wiki 폴더와 읽을 프로젝트 폴더를 명시한다.

```sh
openwiki visualize /path/to/project/openwiki --project-root /path/to/project
```

`--project-root`를 생략하면 Wiki만 제공하며 누비에 소스 도구를 노출하지 않는다. 누비 채팅 입력창의 코드 아이콘에서 연결한다. 현재 탭 주소를 찾지 못하면 서버 주소를 입력한다. 필요하면 해당 OpenWiki 탭을 열고 연결하며 별도 코드를 복사할 필요는 없다.

## 완료 조건

1. 로컬 OpenWiki 서버의 읽기 API와 인증 계약을 만든다.
2. 확장의 연결 UI/worker 클라이언트/프로젝트별 도구를 연결한다.
3. 실제 설치된 확장에서 연결 → 검색 → 소스 인용 → 화면 비교를 검증한다.

첫 완료 시나리오는 “열린 화면의 저장 버튼을 찾아 관련 파일과 줄을 설명하기”다. Wiki만 있을 때 원본 소스를 읽었다고 답하지 않고, 파일 변경 후 다시 읽으면 새 해시/내용을 반환해야 한다. 서버 종료, 권한 거부, 만료 토큰, 경로 탈출, 여러 프로젝트 혼동, 페이지 없이 코드 질문, 브라우저 재시작/재연결을 함께 검사한다.

소스 수정·빌드·미리보기는 이 읽기 경로가 검증된 뒤 기존 [개발 연계 설계](OPENWIKI-LOCAL-DEVELOPMENT.md)의 별도 변경/검증 단계로 진행한다.
