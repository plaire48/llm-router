# 결과를 보고 다음 행동을 고르는 누비

사용자 요청을 작은 단계로 나누고, 각 도구의 실제 입력과 결과를 다음 모델 요청에 전달한다. 모델은 관찰한 결과에서 남은 행동을 고른다. 작업 계획은 고정 실행 목록이 아니며 화면 변화와 오류에 맞게 수정한다.

## 비교한 방법

2026-09-22에 공식 문서와 구현을 확인했다. 아래 선택은 누비의 확장 단독 실행 조건에 대한 판단이며, Qwen에서의 성능 순위를 입증한 결과가 아니다.

| 근거 | 누비에 적용하는 원칙 | 적용 방식 |
| --- | --- | --- |
| [ReAct 논문](https://arxiv.org/abs/2210.03629) | 판단과 행동을 번갈아 수행하며 외부 결과로 계획을 조정 | 다음 모델 호출이 직전 도구 입력과 출력을 비교한 뒤 다음 행동을 선택 |
| [Pi 실행 루프](https://github.com/earendil-works/pi/blob/main/packages/agent/src/agent-loop.ts) | 대화 상태, 도구 호출과 결과, 사전 실행 검사, 진행 이벤트 | 이미 설치한 `@earendil-works/pi-agent-core@0.86.1`의 `beforeToolCall`을 사용. 순차 실행만으로는 호출 사이 모델 판단이 생기지 않으므로 첫 실제 도구 뒤 나머지 제안을 보류 |
| [Browser Use 단계 구현](https://github.com/browser-use/browser-use/blob/main/browser_use/agent/service.py) | 현재 브라우저 상태와 이전 결과를 준비하고 다음 행동을 선택하며 오류를 피드백 | 기존 DOM/캡처 결과와 부분 실행 기록을 같은 Pi 대화에 유지. 패키지를 새로 번들하지 않고 관찰과 재판단 구조를 참고 |
| [Stagehand observe](https://docs.stagehand.dev/v3/basics/observe) | 관찰된 행동 후보를 검토한 다음 실행 | 기존 의미 기반 ref와 Playwright facade 유지. 관찰되지 않은 대상의 추측 실행을 허용하지 않음 |
| [LangGraph interrupt](https://docs.langchain.com/oss/javascript/langgraph/interrupts) | 중단 후 재개 시 부수 효과가 중복되지 않도록 승인과 실행을 분리 | 기존 질문/HITL과 일회 승인, 실행 기록 기반 재개를 유지. LangGraph 의존성은 추가하지 않음 |

Pi 최신 main의 추가 API를 설치 버전에 있는 것으로 가정하지 않았다. 이 변경은 설치된 실행기와 회귀 검사에서 확인한 훅만 사용한다. 외부 소스 코드를 복사하거나 다른 런타임을 설치하지 않는다.

## 이번에 바꾼 동작

1. 읽기 전용 스킬에도 도구 결과 후 재판단 규칙을 적용한다. 도구를 여러 개 제안해도 첫 실제 작업의 결과를 모델이 읽기 전에는 후속 작업을 실행하지 않는다. 기존 권한과 검증 도구 범위는 유지한다.
2. 다음 모델 요청에 직전 작업의 반환/실패/부분 실행 상태를 전달한다. 실제 도구 호출과 결과는 쌍으로 보존하며, 이미 반영한 내용을 다시 쓰지 않고 남은 부분만 처리하도록 한다.
3. 페이지를 변경한 단계는 `verify_page`가 통과하기 전에 새 완료 표시를 저장하지 않는다. 미완료 계획 수정과 실제 검증은 계속할 수 있다.
4. Pi 사전 검사를 통과한 도구만 실행 중으로 표시한다. 보류한 호출이나 이전 오류 때문에 실행하지 않은 호출에 가짜 스피너/실패 기록을 만들지 않는다.
5. 공개 진행 설명은 의미 있는 확인 결과와 다음 행동만 짧게 남긴다. 모델의 내부 reasoning 필드나 원시 입력/출력을 UI와 진단에 저장하지 않는다.

예를 들어 제목과 본문 입력 요청은 화면 확인 → 초안 입력 → 실제 값 확인 → 계획 갱신 → 최종 요구사항 검토로 진행한다. 검증이 실패하면 새 관찰과 오류를 모델이 읽고 해당 부분만 고친다. 필요한 사용자 선택은 질문 폼에서 받고 최종 등록/발송은 기존 HITL에서 승인받는다.

## 검증 기준

- 첫 페이지 결과에 답이 있으면 미리 제안한 추가 읽기는 실행되지 않는다.
- 입력 성공 직후 계획 완료를 제안해도 실제 결과 확인 전에는 완료 개수가 늘지 않는다.
- 실패한 코드 뒤의 추측 입력은 실행되지 않으며, 다음 모델 호출이 오류와 관찰을 받아 방법을 바꾼다.
- 부분 실행이나 복구 중에 이미 완료한 입력을 반복하지 않는다.
- 질문에는 실행을 멈추고, 답변 후 원래 목표를 유지한다. 승인 없는 최종 발송을 실행하지 않는다.
- 중간 설명, 계획, 실제 실행 상태가 좁은 창과 넓은 창에 보이고 이력/새로고침 후 복원된다.

합성 모델 응답으로 분기와 브라우저 동작을 확인하는 회귀 검사와 실제 Qwen 평가를 구분한다. 실모델 기준은 `QWEN3.8-27B-FP8-256K`이며 `npm run eval:agent`는 전용 환경변수가 설정된 경우에만 격리된 평가 페이지를 사용한다. 성공률은 요청별 최종 DOM 상태, 잘못된 변경/중복 실행 여부와 답변 근거로 평가한다. LLM 검토가 성공을 선언한 것만으로 정확도를 기록하지 않는다.

이번 후보는 단위 319개, Chrome 11개 스위트 25회와 창을 띄운 진행/질문 시나리오 1회를 통과했다. 핵심 7개 스위트는 새 프로필로 각각 3회 실행했다. 실모델 평가는 인증 환경변수가 없어 `not_configured`로 남겼다. [검증 보고서](evidence/beta-1.0.0-stepwise/report.json)와 [요약](evidence/beta-1.0.0-stepwise/summary.json)에 범위와 해시를 기록했다.

배포 식별자는 `1.0.0-beta.10`, Chrome 버전은 `1.4.13`, 표시 이름은 `Beta 1.0.0`이다. 검증한 ZIP의 SHA-256은 `9beea3a6e13523be696f1740302ee890fd74192c18b946d0696d56f838f891c4`이며 재빌드 없이 승격한다.
