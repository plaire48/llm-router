# 검토 실행 근거 전달과 후속 검증

2026-09-28. 사용자의 계속 검증·보완 요청으로 이전 5개 실측의 E-07/E-08을 이어서 점검했다. 이전 전체 점수는 답변 전달 4/5, 독립 과제 통과 2/5이며 이번 고정 입력 검사로 바꾸지 않는다.

## 반영한 변경

- `src/api.js`가 결과 검토에 실제 포함된 사용 가능한 `execution_receipt`를 범위 감사에도 전달한다. 모델의 실행 요약을 새 영수증으로 만들지 않는다. 범위 감사는 그 사본을 고정하고 문맥 한도 초과 시 기존 비완료를 유지한다.
- `review-scope.js`의 첫 요청부터 검사 항목 target과 그 항목에서 사용할 인용 anchor ID 대응을 명시한다. 실모델이 target에 anchor ID를 반환했던 형식 오류의 예방 조치다. 엄격한 기존 파서는 유지하며 잘못된 ID를 추정해서 교정하지 않는다.
- `goal-review.js`의 상충하는 읽기 전용 지침을 정리했다. 실제 agent 동작과 명시적 금지를 비교하며 전역 서버 상태 불변을 새로 요구하지 않는다. 저장 결과와 미확정 쓰기는 여전히 실제 상태 증거가 필요하다.
- 공개 페이지 평가의 `evaluation-public-read.mjs`에 모델에게 제공된 구조화 표를 추가했다. 날짜/값/행/열/span과 원본 및 수집 누락을 보존한다. 허용된 공개 URL에서만 opt-in으로 수집하며 refs, 입력 value, 임의 필드를 버린다. 이 변경은 제품의 일반 로그를 늘리지 않는다.

## 방법과 선택 근거

[기존 방법론·출처 검토](SOURCE-SCOPE-REPAIR-2026-09-28.md)를 재사용했다. Anthropic의 실제 실행 기록과 결과를 분리하는 평가 방식, 기존 Codex식 도구 계약 검증, agent-browser의 문서/관찰 식별 보존이 이번 판단의 근거다. 추가 프레임워크나 외부 런타임은 도입하지 않았다. Claude 배포 코드/프롬프트는 복사하지 않았다. 원래 지시·실행 근거·평가 결론을 분리하고 같은 입력의 실패/성공을 함께 남겼다.

## 실모델 재검사와 한계

전용 평가 Chrome의 기존 ChatGPT 로그인에서 GPT-5.6 Luna로 5개 고정 입력 유형을 버전별 3회 실행했다. 인증은 확장 안의 기존 어댑터로만 사용했고 인증값을 다른 프로필이나 파일에 복사하지 않았다. 테스트 모듈을 별도 파일로 추가했으며 기존 에이전트 작업을 재실행하거나 창을 닫지 않았다.

`verification/review-dispatch-2026-09-28/{v1,v2,v3}/`에 입력, 번들 해시, 응답 JSON, 파서 결과와 시간 기록이 있다. 고정 원문은 E-07 sequence 380이며 E-08 sequence 604의 마지막 검토를 사용했다. **E-08의 당시 후보 답변 전체와 원래 모델 요청은 저장돼 있지 않다.** 빈 후보 답변과 저장된 도구 시작 사건으로 재구성한 영수증을 사용한 축소 재현이며 원래 실행의 완전 재생이 아니다. v3에는 실제 UI에서 다시 확인한 원래 읽기 전용 부가 지시를 포함했다. v1/v2와 v3의 결과를 엄밀한 동일 입력 A/B로 비교하지 않는다.

| 검사 | v2 결과 | 의미 |
|---|---:|---|
| E-08 마지막 검토의 범위 교정 | 0/3 교정 | `unknown` 유지. 정체 해결을 확인하지 못함 |
| 명시적 클릭 금지 + 미확정 클릭 | 3/3 비완화 | 금지 조건을 삭제하지 않음 |
| 저장 결과 미확정 + 재전송 금지 | 3/3 비완화 | 불확실성을 완료로 바꾸지 않음 |
| E-07 고정 원문의 올바른 날짜/값 답변 | 3/3 complete | 축소된 검토 입력에서의 판단 |

v1에서는 올바른 날씨 답변을 1회 잘못 거절했고, E-08 검사에서 최초 형식 오류 후 판단이 바뀌었다. v3의 실험적 `execution_evidence_conflict` 분기는 E-08 교정을 개선하지 못해 **최종 코드에서 제외**했다. v3 코드/번들은 실패 실험 기록으로만 보관한다. 모델이 실제 공개 사이트를 탐색하고 정답을 사용자에게 전달한 성공률은 이 표로 측정하지 않았다. 최종 코드의 검토 계약은 v2이며 표 수집은 후속 실측 진단용 추가 변경이다.

## 로컬 검증 중 발견한 별도 문제

초기 전체 검사에서 지침 증가로 두 원문의 문맥 보존 검사가 실패했다. 지침을 짧게 정리하고 원문 예산과 엄격한 보존 검사를 유지해 재검사했다.

전체 검사 중 Wiki 하위 조회 이벤트의 최초 도착 순서를 첫 원문 범위로 가정하는 검사가 실패했다. 독립 워커는 시작 순서가 바뀔 수 있으므로 범위 0의 배정으로 해당 이벤트를 찾아 검증하도록 수정했다. 실제 원문 첫 범위가 없으면 여전히 실패한다.

선택 Chrome 검사는 기본 headless-shell이 확장 service worker를 시작하지 못했다. 두 실행기에 기본 실제 Chromium 경로를 명시하고 기존 CHROME_BINARY override를 유지했다. 이 환경 실패를 제품 agent 실패나 실모델 실패로 계산하지 않는다.
