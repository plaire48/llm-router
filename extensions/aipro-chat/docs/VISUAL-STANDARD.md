사용자 기준 HTML의 mini-card, approve-box를 공통 interaction-card와 옅은 입력 영역으로 연결한다. 승인, 텍스트 선택지, 이미지 선택지, 짧은 답변, 긴 서술형에 같은 색상·모서리·간격·글꼴을 쓴다. 본문과 입력 이름은 14/22px, 모달 제목은 16/24px다. 버튼의 조작 크기는 CX의 포인터 조건을 유지한다.

질문 아래에서 직접 답변하며 전송은 이름과 툴팁을 갖춘 아이콘으로 표시한다. Enter는 한 줄 답변을 보내고, 서술형에서는 줄을 바꾼다. Ctrl/Command+Enter는 전송한다. 한글 조합 Enter는 전송하지 않는다. 선택지 아래의 직접 입력은 항상 표시한다. 구체적인 형식 안내는 입력 뒤에도 남기고, 전송 단축키는 전송 버튼 툴팁에 둔다. 입력은 수동 조절 핸들 없이 내용에 따라 일정 높이까지 자동으로 자란다. 긴 답변에만 더 보기/접기를 표시하고, 원문과 줄바꿈 및 선택 범위를 유지한다. 펼친 입력보다 긴 내용은 내부 스크롤로 모두 확인한다. 질문 초안은 채팅 입력과 첨부를 건드리지 않고 해당 대화에 보관한다.

승인에는 실제 등록/발송 등 동작명을 남긴다. 편집창은 CX 공통 모달과 입력을 사용한다. 창을 닫아도 해당 화면의 수정 초안을 보관하고, 미반영 수정이 있으면 승인 대신 수정 계속을 제공한다. 페이지에 반영한 뒤 에이전트가 검증하고 새 승인을 받는다. 최종 실행 권한의 기존 검증은 유지한다.

## Beta 1.0.0 글꼴 일관성

상태 전환 규칙: 확인 중, 완료, 중단, 실패는 동일한 14px/22px/400을 사용한다. 계획의 현재 단계도 완료될 때 굵기가 바뀌지 않는다. 의미 있는 Markdown 강조는 유지하며 아이콘과 옅은 상태 색면으로 진행 여부를 구분한다. 본문/항목명/메타데이터는 `agent-deck.css`의 공통 서체 토큰으로 관리한다. 모달의 삭제 확인 버튼과 상단 토스트도 같은 행간을 사용한다. 성공/주의 색은 HTML 원색을 잉크와 섞어 옅은 배경에서 본문 대비 4.5:1 이상을 유지한다. 모델이나 연결 상태에 따라 글꼴과 글자 크기를 바꾸지 않는다.

모달의 공통 여백은 CX 공개 토큰으로 지정한다. 폼은 옅은 면과 초점 강조를 공유하며 확인창의 취소는 이름과 툴팁이 있는 아이콘이다. 삭제/발송 같은 결과를 구분해야 하는 동작과 입력 이름은 짧은 텍스트를 유지한다. 상세 펼침은 내용에만 240ms의 짧은 등장 효과를 주고 모달과 상단 토스트는 움직이지 않는다. 모션 감소에서는 즉시 표시한다.

## 지속 점검 계약

`npm run verify:identity`는 후보를 새로 빌드하고 실제 Chrome에서 모달/서체/접근성/피드백/캐릭터/첫 화면/질문/승인/첨부/캡처/코드/연결 설정/제공자 전환/이력을 검사한다. 320px, 360px와 넓은 화면은 각 시나리오에서 확인한다. 원본 HTML의 해시는 위 기록과 동일하다.

중첩된 서버 연결, 인증 헤더, 스킬 참고 자료는 `deck-subsection`을 사용한다. 제목과 본문은 14/22px, 진한 잉크, 같은 펼침 화살표/초점/열림 동작을 유지하며 카드를 다시 중첩하지 않는다. 모션 감소에서는 전환을 끈다. 공통 브라우저 검사 `assertModalTypography`는 폰트뿐 아니라 중첩 펼침과 아이콘 버튼의 이름/툴팁도 확인한다.

텍스트는 상태나 필요한 행동을 먼저 쓴다. 이미 제목/아이콘으로 알 수 있는 기능 설명은 반복하지 않는다. 기술 규격은 도움말에 두고, 연결 정보의 보관/초안 유실 가능성/승인/복구에 필요한 설명은 본문에 짧게 남긴다. 의미가 모호한 조작까지 아이콘으로 감추지 않는다. 버전과 날짜 같은 메타데이터 외에는 가독성을 위해 글자를 줄이지 않는다.

긴 안내는 핵심 문장 하나와 짧은 소제목/설명으로 나눈다. 핵심 문장은 잉크색/400을 기본으로 하고 중요한 구절만 `--brand-ink`/600으로 강조한다. 소제목은 `--brand-ink`/600, 상세는 `--layout-muted`/400을 사용하며 모두 14px/22px를 유지한다. 문단 전체에 강조색을 칠하지 않는다. 진한 색은 핵심 구절과 조작, 옅은 색은 배경과 구획에 사용한다. 보조 설명도 본문 크기와 읽을 수 있는 대비를 유지하며 opacity로 흐리게 만들지 않는다. 이미지와 아이콘은 의미 전달에 도움이 될 때 사용하고 같은 내용을 텍스트로 반복하지 않는다. 도움말의 화면과 배포 GUIDE.md는 같은 원본을 사용한다.

## 위키를 포함한 신규 화면의 유지 기준

2026-09-24: 사이트 위키도 공통 DeckDisclosure를 사용한다. 문서 이름 자체를 펼침 조작으로 제공하여 중복 제목/문서 보기 문구를 줄인다. 출처 주소와 확인 날짜는 펼친 상세에 둔다. 저장은 접근 가능한 이름과 툴팁을 유지한 아이콘으로 모달 고정 푸터에 둔다. 중복 닫기는 제거하고 헤더 닫기/Escape를 유지한다. 초안 작성, 건너뛰기, 최종 삭제 확인은 선택 의미를 전달하는 짧은 글자를 유지한다.

일반 문서는 본문 14/22px, 제목 16/24px, 확인 날짜 12/16px로 표시하며 진행 기록용 축약 Markdown 스타일을 일반 문서에 적용하지 않는다. 기존 typography/UI simplicity 검사와 위키의 편집/중첩 문서/출처 화면도 verify:identity에서 실제 계산 스타일을 확인한다.

## 2026-09-25 유지 검사 보강

통합 설정 안의 중첩 펼침은 `deck-subsection` 또는 `DeckDisclosure`를 사용한다. 브라우저 기본 삼각형/서체로 남겨두지 않는다. 실제 모달 검사가 이 계약을 검사한다. 새 UI도 공통 검사와 좁은 화면/펼친 상태 검증에 포함한다.

파일/녹화/예약 설정도 본문 14/22px, 제목과 같은 잉크색 펼침, 공통 초점/화살표/모션 감소 기준을 따른다. 핵심 안내 한 문장을 먼저 보여주고 실행 조건의 상세는 펼친다. 입력명은 유지하고 절차 저장 같은 익숙한 보조 동작은 CX ActionButton의 이름/툴팁을 가진 아이콘을 사용한다. 예약/녹화처럼 대상을 구분해야 하는 동작은 짧은 글자를 유지한다.

`verify:identity`는 native 확인창도 포함한다. 설정의 중첩 내용, 아이콘 이름/툴팁과 320/360/1280px 계산 스타일을 함께 검사한다. 상세 결과는 [아이덴티티 재점검](IDENTITY-RECHECK-2026-09-25.md)에 기록한다.

같은 기능은 브라우저·Office 공통 화면과 Desktop에서 같은 CX 그림을 쓴다. 설정은 `sliders`, 대화/작업/진행 이력은 `clockRewind`, 영구 삭제는 `trash`, 닫기와 선택 해제는 `xClose`다. 예약 일시 중지는 취소가 아니므로 짧은 글자로 표시한다. 버튼의 접근성 이름과 툴팁은 동작 대상을 포함한다. 기존 `…` 설정 표기는 이 규칙으로 대체한다.

## 채팅 표현

기준 HTML의 파스텔 배경과 흰 카드를 유지한다. 사용자 메시지는 기존의 옅은 파란 면을 쓴다. Codex의 대화 읽기 흐름을 참고해 누비의 답변은 길이에 상관없이 배경과 테두리 없는 본문으로 표시한다. 답변의 제목, 목록, 코드와 근거는 본문 위계로 구분한다. 빈 대화부터 입력창은 아래에 유지하고 인사말만 그 위 공간에 둔다. 입력창의 보조 조작은 테두리 없는 아이콘으로, 전송처럼 주 동작만 면색으로 구분한다. 설정의 여러 항목은 독립 버튼처럼 보이지 않게 얇은 구분선으로 나누고 펼친 항목만 카드로 표시한다. 360×480, 360×800, 1100×850 화면에서 말풍선 없는 답변과 입력 위치를 확인한다.

배경 토큰 `--deck-background`는 기준 HTML과 같은 값이다. 빈 화면에서 작아졌던 마스코트와 청록색 제목을 복원해 기존 색감이 드러나게 했다. 낮은 창에서는 마스코트 크기만 줄여 잘림을 막는다. 이 변경은 공통 CX 아이콘과 CSS 토큰으로 해결하며 별도 UI 라이브러리를 추가하지 않는다.

진행 기록의 새로고침과 페이지 이동은 CX `ActionButton`을 사용한다. 아이콘의 접근성 이름, 마우스/키보드 툴팁과 기존 동작을 함께 유지하고 툴팁을 닫아도 읽던 기록을 접지 않는다. 유지 검사와 화면 근거는 [가독성 후속 점검](IDENTITY-READABILITY-2026-09-25.md)에 기록한다.

`DeckGuidance`는 의미를 나타내는 아이콘, 핵심 문장, 필요한 상세를 공통으로 구성한다. 장식 아이콘은 읽기 도구에서 중복 안내하지 않는다. 녹화, 예약, 위키 갱신에 적용했고 예약의 반복 안내는 실행 조건 한 곳으로 합쳤다. 자동 모달 검사는 글꼴/크기와 함께 핵심/상세/볼드의 계산 색상과 굵기를 확인한다. 자동 검사로 문장의 의미 적합성을 보증하지 않으므로 실제 화면에서 강조 대상과 상세의 필요성을 함께 검토한다.

설치된 CX의 공개 Icon과 공통 토큰을 재사용해 의존성을 추가하지 않았다. [W3C 작성 지침](https://www.w3.org/WAI/tips/writing/)의 간결하고 이해하기 쉬운 내용과 [디자인 지침](https://www.w3.org/WAI/tips/designing/)의 대비, 색 이외의 의미 표시, 여백에 의한 구분을 적용했다.

2026-09-26: 빈 대화부터 입력창을 하단에 고정하고 인사말만 위 공간에 배치한다. 승인 미리보기 글자를 누르면 검증된 원문을 같은 카드에서 편집하며 최종 승인과 수정 반영을 구분한다. 과거 메시지를 읽을 때만 이름과 툴팁을 갖춘 원형 아래 화살표를 표시하고 내용 높이가 변해도 읽는 위치를 유지한다.


## 2026-09-26 가독성 유지 보완

반영 대기/보류는 날짜나 버전이 아닌 작업 상태이므로 본문 14px/22px를 사용한다. 한글 답변은 단어 단위로 줄바꿈하되 긴 URL/식별자는 영역을 넘지 않게 줄바꿈한다. 일반 문장 400과 핵심 구절 600/진한 블루를 구분하고, 보조 설명은 크기를 줄이지 않고 보조색을 사용한다.

녹화와 프로젝트 연결의 핵심 안내는 기존 `DeckGuidance`를 재사용한다. 녹화 시작과 선택한 모델만 강조하며 입력값 미보관과 전달 범위는 남긴다. 모델의 답변 지침도 결과/다음 행동 우선, 핵심 구절만 볼드, 필요한 대상/조건/근거/한계 보존으로 맞춘다. 모델 답변에서 임의로 문장을 삭제하거나 생성한 이미지 URL을 자동 표시하지 않는다. 실제 캡처와 의미 있는 기존 아이콘을 사용한다.

반영 내용과 검증 범위는 [가독성 재점검](READABILITY-2026-09-26.md)에 기록한다.


## 2026-09-26 블루 상태와 HTML 모션

사용자가 초록색 제거 대상을 글자/아이콘/상태 표시로 확정했다. 이 최신 결정은 위의 성공 녹색 및 UI 제목 청록 규칙에 우선한다. 성공과 답변 완료, 설정 아이콘과 제목은 진한 블루/옅은 블루를 사용하고 체크/상태 이름으로 의미를 함께 전달한다. 녹색 이름의 호환 토큰도 블루에 연결한다. 배경/캐릭터의 원래 민트와 청록은 유지한다.

기준 HTML의 `floaty`(6초, -11px), `rise`(0.55초, 18px), `pop`(0.4초, scale .88/8px)을 환영 캐릭터 바깥 껍데기, 메시지, 작은 컨텍스트/상태 요소에 적용한다. 기존 3.2초 반짝임과 원본 easing을 유지한다. 모달 전체의 확대/이동은 고정 토스트를 움직일 수 있어 적용하지 않는다. OS 모션 감소와 모달/숨김/입력 시 기존 정지 범위를 유지한다. 모션은 실행 완료 근거가 아니다.

[실제 반영과 검증](BLUE-MOTION-2026-09-26.md)을 따른다.

녹화 기록 목록은 순서를 유지하되 불필요한 숫자 마커 없이 동작 아이콘과 짧은 내용을 표시한다. 목록 안쪽 좌우 여백을 동일하게 두고, 상태의 서로 다른 정보는 중간점 대신 줄바꿈으로 구분한다. 단계 번호로 참조해야 하는 별도 업무까지 일괄 제거하는 규칙은 아니다.

## 2026-09-26 입력창 추가 메뉴

브라우저 입력창의 파일 첨부, 현재 페이지 연결, 스킬 선택은 `+` 하나로 펼친다. 선택된 프로젝트 연결도 같은 메뉴에 둔다. 메뉴 안에서는 기존 아이콘과 짧은 기능 이름을 함께 표시하고, 모델 선택은 입력창에서 바로 조작한다. 메뉴에는 개별 버튼 테두리를 추가하지 않는다. 바깥 클릭/Esc 닫기와 모달 종료 후 + 초점 복귀를 유지한다.

계획과 하위 작업에도 공통 Markdown 강조를 적용하며 공개 진행 설명의 줄바꿈과 목록 구조를 보존한다. 본문 14px/22px와 기존 블루/배경 토큰을 유지한다. [반영 근거와 화면 검증](COMPOSER-ADD-MENU-2026-09-26.md)을 따른다.
