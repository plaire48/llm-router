# 여러 출처의 후속 분석과 진단 보존

## 문제와 변경

NQ-41: 기존 자동 비교 분석은 두 출처를 배정한 뒤 한 번만 실행하는 플래그와 과거 작업 기록으로 후속 위임을 막았다. `comparison-analysis.js`에서 관찰한 출처를 관리하고 `agent-runtime.js`의 도구 결과/보고 수집/최종 판단 경계에서 남은 배정을 진행한다. 완료 결과가 이미 전달된 작업은 용량에서 제외한다. 한 실행의 자동 분석은 최대 16개 출처이며 동시 실행 2개, 실행 중 또는 미전달 작업 6개 제한은 기존 Pi/p-limit 조정기가 담당한다.

원문 전체를 모든 워커에 반복 전송하지 않는다. 각 워커는 고정된 출처 근거 ID만 읽고 요약과 미확인을 돌려준다. 주 실행기가 탐색과 최종 검토를 맡는다. 같은 출처는 한 번 배정하며 페이지 표시용 주소가 실제 쿼리 출처를 중복 생성하지 않는다. 대기 용량 부족만 수집 뒤 재시도하고, 근거 만료/검증/전송 실패는 같은 작업을 자동 반복하지 않는다. 사용자 정정, 입력 대기, 쓰기, 미확정 쓰기와 복구 중에는 자동 배정을 멈춘다. 16개 초과 출처나 읽지 않은 영역을 분석 완료로 계산하지 않는다.

NQ-42: 기존 검토/종료 진단은 최근 세션 이벤트에만 남았다. `agent-diagnostic-journal.js`가 이미 쓰는 `idb` 8.0.3과 `trace-journal.js`의 트랜잭션/보존/페이지 조회를 재사용한다. 별도 DB에 원자 순번으로 저장해 브라우저 재시작 뒤에도 조회한다. 실행별 400개, 전체 10000개, 최대 256개 실행, 조회당 50개로 제한하며 삭제된 수를 함께 반환한다.

저장 값은 검토 범위/결과/충족 수와 답변/사용자 대기/취소/실패, 검증 여부, 허용된 오류 코드/종료 이유뿐이다. 본문, 질문, 모델 검토 문장, URL, 인증값은 저장하지 않는다. 현재 lease 소유자만 기록할 수 있고 조회는 신뢰한 확장 UI와 실제 provider/conversation/assistant message를 대조한다. 대화 삭제 후 실제 기록도 제거한다. 저장 실패로 유효한 결과를 버리지 않는다. 누락된 진단을 성공으로 추정하지 않으며 이 저장소는 자동 실행 복구나 미확정 쓰기 재전송 큐가 아니다.

`GET_AGENT_DIAGNOSTICS`로 조회하고 네이버 SSO 평가 스크립트가 `agentDiagnostics`와 `diagnosticRetention`에 수집한다. 평가용 세션의 네트워크 시간 기록과 구분한다. 별도 제품 진단 화면과 전체 모델 대화 영구 기록은 이번 범위에 추가하지 않았다.

## 검증

1. 9개 출처와 재방문을 실제 Pi 실행기에 넣어 워커 9개, 고정 근거 읽기와 답변 18회를 확인한다. 모델 응답은 합성이다.
2. 용량 부족 뒤 수집/재배정, 같은 출처 중복 방지, 최신 대기 근거, 전송/검증 실패의 반복 방지, 사용자 정정/쓰기 경계를 검사한다.
3. 실제 Chrome IndexedDB에 410개를 동시에 기록해 원자 순번, 최신 400개/50개씩 페이지 조회와 원문 제외를 확인한다.
4. Chrome 프로세스를 닫고 동일 프로필로 다시 열어 세션 저장소 소멸과 진단 보존을 함께 확인한다. 다른 provider/대화/메시지 조회, 오래된 lease 쓰기, 대화 삭제 후 물리 기록 제거를 검사한다.
5. 전체 앱의 합성 모델 검토 복구에서 실제 호스트가 보낸 검토/종료 진단이 영구 저장소에 도착하는지 확인한다. 기존 DOM 쓰기는 한 번만 수행된다.

중간 검사에서 Node의 격리된 background 테스트 로더에 새 모듈 경로가 빠진 문제가 발견됐다. 로더 경로를 보완한 뒤 해당 79개 검사가 통과했다. 제품 Chrome에서는 새 모듈 번들과 실제 저장 경로가 통과했다.
