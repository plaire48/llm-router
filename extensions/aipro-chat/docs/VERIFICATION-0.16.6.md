# 0.16.6 브라우저 코드 실패 복구와 상태 표시

검증일: 2026-09-21

## 확인한 문제와 변경

- Playwright 실행 오류가 일반 실패 문구로 합쳐져 모델이 코드를 수정할 단서가 부족했다. 문법, 미지원 함수, 모호한 locator, 편집 불가능한 대상, 시간 초과와 변경된 페이지를 고정 원인과 수정 지침으로 구분한다. 모델에 원시 예외 대신 현재 페이지 관찰과 다음 단계 지침을 전달한다.
- 생성 코드가 브라우저 RPC를 await하지 않고 반환해도 성공으로 처리될 수 있었다. 미완료 RPC가 남은 반환은 대기 누락으로 처리한다. 실제 RPC 완료와 호스트 promise 정리 시점을 구분해 정상 await를 실패로 오인하지 않는다.
- 같은 실패에도 매번 새 관찰 ref가 붙어 반복 판정이 무력화됐다. 동일 인자와 오류를 기준으로 진행 없는 반복을 감지한다. 기존 3회 중단 기준을 유지하며 성공하거나 진행하는 작업에 총 횟수 상한은 추가하지 않는다.
- 스크립트 실패 후 기존 요청에서 허용된 입력, 클릭과 이동 도구도 다음 모델 요청에 제공한다. 새 권한을 부여하거나 실패한 동작을 자동 재실행하지 않는다. 모델은 현재 결과를 확인하고 수정된 코드 또는 기본 도구를 선택한다.
- 작업 목록의 모호한 확인 필요 문구를 짧은 원인으로 바꿨다. 최종 요구사항 검토가 통과하고 요청이 완료된 경우에만 과거 오류를 복구됨으로 표시한다. 원래 실패 기록은 보존한다. 진행 중, 중단, 검토 미완료는 복구된 것으로 표시하지 않는다. 실행 이력은 최근 32개와 고정 원인만 보관한다.

## 검증

- `npm test`: 232개. 원인별 오류, 비공개 값 제외, await 누락/정상 await 구분, 허용된 도구 범위, 새 ref에 가려진 동일 실패 반복과 복구 표시 조건을 포함한다.
- `script-recovery-browser`: 실제 Chromium 확장에서 6개. 문법 오류, 미지원 `page.evaluate`, 중복 locator와 편집 불가능한 대상을 재현했다. 같은 사용자 요청에서 기본 입력 도구로 제목/본문을 정확히 한 번씩 입력하고 페이지 검증과 독립 요구사항 검토를 마쳤다. 진행 중 원인 표시, 복구 상태, 재진입 유지, 좁은/넓은 화면을 확인했다. 같은 실패 반복은 종료하고 이전 입력은 다시 쓰지 않았다.
- `browser-agent-browser`: 기존 16개. 코드 오류 후 수정, iframe/Shadow DOM 입력, 캡처/좌표 조작, 새 창 전환, 취소와 종료 경로를 확인했다.
- `output-recovery-browser`: 기존 8개. 21,796자 분할 입력, 출력 중단 복구, 중복 방지, 이후 실행과 서식 유지가 통과했다.
- `npm run design:check`, `npm run build`: 기존 CX 구성과 0.16.6 설치 ZIP을 확인했다. Vite의 기존 청크 크기 안내는 유지된다.

모델 응답과 업무 사이트는 합성 fixture이며 브라우저 동작은 실제 Chromium/Playwright 실행이다. 사용자가 겪은 정확한 스크립트와 회사 사이트는 확보하지 못했으므로 해당 현상의 단일 원인이나 실제 사내 모델 성공을 확인한 결과는 아니다. 코드 실행의 관측 가능한 결함을 수정하고 복구 경로를 검증한 범위다. 테스트용 진단 hook과 확대 권한은 임시 설치 복사본에만 넣으며 배포 파일에 포함하지 않는다.
