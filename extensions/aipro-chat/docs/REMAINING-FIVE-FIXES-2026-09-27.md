## 방법론과 코드 근거

- **Claude 브라우저 1.0.94 배포 코드 재확인**: `sidepanel-so8SIo6y.js`의 1674700 부근 실행 루프와 `mcpPermissions-tSjXinpi.js`의 `processToolResults`를 읽었다. 도구 ID별 오류 결과와 권한 대기 분리 패턴을 참고해 누비의 권한 거부를 실행 실패/승인 소비와 분리했다. 원본 파일 해시와 배포 경로는 [기존 정적 분석](CLAUDE-HARNESS-STATIC-2026-09-26.md)을 따른다. 배포 코드를 OSS로 간주하거나 코드/프롬프트를 복사하지 않았다.
- **[OpenCode compaction](https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/packages/opencode/src/session/compaction.ts)**: `select`의 최근 turn 보존과 `prune`의 완료 도구 출력 정리를 확인했다. 누비는 화면 동작용 ref와 출처 근거의 수명을 분리한다. OpenCode의 출력 절단 크기나 런타임을 그대로 도입하지 않았다. MIT.
- **[OpenAI Codex compact.rs](https://github.com/openai/codex/blob/814de47b69dd63a2660fd14f9af66690888d183e/codex-rs/core/src/compact.rs)**: 사용자 메시지를 요약과 별도로 재구성하고 절단 시 retained source 불완전을 표시하는 구현을 확인했다. 누비도 원래 요구와 근거의 범위를 유지하며 부족한 원문을 읽었다고 처리하지 않는다. 기존 plan handler의 계획 이벤트와 실제 결과 분리도 유지한다. Apache-2.0.
- **[Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)**와 **[Claude Code subagents](https://code.claude.com/docs/en/sub-agents)**: 필요한 참조를 유지하고 독립 문맥의 역할을 제한하는 방법을 적용했다. 공개되지 않은 Claude Code 핵심 구현을 확보했다고 주장하지 않는다.
- **[Chrome 선택 권한](https://developer.chrome.com/docs/extensions/reference/api/permissions)**: 사용자 동작 안에서 권한을 요청하고 사용 전에 현재 권한을 검사한다. 승인 버튼 클릭과 호스트 검사를 모두 구현했다.

새 의존성을 추가하지 않았다. 기존 Pi, Playwright CRX, Readability/Turndown, LangChain/MiniSearch를 사용한다. 작은 페이지 번호 식별과 권한/소유권 수정에 별도 대형 하네스를 추가해도 실익이 없고 확장 용량과 상태 경계만 늘어난다.

## 검증 한계

- 자동 페이지 구분은 단일 가시적 `1 / 3쪽`, `Page 1 of 3` 같은 명시적 위치와 이전/다음 컨트롤이 있는 경우다. 모호한 복수 카운터, 무한 스크롤이나 숨은 페이지는 추정하지 않는다. 자동 읽기는 실행당 최대 16개이며 각 발췌의 범위/누락을 유지한다. 페이지 번호는 전체 데이터 열람이나 동일 시점의 데이터 정합성을 증명하지 않는다.
- 출처를 보존해도 오래된 DOM/ref로 클릭하거나 쓰기 완료를 판정하지 않는다. 실제 원문에 있는 항목 ID로 중복을 제거하고 읽은 범위를 확인해야 한다.
- 사이트 복구는 허용된 소유 탭의 재탐색이다. CAPTCHA, 로그인, 접근 제한이나 서버 장애를 우회하지 않는다.
- 권한 거부 UI 회귀는 Chrome API의 사용자 결정만 주입했다. 실제 OS 권한 프롬프트의 클릭은 별도이며, 실제 다운로드와 파일 바이트 검증은 권한을 부여한 격리 프로필에서 수행한다.
- 작업 종료 시 초안과 사용자 탭을 자동 삭제하지 않는다. 누비 그룹을 접는 것이 기본 정리다.
- 로컬 회귀는 실제 브라우저와 합성 모델을 사용한다. 동일 새 후보의 30개 실모델 독립 재채점 전에는 개선 후 품질을 미측정으로 둔다.

최신 진행과 후보 해시: `verification/browser-30/remaining-fixes/summary.json`. 이전 기준선과 원본 실패 기록은 유지한다. 배포는 하지 않는다.
