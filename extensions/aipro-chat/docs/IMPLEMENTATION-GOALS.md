# nubi 미반영 기능의 실행 목표

**현재 품질 작업의 우선순위와 검증 상태는 [통합 품질 목록](BROWSER-QUALITY-BACKLOG.md)을 먼저 확인한다.** 이 문서의 날짜별 표는 제품 목표와 과거 이력이며 이미 반영한 기능을 다시 미구현으로 분류하지 않는다.

현재 릴리스: **nubi Beta 1.0.0**. 이름과 버전 변경은 기능 목표의 완료 상태를 바꾸지 않는다.

**2026-09-23 브라우저 확장 후속 구현:** HTTP/HTTPS MCP 연결과 사용자 헤더, 1회 승인 호출, `scripts/*.browser.js` 스킬, JSM 화면 수집/검색/첨부 보관/선택 폴더 저장을 구현했다. [범위와 제약](BROWSER-INTEGRATIONS.md)을 우선한다. 아래 과거 표의 외부 MCP 전체 미구현 표기는 이 범위에서 해소됐으며, Python/Node 실행과 라이브러리 설치, stdio/구형 SSE/OAuth MCP, ZIP 스킬 가져오기, JSM 전체 API 수집, Desktop 자동 동기화는 남아 있다. A2A는 사용자 요청대로 제외한다.

**2026-09-23 재점검:** 아래 2026-09-22 표와 세부 누락은 당시 기록이다. 목표 7의 채팅 화면 종료 후 지속 실행은 [worker 실행기](BACKGROUND-EXECUTION-DESIGN.md)로 구현했다. 동일 프레임 DOM 드래그도 [7단계 하네스](BROWSER-HARNESS-SEVEN-STAGES.md)에 후속 반영했다. 로그인/일반 읽기는 debugger 없이 동작하지만 실제 Playwright 조작의 표시줄은 남는다. 스트림 복구와 현재 검증 범위는 [품질 점검](STREAM-FAILURE-QUALITY.md)을 따른다. 실제 모델 기준선, 회사 계정/Windows 검증과 로컬 실행형 스킬은 완료로 올리지 않는다.

2026-09-22. 한 목표의 동작과 설치본을 검증한 뒤 다음 목표로 이동한다. 설계, 구현, 브라우저 검사, 실제 계정 검증과 배포를 구분한다. 일반 브라우저 사용에는 라우터 설치를 요구하지 않는다. 모든 UI는 사용자 HTML과 CX 스킬, 기존 deck 토큰을 따른다.

## 목표 1 범위

후속 사용자 수정: 서버/매번 연결이 기본이 아니라, 설정에 OpenWiki 폴더를 미리 지정하고 필요할 때 검색해 브라우저 작업에 활용한다. 1.1.1은 저장한 폴더 핸들로 직접 읽으며 서버 연결은 원본 소스 조회용 선택 기능으로 유지한다.

서버는 OpenWiki-SDS 0.6.0, 확장은 누비 1.1.0 후보를 사용한다. 기존 OpenWiki 시각화 서버에 인증된 읽기 API를 추가하며 별도 브리지는 없다. 첫 연결의 일회 코드와 세션 토큰은 모델/진단에 전달하지 않는다. 프로젝트 이름만 채팅에 표시한다.

검사할 흐름:

- 프로젝트 연결 → Wiki 검색 → 관련 소스 조회 → 파일/실제 줄 범위 인용.
- 페이지 미연결, Wiki만 연결, 소스 내용 변경, 재연결, 연결 해제와 서버 종료.
- 만료/재사용된 코드, 토큰 없는 접근, 다른 프로젝트 결과, 제외 파일과 경로 이탈.
- 320/360px 사이드 패널과 큰 창에서 모달, 오류/재시도, 초점 복귀와 아이콘 설명.

이 목표는 코드 이해를 위한 읽기 연결이다. 코드 수정/빌드, 정적 Wiki 연결, 완전한 화면-컴포넌트 자동 매핑과 실제 모델의 자율 성공률은 별도 범위다.

목표 1 결과: [1.1.1 폴더 활용 검증](VERIFICATION-1.1.1.md), [1.1.0 서버 연결 검증](VERIFICATION-1.1.0.md). 설정 폴더 저장과 재시작 복원, 검색 결과로 브라우저 입력/검증, 설치 ZIP까지 완료했다. OS 폴더 선택 완료와 실제 디스크 권한 지속성은 별도 확인 대상이다. 회사 실계정과 실제 모델 성능 검증은 목표 8에 남긴다.

## 승인과 질문 폼 개선

사용자 추가 요청에 따라 1.3.0에서 HITL 승인/편집과 객관식/주관식/서술형 질문의 공통 CX 폼을 적용한다. [검증 결과](VERIFICATION-1.3.0.md). 앞선 목표의 완료 상태를 확대 해석하지 않으며, 브라우저 작업 품질과 로컬 빌드 등 대기 목표는 유지한다.

## 목표 3 진행

[1.4.0 설치본과 검증](VERIFICATION-1.4.0.md). 단위 285개와 변경 범위의 Chrome 34회 검사를 통과했다.

1.4.0은 문법, 정적으로 식별한 미지원 API와 명백한 await 누락을 실행 전에 검사한다. 잘못된 스크립트는 디버거 연결과 페이지 쓰기 없이 현재 화면 관찰과 오류 줄 위치를 반환한다. 실행 중 대상 없음, 다중 일치, 가림, 비활성, 숨김, 입력 불가와 페이지 변경을 구분한다. 정상적인 지연 로딩은 기다리고, 앞선 쓰기는 재실행하지 않은 채 남은 동작을 수정한다.

실제 모델의 자율 과제 성공률과 검증된 절차 재사용은 아직 남아 있다. 디버거를 쓰지 않는 일반 조작, 로컬 제작/빌드, 외부 MCP/실행형 스킬, 창 종료 후 지속 실행도 이 변경으로 완료된 것은 아니다.

추가 품질 과제도 남아 있다. 실제 모델의 과제 성공률/복구율 측정과 검증된 절차 재사용은 합성 응답 Chrome 회귀 검사로 대신하지 않는다. 현재 모델의 이미지 지원 판정도 일반적인 능력 탐색으로 확장된 상태는 아니며 AI Pro의 Qwen3.8 조건 등 제공자별 구현 범위를 따른다.

승인 편집의 연필과 수정 후 재검증은 구현했지만, 반영 전 편집 중인 값은 화면 내 상태다. 편집 모달을 닫았다 여는 것은 유지하고 페이지 새로고침까지 저장하지 않는다. 이것은 이미 저장하는 질문 답변 초안과 구별한다.

이미 반영한 OpenWiki 폴더 읽기, 첨부/붙여넣기, 객관식/서술형 질문, HITL 초안 편집, 대화 이력, 자동 컨텍스트 압축, 캡처/이미지 다운로드, 스킬 파일 공유는 미구현 목록에 다시 넣지 않는다. 최신 로컬 ZIP을 생성한 것과 GitHub/스토어 게시도 구분한다.

확인한 코드: `project-tools.js`의 읽기 전용 도구, `browser-script-api.js`의 제한된 메서드, `browser-dom.js`/`browser-agent.js`의 파일 입력 제외, `help-content.js`의 스킬 실행 범위, `src/App.jsx`의 대화 실행 수명, `context-state.js`의 사용자 선택 재개, `account-usage.js`의 ChatGPT 전용 한도 조회, `src/ActionApproval.jsx`의 편집 상태.

## Beta 전체 검증에서 추가 확인한 보완점

2026-09-22. 페이지 안의 DOM 모달과 새 탭/별도 창은 현재 회귀 검사 대상이지만, 브라우저 기본 JavaScript 확인창은 별개다. 실제 Chrome의 합성 페이지에서 `confirm()`이 자동 취소되고, 클릭 도구에는 명령 반환과 취소된 화면 관찰만 전달되는 것을 재현했다. 모델이 확인창 자체를 관찰하거나 승인된 선택을 수행하는 도구는 없다. 2026-09-23에는 유형/취소 결과 관찰, 후속 쓰기 차단과 질문 폼 전환을 구현했다. 승인 직후의 추가 확인도 자동 수락하지 않는다. 2026-09-24에는 살아 있는 confirm/prompt의 일회 사용자 응답과 승인 수명을 연결했다. 원래 클릭을 반복하지 않으며 실제 결과 검증을 별도로 유지한다. 현재 범위는 [확인창 사용자 선택](NATIVE-DIALOG-APPROVAL.md), 이전 재현은 [기본 확인창 품질 점검](NATIVE-DIALOG-QUALITY.md)을 따른다.

상단 `beta` 표시를 추가한 뒤 320px에서 로그아웃 버튼이 잘리는 문제는 공통 간격 조정으로 수정하고, 로그인 전후 모든 상단 버튼의 가시 영역 검사를 추가했다. 이는 위 미지원 기능과 구분되는 수정 완료 항목이다.
