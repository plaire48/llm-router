# 누비 브라우저 Agent 품질 평가

현재 품질 작업 순서와 최신 후보의 검증 결과는 [통합 품질 목록](BROWSER-QUALITY-BACKLOG.md)을 따른다. 아래는 당시 평가와 후속 과제의 이력이다.

2026-09-24 / beta33. 평가 대상은 Chrome 확장이다. 실제 운영 성능을 회귀 통과율로 대체하지 않는다.

## 냉정한 판정

beta33 변경 후 18개 합성 시나리오를 3회씩 실행한 54회가 모두 통과했다. 그러나 실제 Qwen의 요구사항 해석, 최초 도구 선택 성공률, 사내 업무 완료율은 미측정이다. 그러므로 제품의 실전 품질을 100점이라고 평가할 근거가 없다.

평가 인증 환경을 값 노출 없이 확인했으며 `NUBI_EVAL_TOKEN`이 없다. 이번 실모델 평가 명령은 not_configured로 끝났다. 미측정을 0점 또는 성공으로 합산하지 않는다.

사용자 지시에 따라 임의의 검증 충족도 60/100 척도는 폐기했다. 공식 방법론 기반 지표만 계산하고 자체 과제와 공개 벤치마크를 분리한다. 공식 오픈소스를 사용한 자체 평가이며 제3자 인증은 아니다.

회귀 근거: `verification/pre-release-2026-09-24T07-43-01-002Z/report.json`. 원본 실행 기록은 보존한다. 새 평가 방법론으로 다시 집계한 보고서는 verification/quality-beta33/QUALITY.md다. 원본 기록의 당시 내부 척도를 현재 성능 점수로 사용하지 않는다.

## 이번에 실제 적용한 개선

1. **미확정 입력과 대상 상태의 결합**: fill_form 응답을 잃으면 모든 입력란에서 요청 값을 검증해야 한다. 관찰한 토글은 동일 대상의 control_state 검증이 필요하다. 일반 제목, 다른 입력란, 일부 필드만의 검증은 다음 변경/최종 승인을 허용하지 않는다. 새 ref는 동일 URL/frame/유일한 역할과 이름으로 연결하고 모호하면 자동 해소하지 않는다. 원래 입력값은 런타임 메모리만 사용하고 추가 저장/진단 출력하지 않는다.
2. **미해결 상태 전달**: 검증 실패에 포함된 최신 관찰/ref도 다음 검증에 전달한다.  verify_page 자체는 성공해도 이전 작업과 무관하면 unresolvedAction과 복구 안내를 모델에 돌려준다. 단계 완료 표시와 다음 쓰기는 보류한다. 실제 결과가 확인되면 완료된 작업을 반복하지 않고 이어간다.
3. **실모델 반복 평가**: 기존 격리 평가의 8개 과제를 기본 3회씩 실행하도록 개선했다. NUBI_EVAL_REPEATS=1~5를 지원한다. 계획 회차가 누락되거나 중복 기록이면 점수를 산정하지 않는다. 성공/실패를 각 회차로 보존하고 시간/요청 수/실제 DOM/부작용을 기록한다. 보고서는 타임스탬프별로 남겨 이전 실패 기록을 덮어쓰지 않는다. 미구성 상태를 실제 모델 호출로 표시하지 않는다.
4. **공식 지표와 채점기**: 임의의 종합 점수를 없애고 실모델 반복 결과의 pass@1, pass@k, pass^k를 추가했다. WebArena-Verified 1.2.3 공식 채점기를 별도 평가 명령으로 연결하고 버전과 평가기/데이터 해시를 검사한다. 공식 예제 성공과 의도적으로 틀린 예제 실패를 확인했다. 예제 점수는 누비 능력 점수가 아니다.

범위 제한: 동일 이름의 다른 요소가 나중에 생기는 경우, 일반 링크의 서버 처리, 불투명한 스크립트 전체 결과를 이번 대상 매칭으로 증명하지 않는다. 같은 URL/frame/역할/이름은 DOM 객체 동일성 증명이 아니다. 호스트의 fresh ref 검증과 최종 요구사항 검토를 유지한다. 입력이 부분 반영됐거나 목표와 다른 값이면 이 자동 해소 경로는 열리지 않으며 추가 확인이 필요하다. 원래 값을 모르는 상태에서 미반영을 추정하지 않는다.

## 다음 우선순위

P1: 실제 Qwen 3.8 27B의 같은 과제 3회 결과를 확보한다. 평가 토큰은 로컬 환경으로만 지정하며 채팅에 보내지 않는다. P2: 실패한 사내 페이지를 비식별 fixture로 추가한다. P3: 위키/하위 분석 on/off를 비교해 품질·총 토큰·시간이 실제로 개선되는 경우에 활성 범위를 넓힌다. P4: 외부 서버의 업무 완료 영수증을 제공하는 사이트별 스킬을 보강한다. 지원하지 않는 일반 서버 결과를 추정해 자동 재실행하지 않는다.

## 공개 평가 방법 적용

- [WebArena-Verified](https://github.com/ServiceNow/webarena-verified): 공식 과제와 결과 채점기의 기준을 사용한다. 자체 과제를 WebArena라고 이름 붙이지 않는다. 새 `npm run eval:webarena`는 이미 수집된 task별 `agent_response.json`과 `network.har`를 공식 코드로 채점한다.
- [BrowserGym](https://github.com/ServiceNow/BrowserGym): 다양한 공개 과제를 통합하는 후보로 검토했다. 현재는 누비의 Chrome 확장 실행기를 유지하고 외부 채점기를 쓰는 편이 실제 제품을 평가하기에 적합하므로 BrowserGym Agent로 재구현하지 않았다.
- [Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents): 과제/시도/채점/실제 결과를 분리한다. pass@1은 균등 반복 과제의 시도 성공률, pass@k는 한 번 이상 성공한 과제 비율, pass^k는 k회 모두 성공한 과제 비율의 관측값으로 보고한다. 3회 반복만으로 정밀한 성공 확률을 보장하지 않는다.
- [OpenAI](https://developers.openai.com/api/docs/guides/evaluation-best-practices): 요구사항, 도구 선택, 인자, 전달, 최종 결과를 별도 검사하고 실패 사례를 회귀에 축적한다.

현재 확인: 제품 단위 검사 606개와 Chrome 54회 통과, 디자인 검사 통과, candidate 빌드 성공. 이후 변경은 평가 스크립트/문서뿐이며 제품 실행 코드는 동일하다. 평가 스크립트 추가 검사는 별도로 기록한다.

이 기록 당시 남은 필수 조건: 실제 모델 평가 인증, 격리된 WebArena 사이트, 누비 실제 실행의 공식 형식 답변/HAR 수집 어댑터와 task별 초기 상태 재설정. 후속 NQ-08에서 실행 연결을 구현했고 실제 환경 검증은 여전히 대기한다. 현재 Docker 서버는 실행되지 않았다. 공식 채점기는 연결했지만 누비의 WebArena 종단 실행과 812개 전체 과제 점수는 아직 없다. 공개 벤치마크 점수와 실제 사내 업무 성공률 모두 미측정이다. 현재 결과만으로 외부 에이전트보다 우수하다고 결론 내리지 않는다.

공식 평가 실행법과 한계: [PUBLIC-BENCHMARK-EVALUATION.md](PUBLIC-BENCHMARK-EVALUATION.md).

최종 평가 코드 변경 후 `npm test`: 609/609 통과. 공식 채점기 연결은 정답 대조군 exit 0 / 오답 대조군 exit 1로 확인했다. 공개 배포는 수행하지 않았다.
