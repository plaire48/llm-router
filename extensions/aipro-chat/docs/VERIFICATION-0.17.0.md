# 0.17.0 브라우저 작업의 관찰과 복구

기존 Pi 실행 루프와 AI Pro/ChatGPT/FabriX 연결을 유지하고, 잘못된 DOM 이름과 모호한 대상, 부분 실행 실패 때문에 브라우저 작업이 어긋나는 경로를 보강했다. UI에 새 설정이나 모드를 추가하지 않는다.

## 변경

- 기존 수동 이름 조합을 고정 버전 dom-accessibility-api 0.7.1로 교체했다. `aria-labelledby` 입력, 선택 목록, 검색 입력과 숫자 입력의 이름/역할을 실제 Playwright role locator와 대조했다. 접근성 이름과 fallback 표시 이름은 별도로 전달한다.
- 관찰에 모달/폼/행 맥락, 필수/읽기 전용/잘못된 입력 상태, 선택 항목, 상태/오류 안내와 생략 개수를 제공한다. 긴 페이지는 열린 대화상자의 요소부터 담으며 query는 주변 영역 이름으로도 좁힐 수 있다.
- `browser.ref(ref)`가 최신 관찰의 실제 노드를 대상으로 동작한다. 같은 이름의 컨트롤과 iframe/shadow DOM에서도 selector를 추측하지 않는다. 이전 관찰, 교체된 노드와 숨겨진 대상은 실행 전에 거절하고 최신 관찰을 반환한다.
- QuickJS facade, 호스트 허용 목록과 모델 안내가 `browser-script-api.js`의 공통 계약을 사용한다. 런타임에서 임의 JavaScript를 확장 권한으로 실행하거나 로컬 파일/Node 접근을 추가하지 않는다.
- 스크립트 응답에 명령별 순번, 반환/실패 상태와 동작 발행 여부를 제공한다. 입력 후 클릭 실패를 구별해 빠진 동작만 수정할 수 있다. 최근 32개 기록을 반환하지만 총 실행 횟수를 제한하지 않는다. 코드/인자/입력값은 이 기록에 포함하지 않는다.
- 최종 발송/등록 승인은 같은 가드를 사용한다. 동작 반환이나 스크립트의 자체 성공 문장을 실제 요구사항 검증으로 취급하지 않는다.

관찰용 라이브러리는 빌드 시 직렬화 가능한 정적 함수 안에 번들한다. 기본 관찰에는 debugger를 연결하지 않으며 실제 조작은 기존 Playwright 경로를 사용한다. 원본 라이선스를 설치 ZIP에 포함한다.

## 검증

`npm test` 243개와 `npm run design:check`, `npm run build`를 통과했다.

실제 Chromium에서 설치 ZIP과 같은 확장 실행 경로로 다음 검사를 수행했다.

| 검사 | 결과 |
| --- | --- |
| `browser-specialist-browser` | 7개 통과. 접근성 이름/역할, 모달 구별, 필수/읽기 전용/disabled 상태, 비밀/입력값 생략, debugger 없는 읽기, ref 입력과 종속 선택 목록, iframe/shadow, 부분 실패 복구, 중복 입력 없음, 오래된 ref 거절, 결과 검증과 승인 유지, 긴 페이지 범위 조회 |
| `browser-agent-browser` | 16개 통과. 일반 대화/페이지 연결, 새 탭의 메일 초안, 신뢰된 입력, 선택 목록, 스크립트 수정, 캡처/좌표, 중지와 재진입 |
| `script-recovery-browser` | 6개 통과. 문법/미지원 API/중복 대상/잘못된 입력 대상의 오류 구분, 복구와 진행 없는 반복 중단 |
| `browser-popups-browser` | 8개 통과. 지연 새 창, named 창 재사용, 닫힌 창 복귀, 중첩 팝업과 취소, 65회 연속 입력 |
| `popup-approval-browser` | 7개 통과. 새 창 초안, 패널 새로고침, 연필 수정, 승인 후 원래 창 복귀, noopener와 닫힌 자식 창 |
| `harness-browser` | 6개 통과. 저장 실패 복구, 누락한 본문만 보완, 잘못된 완료 보류, worker 검증 강제와 재개 시 새 검증 |

`harness-browser`는 기존 최종 승인 가드에 맞춰 테스트의 실제 초안 저장 버튼을 “초안 저장”으로 명확히 표시하도록 수정했다. 제품의 “저장” 승인 가드를 완화하지 않는다. 이 검사는 잘못된 완료 선언 보류, 누락한 본문 보완과 새 검증을 확인한다.

## 증거의 범위

사이트는 로컬 합성 fixture이고 도구 선택/모델 응답은 테스트에서 지정했다. DOM과 실제 Chrome 조작, 입력 유지, 이벤트, 창 이동과 중복 실행 여부는 실제로 검사했다. 실제 AI Pro/ChatGPT/FabriX 모델이 스스로 같은 과제를 해결하는 성공률이나 다른 범용 Agent와의 우열을 측정한 결과는 아니다.

새 DOM 라이브러리가 모든 사이트에서 브라우저/Playwright와 동일한 접근성 계산을 보장하지는 않는다. 불명확한 이름과 역할에는 관찰 ref를 사용하고, 실제 페이지 결과를 계속 검증한다. 사이트 자동 저장과 서버 영속성은 서비스에서 별도 확인해야 한다.
