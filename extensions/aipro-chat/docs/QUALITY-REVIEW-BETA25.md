# Beta 25 품질 점검

## 수정한 문제

두 하위 분석이 실행 슬롯을 사용하는 동안 세 번째 과제가 대기하고 있을 때, `collect_analysis`를 먼저 호출하고 세 번째 과제를 취소하면 수집 대기가 끝나지 않았다. 취소 상태는 바뀌지만 대기열의 Promise는 실행 차례까지 미완료로 남아 있었기 때문이다.

작업의 논리적 완료와 스케줄러의 실행 완료를 분리했다. 대기 중 취소는 기존 수집자에게 즉시 전달한다. p-limit은 실행 동시성 2개를 계속 관리하며, 취소된 항목이 실행 차례에 도착해도 모델을 부르거나 진행 기록을 다시 표시하지 않는다. 실행 중 중지와 전체 중지는 기존 AbortSignal 및 대기열 폐기 경로를 유지한다.

회귀 검사는 실제 Pi 런타임으로 두 모델 호출을 보류하고 세 번째 과제의 취소를 검증한다. 특정 ID를 기다리는 수집과 다음 완료를 기다리는 수집을 모두 확인한다. 수정 전 동일 검사가 시간 초과로 실패했다. 다른 과제의 모델을 중단하지 않는지, 대기열이 나중에 풀려도 취소 기록이 되살아나지 않는지도 검사한다.

## 방법론과 오픈소스 판단

- [p-limit 공식 문서 및 구현](https://github.com/sindresorhus/p-limit): 실행 동시성과 대기열을 구분한다. `clearQueue`는 전체 대기열 폐기이며 실행 중 작업을 취소하지 않는다. 한 과제를 중지하기 위해 다른 과제를 버리지 않고, 조정기가 작업 완료 신호를 소유하도록 보완했다. 기존 MIT p-limit 7.3.3을 유지한다.
- [Pi 공식 agent loop](https://github.com/earendil-works/pi/blob/main/packages/agent/src/agent-loop.ts): 기존 Pi의 취소 신호 및 도구 결과 전달 구조를 유지한다. 중복 런타임이나 별도 에이전트 SDK는 추가하지 않았다.
- [Anthropic 컨텍스트 엔지니어링](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): 역할별 좁은 문맥과 압축된 인계를 유지한다. 이번 검토에서는 근거 재조회, 압축 시 문서 범위와 실행 기록 보존, 취소 후 늦은 응답 폐기 경로를 관련 회귀 검사로 확인한다.

p-queue로 전체 스케줄러를 교체할 필요는 없었다. 현재 결함은 동시 실행 정책이 아닌 수집 완료 신호에 있었으며, 기존 라이브러리 위의 작은 수정으로 재현 검사를 통과한다.

## 검증 경계

최종 검사 수와 동일 후보 ZIP의 해시는 `verification/quality-beta25/verification.json`에 기록한다. Chrome 검사는 합성 모델 및 테스트 페이지를 사용한다. 사내 Qwen 3.8 27B 실제 정확도, SSO 실계정, FabriX/OpenWiki 운영 서비스는 별도 확인 대상이다. 이번 변경은 브라우저 쓰기 재시도, 승인, CX 스타일을 바꾸지 않는다.
