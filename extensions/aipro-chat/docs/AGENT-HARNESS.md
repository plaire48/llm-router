# Browser agent harness

누비 Beta 1.0.0은 오픈소스 Pi의 Agent 실행 루프에 브라우저 관찰, 도구 선택, 결과 검증과 요구사항 검토를 연결한다. 사용자에게 별도 라우터나 Node 설치를 요구하지 않는다. [오픈소스 비교와 선택](OPEN-SOURCE-HARNESS.md), [7단계 개선과 현재 검증 범위](BROWSER-HARNESS-SEVEN-STAGES.md).

0.17.0은 실행 기반을 유지하면서 브라우저 관찰과 스크립트 대상 지정, 부분 실패 피드백을 보강했다. dom-accessibility-api가 이름/역할을 계산하고 관찰 결과에 영역, 필수/읽기 전용/오류 상태와 생략 개수를 포함한다. `browser.ref(ref)`는 관찰된 실제 노드에 연결한다. 같은 이름의 버튼은 모달/폼/행의 맥락으로 구별하고, 오래된 ref는 실행하지 않는다. [이번 검증 범위](VERIFICATION-0.17.0.md).

스크립트 결과의 `execution.commands`에는 최근 32개 명령의 순번, 고정 메서드명, 반환/실패 여부와 동작 발행 여부를 담는다. 인자, selector, 코드와 입력값은 넣지 않는다. 이는 실행 명령의 결과이며 요구사항 충족의 증거를 대체하지 않는다. 실패한 다음 클릭 때문에 이전 입력을 다시 실행하지 않도록 최신 관찰과 함께 사용한다. 명령 개수 제한은 없다.

## 실행 흐름

1. 사용자 목표와 성공 조건을 해석한다. 복잡한 작업은 `update_plan`으로 짧게 기록한다.
2. `select_tools`로 입력, 상호작용, 탐색, 스크립트, 이미지, 저장소 중 필요한 그룹을 선택한다. 스킬과 제공자가 허용한 실제 스키마만 광고하며 worker의 소유권 검사를 유지한다.
3. Pi가 순서대로 도구를 실행한다. 첫 실제 도구 결과 뒤에는 같은 응답의 나머지 호출을 보류하고, 모델이 결과를 읽은 다음 다음 행동을 선택한다. update_plan/select_tools 메타데이터만 앞에 함께 실행할 수 있다. Playwright CRX가 브라우저 동작을 수행하며 QuickJS가 생성 코드를 격리한다. 오류와 현재 관찰은 모델에 돌아간다. 같은 응답에 남은 호출은 보류하고 수정한 다음 응답을 받는다. 이미 수행한 입력을 임의로 반복하지 않는다.
4. `verify_page`가 입력값, 화면의 결과 문구와 주소를 다시 읽는다. 최대 5초 기다리며 두 번 연속 통과해야 성공한다. 미검증 상태로 종료하려 하면 최대 두 번 검증을 요구한다.
5. 도구 없는 별도 모델 요청이 원래 사용자 요구, 대화 맥락, 실제 관찰과 답변 초안을 대조한다. 실행자가 선택한 검사항목만 따르지 않고 누락된 요구도 찾도록 지시한다. 전체 요청이 충족되어야 최종 답변을 내보낸다.
6. 누락이 있으면 Pi `followUp`으로 보완 지시를 전달한다. 빠진 항목을 수정하고 다시 검증한다. 새 관찰이나 검사 결과로 진전이 있으면 보완을 계속한다. ref만 달라지는 동일 근거로 반복 결론을 내면 중단한다. 사용자 정보가 부족하다는 blocked 판정은 질문으로 연결한다.

새 계획에는 단계별 `expected_outcome`을 요청하고 상태만 갱신해도 보존한다. 이 조건이 있는 단계를 완료시키기 전 별도 검토가 실제 검사와 조건을 대조한다. 무관한 검사 통과로 완료를 대신하지 않으며 단계 검토 성공은 전체 목표 완료로 저장하지 않는다. 조건 없는 구버전 계획에도 기존 객관적 검사와 최종 요구사항 검토는 적용한다.

연속 도구 오류 2회 또는 브라우저 작업 도구 5회 이상 실행 뒤 다음 모델 판단 전에는 같은 제공자/모델의 도구 없는 중간 검토를 받는다. 원래 요구사항과 현재 근거를 다시 대조해 다음 방법을 수정한다. 단순히 아직 작업 중이라는 이유로 사용자에게 질문하지 않는다. 중간 검토의 출력 형식/길이 복구가 실패하면 불확실성을 유지하고 현재 근거를 다시 확인하게 하며 최종 검증을 생략하지 않는다. 인증 거절, 사용자 취소, 연결 재시도 소진은 원래 오류로 종료하고 사용자 요구가 누락된 것으로 바꾸지 않는다.

예: 제목과 본문을 저장해달라는 요청에서 제목만 확인되면 완료시키지 않는다. 본문을 보완하고 두 입력값과 저장 안내를 다시 확인한다. 메일 초안 요청을 발송으로 확대하지 않는다.

## 긴 본문과 출력 복구

긴 작성은 관찰 → 짧은 계획 → 절별 작성/반영 → 전체 검증으로 진행한다. 출력 한도는 누비가 복구하며 사용자에게 원래 요청을 나누라고 요구하지 않는다. 첫 문단은 fill하고 다음 문단은 appendText로 기존 문서를 덧붙인다. 이전 길이와 가능하면 digest를 함께 검사하므로 이미 적용된 구간을 무조건 다시 쓰지 않는다. 최종 field_digest는 전체 본문 유지, field_contains는 요청한 구절 포함, 화면 안내는 가시적 저장 상태를 확인한다. 이 검사는 서버 영속성이나 의미 품질을 독립적으로 보증하지 않는다.

잘린 도구 호출은 실행하지 않고 새 완전한 호출로 재생성한다. 텍스트 응답은 마지막 부분을 참고해 이어 생성한다. 본문/완전한 호출의 진전 없이 출력 한도에 3회 연속 도달하면 중단한다. 요청별 사용량은 모두 기록하고 컨텍스트는 마지막 실행 요청 기준을 유지한다. HTTP 실패나 불확실한 브라우저 쓰기를 이 정책으로 재실행하지 않는다. 결과 검토 자체가 잘린 경우에는 도구 없이 같은 근거를 한 번 다시 검토한다.

## 검증 계약

- 요구사항별 `met`, `unmet`, `unknown`과 실제 관찰 ID를 검증한다. 없는 ID, 잘린 관찰, 오류 결과와 이전 동작으로 무효화된 증거는 완료 근거로 받지 않는다.
- 생성 스크립트의 반환값은 주장이므로 제외한다. 실행기가 수집한 관찰만 사용한다. 최신 지원 이미지 하나만 해당 관찰 ID와 함께 전달한다.
- 검토의 JSON, 내부 추론과 완료 전 답변 초안은 사용자에게 스트리밍하지 않는다. 진행 상태는 기존 채팅의 `요청사항 확인 중`에 표시한다.
- worker는 동작 전 검증 대기를 저장하고 `verify_page`로 통과시킨다. 미검증/실패 상태나 진행 중인 요구사항 검토가 있으면 `FINISH_CHAT` 완료를 거부한다.
- 명시적으로 이어가면 새 관찰을 먼저 수집한다. 이전 실행의 검증 의무를 보존하고 기존 통과도 다시 확인한다. 창을 여는 것만으로 자동 재실행하지 않는다.
- 체크포인트에는 검토 상태, 검사 개수와 시각만 추가한다. DOM, 입력값, 코드와 검토 원문은 별도로 저장하지 않는다. 원래 사용자 대화의 보관 정책은 유지한다.

## 오픈소스와 추가 정책의 경계

Pi 0.86.1의 `Agent`, `beforeToolCall`, `afterToolCall`, `subscribe`, `followUp`을 실제 실행에 사용한다. 누비는 제공자 변환, Chrome 권한, 브라우저 증거와 완료 정책만 추가한다. Nanobrowser는 실행/완료 판단 분리의 참고이며 해당 패키지나 소스를 포함하지 않았다.

AI Pro, ChatGPT와 FabriX는 같은 루프를 사용한다. 검토도 현재 선택한 제공자/모델을 사용하며 계정을 바꾸지 않는다. 사용량이 제공되면 검토 요청까지 집계한다. 컨텍스트 표시는 마지막 실행 요청 기준이며 별도 검토의 입력량으로 덮어쓰지 않는다.

## 한도와 미검증 범위

- 모델/도구 실행과 요약에는 누적 횟수 상한을 두지 않는다. 최종 검토는 진전이 없는 반복을 중단한다. 동일 호출/결과 3회 반복은 질문으로 전환하며, 사용자 중지, 요청 시간과 모델 입력 한도는 유지한다.
- 일반 대화는 브라우저 도구가 실제 실행되지 않으면 별도 검토 호출을 하지 않는다. 모델이 필요한 브라우저 도구를 전혀 선택하지 않는 문제까지 이 검토가 해결하는 것은 아니다.
- 검토는 같은 모델을 별도 맥락에서 호출한 평가다. 모델 오류와 프롬프트 주입을 완전히 제거하거나 독립된 정답 판정기를 보증하지 않는다. 입력과 페이지 내용은 신뢰할 수 없는 데이터로 구분한다.
- 가시적인 저장 안내는 페이지 증거다. 서버 영속성은 실제 서비스의 저장 후 재조회 등 별도 근거가 필요하다.
- 수동 입력 제안/검토, 제공자별 대화 분리, 기존 권한과 중지 동작을 유지한다. 외부 MCP, 로컬 파일/프로세스 접근은 추가하지 않는다.

## 페이지 읽기와 평가

읽기/분석은 콘텐츠 스크립트의 DOM 관찰을 우선한다. 인라인 텍스트 순서와 긴 문단을 유지하고, browser_snapshot의 query로 관찰된 키워드 주변을 발췌한다. textFiltered는 전체 페이지가 아닌 발췌임을 뜻한다. 일반 읽기는 verify_page를 필수로 요구하지 않으며 최종 답변은 관찰 근거와 원래 요구를 대조한다.

[페이지 분석과 하네스 검증](VERIFICATION-BETA-1.0.0-ANALYSIS.md), [실모델 평가](AGENT-EVALUATION.md)를 구분한다. 합성 모델 회귀는 오류 처리/제어 흐름 검사이며 GLM/Qwen의 정확도 점수가 아니다.

## 단계별 실행과 이어가기

[판단 경계와 검증](ADAPTIVE-TOOL-TURNS.md)을 따른다. 질문은 실제 사용자 선택이 필요할 때만 받으며 일반 조회와 요청된 초안 작성에는 추가 승인을 요구하지 않는다. Playwright의 새 화면 관찰은 다음 모델 판단으로 연결하고, 최종 반영은 기존 초안 검증/승인/수정 흐름을 유지한다.
