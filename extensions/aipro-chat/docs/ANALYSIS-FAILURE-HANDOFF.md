# 실패한 분석을 이어가는 하네스

## 확인한 문제와 반영

Pi 실행기는 같은 결과의 반복을 감지했지만, 하위 분석에서 `agent_stalled`가 나면 일반 실패로 끝났다. 또한 실패 상태의 과제는 재사용 대상이 아니어서 부모가 같은 과제를 다시 맡길 수 있었다. 보고 형식이나 압축 후 인계가 실패하면 읽은 근거는 일부 남아도 다음 행동을 위한 구조화된 보고가 없었다.

1. 반복 감지로 종료된 하위 분석은 남은 할당량 안에서 **도구 없는 인계 호출을 한 번** 수행한다. 전체 실패 대화 대신 과제, 실제 읽은 발췌, 출처, 미완료 문서 범위를 전달한다. 중간 브라우저 동작과 조회를 다시 실행하지 않는다.
2. 보고 형식 검증 실패, 할당량 소진, 컨텍스트 초과는 **검증된 부분 보고 형식**으로 근거를 인계한다. 실패한 모델의 주장은 모두 제외한다. 원본 근거는 출처의 성공/실패 상태, 실제 읽은 범위와 함께 반환한다. 읽었다는 사실을 이해나 완료로 간주하지 않는다.
3. 실패하거나 복구 인계한 같은 과제는 실행 중인 부모 작업 안에서 재사용한다. effort만 늘려 다시 실행하지 않는다. 과제/제약/범위/출처가 바뀌면 새 작업을 허용한다. 이는 새로 관찰한 근거를 활용할 수 있게 하며, 문구가 달라도 의미상 같은 과제를 모두 감지하는 기능은 아니다. 종료 이력은 기존 최대 32개 정리 정책의 적용을 받는다.
4. 인증과 네트워크 오류는 실패로 유지한다. 사용자 중지 중에는 인계를 시작하거나 늦은 결과를 반영하지 않는다. 복구 인계 중 취소를 무시하는 모델도 대기 슬롯을 반환한다.

`status=done`은 하위 실행의 종료다. `report.status=partial`을 함께 저장하고 기존 UI는 **일부 확인**으로 표시한다. 메인 완료는 기존 별도 검증을 통과해야 한다. 새 모달이나 복구 버튼은 추가하지 않는다.

## 공식 사례와 선택 근거

2026-09-24에 공식 문서와 공개 소스를 확인했다. 다음은 패턴 적용이며 외부 런타임 전체를 복사하거나 설치한 것이 아니다.

| 근거 | 누비 적용 | 도입하지 않은 부분 |
| --- | --- | --- |
| [OpenCode session/processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)의 동일 도구/입력 3회 감지와 `doom_loop` | 기존 의미 기반 반복 감지는 유지하고 하위 분석 종료 뒤 인계를 보강 | 반복을 사용자에게 다시 승인받아 무조건 계속하는 경로 |
| [OpenAI Agents JS errorHandlers.ts](https://github.com/openai/openai-agents-js/blob/main/packages/agents-core/src/runner/errorHandlers.ts)의 상태 전달, 처리한 오류 중복 방지, 대체 출력 스키마 검증 | 읽기 증거 보존, 1회 인계, 형식 검증 실패 시 주장 없는 부분 보고 | OpenAI SDK를 Pi와 중복 실행하거나 쓰기 작업 재생 |
| [Anthropic 도구 설계](https://www.anthropic.com/engineering/writing-tools-for-agents)의 구체적인 오류 피드백과 제한된 출력 | 부모에게 기존 결과 수집/접근 변경을 명시하고 실제 발췌만 인계 | 실패 대화 전체를 반복 삽입하거나 프롬프트만으로 복구 보장 |
| [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)의 격리된 하위 문맥과 압축된 반환 | 기존 과제별 문맥과 해시/범위 보존 사용 | 별도 장기 기억 저장소와 무제한 하위 에이전트 |

OpenCode와 OpenAI Agents JS는 MIT 공개 구현을 방법론 검토에 사용했다. 새 의존성은 추가하지 않았다. 기존 Pi 0.86.1의 실행/중지, p-limit 7.3.3의 동시 실행, p-retry 8.0.1의 전송 재시도를 유지했다. OpenCode 전체 런타임은 확장 단독 동작에 맞지 않고, SDK를 겹치면 재시도와 상태 소유자가 중복된다.

## 검증과 남은 범위

- `analysis-handoff.test.mjs`: 실제 Pi 반복 종료, 한 번의 인계, effort 변경 중복 방지, 새로운 출처/과제 허용, 잘못된 보고 주장 제거, 인증 실패 분리, 인계 중 중지와 늦은 응답 격리.
- 기존 분석/문서 분할 테스트: 인용 검증, 읽은 범위와 미완료 범위, 압축 실패, 권한 격리를 유지한다.
- `role-agents-browser.mjs`: 실제 Chrome 확장에서 합성 Qwen 응답으로 실패 반복 → 부분 인계 → 중복 위임 방지 → 부모의 원본 근거 검증 → 완료를 실행한다. 새로고침 뒤 부분 상태와 CX 진행 기록도 확인한다.

실제 Qwen 판단 정확도와 사내 서비스 성능은 이 합성 검사로 증명하지 않는다. 작업 전체를 자동 성공시키거나, 같은 의미의 다른 표현을 모두 중복으로 차단하거나, 브라우저 종료 후 자동 재개하는 변경도 아니다. 다음 평가는 실계정에서 과제 완료율, 반복 도구 수, 복구 호출 수, 토큰 비용을 함께 비교해야 한다.
