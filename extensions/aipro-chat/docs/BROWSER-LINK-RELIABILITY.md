# 링크 실행과 질문 복구

버튼처럼 보이지 않는 링크도 실제 요소를 클릭하고 열린 화면을 확인한다. 기존 확장 내부 Playwright와 Pi를 유지하며 별도 Python 서버를 추가하지 않는다.

## 재현한 문제

- `display: contents` 링크는 자기 영역이 없어 숨김으로 판정됐다. 보이는 자식 카드가 있어도 관찰과 실행에서 빠졌다.
- `onclick` 텍스트와 `cursor: pointer` 카드는 역할이나 tabindex가 없으면 실행 대상에 포함되지 않았다.
- 일반 카드의 `id="card"`도 결제 입력란으로 오인해 제외됐다.
- 의미 기반 클릭은 가림과 비활성 상태를 구분하지 않고 일반 실행 실패로 반환했다.
- “신청 내역 보기” 같은 조회 링크를 최종 신청 동작으로 오인해 승인을 요구했다.
- 요구사항 검토가 같은 보완을 반복하면 질문 대신 `goal_incomplete`로 종료했다.
- Markdown h5/h6는 기본 스타일 때문에 각각 11.62px와 9.38px로 표시됐다. 일부 제목 굵기는 900, 줄 높이는 20.8px였다.

## 반영

관찰에는 링크 목적지 표시와 새 창 속성, 이벤트/포인터 후보와 실제 DOM 참조를 포함한다. 포인터를 상속받은 자식들은 중복 후보로 만들지 않는다. 일반 카드와 보호해야 할 결제 입력란을 구분한다. 역할이 없는 후보를 버튼이라고 추측하지 않고 관찰한 ref로 실행하도록 도구 안내를 보강했다.

영역이 없는 링크는 원래 링크를 검증한 뒤 그 안의 보이는 비대화형 자식에 실제 포인터 입력을 보낸다. DOM click(), 강제 클릭, URL 직접 이동으로 사이트 동작이나 승인을 우회하지 않는다. Playwright의 정상 대기와 hit testing을 유지한다. 링크의 destination은 query/hash를 뺀 표시용 정보이며, 이동 URL을 재구성하는 데 쓰지 않는다.

클릭 후에는 기존 팝업 감시로 새 탭/창을 찾고 목적지의 최신 관찰을 반환한다. 실패에는 가림, 비활성, 숨김, 대상 변경 등 복구 사유를 전달한다. 모델은 결과를 보고 다음 작은 작업을 선택하며 이미 시도한 동작을 자동 반복하지 않는다. 최종 등록/발송은 기존 검증과 HITL을 유지한다.

이름이 명확히 내역/목록/상세 보기나 화면/양식 열기인 링크는 준비 단계로 구분한다. “발송하기”, “신청”, “내역 삭제”처럼 최종 실행 또는 모호한 이름은 승인 보호를 유지한다.

계획 단계도 질문을 반환할 수 있다. 검토에서 필요한 정보가 없으면 선택지 또는 서술형 질문을 표시한다. 보완에 진전이 없으면 질문 전용 모델 호출로 다음에 필요한 한 가지를 묻고 답변을 기다린다. 이 호출은 페이지 도구를 실행할 수 없다. 답변 후 원래 목표와 미완료 단계에서 이어간다.

폰트는 Noto Sans KR를 유지하고 제목 16/24px, 본문 14/22px, 날짜와 버전 12px로 통일했다. Markdown의 제목 의미는 유지한다. 코드 블록만 기존 13px 모노스페이스를 사용하고 터치 입력은 16/24px를 유지한다.

## 참고한 공식 문서와 오픈소스

| 자료 | 적용한 원칙 |
| --- | --- |
| [Playwright actionability](https://playwright.dev/docs/actionability) | 보임, 안정성, 입력 수신 가능 여부와 활성 상태를 확인한 후 실제 입력. force는 사용하지 않음 |
| [Playwright locators](https://playwright.dev/docs/locators) | 실제 역할/이름과 정확한 대상 구분. 링크를 button으로 추측하지 않음 |
| [Playwright pages](https://playwright.dev/docs/pages) | 클릭 전에 새 페이지 감시를 등록하고 열린 대상으로 전환 |
| [Playwright MCP](https://github.com/microsoft/playwright-mcp) | 스냅샷에 근거한 참조 클릭과 다음 관찰 |
| [browser-use clickable detector](https://github.com/browser-use/browser-use/blob/main/browser_use/dom/serializer/clickable_elements.py) | 의미 요소만으로 부족한 이벤트와 포인터 후보 보완 |

2026-09-22에 확인했다. 패턴을 참고해 현재 확장에 구현했으며 해당 프로젝트의 Python 코드나 런타임을 가져오지 않았다. 어떤 도구가 모든 사이트에서 더 정확하다는 벤치마크 주장은 하지 않는다.

## 검증 범위와 한계

실제 Chrome에서 합성 사이트의 텍스트, 카드, 이벤트, 아이콘, iframe, shadow DOM, 새 탭 링크를 실행한다. 가림과 비활성에서는 클릭/이동을 강행하지 않는다. 질문 생성, 새로고침, 답변 후 1회 입력과 결과 검토를 함께 검사한다.

의미/속성/포인터 힌트가 전혀 없는 이벤트 위임 요소, 닫힌 shadow root, canvas 내부 대상은 이 DOM 개선만으로 모두 식별할 수 없다. 필요한 경우 기존 시각 도구와 추가 관찰을 사용한다. 사내 실제 페이지와 실제 모델의 전체 성공률은 이 합성 회귀로 입증되지 않는다.
