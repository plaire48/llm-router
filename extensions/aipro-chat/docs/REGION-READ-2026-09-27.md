# 관찰 영역 다시 읽기

E07 실측에서 다른 날짜와 제공자의 숫자를 섞은 답변이 확인됐다. 기존 검색 요약과 영역 메타데이터만으로는 이를 막지 못했다. 이번 변경은 이미 관찰한 영역의 가시 원문을 날짜, 제목, 항목명과 함께 다시 읽는 경로다. 특정 사이트나 날씨 정답을 코드에 넣지 않는다.

## 실제 적용

- `read_page(mode="region", region_ref=관찰값)`은 이전 스냅샷에 반환된 영역만 읽는다. 새 검색이나 링크 클릭은 하지 않는다.
- 별도 읽기 전용 노드 캐시를 사용한다. 동일 탭, 최상위 문서, 대상 프레임 문서와 영역 노드를 호출 전후에 확인한다. 사라짐, 교체, 숨김, 다른 문서와 잘못된 인수는 명시 오류다.
- 기존 DOM 수집기와 Playwright/Chrome scripting 경로를 재사용한다. 새 라이브러리는 추가하지 않는다. 입력값과 비밀 필드 제외, 본문 16,000자, 노드 5,000개, 영역 메타데이터 4,000자 한도는 유지한다.
- 읽기 결과에 action ref를 만들지 않는다. 기존 action ref도 갱신하지 않는다. opaque region ref 변경만으로 복구 진전이나 새 근거를 계산하지 않으며 원래 영역 index, 문서, 프레임, 본문과 출처 문맥은 비교에 남긴다.

## 검증과 제한

단위 검사 38개, source-only Chrome 영역 검사 5항목과 기존 DOM 영역 회귀 8항목을 통과했다. 실제 수집기에서 현재 카드와 다른 날짜/제공자 카드의 값을 구분하고 검토용 원문 재조합이 일치하는지 확인했다. 합성 입력값을 제외하며 오래된 노드, 다른 프레임, 잘린 긴 영역과 기존 action ref 불변을 검사했다.

실제 확장 경로 검사는 `tests/region-extension-browser.mjs`에 추가했다. 새 후보 빌드 후 별도 Chrome에서 scripting 읽기, Playwright 연결 후 읽기, iframe 범위와 탐색 후 stale 거부를 검증한다. 작성 시점에는 이 통합 검사를 아직 실행하지 않았다.

**실제 E07 모델의 정확도 개선 효과는 아직 측정하지 않았다.** 영역 하나에 여러 카드나 날짜가 들어갈 수 있다. 영역이 같다는 사실만으로 라벨과 값의 의미 관계, 날짜의 현재성, 페이지 전체 열람이나 과제 완료를 인정하지 않는다. 잘린 범위는 partial로 남고 모델이 원문의 제목, 날짜, 항목을 대조해야 한다. 스크린샷의 PRIVATE_* 표기는 테스트용 합성 문자열이다.

검증 화면: `verification/browser-30/region-read-mixed-cards.png`. 결과: `verification/browser-30/region-read-browser.json`.

기존 BP의 적용 범위는 출처와 연결된 작은 읽기 도구, 정확한 문서 바인딩, 구체적인 오류 계약이다. 기존 DOM 수집과 Playwright 기능으로 충분하므로 별도 사이트 파서나 새로운 추출 라이브러리를 도입하지 않았다. 기존 평가 기준과 실제 모델 성공 판정은 그대로 유지한다.
