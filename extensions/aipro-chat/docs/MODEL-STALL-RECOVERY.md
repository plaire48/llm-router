# 캡처 이후 모델 대기 복구

2026-09-24, Beta 1.0.0 후보 16. 사용자 실계정 기록은 확보하지 않았으므로 이번에 재현한 결함과 실제 장애의 원인이 같다고 단정하지 않는다.

## 재현한 문제

- API 연결 유지용 SSE 주석/빈 이벤트까지 모델 활동으로 처리해 120초 유휴 제한과 작업 heartbeat를 계속 갱신했다.
- `finish_reason`은 받았지만 `[DONE]`/EOF가 오지 않으면 다음 도구 호출로 넘어가지 못했다.
- `[DONE]`까지 받았어도 `reader.cancel()` 정리가 끝나지 않으면 결과 반환이 멈췄다.
- 내용이 계속 오지만 완료되지 않는 추론에는 요청 단위의 절대 제한이 없었다.

`tests/model-stall.test.mjs`에서 네 경우 모두 수정 전 실패를 확인했다. 화면의 “다음 단계 확인 중”은 별도 작업이 아니라 실행 중인 도구가 없는 동안의 기존 표시다. 모델 대기가 실제로 끝나지 않으면 이 표시도 계속 남는다.

## 적용

| 상황 | 처리 |
| --- | --- |
| 15초 이상 모델 요청 | 기존 진행 기록에 모델 응답 대기 표시 |
| 실제 내용/추론/도구 인자가 120초간 없음 | 해당 추론 요청 취소, 지수 지연 후 재연결 |
| 한 추론 요청이 5분을 넘음 | 새 데이터가 있어도 해당 요청 종료 및 제한된 재시도 |
| 완료 신호 이후 연결만 유지됨 | 사용량 수신을 최대 1초 허용한 뒤 다음 단계 진행 |
| 정리 중인 스트림이 응답하지 않음 | 취소 요청을 보내되 정리 완료를 결과 반환의 조건으로 두지 않음 |
| 최대 3회 재시도도 실패 | 기존 오류/이어가기 상태로 종료. 진행 중 표시를 남기지 않음 |
| 사용자 중지/인증 오류 | 자동 재시도하지 않음 |

횟수와 시간은 누비의 로컬 정책이다. 작업 전체나 페이지 행위 횟수를 제한하는 값이 아니다. 매 요청의 완료된 캡처/도구 결과/계획은 그대로 두고 **모델 호출만** 재시도한다. 브라우저 입력/클릭이나 확정되지 않은 제출을 자동 재전송하지 않는다. 스트림이 끝나지 않은 도구 인자는 실행하지 않는다. 늦게 도착한 취소된 요청의 출력은 기존 signal 검사로 배제한다.

## BP와 오픈소스 판단

- [Codex 실행 루프](https://openai.com/index/unrolling-the-codex-agent-loop/): 도구 결과를 문맥에 붙이고 모델을 다시 호출하는 경계를 유지한다. 재연결을 위해 도구 실행 전체를 재시작하지 않는다.
- [Codex 공식 설정](https://learn.chatgpt.com/docs/config-file/config-reference): 스트림 유휴 시간과 스트림/HTTP 재시도 횟수를 별도로 둔다. 누비의 120초/5분 정책이 Codex의 기본값이라는 의미는 아니다.
- [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents): 세션 기록, 하네스, 실행 도구를 분리한다. 기존 누비 체크포인트와 완료 결과를 사용하며 이 변경으로 분산 영속 실행 시스템을 도입했다고 주장하지 않는다.
- [Anthropic 장기 실행 하네스](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents): 단계별 진행과 검증 가능한 상태를 남긴다. 이번 복구도 성공한 페이지 작업을 반복하지 않고 다음 판단만 이어간다.
- 실제 런타임: MIT Pi `@earendil-works/pi-agent-core` 0.86.1의 Agent 루프와 MIT [p-retry](https://github.com/sindresorhus/p-retry) 8.0.1의 취소/선택적 재시도/지수 지연을 재사용했다. 신규 프레임워크를 추가하지 않았다. SSE 해석/제공자별 종료 규칙은 기존 누비 어댑터에서 관리한다. 새 라이브러리가 응답의 의미나 부작용 여부를 대신 판단할 수 없기 때문이다.

## 검증 범위

단위 검사에서는 무한 스트림 정리, 종료 신호 후 keepalive, 실제 진행 판정, 절대 제한, 늦은 결과, 중지, 재시도 소진을 확인한다. Chrome 장애 주입은 실제 HTTP SSE로 캡처 후 대기를 만들며 격리된 테스트 사본의 시간만 단축한다. 생산 타이머/인증 권한을 우회하는 설정은 제품에 추가하지 않는다. Qwen 응답은 합성이며 회사망/실제 모델 성능은 별도 검증이다.

초기 Chrome 재현은 테스트 사본에 일부 사이트 권한만 미리 허용해 전송 시 권한 창에서 대기했다. 모델 요청이 0회였음을 확인하고 기존 Chrome 회귀와 동일하게 테스트 사본에 HTTP/HTTPS 권한을 미리 부여했다. 제품의 사이트 권한 확인은 변경하지 않았다. 이후 실제 SSE 장애 주입에서 캡처 후 대기/재연결/진행/소진/사용자 중지를 확인했다.
