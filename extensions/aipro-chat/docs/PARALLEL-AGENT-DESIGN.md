# 역할별 병렬 에이전트 검토

2026-09-22. 아래는 초기 목표 설계다. **로컬 beta12 후보에 같은 연결의 역할별 비동기 분석을 구현했다.** 실제 구현 범위와 검증 경계는 [구현 기록](ROLE-AGENTS-IMPLEMENTATION.md)을 따른다. 공개 beta11에는 이 기능이 없다. Qwen 3.8 27B의 실제 정확도와 총 토큰 비교는 별도 평가가 필요하다.

## 권장 구성

누비가 계획과 사용자 대화를 맡고, 독립적인 분석만 별도 Pi Agent에 위임한다. 페이지 조작과 HITL은 주 실행기에 남긴다. 기본은 같은 AI Pro 계정이며, 다른 제공자는 사용자가 역할별 연결 대상으로 선택한 경우에만 사용한다. 다른 제공자에 로그인해 있다는 이유만으로 페이지나 사내 자료를 전달하지 않는다.

예: “이 페이지와 OpenWiki를 보고 작성 화면을 완성해줘.”

1. 누비가 현재 화면을 한 번 관찰하고 작업을 나눈다.
2. 화면 분석 담당은 캡처와 DOM을, 코드 분석 담당은 필요한 Wiki 문서만 읽는다. 서로 의존하지 않는 분석은 동시에 실행한다.
3. 각 담당의 결과가 도착하면 누비가 근거와 누락을 확인하고 다음 행동을 정한다. 모든 하위 작업이 끝날 때까지 대화를 숨기지 않는다.
4. 주 실행기 하나가 관찰한 필드에 초안을 반영한다. 변경 이후 새 관찰로 검증하고 최종 등록만 HITL로 처리한다.

| 역할 | 입력과 반환 | 모델 선택 |
| --- | --- | --- |
| 주 실행기 | 원래 요구, 제약, 계획, 완료 기록을 유지 | Qwen 3.8 27B 기본 |
| 화면 분석 | 특정 관찰의 DOM/이미지 → 요소 후보와 근거 | 인증된 목록의 이미지 지원 Qwen |
| 문서/코드 분석 | 질문과 필요한 Wiki 발췌 → 수정 후보와 출처 | Qwen 기본, Coder 계열은 같은 평가로 비교 |
| 검토 | 원래 요구와 최신 결과 → 충족 여부, 누락, 다음 확인 | Qwen의 독립 문맥 기본, 다른 모델은 설정과 평가 후 선택 |

모델 이름만으로 우수한 역할을 단정하지 않는다. 동일 모델의 별도 문맥도 충분한 선택지다. AI Pro/ChatGPT/FabriX는 기존 어댑터를 재사용하며, FabriX는 현재 확인된 텍스트 계약을 유지한다.

## BP와 오픈소스 비교

- [Anthropic의 다중 에이전트 사례](https://www.anthropic.com/engineering/multi-agent-research-system): 주 에이전트가 작은 범위의 조사를 나누고 하위 에이전트가 독립 문맥에서 결과를 압축하는 방식이다. 대규모 병렬 조사에 유리하지만 전체 토큰이 증가할 수 있다. 누비에는 역할별 위임과 근거 반환 패턴을 적용할 수 있다. 이 사례의 성능 수치를 Qwen 성능으로 간주하지 않는다.
- [Pi 공식 subagent 예제](https://github.com/earendil-works/pi/tree/main/packages/coding-agent/examples/extensions/subagent): 독립/병렬/연쇄 실행, 역할별 모델, 진행 상태와 사용량을 제공한다. MIT. 실제 예제는 `node:child_process`로 Pi 프로세스를 실행하므로 확장에 그대로 넣을 수 없다. 누비에 설치된 `pi-agent-core@0.86.1`의 독립 Agent와 이벤트를 사용하고 브라우저용 작업 조정 계층을 추가하는 것을 우선한다.
- [Deep Agents JS](https://docs.langchain.com/oss/javascript/deepagents/subagents): 하위 에이전트별 모델과 도구, 독립 문맥, 요약 반환을 지원한다. [MIT](https://github.com/langchain-ai/deepagentsjs/blob/main/LICENSE). LangChain/LangGraph 기반이므로 기존 Pi와 두 개의 실행 상태를 관리하게 된다. 설계 패턴을 참고하며 MV3 번들/기존 어댑터 호환성은 아직 검증하지 않았다.

선택 제안: **현재 Pi를 유지하고 역할, 문맥 분리, 병렬 조정만 추가한다.** 새 CLI나 로컬 서버 설치를 전제로 하지 않는다. 외부 예제를 복사한 구현은 아직 없다.

## 문맥과 동시 실행 계약

- 하위 입력은 작업 목표, 꼭 지킬 제약, 관련 근거 ID, 허용 도구, 완료 조건으로 한정한다. 전체 대화 복제를 기본으로 하지 않는다.
- 반환은 요약, 근거 ID, 확인된 사실, 남은 불확실성, 산출물 참조다. 큰 DOM/이미지/코드는 기존 로컬 저장소에 두고 필요한 부분만 다시 읽는다. 요약이 원본을 대체하지 않는다.
- 병렬 허용은 고정된 관찰을 이용한 분석과 독립 문서/API 읽기부터 시작한다. 페이지 읽기도 관찰 ref나 활성 탭을 갱신하면 공유 상태 작업이다. 같은 문서의 새로운 관찰/클릭/입력/이동/팝업 전환은 직렬화한다. `run_playwright` 전체를 읽기 작업으로 간주하지 않는다.
- 두 개 이상의 병렬 슬롯, 제공자별 요청 제한과 토큰 예산을 작업 조정 계층에서 관리한다. 첫 버전은 위임 깊이 한 단계로 제한하고, 계속 진행할 일은 주 에이전트가 다음 작은 작업으로 재배정한다. 단순 작업은 위임 비용을 만들지 않는다.
- 질문과 승인은 누비가 한곳에서 표시한다. 하위 에이전트는 등록/발송 권한을 만들지 않는다. 결과는 관찰 문서와 버전에 연결하며 페이지 변경 후에는 다시 검증한다.
- 취소는 실행 중인 자식에게 전파한다. 늦게 온 응답은 현재 계획에 자동 반영하지 않는다. 실패한 분석만 재시도하고 이미 실행한 쓰기는 반복하지 않는다.
- 각 하위 실행의 usage를 제공자와 실행 ID별로 집계한다. 주 대화의 컨텍스트 사용량과 전체 토큰 합계를 분리한다. 전체 호출량 감소는 측정 전까지 주장하지 않는다.

## 현재 코드에서 필요한 변경

| 위치 | 필요한 변경 |
| --- | --- |
| `agent-runtime.js` | 주 Agent가 승인된 역할의 작업을 시작/관찰/취소하도록 위임 도구 추가. 독립 Agent별 transcript 분리 |
| `src/api.js` | 현재 전역 credential을 역할별 검증된 연결로 전달. 하위 출력이 주 답변 스트림을 덮어쓰지 않게 분리 |
| `public/background.js` | 단일 `chatLease` 아래 자식 실행 ID/제공자/도구/문서 소유권 관리. UI 다중 세션은 별도 최상위 lease 설계 필요 |
| `browser-agent.js` | 같은 문서와 브라우저 컨텍스트의 조작 잠금 유지. 분석용 관찰 복사와 새 관찰 생성 분리 |
| `context-manager.js` | 위임에 필요한 문맥 선택, 근거 참조, 결과 압축. 부모/자식 요약과 취소 상태 분리 |
| `usage-ledger.js` 및 실행 이력 | 하위 실행별 중복 없는 집계, 역할별 접힌 진행 행과 완료 결과 |

현재 `toolExecution: sequential`을 `parallel`로 바꾸는 것만으로 해결되지 않는다. 하네스는 앞 도구의 결과를 보지 않은 후속 동작을 보류하며 브라우저 실행기와 worker도 하나의 활성 작업을 전제로 한다.

## 적용 전 평가

같은 Qwen 모델, 같은 요청/화면에서 단일 실행과 역할별 병렬 실행을 비교한다. 실제 모델 평가와 합성 Chrome 검사를 따로 기록한다.

1. 독립 문서 3개 조사: 실제 동시 요청, 누락 없는 출처/요약, 소요 시간과 전체 토큰 비교.
2. 같은 탭의 클릭과 입력: 동시 호출이 와도 충돌 없이 직렬화되고 최신 ref만 사용.
3. 화면 분석과 Wiki 분석: 선택한 자료만 각 역할에 전달되고 부모에 큰 원문이 중복되지 않음.
4. 자식 한 개 실패/429/출력 한도: 다른 결과 유지, 실패한 분석만 복구, 페이지 쓰기 중복 없음.
5. 사용자 취소/세션 전환/새로고침: 자식 취소, 다른 세션으로 늦은 결과 유입 없음.
6. 선택하지 않은 제공자와 권한: 요청 0회, 토큰/쿠키가 모델 입력이나 진단에 없음.
7. 초안 완료 후 HITL: 하위 검토의 성공 여부와 별개로 원래 요구의 검증 및 사용자 승인 유지.
