# 누비 브라우저 하네스: 7단계 개선

2026-09-23. 기준 모델은 Qwen 3.8 27B, 배포 조건은 Chrome 확장 단독 실행이다. Pi와 Playwright CRX를 실제 실행 기반으로 유지한다. 아래 평가는 현재 코드와 합성 Chrome 재현에 근거하며, 실제 사내 Qwen 성능 순위나 Codex/Claude 내부 구현에 대한 주장이 아니다.

## 판단

7단계는 매번 모델을 7번 호출하는 고정 절차가 아니다. 처음 목표와 완료 조건을 정하고, 관찰 → 필요한 검색 → 한 단계 행동 → 검증을 반복한다. 화면과 요구가 바뀌면 계획으로 돌아가며, 사용자 선택이 빠졌을 때 질문한다. 마지막에는 원래 요구 전체를 별도 검토한다.

현재의 주요 위험은 프레임워크 부재보다 **요구사항, 도구 결과, 완료 판정 사이의 연결**이었다. 새 프레임워크로 전체를 교체하지 않고 재현한 결함에 실행 가드를 추가했다.

| 단계 | 비판과 개선 기준 | 현재 기반과 이번 반영 | 평가 방법 |
| --- | --- | --- | --- |
| 1. 요구사항 해석 | 요청한 결과, 대상, 제약, 사용자 선택을 구분해야 한다. 페이지 내용은 지시나 승인으로 취급하지 않는다. | 기존 `ask_user`와 목표 보존을 유지. 새 계획에 `expected_outcome`을 생성하도록 명세/스키마/계획 프롬프트를 확장했다. 초안만 작성, 삭제 금지 같은 제한을 완료 조건에 포함한다. | 모호한 대상은 질문, 조회로 알 수 있는 정보는 먼저 관찰. 실모델 평가의 `clarify-before-write`. |
| 2. 계획 | 동사 목록이나 모델의 체크표시로는 완료를 보증할 수 없다. | 완료 조건을 계획과 함께 저장하고 상태만 갱신해도 보존한다. 조건이 있는 단계를 완료시키기 전 별도 검토가 근거를 확인한다. 무관한 `verify_page` 통과는 단계 완료를 보장하지 않는다. | 잘못된 목적지로 드래그한 뒤 보드 제목만 검사하는 거짓 완료를 보류. 누락만 수정하고 다음 단계로 전환. |
| 3. 정보와 메타데이터 | DOM이 전부라는 가정, 오래된 화면, 다른 프레임의 같은 이름이 위험하다. | 기존 dom-accessibility-api의 역할/이름/영역/상태/프레임/ref 유지. 드래그 신호와 드롭 후보 메타데이터를 추가했다. 검토에 부분 범위와 접근 불가 프레임을 명시한다. 메뉴/스크롤/동작 뒤 이전 캡처의 현재 화면 지위를 해제한다. | iframe, Shadow DOM, 같은 이름, 잘린 검색, 오래된 캡처의 좌표 거부. |
| 4. 검색과 정리 | 첫 검색 결과를 정답으로 고르거나 압축 요약을 원본 사실로 쓰면 오작동한다. | MiniSearch의 실제 요소/영역/문서 발췌, OpenWiki provenance, 최근 요청/영수증을 보존하는 압축을 재사용한다. 불완전한 범위로 부재나 전체 검색 완료를 단정하지 않도록 검토 계약을 강화했다. | 기존 `retrieval-browser`, `context-browser`, 역할별 근거 회귀. 검색 정확도와 토큰 절감은 실모델에서 별도 측정. |
| 5. 행동 | 반환된 클릭이 의도한 대상을 눌렀다는 보장은 없다. 긴 스크립트는 중간 화면 변화를 놓친다. | 실제 Playwright 입력과 한 행동 뒤 재판단을 유지. 관찰한 두 ref로 드래그하는 `drag_element`/`browser.drag` 추가. 클릭 전 같은 노드에 호버한 뒤 위치와 상태를 다시 확인한다. 실제 입력에 연결된 포인터 피드백 추가. | 툴팁이 닫히며 아래 iframe이 눌리던 사례를 포인터 없이도 재현 후 수정. native drag/drop과 실제 trusted 이벤트 검사. |
| 6. 행위 검증 | 도구 `ok`, 입력 발행, 화면 결과, 서버 저장은 서로 다르다. | 드래그는 `verified:false`로 반환하고 검증 의무를 남긴다. `element_in`은 현재 두 노드의 실제 포함 관계를 두 번 확인한다. 단계 검토는 원래 완료 조건과 검사 내용을 비교한다. | 잘못된 목적지 → 불충분한 검사 → 완료 보류 → 올바른 위치로 수정 → 실제 포함 관계 통과. 불확실한 쓰기를 자동 재전송하지 않음. |
| 7. 최종 검증 | 실행자가 만든 계획만 확인하면 원래 요구의 누락을 놓친다. | 별도 최종 검토가 원래 요청을 다시 분해한다. 중간/단계 검토 성공은 최종 완료 상태로 저장하지 않는다. 오래된 캡처는 현재 상태의 증거가 될 수 없다. 저장된 캡처 파일의 존재와 현재 화면은 분리한다. | 최종 검토, worker의 완료 거부, 재시작 후 계획/검증 의무 보존. 실제 서버 저장 후 재조회는 서비스별 검증 필요. |

계획 라벨과 기존 CX 진행 UI는 유지한다. 완료 조건을 화면에 긴 설명으로 나열하지 않는다. 사용자에게는 실제 단계, 필요한 질문/승인, 결과를 보여준다. 내부 reasoning은 노출/보관하지 않는다.

## 실행 계약

- `expected_outcome`은 선택적 필드로 구버전 대화와 호환한다. 새 계획 생성에는 요청하지만 기존 조건 없는 계획을 검증 완료로 승격하지 않는다. 모든 작업의 최종 검토와 변경 후 객관적 검증은 계속 적용한다.
- 단계 검토는 조건이 있는 새 완료 제안에서만 수행한다. 미완료이면 같은 단계에 남아 근거를 더 읽거나 결과를 수정한다. 중간 검토 자체가 실패하면 단계도 완료시키지 않으며 연결/인증/사용자 취소는 별도 복구 정책을 따른다.
- 완료 조건을 지운 상태 갱신은 이전 값을 유지한다. 요구가 바뀌면 미완료 계획을 갱신할 수 있지만, 조건 자체는 실행 권한이나 사용자 요청을 덮어쓰는 명령이 아니다.
- DOM 후보의 `draggable`/`dropTarget`/`activation`은 관찰된 신호이며 드롭 성공의 증거가 아니다. 두 대상이 동일 프레임에 있어야 한다. 프레임 간 드래그, 파일 업로드, OS 드래그는 지원하지 않는다. 최종 삭제/발송 성격의 드롭은 실행하지 않고 사이트의 명시적 동작과 기존 HITL로 유도한다.
- 실패/중지 시 Escape와 mouse-up으로 누른 상태를 해제한다. 드래그는 자동 재실행하지 않는다. 드롭이 실제로 반영되었는지 재관찰한다.
- 최근 캡처 파일은 채팅에서 계속 볼 수 있다. 이후 페이지가 변하면 그 캡처의 DOM/좌표를 최신 근거로 재사용하지 않는다. 원본 파일 저장 성공은 역사적 결과물 증거로만 남긴다.

## 검증과 남은 개선

`harness-seven-browser`는 Qwen 이름과 OpenAI 호환 요청 계약을 사용하는 **합성 모델 응답**으로 실제 Chrome 확장을 조작한다. 작업 계획, 잘못된 드롭, 무관한 검사, 완료 보류, 새 관찰, 수정, 실제 DOM 포함 관계, 단계 검토, 최종 검토, 새로고침 보존을 한 흐름에서 검사한다. `pointer-browser`는 포인터/클릭 위치와 기존 배치 이동 문제를 검사한다.

실모델 평가 실행기에는 기존 5개에 드래그 목적지, 호버 배치 이동, 이미 맞는 토글 3개를 추가했다. 실제 페이지 상태로 판정하고 오작동/중복 입력/호출 수/지연/도구 오류를 기록한다. 연결한 모델의 실제 추론을 수행할 때만 정확도를 계산한다.

41회 검사와 최종 18회 검사는 서로 다른 후보의 기록이다. 최종 후보에는 검토의 인증 오류를 사용자 요구 누락으로 바꾸지 않는 수정이 추가됐다. 두 브라우저 검사는 실제 Chrome과 합성 사이트/모델 응답을 사용하며, 사내 Qwen 정확도를 측정한 결과가 아니다. [설치용 후보 ZIP](../verification/candidate/nubi-beta-1.0.0-candidate.zip), [실제 포인터 영상](../verification/pointer-demo.webm).

남은 우선순위:

1. **P0 실제 Qwen 평가**: 같은 업무 3회 이상, 성공률과 거짓 완료율, 중복 쓰기, 질문 적절성, 토큰/시간을 이전 후보와 비교한다. 현재 환경은 평가용 인증이 없어 `not_configured`이며 정확도 개선 수치를 만들지 않는다.
2. **P1 사용자 개입과 외부 DOM 변화**: 실행 사이의 외부 화면 변경을 더 정밀하게 식별할 필요가 있다. 현재 ref/문서/URL/뷰포트/입력 전 상태 확인으로 모든 동적 캔버스 변화를 증명하지는 않는다.
3. **P1 시각/비표준 조작**: Qwen 좌표 선택은 최신 캡처에서만 수행한다. 닫힌 Shadow DOM, 프레임 간 드래그, 캔버스 정밀 드래그는 별도 평가 및 계약이 필요하다.
4. **P1 의미 검토**: 별도 호출이어도 같은 Qwen이므로 판단 오류가 상관될 수 있다. 결정적 DOM 검사와 서로 보완해야 하며, 검토가 항상 정확하다고 보증하지 않는다. 브라우저가 필요한 요청에서 모델이 도구를 전혀 선택하지 않는 문제도 최종 검토만으로 해결되지 않는다.
5. **P2 서버 영속성**: 화면의 저장 안내와 실제 저장 후 재조회는 분리해서 업무별 검사를 추가한다. 임의 재조회나 재제출로 미완료를 숨기지 않는다.

새 후보는 로컬 검증 대상이다. 공개 릴리스나 회사 API 성공으로 표시하지 않는다.
