# Claude 확장 분석의 누비 적용 상태

기준은 [Claude 1.0.94 정적 분석](CLAUDE-HARNESS-STATIC-2026-09-26.md)이다. 해당 배포본의 코드 흐름을 참고했으며 Claude 원본 번들/프롬프트를 복사하지 않았다. 이 문서는 Claude 최신 버전이나 실모델 우열을 판정하지 않는다.

## 분석 항목과 현재 구현

| 분석 항목 | 누비 코드/상태 | 이번 판단 |
| --- | --- | --- |
| 도구 실패도 같은 호출 ID의 결과로 모델에게 전달 | `agent-runtime.js`의 Pi toolResult 변환, `tool-errors.js`의 안전한 오류 피드백 | 기존 유지. 예외 문자열에는 입력/인증값이 섞일 수 있어 임의 원문을 그대로 전송하지 않음 |
| 화면 변경/쓰기 순차 처리 | `beforeToolCall`의 실제 결과 소비와 이후 선행 제안 보류 | 기존 유지. 읽기 워커만 제한된 병렬 실행 |
| 승인/사용자 대기와 통신 실패 분리 | `agent-turn-boundary.js`, 같은 실행의 질문/승인 상태, `model-recovery.js` | 기존 유지. Claude MCP 팝업의 30초 만료를 일반 질문 폼에 도입하지 않음 |
| 일시 추론 오류의 backoff/jitter와 활동 감지 | 기존 MIT `p-retry@8.0.1`, cooldown, parsed-event idle clock | 기존 유지. Claude의 10회/300초 수치를 근거 없이 복제하지 않음. 현재 누비 추론 idle 120초와 단일 시도 300초는 사용자 답변 대기 시간이 아님 |
| 작업 탭 소유권과 새 관찰 | 기존 workspace/tab ownership, document/ref 재검증과 오류 탭 복구 | 기존 유지. 사용자 다른 탭 활성화나 미확정 쓰기 재전송으로 우회하지 않음 |
| 문맥 압축 뒤 요구사항/근거 보존 | 기존 원 요청/사용자 답변/영수증 계약과 [본문 보존 개선](RESEARCH-COMPLETION-2026-09-26.md) | 기존 유지. 요약으로 승인이나 문서 현재성을 대신하지 않음 |
| 결과를 돌려준 뒤 다음 판단 계속 | 최종 `revise` 반복 시 구체적 분석 없이 사용자 질문으로 전환되던 경로 | **이번 보강**: 기존 읽기 전용 recovery 워커를 한 번 실행하고 원문 근거에 기반한 다음 조회/검사 조언 전달 |
| 모델 응답 종료와 작업 결과 구분 | 기존 optional hook은 평가용 계측에서만 사용하고 일반 background는 agent 진단을 폐기 | **이번 보강**: 검토 범위/집계와 answer/waiting_user/failed/cancelled를 별도 세션 이벤트로 보존. 최종 검토 통과 여부도 분리 |

Claude 일반 사이드패널 코드에서 누비와 같은 독립 요구사항 완료 게이트는 확인하지 못했다. 따라서 최종 검토 복구는 Claude의 직접 복제 기능이 아니라, 오류 피드백을 다음 판단으로 연결하는 패턴을 누비의 기존 검토기에 적용한 것이다.

## 이번에 고친 경로

최종 검토가 `revise`를 반환하고 다음 후보 답변에서도 같은 실제 근거만 남아 있으면 기존에는 사용자에게 추가 정보를 묻는 경로로 넘어갔다. 이제 분석 연결과 고정 근거가 있으면 같은 근거당 recovery 워커 한 건으로 누락된 조회/검사 방법을 찾는다. 주 실행기가 보완한 후보는 다시 전체 요구사항 검토를 받아야 한다. 워커 조언이나 답변 표현만 바꾼 것을 진전으로 세지 않는다.

Pi 0.87.1의 실제 `agent-loop.js`를 확인했다. `prepareNextTurn`은 한 loop 안에서 직전 turn이 있을 때 호출되므로, 최종 검토 뒤 별도의 `continue()` 첫 호출에만 복구를 예약하면 실행되지 않는다. 최종 검토 복구는 continue 이전에 준비하도록 연결했다. 또한 Pi의 follow-up은 한 번에 하나씩 소비하므로 검토 피드백과 워커 조언을 하나의 메시지로 전달해 다음 판단에 둘 다 도착하도록 했다. 단계 검토 복구는 기존 turn hook을 유지하며 같은 준비 함수를 재사용한다.

`blocked`는 실제 사용자 정보/선택 질문을 유지한다. 조언 뒤에도 근거가 그대로이면 작업을 보존하고 `다시 확인` 또는 `중지`로 대기한다. 분석 연결이 없을 때도 기술적 검증 실패를 사용자 입력 부족으로 꾸며 묻지 않는다. 사용자 정정은 예정/실행 중 복구 워커를 취소하고 낡은 조언을 전달하지 않는다. 미확정 쓰기는 기존 조회/검증 경로가 먼저 처리하며 이 복구로 해소하지 않는다.

추가 재현에서는 워커 결과 수집이 시작된 뒤 도착한 사용자 수정이 모델 응답까지 기다리는 문제도 확인했다. 수정 전에는 1.5초 테스트 제한으로 전체 실행이 취소됐고, 수정 후에는 250ms 간격의 입력 확인으로 느린 워커만 중단한 뒤 새 요청을 처리했다. 이는 입력 확인 주기와 합성 재현 결과이며 실서비스 응답 지연 수치는 아니다. 단계/최종 복구가 같은 대기 함수를 사용한다. 이 추가 변경 도중 실행 중이던 첫 gate는 입력 해시 변경으로 무효화됐으며 최종 후보는 아래 별도 gate로 다시 검증했다.

종료 진단은 `completion-errors.js`의 허용된 값만 background의 소유 실행에 기록한다. 검토 문구/후보 답변/본문/인증값/임의 예외 문자열은 보존하지 않는다. 검토는 범위와 met/unmet/unknown 개수, 실행은 답변/사용자 대기/실패/취소와 알려진 오류 코드만 남긴다. 세션 이벤트 최대 40개이며 화면 재진입에는 남지만 브라우저 재시작을 견디는 영구 실행 기록은 아니다. 진단 저장 실패가 작업 결과를 바꾸지 않으며, 진단 중 사용자 취소도 지킨다.

## 선택한 근거와 비용

- [Anthropic 응답 종료 사유](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons): 응답 종료 원인은 후속 처리의 입력이며 업무 완료 자체와 다름. 누비에서 현재 제공자가 정규화한 finishReason과 호스트 최종 검토를 구분하며 Claude 제공자 연동을 새로 도입하지 않음.
- [p-retry 공식 소스](https://github.com/sindresorhus/p-retry): 이미 번들한 MIT 전송 재시도 유지. 브라우저 작업 전체 재시도나 미확정 쓰기 재전송에는 사용하지 않음.
- Pi/p-limit의 기존 워커 실행과 고정 근거 조회를 재사용. 새 라이브러리/CLI/인증 저장소는 추가하지 않음. 추가 모델 비용은 실제 근거 진전이 멈춘 최종 검토에만 발생하며, 같은 근거에 워커를 반복 실행하지 않음.

## 검증 기준

- 단위: 최종 revise 반복 → 워커 한 건 → 필요한 원문 조회 → 전체 검토 통과, 조언만으로 성공 금지, blocked 직접 질문, 정정 시 취소, 분석 연결 없는 기술적 대기.
- 진단: 최종 검토 성공과 일반 답변 구분, 사용자 대기/인증 실패/취소 구분, 원문과 임의 코드 제거, 진단 오류 격리.
- 실제 Chrome: `final-gap-recovery-browser`는 실제 페이지와 Pi 워커를 사용하되 모델 응답은 합성이다. 실제 원문을 추가 조회하고 최종 검토가 통과해야 종료하며 페이지 이동/쓰기/승인 없이 복구한다.
- 실제 Chrome: `review-recovery-browser`는 원래 DOM 입력 다섯 번이 한 번씩만 실행되고 중복 쓰기가 차단됨을 검사한다. 일반 앱 실행의 agent 진단 저장과 화면 재진입 보존도 확인한다.

이 검사는 실제 선택 모델의 네이버 완주율 측정이 아니다. 앞선 실제 모델 재시험은 SSO 로그인 미완료였으며, 이번 변경으로 실제 완주가 해결됐다고 판정하지 않는다.

최종 [검증 보고서](../verification/pre-release-2026-09-26T08-52-36-913Z/report.json)는 단위 **958개**, 디자인 검사, 후보 빌드, 실제 Chrome **26회**를 통과했다. Chrome은 관련 8종을 새 프로필에서 3회씩 반복하고 새 복구/원문 연결 2종을 각각 1회 검사했다. 최종 소스/검사 입력 및 빌드 해시가 보고서와 일치한다. 전체 고정 baseline 100회나 실계정 모델 시험으로 표시하지 않는다.

후보 ZIP SHA-256: `2fb3d2f6a582e0f67db0892f335635ce94c9f7a1b33754be80673754e3afdf00`. 출시 ZIP 교체나 외부 배포는 하지 않았다. [복구 시나리오 결과](../verification/final-gap-recovery/browser.json)는 원문 화면 관찰 1회, 본문 조회 1회, recovery 워커 1건, 최종 검토 3회 뒤 답변 완료를 기록했다. 이 횟수는 합성 모델 시나리오의 동작 검증이다.
