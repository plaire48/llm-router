# Claude 비교 후속: 녹화 종료와 저장 복구

2026-09-25 재점검. 기존 13항목의 26/26은 기능 경로의 존재만 나타낸다. 만료, 탭 종료, 저장 실패와 응답 유실을 통과했다는 뜻으로 확장하지 않는다. 이번에는 이 네 가지 복구 조건을 별도로 채점했다.

## 소스 재확인

Google 공식 update2 주소로 받은 Claude CRX 1.0.94의 SHA-256은 이전 검토와 동일하다. 설치하거나 실행하지 않고 `SavedPromptsService`의 알람 등록/저장 목록 대조, worker의 탭 종료 처리, MCP 번들의 이벤트 연결/해제를 읽었다. 이 정적 코드는 Claude의 녹화 초안 저장 실패 복구 성능을 입증하지 않는다. 재사용 허가를 확인하지 못해 제품 코드에 복사하지 않았다. [배포 코드 해시와 식별자](../verification/claude-lifecycle-2026-09-25/claude-recheck.json).

[Claude 공식 안내](https://support.claude.com/en/articles/12012173-get-started-with-claude-in-chrome)는 classic 패널의 절차 녹화와 반복 업무를 설명한다. Cowork 패널 및 Claude Code 결합 기능과 동일시하지 않는다. 나머지 기능의 전체 비교는 [기존 표](CLAUDE-BROWSER-COMPARISON-2026-09-25.md)를 유지한다.

## 복구 검증 점수

0 = 해당 실패 시 보존/중복 방지 없음, 1 = 수집 자체만 중단되는 부분 대응, 2 = 명시한 종료/저장 계약을 로컬 회귀로 확인. 아래 네 조건만의 점수이며 제품 정확도나 실서비스 성공률이 아니다. Claude의 내부 실패 복구는 실행하지 않았으므로 점수를 만들지 않는다.

| 조건 | Claude 내부 복구 | 누비 수정 전 | 누비 수정 후 | 근거 |
| --- | --- | ---: | ---: | --- |
| 녹화 만료 후 종료와 초안 | 미측정 | 1 | 2 | nonce별 실제 Chrome alarm, 설정 조회/worker 시작 재확인 |
| 녹화한 탭 종료 후 초안 | 미측정 | 1 | 2 | 실제 탭 닫기 후 session 종료와 검토 초안 |
| 초안 쓰기 실패 시 보존 | 미측정 | 0 | 2 | 수정 전 실패 재현, 중지된 session 체크포인트 유지 후 재시도 |
| 절차 저장 응답 유실 시 중복 방지 | 미측정 | 0 | 2 | 실제 저장 후 오류를 주입하고 같은 초안 저장 재요청 시 1개 유지 |

수정 전 만료/탭 종료의 1점은 기존 소스에서 수집 중지까지만 확인한 정적 평가다. 저장 실패/응답 유실의 0점은 새 검사로 수정 전에 재현했다. 수정 후 점수는 해당 로컬 회귀 결과에 근거한다.

누비의 이 네 조건은 **2/8 → 8/8**이다. 기존 기능 지원 26/26과 합산하지 않는다. 단위 오류 주입과 실제 Chrome 시나리오의 증거 종류도 구분한다.

## 개선 목록과 반영

- **C10 완료:** 만료 알람, 탭 종료, worker 재시작 및 설정 조회에서 녹화 상태를 대조한다. 100단계에 도달하면 검토 초안으로 종료한다. 오래된 nonce의 알람과 늦은 이벤트는 새 녹화를 종료하거나 초안을 바꾸지 못한다.
- **C11 완료:** 종료 의도를 session에 먼저 기록하고 수집을 중지한다. local 초안을 저장한 뒤 session을 제거한다. 저장 실패 시 같은 nonce/초안 ID로 재시도할 수 있다. 녹화 내용에 입력값을 추가하지 않는다.
- **C12 완료:** 검토한 초안 ID를 절차에 연결한다. 절차와 초안 소비를 같은 local.set 호출로 저장하고 응답이 유실되어도 이미 저장한 절차를 반환한다. 다른 이름/목표를 같은 요청으로 조용히 덮어쓰지 않는다. Chrome 저장소 전체에 걸친 DB 트랜잭션을 주장하지 않는다.

## 방법론과 오픈소스 선택

- Chrome의 [worker 수명](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle), [알람](https://developer.chrome.com/docs/extensions/reference/api/alarms), [저장소](https://developer.chrome.com/docs/extensions/reference/api/storage) 계약을 적용했다. 페이지의 타이머만 믿지 않고 알람과 저장 상태를 대조한다. Chrome 150 전용 옵션을 추가하지 않았다.
- 기존 **Playwright CRX Apache-2.0**와 Chrome fixture를 재사용해 알람/탭 종료/worker 강제 종료를 확인했다. 기존 Pi, 선택 모델, 실제 행동 승인과 완료 검증은 유지했다.
- **rrweb MIT**는 재검토했지만 추가하지 않았다. [rrweb](https://github.com/rrweb-io/rrweb)의 DOM 기록/재생 기능은 이번 session/local 저장 순서와 중복 저장 결함을 해결하지 않는다. 별도 프레임워크나 새 패키지를 넣지 않고 원인 경로를 수정했다.
- 실패 주입 → 실패 보존 → 같은 조건 재검증, 저장 전 중지 표시, 고정된 요청 ID로 중복 억제하는 패턴을 적용했다.

## 검증 범위와 남은 차이

수정 전 저장 실패/응답 유실 검사 2개가 실패했고 수정 후 통과했다. 녹화 만료, 탭 종료, 100단계, stale alarm, worker 복구를 추가 검사했다. 실제 Chrome은 로컬 사이트와 합성 모델을 사용한다. 최종 전체 회귀 수치는 [검증 요약](../verification/claude-lifecycle-2026-09-25/report.json)에 기록한다.

녹화는 여전히 동일 사이트 최상위 화면의 의미 기반 절차이며 영상/GIF와 다른 origin/iframe 자동 녹화는 지원하지 않는다. 활성 녹화의 session 체크포인트는 Chrome 전체 종료 시 사라질 수 있으며 그 이후 복원을 보장하지 않는다. UI는 검토용 초안 한 개를 관리한다. 월/연 달력 주기의 예약, 외부 비밀번호 관리자 연계 등 Claude 제품의 모든 부가기능과 동등하다는 뜻이 아니다. 실제 Claude/Qwen 성공률, OS 알림의 화면 표시, 조직 정책 실배포는 여전히 미측정이다.
