# 30개 완주 재검증

목표는 같은 후보의 30개 과제 중 **24개 이상 독립 판정 통과**다. 진행률, 코드 수정률, 실제 완주율을 합치지 않는다. 최신 실행은 SSO 인증 시간 만료로 중단됐으며 **0/30 실행, 품질 미측정**이다.

## 완료 기준

1. 원래 요구사항을 유지한 계획이 존재하고 모든 단계가 완료돼야 한다. 2/3, 빈 계획 0/0은 탈락이다. 과제에 따라 계획 단계 수는 다를 수 있다.
2. 마지막 요구사항 검토가 완료돼야 한다. 단계 검토를 최종 검토로 대체하지 않는다.
3. 실제 저장 상태가 done이고 실행 중 표시가 없으며 최종 답변이 화면에 보여야 한다.
4. 정답, 실제 입력 값, 원문 출처, 저장 파일 등을 독립적으로 대조한다. 모델의 완료 선언이나 자체 검토만으로 통과시키지 않는다.
5. 불필요한 질문에서 멈추거나 시간/호출 한도에 도달하면 성공이 아니다. 예정된 H-10 입력 대기와 정정은 같은 실행에서 처리한다.

## 벤치마킹과 적용 범위

- 다운로드한 Claude 브라우저 1.0.94의 `processToolResults`가 실행, 권한 대기, 재시도 시간을 나누고 각 도구의 오류를 반환하는 구조를 확인했다. 누비에도 단계별 관측을 적용했다. 배포 코드를 오픈소스라고 부르거나 복사하지 않았다. 파일/해시는 [기존 코드 분석](CLAUDE-HARNESS-STATIC-2026-09-26.md)과 [개선 목록](LIVE-FAILURE-FIXES-2026-09-27.md)에 있다.
- [OpenCode compaction 소스](https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/packages/opencode/src/session/compaction.ts), MIT: 필요한 최근 결과를 보존하면서 도구 출력의 문맥 비용을 관리하는 패턴을 참고했다. 이번에는 압축을 더 늘리지 않고 누락된 공개 결과부터 전달했다.
- [Codex compact.rs](https://github.com/openai/codex/blob/814de47b69dd63a2660fd14f9af66690888d183e/codex-rs/core/src/compact.rs), Apache-2.0: 원래 사용자 요구와 재구성 문맥의 구분을 참고했다. 원래 요구를 줄여 완료 처리하지 않는다.
- [Anthropic 문맥 관리](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): 필요한 정보 선택과 역할별 문맥 분리를 참고했다. 이미 있는 Pi, MiniSearch와 읽기 전용 하위 분석을 유지했다. 동작하는 브라우저 쓰기를 병렬화하지 않는다.
- [Aside 실제 평가 코드 분석](ASIDE-BENCHMARK-2026-09-27.md): 부분 조건별 결과와 전체 과제 완주를 분리하는 방식을 유지한다. 다른 모델/과제의 공개 점수를 누비 점수로 전용하지 않는다.

추가 라이브러리는 도입하지 않았다. 기존 Pi/Playwright CRX/Readability/Turndown/MiniSearch로 재현된 연결 문제를 수정할 수 있다. 새 의존성의 비용을 늘리기 전에 실제 지연 감소를 확인한다.
