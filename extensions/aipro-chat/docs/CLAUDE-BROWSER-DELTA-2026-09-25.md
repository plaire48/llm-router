# Claude in Chrome 대비 누비의 예약·재사용 품질 재평가

검토일: 2026-09-25. [기존 13개 기능 비교](CLAUDE-BROWSER-COMPARISON-2026-09-25.md)와 [최근 재점검](CLAUDE-BROWSER-RECHECK-2026-09-25.md)을 현재 소스에 맞춰 확장한다. Claude는 [공식 기능 문서](https://support.claude.com/en/articles/12012173-get-started-with-claude-in-chrome)와 배포 CRX 1.0.94의 정적 메타데이터로 확인했다. 누비는 현재 소스·단위 검사·합성 사이트 Chrome 검사로 확인했다. 배포 JS는 재사용 허가 라이선스를 확인하지 못해 복사하지 않았다. 실제 동일 계정·사이트·정답의 성공률은 측정하지 않았다.

점수는 **개별 기능 경로**에만 적용한다. 0=경로 없음, 1=제한된 대체 경로, 2=명시한 경로 있음, —=비교 근거 없음. D=Claude 공식 문서, S=Claude 배포본 정적 식별자, L=누비 로컬 검사. D/S와 L은 동일 강도의 증거가 아니다. 안전성이나 실모델 품질의 총점은 계산하지 않는다.

기존 26/26은 앞서 선정한 13개 기능의 실행 경로만 평가했으므로 이 표의 차이나 정확도를 가리지 못한다. Claude의 녹화는 공식 문서상 classic 패널 전용이고 새 Cowork 패널의 기능을 모든 패널에 일반화하지 않는다. [권한·승인 안내](https://support.claude.com/en/articles/12902446-claude-in-chrome-permissions-guide)의 자동 승인 정책과 누비 HITL은 동등하다고 판정하지 않는다.

## 구현 순서와 근거

1. **P0, 반영:** 예약 `waiting`·`context_changed`가 재개되지 않는 실제 코드 경로를 고쳤다. UI에서 원래 이름·요청·URL을 가져와 새 시각을 명시적으로 받는다. 백엔드는 새 인증/정책과 입력을 검증해 같은 ID를 한 번만 재등록한다. `unknown`은 이전 실행의 결과가 미확정이므로 자동 재등록하거나 이 버튼으로 재전송하지 않는다.
2. **P0, 반영:** `done`을 곧 업무 성공으로 읽지 않도록 독립 검토 여부를 영수증에 저장하고 화면 문구를 나눴다. 재발 방지를 위해 일반 모델 응답과 검증 통과를 별도로 검사한다.
3. **P1, 반영:** 월·연 반복은 처음 지정한 날짜를 기준으로 다음 일정을 계산한다. 1월 31일은 2월 마지막 날 뒤 3월 31일로 돌아가고, 2월 29일은 비윤년의 2월 마지막 날 뒤 윤년에 다시 29일을 사용한다.
4. **P1, 반영:** 일반 프롬프트 shortcut을 스킬·녹화 절차와 별개로 저장한다. 이름 충돌/저장 포맷을 검증하고, 동일 확장 origin의 여러 창은 Web Locks로 저장을 직렬화한다. `/p:` 선택과 직접 전송 버튼의 명령 인식은 먼저 프롬프트를 초안에 불러올 뿐 에이전트를 실행하지 않는다.
5. **P1, 제외:** 연결 페이지에서 고정 추천 버튼 두 개와 추가 설명을 시험했으나 시작 화면이 복잡해진다는 사용자 피드백을 받아 컴포넌트·테스트·검증 계획에서 제거했다. 현재 관련 자동 제안 기능은 없다.
6. **범위 별도:** 계정 서버를 요구하는 기기 간 이어받기는 로컬 확장 단독 설치와 충돌한다. 선택 모델·인증 경계를 확정하는 별도 설계 없이 도입하지 않는다.

## 오픈소스·공개 방법론 검토

| 후보 | 적용 판단 |
| --- | --- |
| [Chrome alarms API](https://developer.chrome.com/docs/extensions/reference/api/alarms) | **재사용.** 새 의존성 없이 일회 알람과 영수증을 유지한다. Chrome이 닫혔거나 절전 중인 기기를 깨울 수 없으므로 놓친 실행은 자동 재생하지 않는다. |
| [date-fns](https://github.com/date-fns/date-fns) MIT | **검토 후 미도입.** 단순 `addMonths`만 사용하면 월말 기준일 보존 계약을 별도로 구현해야 한다. 현재 두 달력 경계의 작은 함수와 고정 회귀가 의존성 추가보다 범위가 명확하다. |
| [Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API) | **적용.** 여러 누비 탭의 프롬프트 바로가기 저장을 동일 origin 배타 잠금으로 직렬화한다. Chrome 확장 화면에서 API 존재를 확인했고, 사용 불가 시 저장을 거부한다. |
| [Anthropic computer-use 예제](https://github.com/anthropics/claude-quickstarts) MIT | **참고.** 예제의 도구 후 실제 상태 확인·위험 동작 승인 원칙을 기존 누비 하네스와 대조했다. Claude in Chrome 제품 소스가 아니며 코드를 가져오지 않았다. |
| Claude in Chrome CRX | **정적 비교만.** 저장소에 라이선스와 실행 코드를 편입하지 않았다. |

## 검증 범위

- 단위: 차단된 예약의 명시적 재등록, 중복/미확정 재실행 거부, 응답과 검증 결과 구분, 월말·윤년의 원래 날짜 보존.
- 실제 Chrome 합성 사이트: 기존 업로드/다운로드·녹화·정책·알람 경로와 함께 중단 상태의 화면 재예약, 동일 ID/새 alarm, 월 반복 선택 확인.
- 바로가기: 실제 Chrome에서 저장·재진입·편집·삭제, `/p:` 초안 호출, 기존 `/wiki`, 360/1000px 화면과 Web Locks API 존재를 확인했다. 동시 저장의 직렬화는 모의 잠금을 사용한 단위 검사이며 두 실제 창의 경합은 별도 실험이 필요하다. 제거한 페이지 추천은 최종 후보의 검사/기능에 포함하지 않는다.
- 실제 회사 사이트 등록/저장, Claude 실계정 비교, Qwen 성공률, OS 알림 표시, 브라우저 종료 후 예약 성공은 이 검사로 입증되지 않는다.
