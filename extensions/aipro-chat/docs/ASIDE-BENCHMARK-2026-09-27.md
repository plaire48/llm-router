# Aside 분석과 누비 적용

확인일: 2026-09-27. Aside 브라우저 본체와 공개 평가 실행기는 다른 코드다. [공식 기술 글](https://aside.com/blog/how-we-built-the-sota-browser-agent-that-outperforms-fable)은 브라우저를 오픈소스로 공개하지 않는다고 명시한다. 본체의 하네스 구현을 확보하거나 동일 성능을 검증한 상태가 아니다.

## 실제 읽은 소스

| 대상 | 고정 버전과 라이선스 | 확인한 내용 |
|---|---|---|
| Aside 공식 `aside-benchmarks` | `7cde728f6af4ba10065fc9e0557762d0e156d3dd`, MIT | `odysseys/runner/grader.ts`, `trajectory.ts`, README, LICENSE |
| gstack의 Aside 연동 | `01593aa67c94780528e8f5121e47362502410ced`, MIT | `scripts/resolvers/aside.ts`, LICENSE. Aside 본체가 아닌 외부 연동 코드 |
| Aside 공식 설계 설명 | 2026-06-25 기술 글 | Pi 기반, Playwright 형태 인터페이스, 간결한 관찰과 지침, 비동기 사건 전달, 자체 Chromium 변경 |

[공식 채점 코드](https://github.com/at-inc/aside-benchmarks/blob/7cde728f6af4ba10065fc9e0557762d0e156d3dd/odysseys/runner/grader.ts)는 요구 조건을 하나씩 평가하고 평균 조건 점수와 모든 조건을 만족한 과제를 구분한다. trajectory 코드는 도구 호출 ID로 결과를 연결하고 스크린샷을 별도 파일로 보존한다. 긴 출력은 앞뒤를 남기고 잘린 양을 표시한다. 원문 중간에 필요한 근거가 있다면 이 축약만으로 완전성을 판정할 수 없다.

[gstack 연동 코드](https://github.com/garrytan/gstack/blob/01593aa67c94780528e8f5121e47362502410ced/scripts/resolvers/aside.ts)는 자신이 연 탭과 사용자 탭을 구분하고, 프로세스 종료 코드만으로 성공을 인정하지 않는다. 새 snapshot 이후 이전 ref를 재사용하지 않으며 산출물을 실행 디렉터리 밖으로 보존한다. 누비의 권한이나 실행 지침으로 가져오지 않고 구조적 참고로 읽었다.

다운로드한 고정 소스와 원본 라이선스는 `verification/browser-30/aside-research/`에 보존했다. 본체 설치나 사용자 로그인 세션 접근은 하지 않았다. 분석 소스를 제품 번들에 복사하지 않았다.

## 비교와 적용

| 관점 | Aside 공개 근거 | 누비 판단과 실제 반영 |
|---|---|---|
| 실행 기반 | Pi와 Playwright 형태 도구 | 이미 Pi와 Playwright CRX 사용. 하네스 교체 대신 현재 연결 오류 수정 |
| 지침 충돌 | 짧고 일관된 지침을 강조 | 과거 원문을 허용하면서 모든 인용에 fresh를 요구하던 검토 문장 제거. 원문 근거와 현재 상태 readback 구분 |
| 평가 | 조건별 점수와 완전 성공 분리 | `evaluation/browser-score.mjs`에 조건별 성공/실패/미확인 집계 추가. 3/3 및 최종 전달 조건은 그대로 유지 |
| 관찰 | 핵심 a11y 정보와 focus/frame/clickable | 누비의 기존 구조화 DOM과 ref 사용 유지. 실제 네이버 fieldset 구조를 검색 판정과 회귀에 반영 |
| 장기 문맥 | 불필요한 출력 최소화 | 원문 스냅샷과 현재 조작 ref를 분리하는 기존 구조 유지. 모델 요약을 원문으로 승격하지 않음 |
| 탭 | 전용 Chromium을 수정해 전경 방해 억제 | 확장만으로 Blink 패치를 재현할 수 없음. 기존 소유 탭 그룹과 포커스 보호를 유지하며 동일 기능이라고 표시하지 않음 |
| 성공 신호 | 실행 결과와 오류 구분 | 호스트 도구 호출 기록을 검토에 전달. 순수 읽기 실행의 무동작 근거만 제공하고 서버 상태를 증명하지 않음 |
| 화면 검증 | 스크린샷 별도 보존 | 실제 E-06의 저장 PNG, 페이지 내용, 답변 표시를 별도 대조 |

이번 적용은 검증된 패턴의 자체 구현과 기존 오픈소스 활용이다. 새 런타임 의존성은 없다. 외부 CLI 설치, 무제한 쉘, 웹사이트 내부 API 우회, 자동 승인 확대는 이번 결함 해결에 필요하지 않다.

## 점수 해석

Aside의 [공개 결과](https://github.com/at-inc/aside-benchmarks/blob/7cde728f6af4ba10065fc9e0557762d0e156d3dd/README.md)는 다른 모델, 과제, 채점기와 실행 예산에서 나온 제공자 보고다. 누비 Luna 실측과 직접 우열 점수로 비교하지 않는다.

누비의 07:29 후보 집중 재시험은 조건 12개 중 9개 충족, 1개 실패, 2개 미확인이다. 조건 충족 하한은 75%지만 과제 완주는 2/4, 50%다. M-09는 필요한 번호와 합계를 수집했어도 사용자 확인을 다시 요구해 최종 전달에 실패했다. 조건 점수는 개선 위치를 찾기 위한 보조 지표이며 80% 목표를 대신하지 않는다.

평가기 회귀는 미완료 과제의 조건 점수가 100%여도 완주 실패를 유지하고, 근거 없는 조건/순서가 바뀐 조건/실모델 응답 증거가 없는 결과를 미확인으로 유지하는지 검사한다. Aside의 자동 채점기를 누비에 호출하거나 Aside 벤치마크를 수행한 것은 아니다.
