# 하위 분석과 첫 단계 복구 점검

요청은 사용자 계획의 첫 단계를 실제 브라우저 행동과 검증까지 완수하는 것이다. 워커 수만 늘리면 액션 정확도가 올라가는 구조는 아니다. 누비의 하위 분석은 실제 Pi 호출로 문서/고정 화면/실패 기록을 조사한다. 클릭과 입력, 현재 탭의 관찰, 승인과 최종 결과 검증은 주 실행기가 담당한다.

## 확인한 공백과 반영

| 공백 | 실제 변경 | 경계 |
| --- | --- | --- |
| 실패 기록이 이미 실행 메모리에 있어도 recovery 분석가는 첫 호출에서 ID 목록만 받아 원문 조회를 위한 모델 왕복이 필요했다. | 배정된 작은 고정 기록을 첫 과제에 `evidence_reads`로 함께 전달한다. 오류 기록을 우선하고 최대 2개, 원문 각 2,400자 이하, 패킷 합계 직렬화 5,000자 이하로 제한한다. 원래 과제/제약/완료 조건은 그대로 전달한다. | 다른 과제의 근거, 부모 대화, 라이브 실행기와 이미지 바이트를 전달하지 않는다. 긴 원문/이미지는 기존 명시적 reader로 조회한다. 성공한 근거 읽기만 사실 조사에 사용할 수 있고 recovery는 오류 자체만 진단할 수 있다. |
| 할당량/문맥 한도의 마지막 모델이 complete와 빈 미확인/다음 행동을 반환하면 호스트는 partial만 붙였다. 첫 단계의 빠진 확인을 어떻게 이어갈지 정보가 없었다. | 강제 인계를 partial로 유지하고 비어 있는 미확인/다음 행동을 호스트가 보완한다. 실제 읽은 근거와 원래 완료 조건을 대조한 뒤 미확인 항목만 이어가도록 안내한다. 모든 모델 인계에 `recovery.reason/method`를 보존한다. | 모델이 반환한 구체적인 미확인과 다음 행동은 그대로 둔다. 동일 실패를 effort 증가로 재실행하지 않는다. 모델 선언을 사용자 업무 완료로 바꾸지 않는다. |
| 컨텍스트 초과의 작은 인계가 기본 이유 `analysis_budget`으로 기록됐다. | 실제 `context_overflow` 이유를 작은 인계와 반환값에 전달한다. | 인증/네트워크 실패와 취소는 정상 인계 성공으로 바꾸지 않는다. |

첫 근거 전달은 **recovery 위임을 선택한 경우**에 적용된다. 모든 브라우저 실패에 자동으로 recovery 워커를 시작하는 변경은 아니다. 작은 오류와 새 관찰을 함께 받은 합성 Pi 시험에서는 명시적 도구 조회 없이 모델 호출 1회로 진단을 반환했다. 기존 ID만 전달하는 방식에서는 조회 요청과 보고를 위한 모델 결정이 각각 필요했다. 이것은 호출 수의 구조적 개선이며 실제 모델 응답 시간이나 복구 성공률 측정값은 아니다.

## 공식 방법론과 오픈소스 검토

| 확인한 공식 문서/소스 | 적용 판단 |
| --- | --- |
| [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)의 명확한 목표, 출력, 도구/출처, 작업 경계와 복잡도에 맞춘 노력 | 기존 과제별 역할/제약/완료 조건과 2개 동시 분석을 유지한다. 실패 원인을 확인하는 데 필요한 작은 실제 기록을 초기 과제에 전달한다. 사이트 간 의존 행동과 쓰기는 병렬화하지 않는다. |
| [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)의 작은 유효 문맥과 격리된 하위 분석 | 부모 대화를 복사하지 않고 배정된 고정 근거만 한도 안에 전달한다. 반환에는 근거, 누락과 다음 행동을 보존한다. 큰 원문을 초기 프롬프트에 넣지 않는다. |
| [OpenCode agents](https://opencode.ai/v2/docs/agents)의 새 문맥을 갖는 child session, 개별 도구 권한과 마지막 단계의 도구 없는 요약 | 기존 isolated Pi 작업, 읽기 전용 권한과 마지막 모델 인계를 재사용한다. 인계가 일반 실패나 빈 partial로 끝나는 공백을 보완한다. OpenCode 런타임을 확장에 추가하지 않는다. |
| [p-limit 공식 소스](https://github.com/sindresorhus/p-limit/blob/main/index.js)와 설치된 7.3.3 `index.js`/MIT 라이선스 | 기존 동시 실행 2개와 `rejectOnClear: true` 대기열 폐기를 유지한다. active와 pending을 분리하는 소스 동작을 확인했다. 브라우저 쓰기에 적용하거나 제한을 무작정 늘리지 않는다. |
| [Pi agent core](https://github.com/earendil-works/pi/tree/main/packages/agent)와 설치된 0.87.1 `dist/agent-loop.js`/package.json의 MIT 라이선스 | 실제 sequential/parallel 실행과 호출 순서의 결과 보존을 확인했다. 기존 읽기 전용 하위 도구 배치만 병렬 실행한다. 다른 SDK/루프를 겹쳐 실행하지 않는다. |

새 의존성을 추가하지 않았다. p-limit과 Pi는 실제 실행에 쓰는 기존 라이브러리다. Anthropic과 OpenCode는 설계 패턴의 참고이며 각 제품 전체나 비공개 Claude 브라우저 코드를 도입했다고 표시하지 않는다. 브라우저 조작 워커 여러 개가 같은 탭을 병렬 변경하거나 recovery가 승인/검증 권한을 얻는 방식은 채택하지 않았다.

## 검증

`node --test tests/analysis-*.test.mjs`로 기존 76개와 새 5개, 총 **81개 통과**했다. 새 회귀는 `tests/analysis-recovery-brief.test.mjs`에 있다.

1. 작은 실패 기록과 새 고정 관찰의 배정 범위, 패킷 한도, 원래 조건과 실제 모델 호출 1회 진단.
2. 긴 원문과 이미지의 명시적 reader 유지.
3. 마지막 모델의 complete 선언이 있어도 partial/미확인/다음 행동 보존과 effort 변경 중복 실행 방지.
4. 컨텍스트 초과의 실제 이유와 읽은 근거 인계.
5. 취소 후 도착하는 모델 보고 폐기.

기존 회귀에서는 두 Pi 분석의 실제 동시 시작, 먼저 끝난 결과의 전달, 역할별 도구 격리, 잘못된 인용 거부, 문서 읽기 범위, 압축과 출력 한도, 취소와 오류 인계도 확인했다. 이번 독립 변경의 검증은 Node/Pi 합성 제공자 시험이다. 실제 Chrome 동작, 실계정 모델, 첫 계획 완료율과 전체 브라우저 성공률은 이 수치로 증명하지 않는다. 주 실행기의 브라우저 액션 개선과 함께 별도로 검증해야 한다.

## 남은 범위

1. 첫 단계 실패의 요소 식별/가림/탭/문서 변경/쓰기 미확정 원인은 주 실행기에서 실제 관찰과 영수증으로 확인해야 한다.
2. 모든 오류에 자동 위임하거나 워커를 더 늘리는 기능은 반영하지 않았다. 독립 조사가 필요한 실패만 좁게 위임하고 다음 행동 전 현재 화면을 재확인하는 경로가 필요하다.
3. 실모델 평가는 같은 업무에서 완료율, 오류 후 새 관찰 수, 반복/중복 액션, 모델 호출/토큰, 실제 시간과 사용자 중지를 함께 비교해야 한다.

## 주 실행기 통합

이 독립 점검 뒤 주 실행기가 반복된 타깃 실패에만 자동 recovery를 연결했다. 모든 오류의 자동 위임은 아니며 상세 시작/취소 조건과 최종 통합 검증은 [첫 계획과 액션 개선](PLAN-ACTION-QUALITY-2026-09-26.md)을 따른다.
