# 여러 단계의 업무 폼 입력

## 흐름

관찰 → 누락 결정 질문 → 작은 단위 입력 → 실제 값 검증 → 다음 구역 → 최종 승인 → 반영 확인.

총 480분이라는 요청만으로 업무 종류나 시간 배분을 만들지 않는다. 이미 받은 업무 내용은 재사용하고, 상시업무 여부나 배분처럼 사용자만 결정할 수 있는 항목을 질문한다. 선택 가능한 근거가 있으면 선택지를 제시하며 하단 직접 입력을 항상 제공한다. 필요한 정보는 한 항목씩 확인한다. 질문은 실행 승인이 아니다.

페이지의 단위가 명확하면 300분을 5시간으로 변환할 수 있다. `MH`처럼 의미가 명확하지 않은 표기나 소수점/날짜 형식은 임의 해석하지 않는다. 한 단계가 끝나면 현재 값과 체크 상태를 확인하고 다음 단계로 이동한다. 다시 돌아오거나 오류가 나도 완료한 입력을 일괄 재실행하지 않는다.

## 구현

- 기존 dom-accessibility-api 기반 관찰의 이름, 설명, 구역과 입력 제약을 재사용한다. 네이티브 `validity`의 `valueMissing`, `stepMismatch` 등 오류 종류를 값 없이 추가 전달한다. 검사를 위해 `checkValidity()`를 호출하거나 웹사이트 이벤트를 발생시키지 않는다.
- `form-workflow.js`의 공통 지침을 주 모델에 제공한다. 계획과 최종 검토도 개별 행, 업무 내용, 단위, 합계, 승인 요구를 구분한다.
- 기존 Playwright 입력과 `setChecked`를 사용한다. 체크 상태가 이미 맞으면 불필요하게 다시 누르지 않는다. 관찰한 참조, 현재 페이지와 실행 권한 검사도 유지한다.
- `verify_page field_valid`는 현재 네이티브 필드의 검증 가능 상태와 제약, `aria-invalid`를 확인한다. 사이트의 모든 업무 규칙을 검증했다는 의미는 아니다.
- `verify_page field_sum`은 현재 관찰한 최대 24개의 고유 입력 참조를 읽고 big.js로 합산한다. 명시적 단위 환산에 한해 양의 십진수 `multiplier`를 쓸 수 있다. 예: `5 × 60 + 180 = 480`.
- 빈 값, 잘못된 제약, 중복 참조, 알 수 없는 숫자 표기, 오래된 참조는 성공으로 처리하지 않는다. 계산에는 입력 문자열을 사용하고 `parseFloat`나 암묵적 빈 값의 0 변환을 하지 않는다. 결과에는 실제 입력값을 반환하지 않는다.
- 합계는 나열한 필드만 증명한다. 모든 행이 포함됐는지, 각 업무에 올바르게 배분했는지, 앞 단계 내용이 유지됐는지는 별도로 확인한다. 다른 단계의 오래된 DOM 참조를 한 합계에 섞지 않는다. 사이트의 최종 요약 화면도 확인한다.

## 방법론과 오픈소스

- [OpenAI computer use](https://developers.openai.com/api/docs/guides/tools-computer-use): 실행 결과를 다시 관찰하고 애플리케이션에서 검증하는 반복 구조를 참고했다. OpenAI 전용 API에 묶지 않고 기존 Qwen/Pi 루프에 적용한다.
- [Anthropic Building effective agents](https://www.anthropic.com/engineering/building-effective-agents): 실제 환경의 피드백을 읽고 막힌 결정에서 사용자 입력을 받는 구조를 참고했다.
- [Playwright actionability](https://playwright.dev/docs/actionability)와 [입력/체크 API](https://playwright.dev/docs/input): 기존 번들 Playwright의 대기 및 명시적 상태 설정을 유지한다.
- [big.js 7.0.1](https://github.com/MikeMcl/big.js), MIT: 합산과 곱셈에 필요한 정확한 십진수 계산을 재사용한다. 더 큰 decimal.js의 삼각함수 등은 이 작업에 필요하지 않아 작은 big.js를 선택했다. 버전을 고정하고 라이선스를 ZIP에 포함한다.

## 평가

`form-values.test.mjs`: 소수 합계, 큰 수, 단위 환산, 누락/형식 불명/제약 오류, 중복 참조와 민감 값 미반환.

`form-workflow-browser.mjs`: 실제 Chrome의 두 단계 공수 폼과 Qwen 형식의 합성 모델 응답으로 질문, 직접 배분 입력, 새로고침, 업무 내용 유지, 체크, 단위 환산, 합계, HITL, 단일 등록과 결과 확인을 수행한다. 잘못된 합계, 오래된 참조와 step 위반도 별도로 검사한다.

실제 사내 사이트와 Qwen의 자율적인 배분 질문 품질은 합성 응답 검사로 입증하지 않는다. 사이트별 필드/단위, 최종 저장과 모델 판단 품질은 실계정 평가가 필요하다.
