# 하네스의 요구사항 보존과 검토 비용

2026-09-23. Qwen 3.8 27B를 기준으로 기존 Pi 하네스를 개선했다. 새 프레임워크나 서버는 추가하지 않았다. 실제 모델의 정확도 향상 수치는 아직 측정하지 않았다.

## 문제와 변경

계획 → 실행 → 관찰 → 검토의 반복은 이미 있었다. 이번에 재현한 문제는 그 반복에서 **검토에 필요한 사용자 조건보다 오래된 페이지 데이터가 우선되는 것**이었다.

| 문제 | 반영 |
| --- | --- |
| 검토 입력이 커지면 앞선 대화를 먼저 삭제해 ‘초안만 작성’ 같은 이전 조건이 사라짐 | 무효화된 화면과 Agent 설명을 먼저 줄인다. 사용자 요청과 요약을 위한 공간을 우선 확보하고 긴 요구도 실제 모델 입력 예산 안이면 유지한다. 그래도 한도를 넘으면 조건을 버려 완료시키지 않는다. |
| 이미 바뀐 페이지의 DOM과 이전 입력 인자가 계속 검토에 들어감 | 실제 결과 상태만 가진 작은 영수증으로 줄인다. `usable:false`를 유지해 현재 결과의 증거로 인용할 수 없다. |
| 같은 읽기 결과가 관찰 ID/ref 차이로 계속 쌓임 | 관찰용 식별자만 제외해 중복을 비교한다. 최근 두 읽기, 다른 내용/DOM ID/프레임/부분 범위, 실패, 쓰기, Wiki 근거는 구분한다. 원본 대화와 도구 호출/결과 쌍은 유지한다. |
| 재조회 번호와 초점만 바뀌어도 검토가 진전으로 판단할 수 있음 | 내용과 실제 대상 중심으로 비교한다. 다른 입력란을 고친 경우는 관찰한 대상의 의미로 구분한다. 변화 없는 재검토는 기존 질문 흐름으로 전환한다. |

이 비교는 루프의 진전 판단에만 쓰며 요소 실행 권한이 아니다. 동작에는 여전히 최신 ref/문서/노드 확인이 필요하다. 중간 검토가 통과해도 실제 `verify_page`와 최종 검토를 생략하지 않는다. 이미 수행한 쓰기, 승인 대기, 사용자 중지는 자동 재실행하지 않는다.

## 방법론과 오픈소스 판단

- [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): 원래 요구를 보존하면서 불필요한 도구 출력을 먼저 정리하는 방법을 적용했다. 요약 모델을 추가 호출하기 전에 동일한 과거 관찰을 결정적으로 줄인다. 실행, 검토, 하위 분석에 같은 전체 대화를 무조건 복제하지 않는다.
- [Pi 실제 압축 구현](https://github.com/earendil-works/pi/blob/a8ed497713ee712b2ba5f27c2ec269d68657465b/packages/coding-agent/src/core/compaction/compaction.ts): MIT. 토큰 예산과 유효한 메시지 경계를 확인했다. 기존 번들 `pi-agent-core@0.86.1`과 호출/결과 보존을 유지했다. CLI 파일 세션이나 별도 런타임은 도입하지 않았다.
- [Browser Use 루프 감지 구현](https://github.com/browser-use/browser-use/blob/d8110c5ff87ccba887aaa726cdb780f2f84bef8d/browser_use/agent/views.py): MIT. 행동 반복과 페이지 상태 정체를 구분하는 패턴을 참고했다. 누비는 기존 DOM/프레임/검증 결과를 비교하며 새 ID나 초점만으로 복구된 것으로 간주하지 않는다. Browser Use Python 런타임이나 전체 정책을 복사하지 않았다.
- [Anthropic agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents): Agent가 ‘완료’라고 말했는지가 아니라 실제 환경 결과를 별도로 검사했다. 변경 전 실패 재현, 변경 후 단위 검사, 설치한 Chrome 확장에서 실제 입력/검증/중복 실행 여부를 분리했다. 합성 모델 회귀는 Qwen의 실추론 성능 평가를 대신하지 않는다.

프롬프트를 계속 늘리거나 검토 Agent 수를 늘리는 것은 이번 결함을 해결하지 못한다. 기존 Pi 실행기 안에서 문맥 선택과 완료 판정을 개선하는 것이 변경 범위와 비용 면에서 적합하다고 판단했다.

## 검증 범위

- `tests/review-context.test.mjs`: 이전 요구 보존, 예산 초과에서 조건 누락 방지, 관찰 ID 정규화, 최신 근거/실패/Wiki 보존, 진전 없는 검토 종료, 다른 입력란 수정의 구별.
- `tests/review-context-browser.mjs`: 실제 Chrome의 별도 작업 창에서 다섯 항목을 한 번씩 작성하고 모든 값을 검사한다. 큰 관찰이 쌓여도 중간/최종 검토가 원래 제한을 받는지 확인한다. 사용자 원본 탭은 유지하고 등록을 실행하지 않으며 새로고침으로 입력을 재전송하지 않는다.
- `verify:browser`의 새 프로필 3회 반복 대상에 해당 시나리오를 추가했다. 실제 회사 계정과 Qwen 연결은 별도 평가 대상이다.

이 변경은 이전 대화 요약의 의미 정확도, 모든 사이트의 DOM 조작, 서버 저장 상태를 보증하지 않는다. 이미 요약된 과거 조건은 그 요약의 품질에 영향을 받는다. 공개 배포는 전체 회귀와 실서비스 검증을 별도로 통과해야 한다.
