# DOM 탐색과 컨텍스트 유지

누비는 사용자 요구 → 페이지 구조 → 관련 근거 검색 → 한 단계 실행 → 결과 확인 순서로 작업한다. 검색 결과의 순위나 요약만으로 대상과 완료를 확정하지 않는다.

2026-09-23에 입력 도움말과 표 검색, 관찰 범위 정보와 쿼리의 추가 탐색을 보강했다. 현재 한도와 검증은 [페이지 정보 선택](BROWSER-INFORMATION-STRATEGY.md)을 따른다. 아래 결과는 앞선 구현 시점의 기록이다.

## 확인한 문제

이전 후보를 실제 Chrome에서 실행해 두 문제를 재현했다.

- `배송 설정의 알림 스위치`는 컨트롤 이름과 섹션 이름에 걸친 표현이라 기존 전체 문구 일치 검색에서 누락됐다.
- 긴 문단은 검색 전에 16,001자로 잘려 뒤쪽의 `배송 기준 37건`을 찾지 못했다.

재현 기록: `verification/retrieval-before.json`. 이 검사는 실제 확장과 합성 페이지를 사용하며 LLM을 호출하지 않는다.

## 적용한 검색

MiniSearch 7.2.0(MIT)을 확장에 번들했다. DOM 이름, 주변 섹션, 역할과 관찰된 식별자를 별도 필드로 비교한다. 간단한 한국어 조사 정리와 camelCase 분리를 사용하며 실제 검색어의 일치 범위를 먼저, 필드 가중치와 라이브러리 점수를 그다음 비교한다. 표준 접근성 이름은 기존 dom-accessibility-api로 계산한다.

순위는 후보 정렬이다. `match.coverage`는 정리된 검색어 중 맞은 비율이며 확률이 아니다. 동명이거나 일부만 맞은 후보도 반환한다. 모델은 영역, iframe, 상태를 비교한 뒤 행동한다. 불충분하면 검색을 좁히거나 기존 캡처 도구로 시각 확인하고, 사용자 선택이 필요한 경우 질문한다. 오타 보정과 추정한 별칭으로 자동 클릭하지 않는다.

이름 없는 section/article도 직접 자식 제목으로 주변 맥락을 제공한다. 제목 목록과 기존 폼/모달/행 맥락을 함께 반환한다. 실제 ref는 현재 관찰의 노드에만 연결되며 검색 순위로 ref를 만들지 않는다. 콘텐츠 스크립트와 Playwright 관찰은 같은 정적 수집기를 쓴다. 페이지 읽기에 debugger를 붙이지 않는다.

본문은 최대 256,000자를 관찰한 범위에서 검색한 뒤 맞은 부분 주변을 발췌한다. 최종 본문은 16,000자 이내이며 긴 발췌에는 생략 표시를 남긴다. 기존 노드 5,000개, 컨트롤 180개, 프레임 16개 제한은 유지한다. `truncated`, `textFiltered`, 검색에서 제외한 개수는 불완전한 범위임을 알려준다. 제한 밖이나 닫힌 Shadow DOM, 권한 없는 프레임의 부재를 단정하지 않는다.

OpenWiki 폴더 검색에도 같은 검색기를 적용한다. 문서 제목, 상대 경로, 코드 심벌과 본문을 비교하고 관련 구간의 실제 줄 번호와 파일 해시를 반환한다. 원본 소스는 기존 로컬 서버 연결에 해당 도구가 있을 때만 `source_search → read_source`로 확인한다. Wiki 설명과 현재 코드, 실행된 화면 근거는 구분한다. 폴더 접근 범위와 읽기 권한은 늘리지 않는다. 검색 인덱스는 요청 메모리에만 존재한다.

## 자동 컨텍스트 압축

기존 75% 입력 예산 임계점과 구조화 요약을 유지하면서 다음을 추가했다.

1. 완전히 같은 오래된 페이지 읽기 결과부터 모델 입력에서 정리한다. 최신 두 읽기와 변경된 관찰은 남긴다. 호출/결과 쌍과 원본 transcript는 유지하며 쓰기, 오류, 이미지, 소스 발췌는 이 단계에서 지우지 않는다.
2. 여전히 크면 Pi의 토큰 예산 방식으로 최근 구간을 남기고 이전 구간을 요약한다. 최근 구간은 입력 예산의 20%, 최대 20K 토큰을 기준으로 하며 최신 도구 호출/결과 쌍은 분리하지 않는다.
3. 원래 목표와 최근 두 사용자 요청의 텍스트를 그대로 유지한다. 모델 요약과 별개로 이전 실행의 최근 16개 결과 상태와 최근 12개 파일 경로/해시/줄 범위를 전달한다. 초과 개수는 표시한다. 인자, 스크립트, DOM, 오래된 실행 ref는 이 보존 기록에 넣지 않는다.
4. 현재 계획, 미검증 상태, 분석 담당 레지스트리는 기존 하네스가 별도로 유지한다. 서버가 컨텍스트 초과를 알려 재요청할 때도 현재 계획과 복구 지침이 붙은 첫 system 메시지를 유지한다. 요약이 성공했다고 기록해도 실제 실패/미검증 상태나 최종 HITL을 덮어쓸 수 없다.

추가 보존 기록은 실행 중 문맥용이며 영구 메모리나 새 승인 토큰이 아니다. 재시작 복원은 기존 durable task와 재관찰 경로를 사용한다. 원본 대화는 보관하고 요약 사용량은 기존 ledger에 합산한다. 실패/취소/저장 실패 때 경계를 앞당기지 않는 규칙도 유지한다. 최신 단일 결과와 필수 지침 자체가 모델 한도를 넘으면 조용히 잘라 완료한 것처럼 진행하지 않는다.

## 검증 범위

- `retrieval-browser`: 이전 실패 재현, 210개 다른 컨트롤 뒤의 대상, 동명 후보, iframe/Shadow DOM, 긴 문단 발췌, 민감 입력 제외, 실제 trusted 클릭 1회와 동등한 Playwright 관찰.
- `evidence-search.test.mjs`, `wiki-folder.test.mjs`: 복합 검색, 심벌/경로, 후보 없음, 관련 발췌와 실제 provenance, 기존 권한/경로/파일 제한.
- `context-evidence.test.mjs`, `context.test.mjs`: 중복 관찰 정리, 변경/오류 보존, 잘못된 모델 요약에도 사용자 조건과 실제 결과 보존, 호출 쌍, Qwen 요청의 system 1개, 적용한 초안 재실행 없음.
- `context-browser`와 기존 작업/승인/폴더 회귀: 새 프로필의 설치 확장, 압축 및 재개, 원본 대화 보존, 실제 페이지 조작과 검증.

테스트의 모델 응답은 합성이다. 실제 Qwen 3.8 27B의 탐색 정확도, 요약의 의미 보존률, 회사 페이지 성공률은 별도 실모델 평가가 필요하다. 새 후보 ZIP은 로컬 검증용이며 공개 릴리스를 바꾸지 않는다.
