# 공유 가능한 브라우저 업무 절차

## 목표와 사용자 흐름

담당자가 조직 내부에서 **사이트/메뉴 → 용어와 입력 기준 → 업무 순서 → 확인 조건**을 한 스킬에 담는다. 사용하는 사람은 파일을 가져와 저장하고 평소처럼 업무를 요청한다. 누비는 관련 스킬과 필요한 자료를 읽고, 현재 화면을 확인하면서 수행한다.

FP의 의미와 작성 규칙은 조직에서 제공한다. 이 구현은 사내 사이트나 FP 계산/작성 정책을 추정하지 않는다. MH 예제는 합성 테스트용이며 배포용 공식 업무 규칙이 아니다.

1. 누비로 실제 브라우저 업무를 수행하고 결과를 확인한다.
2. 스킬 메뉴의 **작업으로 만들기**를 누른다. 실행 기록과 계획, 요약을 바탕으로 초안을 만든다. 누비는 관련 등록 자료를 먼저 읽고, 해결되지 않은 기준은 한 가지씩 질문한다. 근거 있는 2~4개 선택지를 우선하며 직접 입력도 항상 가능하다. 확인된 답은 이어지는 생성과 같은 작업의 실패 후 재시도에 전달된다. 다른 작업의 답을 자동 재사용하지 않는다.
3. **스킬 초안 검토**에서 이름, 사용 목적, 지침과 참고자료를 수정한 뒤 저장한다. 저장 후 대화에 ZIP 파일 카드가 남는다. 검토 화면의 다운로드 아이콘으로 저장과 ZIP 다운로드를 한 번에 할 수도 있다. 실제 작업 성공이 생성된 스킬의 재사용 성공을 뜻하지 않으므로 초안은 검토 대상으로 표시한다.
4. 시험 데이터로 정상/누락/메뉴 변경/등록 승인 사례를 확인한다. 다운로드 아이콘으로 `.skill.zip`을 내보낸다.
5. 받는 사람은 누비의 스킬 가져오기에서 ZIP을 선택하고 내용을 검토해 저장한다. 압축을 미리 풀 필요가 없다. 평소처럼 요청해 자동 검색하거나, 채팅에 `/`를 입력해 스킬을 선택하고 작업 내용을 보낸다. `/공유-업무-초안 ...`처럼 지정하면 그 작업에만 적용되고 기본 선택은 유지된다.

저장은 현재 Chrome 프로필의 `chrome.storage.local`에 한다. PC 경로 입력이나 로컬 실행기는 필요 없다. ZIP 다운로드는 Chrome의 기본 다운로드 위치/매번 위치 묻기 설정을 따른다. 사용자 지정 폴더와의 자동 동기화는 없으며 확장 제거/브라우저 데이터 삭제 전에 ZIP으로 백업한다.

ZIP은 `업무명/SKILL.md`와 `references/{terms,inputs,procedure,checks}.md`를 묶는다. 등록된 브라우저 스크립트/자료도 포함할 수 있지만 크리에이터가 자동으로 실행 코드를 만들거나 설치하지는 않는다. 구조는 Agent Skills의 폴더 방식을 참고했으며, 누비 브라우저 도구와 다른 호스트의 실행 API가 같다는 뜻은 아니다. 기존 JSON과 폴더 가져오기도 유지한다. ZIP은 로컬에서 풀고 총 원문 200KB, 파일 수/경로/중복/UTF-8을 검사한 뒤 검토 화면을 연다. 인증 정보, 작업 이력과 승인 상태를 자동 포함하지 않는다. 작성자가 직접 넣은 개인정보는 검토 후 제거해야 한다.

아직 수행 기록이 없으면 `examples/skills/business-workflow-template/` 또는 `.skill.json`을 가져와 내부 규칙을 작성한다. FP 정의/정책은 제공하지 않은 상태이므로 해당 템플릿은 완성된 FP 스킬이 아니다.

## 이번에 구현한 부분

- 크리에이터: 기존 Pi 실행기, 모델 인증/재시도/사용량 기록을 재사용한다. 등록 자료 읽기와 `ask_user`만 허용하고, 생성 중에는 페이지 수정 도구가 없다. 질문 상태와 답변은 대화에 보존한다. 실패한 동작은 성공 단계로 바꾸지 않으며, 잘못된 생성 형식은 저장하지 않는다.
- ZIP 공유와 `/` 호출: fflate를 브라우저에 번들링하며 다운로드/가져오기와 실제 요청 바인딩을 연결한다. 잘못된 명령이나 같은 명령의 중복 스킬은 임의 선택하지 않는다.
- `find_skills`: 이름/설명 외에도 등록된 `SKILL.md`와 `references/`를 로컬 MiniSearch로 검색한다. 약어, 메뉴 이름, 규칙이 설명에 없더라도 후보를 찾는다. 모델에는 후보 메타데이터만 보낸다.
- `read_skill query`: 선택한 스킬 안에서 필요한 규칙을 최대 3개/본문 4,800문자로 조회한다. 특정 참고 파일로 제한할 수 있다. 원문 경로, 줄 번호와 문자 위치를 반환한다. 긴 줄 중간에서 잘린 검색 결과는 부분 결과로 표시한다.
- 실행 안내: 실제 사이트와 적용 범위를 대조하고 절차를 기존 작업 계획에 반영한다. 누락 정보는 기존 질문 폼, 최종 처리는 기존 HITL, 완료 판단은 실제 화면 검증을 사용한다.
- 스킬 해시 고정과 권한 검사를 유지한다. 검색 결과만으로 도구가 활성화되거나 실행/승인/완료로 처리되지 않는다. 등록 스크립트와 출력용 assets는 업무 지식 검색에서 제외한다.

검색 실패는 문서에 없다는 증명이 아니다. 실제 적용 여부와 지시 이행은 모델이 판단하며, 새로운 규칙으로 모델을 재학습시키는 기능이 아니다. 현재 저장 한도는 스킬 20개, 패키지 200KB이며 검색 서버나 외부 임베딩 서비스로 문서를 보내지 않는다. 조회한 절차와 근거는 이후 사용자가 선택한 LLM에 전달된다.

## 평가와 남은 범위

`workflow-knowledge-browser`는 배포 JSON을 실제 누비 UI로 가져온 뒤 새로고침, 선택 없는 스킬 검색, 용어 조회, 절차/작성 규칙 조회, 실제 입력, 결과 검증을 확인한다. 자료 조회 후 객관식/직접 입력으로 기준을 확인하고, 새로고침 후 답변 이어가기, 잘못된 초안 거부, 참고자료 편집, ZIP 내보내기/가져오기, `/`로 새 입력값 적용까지 확인한다. 원래 탭과 등록 버튼은 변경하지 않는지 검사한다. 모델은 합성 Qwen 응답이며 실제 모델의 스킬 선택 정확도나 사내 FP 업무 성공률을 증명하지 않는다.

사내 검증은 동일 과제를 스킬 사용 전/후로 비교한다. 완료 정확도, 잘못된 입력/중복 등록, 사용자 수정 횟수, 모델 호출 수와 소요 시간을 기록한다. 서로 다른 계정과 메뉴 권한도 검사한다. 공유 파일은 복사본이며 자동 업데이트/동기화, 사용자가 직접 수행한 모든 클릭/DOM의 연속 녹화, 기관별 승인된 스킬 저장소는 아직 구현하지 않았다.

최종 검증은 `verification/workflow-beta26/verification.json`을 따른다.
