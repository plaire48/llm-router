# Beta 24 품질 점검

## 재현 후 수정한 항목

| 문제 | 수정 | 확인 방법 |
| --- | --- | --- |
| 부분/중단 보고가 실패한 조회만으로 사실을 인용할 수 있음 | 완료 여부와 관계없이 각 사실에 실제 관찰 출처를 요구. 실패 원인 분석 역할은 오류 자체를 진단할 수 있음 | partial/blocked 보고의 거짓 날짜를 거부하고 원래 오류 근거를 보존 |
| 하위 분석 예산에서 도구 스키마 크기가 제외됨 | 실제 제공하는 스키마와 메시지를 함께 계산. 입력이 넘치면 도구 없는 작은 인계로 전환 | 큰 스키마가 있는 quick 과제에서 조회 0회, 제한 이내 인계 1회. 실제 전달한 입력과 기록한 문자 수 비교 |
| 범위 배열이나 JSON 필드 순서만 바꿔도 실패 과제를 재시작 | 실패 과제 비교에서 범위를 고정 필드 튜플로 정렬. 실제 범위 변경은 새 과제로 허용 | 같은 범위 역순/필드 역순/effort 변경은 이전 과제 재사용, 다른 범위는 새 호출 |

수정 전에 회귀 검사 4개가 실패하는 것을 확인했다. 수정 후 해당 검사와 기존 Pi 분석/문서/취소 검사에 통과했다. 원본 문서, 인증 계약, 최종 행동 승인, CX 컴포넌트는 변경하지 않았다.

## 방법론과 오픈소스

- [Anthropic 에이전트 평가](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents): 답변 선언과 실제 결과를 분리하고 정상 사례와 실패 사례를 함께 검사한다. 동일한 테스트 입력의 수정 전 실패/수정 후 통과를 기록하고, 브라우저 통합은 새 프로필에서 반복한다.
- [Anthropic 도구 설계](https://www.anthropic.com/engineering/writing-tools-for-agents): 도구 정의와 출력이 문맥을 사용한다는 원칙을 하위 분석 입력 계산에 적용한다. 이 계산은 문자 기반 예산이며 실제 모델 토크나이저/이미지 토큰 수의 정확한 계산은 아니다.
- [OpenAI Agents SDK 오류 처리](https://github.com/openai/openai-agents-js/blob/main/packages/agents-core/src/runner/errorHandlers.ts): 복구 결과도 검증한다는 원칙을 부분 보고의 출처 검사까지 확장한다. 형식 검사만으로 내용의 의미적 정확성을 증명할 수는 없다.
- 기존 Pi의 실제 실행기로 회귀를 검사하고, p-limit/p-retry와 기존 문서 검색 라이브러리를 유지했다. 필요한 검사는 현재 구조에서 해결되어 새 패키지를 추가하지 않았다. npm audit의 운영 의존성 결과는 알려진 공개 취약점 0건이며, 사내 공급망과 전체 보안의 보증은 아니다.

## 남은 검증 경계

실제 사내 Qwen 3.8 27B의 정답률, SSO, FabriX와 OpenWiki 실서비스 호출은 합성 모델 기반 Chrome 검사로 검증되지 않는다. 브라우저/worker 강제 종료 후 자동 재실행, 의미만 같은 다른 과제 표현의 중복 감지, 첨부 OCR은 이번 변경에 포함하지 않는다. 릴리스 업로드와 실계정 평가는 로컬 검사와 구분한다.

최종 검사 수와 ZIP 해시는 `verification/quality-beta24/verification.json`에 기록한다.
