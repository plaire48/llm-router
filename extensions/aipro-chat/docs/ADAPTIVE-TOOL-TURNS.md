# 결과를 보며 이어가는 브라우저 작업

누비 Beta 1.0.0의 내부 업데이트 1.4.10은 **관찰 → 다음 행동 선택 → 실행 → 결과 확인** 사이에 모델의 판단을 되돌려준다. npm 버전은 1.0.0-beta.7이다.

## 발견한 문제

Pi의 `toolExecution: sequential`은 한 응답에 포함된 도구들을 차례로 실행한다. 각 호출이 끝날 때마다 모델을 다시 호출하는 설정은 아니다. 따라서 `read_page → 입력 → 클릭`이 한 번에 생성되면 읽은 내용을 모델이 확인하기 전에 입력과 클릭이 이어질 수 있었다. 하나의 긴 Playwright 스크립트 안에서도 같은 문제가 생긴다.

## 적용

- 기존 오픈소스 Pi Agent Core 0.86.1의 `beforeToolCall` 훅에서 실제 도구 결과 이후의 호출을 보류한다. 모델에는 실행 결과와 미실행 사실을 돌려주고 다음 응답에서 방법을 선택하게 한다. 도구 호출과 결과 쌍은 유지한다.
- 계획 저장과 도구 그룹 선택은 실제 작업 앞에 함께 실행할 수 있다. 보류한 제안은 페이지에서 실행한 것처럼 표시하지 않으며 실패 횟수나 검증 근거로 계산하지 않는다.
- Playwright는 이미 관찰한 입력란 묶음을 한 스크립트로 채울 수 있다. 클릭, 메뉴 열기, 선택값 변경, 페이지 이동, 스크롤, 탭 전환 뒤의 추가 행동은 호스트가 멈춘다. 읽기와 마지막 스냅샷은 허용한다.
- 중단된 스크립트는 `yielded: true`, `completed: false`, 실제 명령 기록과 새 관찰을 반환한다. 오류를 잡거나 `Promise.all`로 나머지 호출을 미리 만들어도 이후 쓰기가 실행되지 않는다. 이 값은 부분 실행이며 전체 작업 완료가 아니다.
- 다음 단계가 불명확하면 기존 질문 카드로 사용자에게 묻고 대기한다. 초안 작성과 검증 후에는 기존 승인과 연필 수정 흐름을 사용한다. 매 클릭마다 승인을 요구하지 않는다.
- 계획 지침에는 요청 결과, 제약과 미확정 선택을 먼저 파악하고 화면 확인 후 계획을 수정하도록 추가했다. Playwright에는 관찰한 역할/레이블/ref와 상태 대기를 사용하도록 안내한다. `expect` 등 노출하지 않은 API를 추가로 지원한다고 표시하지 않는다.

판단 지점이 늘면 모델 호출 수, 지연과 토큰 사용량이 늘 수 있다. 기존 사용량 집계에 이 호출들도 포함한다. 작업 누적 횟수 제한, 외부 서버, Node 설치 요구와 새 브라우저 권한은 추가하지 않았다. DOM과 탭 전환의 모든 변화를 자동 인식하는 범용 안전 경계는 아니다. 입력으로 다른 필드가 교체되는 경우 기존 ref 검증과 실패 복구도 함께 사용한다.

## 오픈소스 선택

[Pi Agent](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md)의 실제 설치된 훅과 도구 실행 루프를 사용했다. 순차 실행과 결과를 보고 재판단하는 흐름의 차이를 설치된 소스에서 확인했다. Pi의 steering 큐도 현재 도구 묶음이 끝난 뒤 처리되므로, 큐만 추가해서 이 문제를 해결했다고 주장하지 않는다.

[Playwright 권장 방식](https://playwright.dev/docs/best-practices)에 따라 관찰한 의미 기반 locator와 대기를 유지한다. 페이지 결과 검증은 기존 `verify_page`가 담당한다. [Nanobrowser](https://github.com/nanobrowser/nanobrowser)의 Planner/Navigator 역할 분리는 비교 기준이다. 해당 소스나 Deep Agents 패키지를 새로 포함하지 않았다.

Deep Agents JS는 계획과 컨텍스트 관리의 별도 비교 후보로 남긴다. 이번 변경은 현재 제공자 연결과 브라우저 실행 경로에서 재현한 묶음 실행 문제를 수정한 것이다. 하네스 교체나 실제 모델 성능 향상은 별도로 평가해야 한다.

## 확인할 흐름

1. 읽기와 추측 입력이 함께 생성되어도 읽기만 실행한다. 부족한 선택을 질문하고, 응답 후 원래 목표를 이어간다.
2. 새 창 열기와 입력이 한 스크립트에 있어도 창을 먼저 확인한다. 다음 모델 호출에서 입력하며 창을 다시 열지 않는다.
3. 변경한 선택값의 결과를 관찰한 뒤 새 ref로 이어간다. 기존 입력을 중복하지 않는다.
4. 실제 초안을 검증한 뒤 승인 대기한다. 새로고침과 초안 수정을 거쳐 승인한 대상에 한 번만 반영하고 결과를 확인한다.
5. 같은 화면의 알려진 필드는 묶어서 작성하고, 대량 작업의 기존 실행 횟수 제한 해제도 유지한다.

Chrome 회귀는 합성 페이지와 합성 모델을 사용한다. 실행 제어 검증이며 AI Pro GLM/Qwen의 요구사항 이해도나 도구 선택 정확도 점수는 아니다. 실모델 평가는 `npm run eval:agent`로 분리한다.
