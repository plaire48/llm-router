# 하네스와 역할별 에이전트 품질 점검

2026-09-23. Chrome 확장 단독 실행, Qwen 3.8 27B 기준. 다른 제공자를 강제하거나 로컬 실행기를 추가하지 않는다.

## 적용 기준

좋은 하네스는 에이전트 수보다 요구사항 해석, 필요한 근거 선택, 도구 사용, 실패 피드백과 검증을 연결하는 것이 중요하다. 주 실행기는 현재 페이지의 쓰기를 소유한다. 독립적인 화면 분석/문서 조사/검토/실패 원인 분석만 별도 문맥으로 맡기며, 결과가 도착하면 다음 판단에 반영한다. 모든 담당의 완료를 기다렸다가 한 번에 결과를 내는 구조가 아니다.

## 실제 구성과 이번 개선

| 실패와 복구 | 현재 상태 재관찰, 부분 실행 기록, 완료된 쓰기 재실행 방지 | 저장 실패/누락 입력 수정과 하위 분석의 실패한 검색 변경 검사 |
| 최종 검증 | 도구 반환과 목표 달성을 구분, 실제 값/저장 결과 검증, 승인 경계 유지 | 실제 Chrome 회귀와 Qwen 자율 평가를 구분 |

## 발견한 결함

압축 후 독립적으로 보존하는 출처 목록은 저장소의 `wiki/source`와 줄 번호만 허용했다. 첨부 문서는 `document_id`와 0부터 시작하는 문자 범위를 반환하므로, 읽기 결과가 압축되면 정확히 어느 범위를 참고했는지 모델 요약에 의존하게 되었다. 전체 첨부 목록 자체가 사라지는 문제와는 다르다.

`context-evidence.js`에서 첨부 문서의 ID, 해시, 문자 범위를 보존한다. 문서명/본문은 복사하지 않는다. 서로 다른 읽기 범위는 구분하며 최근 12개 출처라는 기존 한도와 생략 개수를 유지한다. 실패한 읽기, 비정상 범위와 형식이 맞지 않는 ID는 제외한다. 다시 읽을 때는 대화에 연결된 문서와 해시를 기존 문서 도구가 재검사한다.

연구 담당이 문서를 읽고 근거를 반환한 뒤 주 에이전트가 해당 근거를 확인한 경우도 검사한다. 일부러 출처를 누락한 요약을 반환해도 정확한 첨부 구간을 다시 읽을 수 있어야 한다. 원문을 재조회할 수 있다는 뜻이며, 요약 내용의 사실성이나 전체 문서 이해를 자동 보증하지는 않는다.

## BP와 오픈소스 선택

- [Anthropic 멀티 에이전트 사례](https://www.anthropic.com/engineering/multi-agent-research-system): 독립적인 과제와 명확한 종료 조건, 역할별 문맥, 근거가 있는 짧은 결과. 모든 브라우저 행동을 병렬화하지 않고 이미 적용된 읽기 전용 담당 구조를 유지한다. 다중 Agent가 총 토큰을 늘릴 수 있으므로 단순 작업은 직접 처리한다.
- [Anthropic 컨텍스트 엔지니어링](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): 필요한 정보를 적시에 조회하고 장기 상태를 요약 하나에 맡기지 않는다. 첨부 출처 보존 결함을 고치는 근거로 적용했다.
- [OpenAI Harness Engineering](https://openai.com/index/harness-engineering/): Agent가 볼 수 있는 작업 환경/근거를 정리하고 검증 가능한 피드백으로 품질을 유지하는 원칙을 참고했다. 코딩 저장소 사례를 브라우저의 관찰/행동/결과 검사에 맞춰 사용한다.
- [Pi 0.86.1](https://github.com/earendil-works/pi/tree/v0.86.1), MIT: 현재 주/하위 Agent 실행 라이브러리를 유지한다. [compaction 구현](https://github.com/earendil-works/pi/blob/v0.86.1/packages/coding-agent/src/core/compaction/compaction.ts)의 최근 문맥과 도구 짝 보존 패턴을 기존 브라우저 압축기와 함께 사용한다. Node 세션 관리자를 MV3에 추가하지 않는다.
- MiniSearch 7.2.0와 LangChain textsplitters 1.0.1, MIT: 현재 문서/근거 검색과 분할 라이브러리를 재사용한다. 이번 도구 검색에도 MiniSearch를 사용했다.
- [OpenAI Agents SDK JS](https://github.com/openai/openai-agents-js)는 대안으로 검토했다. 이미 Pi가 담당하는 실행/위임 상태를 두 프레임워크에 중복시키는 전환보다, 확인된 근거 전달 결함을 작은 변경으로 고치는 쪽을 선택했다. 이번에 새 SDK를 설치한 것은 아니다.

## 평가 범위

`analysis-agents`, `analysis-delivery`, `analysis-quality`, `document-tools`, `context-evidence` 단위/계약 검사는 실제 Pi 루프에 합성 모델 응답을 넣는다. 담당 간 자료 격리, 병렬 진행, 먼저 끝난 결과 전달, 실패한 조회 수정, 근거 범위와 압축 후 재조회를 확인한다. 브라우저 회귀는 별도 Chrome 프로필에서 실제 DOM/키보드/포인터/승인/중단 후 재개를 확인한다.

실제 Qwen 3.8 27B 인증이 없어 자율 과제 분해, 문서 해석 정확도, 총 토큰과 지연의 실모델 비교는 아직 미검증이다. 이 단계에서 종합 품질 점수나 다른 제품 대비 우위를 만들어 표시하지 않는다. 실행기 회귀 결과는 배포 문서에 기록한다.
