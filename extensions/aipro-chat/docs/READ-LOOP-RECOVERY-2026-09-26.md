# 반복 조회의 진행 판정과 복구

## 재현한 결함

실제 네이버 실패 기록에는 출처를 반복 이동하며 첫 계획을 마치지 못한 실행이 있다. 이번에는 그 기록만으로 단일 원인을 단정하지 않고 진행 판정의 재현 가능한 결함을 분리했다.

1. 같은 화면을 재방문해 새 Chrome documentId를 받으면 `browser-recovery.js`가 이를 새로운 관찰 내용으로 비교했다.
2. 본문 content_hash는 문서 ID에 결합돼 있어 동일 본문도 재로드하면 바뀐다. 이는 원문 이어읽기와 인용 검증에는 필요하지만, 새로운 정보를 읽었다는 근거가 될 수 없다.

두 단위 재현 검사는 변경 전 실패했다. 수정 후 실제 Chrome 재로드에서도 documentId와 content_hash는 바뀌고 본문 동일성은 유지되는 것을 확인했다.

## 구현

`browser-content.js`는 기존 Readability/Turndown 추출 결과의 전체 텍스트에 Web Crypto SHA-256을 적용한 `content_text_hash`를 추가한다. 이 값은 **진행 비교 전용**이다. 기존 문서 결합 content_hash, source_key, source_document_id와 이어읽기/인용/미확정 쓰기 검증을 대체하지 않는다. 새로운 패키지를 추가하지 않았다.

`browser-recovery.js`는 실제 관찰 구조의 문서 ID와 자동 본문 수집 장부를 진행 비교에서 제외한다. 일반 업무 데이터에 있는 documentId 값은 유지한다. 본문의 서로 다른 구간을 읽는 것은 같은 문서의 내용을 바꾼 것으로 계산하지 않으며, 실제로 다른 본문/출처/읽기 결과는 보존한다. 검사 횟수를 늘리거나 동일 내용을 재방문하는 것으로 반복 상태를 초기화하지 않는다.

`agent-runtime.js`는 다른 작업 없이 읽기/이동을 연속 수행하고 같은 결과가 두 번 이상 반복될 때 기존 Pi 읽기 전용 recovery 워커를 한 번 사용한다. 실제 본문 또는 화면 근거가 있고 사용자 질문 기능이 연결된 실행에만 적용한다. 워커는 고정 근거만 읽고 다른 구간 조회나 근거 있는 정리 방향을 제안한다. 주 실행기가 새 도구 결과와 최종 요구사항을 다시 검토한다. 실패한 검토가 없는데 검토 실패라고 워커에 말하지 않는다.

같은 정규화 요청에는 복구 워커를 반복 생성하지 않는다. 자동 복구는 요청별 한 번, 현재 사용자 요청에서 최대 16개이며 전체 작업 횟수/시간 제한은 아니다. 이미 실행 중인 복구, 미확정 쓰기, 질문 대기에는 자동 위임하지 않는다. 사용자 정정은 느린 워커를 취소하고 낡은 조언을 전달하지 않는다. 조언 뒤에도 같은 조회가 반복되면 원하는 결과를 다시 적으라고 요구하지 않고 현재 근거를 유지한 다시 확인/중지 선택을 제공한다. 모델이 실제로 새 정보를 가져오면 기존 작업을 계속한다.

## 검증과 한계

- 단위: 재로드/수집 메타데이터의 거짓 진전, 본문 변화와 일반 업무 ID 보존, 실제 Pi 워커의 구간 조회/최종 검토, 조언 무시 후 기술적 대기, 정정 시 취소, 미확정 쓰기 차단.
- 실제 Chrome: 긴 원문의 첫 부분을 두 번 읽고 두 번째에 브라우저를 실제 재로드한다. 서로 다른 문서/인용 ID와 동일 본문 해시를 확인한 뒤 워커 한 건을 실행한다. 새 검색으로 첫 구간에 없던 배송비를 읽고 독립 검토가 통과해야 답변한다.
- 호환성: 초기 전체 단위 검사에서 질문 기능 없는 실행에 복구가 들어가 오류 분류가 바뀐 것을 발견했다. 실제 읽은 근거와 질문 기능을 요구하도록 범위를 좁힌 뒤 관련 검사를 재통과했다.

브라우저와 Pi 실행은 실제이며 모델 응답은 합성이다. 실제 네이버 완주율이나 모델 응답 시간 개선률은 아직 측정하지 않았다. 페이지에 계속 변하는 광고/시간 등이 있으면 새 내용으로 판정할 수 있으며, 서로 다른 많은 요청으로 이루어진 모든 의미적 반복을 탐지하는 기능은 아니다. 과거 네이버 실패를 전부 해결했다고 표시하지 않는다.

최종 고정 후보 검증 결과는 아래에 별도로 기록한다.

첫 후보 gate는 기존 error-recovery-browser의 합성 응답기가 새 워커 호출을 일반 조회로 취급해 중단됐다. 워커의 허용 도구/근거 읽기/결과 전달을 명시적으로 응답하고, 6회 A/B 조회 뒤 사용자 요구를 재질문하지 않는 기술적 대기를 검사하도록 수정했다. 단독 Chrome 재검사에서 클릭 영수증 유실의 중복 실행 차단, 추론 복구, 취소와 새 반복 복구가 모두 통과했다. 실패한 gate를 통과로 바꾸지 않고 수정한 입력으로 다시 검증한다.

두 번째 gate의 역할별 워커 검사에서는 정상 분석 뒤 원문 재확인까지 자동 복구로 분류하는 과잉 개입을 발견했다. 연속 읽기 구간에만 자동 복구를 제한하고 도구 작업/보고 전달은 그 구간의 경계로 처리했다. 이는 완료 근거나 실패 해소로 계산하지 않는다. 새 단위 재현과 기존 역할별 Chrome 검사가 통과했으며, 대기 용량이 찬 경우에는 추가 복구를 배정하지 않는다.
