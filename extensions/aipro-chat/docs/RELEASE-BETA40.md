# nubi Beta 1.0.0 — beta40

Chrome 업데이트 번호 **1.4.43**. 기존 `beta39`는 보존하고 이번 변경을 새 ZIP으로 배포한다. ChatGPT·Claude 등 제품 브라우저 에이전트의 방식을 조사해 반영했다.

## 변경

**행동 결과 요약**
- 클릭, 입력, 선택, 스크롤, 이동 결과에 무엇이 바뀌었는지(`effect`)를 붙인다: 주소·제목·새 문서, 대화상자 열림·닫힘, 새 알림 문구, 컨트롤 상태(체크·눌림·펼침·선택·클래스 상태·행 상태), 이름이 바뀐 버튼, 새로 나타나거나 사라진 컨트롤, 순서 변화, 입력칸 포커스, 새 글 줄. 제품 에이전트들은 모델이 결과를 확인하지 않고 가정하는 문제 때문에 행동 뒤 결과를 돌려준다.
- 클릭 뒤 아무 변화가 없으면 그렇다고 알리고, 연속 두 번째부터는 같은 클릭을 반복하지 말고 상태를 읽거나 다른 방법을 쓰거나 사용자에게 물으라고 안내한다.
- 사라진 컨트롤에는 무효가 된 참조를 붙이지 않는다. 칸의 값은 관찰하지 않으므로 비교하지 않는다.

**확인 도구**
- `verify_page` 확인 항목의 형식이 틀리면 어느 항목이 왜 틀렸는지(`invalidChecks`)와 올바른 형식을 알려준다. 예: 선택 상자의 선택값은 관찰된 옵션 값으로 `field_value`를 쓴다. 이전에는 "스크립트를 고쳐라"는 안내만 나가, 모델이 스크립트로 값을 읽다가 검토가 이를 확인으로 받지 않아 사용자 질문으로 끝난 적이 있다.
- `control_state`가 관찰의 상태 단어(예: `starred`, `on`)를 기대값으로 받아, 컨트롤과 그 행의 클래스를 확인할 때 다시 읽는다. 클래스로만 켜지는 별표나 적용된 필터를 확인할 수 있다.

**조사 과제의 최종 검토**
- 최종 검토 뒤 범위 감사가 "새 근거가 필요하다"고 판정하면 그 판정을 모델에 전달해, 답을 다시 쓰기 전에 출처를 읽게 한다. 이전에는 문구 수정 판정만 전달돼 모델이 읽지 않고 답만 다시 썼다.
- 한 번 더 읽고도 같은 공백이 남으면, 더 찾지 않고 도구 없이 근거 없는 문장을 지운 뒤 확인하지 못한 부분으로 밝힌 답을 쓰게 한다. 최종 검토는 그대로 판정한다. **이 항목은 실측하지 않았다.**
- 같은 페이지를 다시 읽을 때 본문이 같으면 앞선 읽기를 유지한다. 본문이 바뀌어 대체된 읽기도 검토자에게 주소와 제목은 남긴다. "다시 열어 확인" 같은 요청에서 검토자가 앞선 방문을 볼 수 있다.

**승인 판정**
- 이미지 버튼(`<input type="image" alt="검색">`)과 버튼 안 이미지의 `alt`를 이름으로 읽는다. 공공기관 상세 검색에서 검색 버튼 하나에 "양식 제출" 승인을 요구하던 문제를 고쳤다. 이름이 "등록"인 이미지 버튼, 이름 없는 이미지 제출은 이전처럼 승인이 필요하다.

권한과 콘텐츠 보안 정책은 beta39와 같다. 새 필수 권한은 없다.

## 설치와 업데이트

ZIP을 풀고 `chrome://extensions`에서 개발자 모드의 **압축해제된 확장 프로그램 로드**를 선택한다. 기존 사용자는 **같은 설치 폴더**의 파일을 교체하고 확장을 새로고침한다. 폴더를 바꾸면 확장 ID와 저장된 대화가 달라질 수 있다. 웹 스토어 배포본은 아니다.

## 알려진 한계

- H-04(세 기관 조사)는 아직 검토를 통과하지 못한다. 다시 읽으러 가도 서울도서관 운영시간 페이지를 찾지 못했다. 이를 위한 마지막 조치(공백이 남으면 확인하지 못한 부분으로 밝히기)는 로그인 없이 실측하지 못했다.
- 행동 결과 요약은 관찰한 것만 비교한다. 입력칸 값, 캔버스, 다른 탭의 변화는 "변화 없음"으로 보일 수 있고, 안내 문구가 이를 밝힌다.
- 실측 기록은 도구 결과의 내용을 남기지 않아, 행동 결과 요약만의 효과는 따로 가를 수 없었다.
- 사내 모델로는 이번 변경을 실측하지 않았다.
