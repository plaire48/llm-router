# 내장 사이트 위키 활용 개선

2026-09-24 / nubi Beta 1.0.0 후보 beta.31

같은 날의 후속 구조 파싱과 한국어 검색 개선은 [내장 위키 품질 개선](WIKI-QUALITY-2026-09-24.md)에 기록한다. 아래 수치는 beta.31의 문서별 근거 선택 회귀 결과다.

누비의 내장 위키는 실제 브라우저에서 확인하고 사용자가 검토한 메뉴, 입력 항목, 업무 설명을 저장한다. 소스 저장소를 분석하는 외부 OpenWiki와 별개이며, DeepWiki 엔진이 확장에 탑재된 것은 아니다.

## 적용한 흐름

1. 현재 페이지를 읽으면 같은 사이트와 제공자의 관련 위키 근거를 자동 전달한다. 일반 대화만으로 탭 본문을 수집하지 않는다.
2. MiniSearch 7.2.0(MIT)로 제목과 소제목, 본문을 검색한다. 긴 절도 900자 구간과 180자 겹침으로 나눠 뒤쪽 내용을 찾는다. 소제목이 지나치게 많으면 문서 전체의 겹친 구간으로 전환해 문서당 색인 조각을 65개 이하로 유지한다. 메뉴 URL 검색도 유지한다. 제목은 원문에서만 가져오며 LLM이 만든 동의어나 규칙을 검색어로 합성하지 않는다.
3. 관련 페이지 3개에서 우선 하나씩 근거를 선택하고 남은 구간을 채운다. 전체 발췌는 기존과 같은 6개 한도다. 각 근거에 URL, 문서 버전, 관찰 시각, 해시, 원문 위치와 검색어 일치도를 제공한다. 일치도는 사실의 신뢰 확률이 아니다.
4. 더 필요한 부분은 search_site_wiki/read_site_wiki로 추가 조회한다. 전체 위키를 매 요청에 주입하지 않는다. 같은 문서라도 다른 구간이 필요하면 새 근거를 전달한다.
5. 실제 관찰이 저장된 지식과 모순되면 이미 전달한 안내를 더 이상 신뢰하지 말라는 결과를 모델에 보낸다. 현재 DOM을 다시 보고 다음 행동을 판단한다.
6. 자동 갱신은 설정에서 켠 경우에만 검증된 작업의 기존 문서를 갱신한다. 일부 항목만 보이거나 항목이 추가된 것은 모순으로 단정하지 않는다. 명시적으로 모순된 관찰은 기존 설명을 재검토 대상으로 제외한다. 사용자가 검토한 업무 설명을 자동 생성 문구로 덮어쓰지 않으며 이전 관찰로 복원할 수 있다.

사이트/제공자 경계, 30일 최신성 제한, 문서 버전 재검사와 현재 작업의 최종 승인 요구를 유지한다. 저장된 안내는 현재 실행의 성공 증거나 권한이 아니다. 검색되지 않은 규칙은 추측하지 않고 외부 OpenWiki 또는 업무 스킬을 확인한 후 필요한 내용만 질문한다.

검색은 어휘 기반이다. 전혀 다른 표현의 동의어를 의미적으로 이해한다고 주장하지 않는다. 원문 단어로 좁혀 읽고 부족한 업무 규칙은 사용자에게 확인한다. 이후 임베딩·재순위 모델 도입은 실제 사내 질문셋에서 정확도/지연/토큰 비용을 비교한 뒤 결정한다.

## 평가

`tests/wiki-retrieval.test.mjs`는 이전 검색 방식과 동일한 합성 문서를 비교한다. 긴 문서에 검색 결과가 몰리는 3페이지 사례에서 관련 문서 재현율@3은 1/3에서 3/3으로 개선됐다. 이 수치는 해당 회귀 사례 한 건의 결과이며 일반 정확도나 사내 업무 성공률이 아니다.

추가 검사는 긴 단일 절의 떨어진 근거, 원문 위치 일치, 약한 일치 표시, 사이트/제공자 격리, 부분 관찰 갱신과 만료된 설명 제외를 포함한다. 실제 Chrome 회귀는 위키 생성/선택형 질문/저장/재사용/화면 변경 통지/자동 갱신/복원을 확인한다. API와 Qwen 응답은 합성이며 실제 Qwen 3.8 27B와 사내 서비스 성능은 미검증이다.
