# nubi Beta 1.0.0 — beta38

Chrome 업데이트 번호 **1.4.41**. 기존 `beta35`는 보존하고 이번 변경을 새 ZIP으로 배포한다. 공개하지 않은 beta36·beta37 후보의 변경도 함께 들어 있다.

## 변경

**조회와 출처**
- 열어 본 페이지의 본문을 자동으로 확보한다. 이미 관찰한 영역을 다시 읽을 수 있고, 열린 PDF의 글도 읽는다.
- 조회 요청에서 다른 페이지로 이동해도 앞서 본 페이지의 글을 검토 근거로 남긴다(최근 6개 페이지). 두 출처를 대조하는 요청에서 검토자가 두 근거를 함께 본다.
- 검색어로 좁힌 관찰에 맞는 글이 없으면, 페이지가 비어 있지 않다고 알려 준다.
- 링크는 누르지 않고 보이는 목적지로 검증한다(`link_page_is`).

**검토와 완료 판정**
- 여러 단계 계획은 단계마다 결과를 검토하고 저장한다.
- 최종 검토는 4회까지다. 조회 요청에서 대부분의 조건을 충족한 답은 "검증 완료가 아님"과 남은 항목을 적어 전달한다. 페이지를 바꾼 작업에는 적용하지 않는다.
- 한 단계의 검토가 4회 연속 수정을 요구하면 사용자에게 계속할지 묻는다.
- 단계 검토가 그 단계 밖의 요구로 되돌린 경우, 검증된 범위 감사가 확인하면 그 단계를 완료로 정한다.

**브라우저 도구**
- 페이지가 표준 `Map` 등을 자체 함수로 바꿔 둔 사이트에서도 화면을 관찰한다. 이전에는 이런 사이트(예: 국립중앙도서관)에서 관찰이 전부 실패했다.
- 자체 파일이 늦게 오는 페이지에서 읽기가 끝없이 기다리지 않는다. 이동은 새 문서가 열리면 성공으로 보고, 아직 로딩 중이면 그렇다고 알린다. 이동 도구는 30초 안에 답한다.
- 기존 값을 그대로 두라는 요청을 검증한다(`field_unchanged`). 값은 페이지 밖으로 나가지 않고, 한 방향 표식만 비교한다.
- 같은 화면을 반복해서 읽거나 같은 스크립트가 반복 실패하면 다시 감지한다. 관찰마다 새로 붙는 영역 ID 때문에 반복 감지가 동작하지 않던 결함을 고쳤다.
- 새 작업 탭의 첫 페이지가 아직 도착하지 않았을 때도 그 탭을 탭 목록에 남긴다.

**문맥 압축**
- 긴 작업의 요약이 발견한 것, 실패한 것, 현재 위치를 따로 남긴다. 요약에 적힌 주소는 실제로 본 주소인지 확인한다.

**사이트 위키와 스킬**
- 사이트 위키가 경로와 주의할 점을 기록하고, 저장할 때 이메일·전화번호·계좌번호 등을 가린다.
- 스킬 초안의 설명에 무엇을 언제 쓰는지 적는다. 직접 선택한 스킬은 절차와 점검 기준을 바로 넣어 다시 찾지 않는다. 스킬별 사용 기록을 보여 준다.

권한과 콘텐츠 보안 정책은 beta35와 같다. 새 필수 권한은 없다.

## 설치와 업데이트

ZIP을 풀고 `chrome://extensions`에서 개발자 모드의 **압축해제된 확장 프로그램 로드**를 선택한다. 기존 사용자는 **같은 설치 폴더**의 파일을 교체하고 확장을 새로고침한다. 폴더를 바꾸면 확장 ID와 저장된 대화가 달라질 수 있다. 웹 스토어 배포본은 아니다.

## 검증 범위

GATE_RESULT

UPGRADE_RESULT

단위 검사 UNIT_RESULT. 운영 의존성 점검에서 보고된 취약점은 0개다.

실제 모델(GPT-5.6 Sol, ChatGPT 로그인) 실측은 누비 내부 검토의 판정이며 독립 채점이 아니다. 과제별 1회 실행이다. 실측은 개발 후보 23~25에서 했다. beta38은 후보 25에 반복 감지 수정, 작업 탭 목록 수정과 검사 수정을 더한 빌드이고, beta38 자체로는 실측하지 않았다. 반복 감지가 다시 동작하므로 같은 과제에서 중간 검토나 사용자 확인이 더 일찍 나올 수 있다.

| 과제 | 수정 전 (후보 22) | 수정 후 (후보 23~25) |
|---|---|---|
| 상품 비교 조회 | 시간 초과 306초 | 검토 완료 212초 |
| 신청 설정 변경(메모 보존) | 시간 초과 302초 | 검토 완료 144초 |
| 영상과 공식 문서 대조 | 제한 공개 368초 | 제한 공개 154초 |
| 두 도서관 토요일 자료실 비교 | 제한 공개 465초 | 제한 공개 256초 |
| 초안 작성(담당 팀 질문, 메모 보존) | 검토 완료 369초 | 검토 완료 408초 |

## 알려진 한계

- 조회 과제에서 작업 중간에 쓴 글도 최종 검토 횟수를 쓴다. 그래서 문구 하나만 고치면 되는 답이 "검증 완료가 아님"으로 전달될 수 있다.
- 계획이 관찰할 수 없는 조건(입력칸의 현재 값 확인)을 완료 기준으로 잡으면 단계 검토가 반복된다.
- 같은 요청이라도 실행마다 읽는 페이지 범위가 달라 결과가 달라진다.
- YouTube의 "동영상" 필터와 "최근 업로드" 정렬을 함께 거는 요청은 네 번 모두 사용자 확인으로 끝났다.
- 두 단계 이상 계획의 쓰기 작업은 단계마다 검토가 한 번 더 들어가 모델 호출이 늘었다.
- 입력 한도가 약 17,000토큰보다 작은 모델은 압축 뒤 대화를 이어 가지 못하고 오류를 알린다. 현재 목록의 모델(256K, 512K)은 해당하지 않는다.
