# 내장 사이트 위키와 외부 OpenWiki

## 목적과 경계

2026-09-24 검색 구조 개선과 후보 비교는 [내장 위키 품질 개선](WIKI-QUALITY-2026-09-24.md)을 따른다. 기존 위키 작성과 검토 저장 흐름에 제목 계층, 표 머리글 보존과 한국어 띄어쓰기 검색을 적용했다.

누비는 코드 저장소 없이도 브라우저에서 관찰한 화면을 문서화한다. 내장 사이트 위키의 원문은 확장 저장소의 사용자 검토 문서다. 이제 확장에 번들한 OpenWiki의 읽기 전용 DeepAgents 코어가 이를 조회한다. 내장 위키와 외부 위키는 각각 독립된 문맥으로 현재 누비 모델을 사용한다. [실행 구조와 검증](OPENWIKI-AGENT-DELEGATION.md)을 따른다. 외부 OpenWiki는 기존 연결을 통해 조회하는 별도의 문서 출처다. 내부 위키를 PC 폴더 초기화나 코드 분석 완료로 표현하지 않는다.

## 사용자 흐름

- `/wiki`: 현재 작업 대상 페이지를 읽고 검증한 후 선택한 제공자의 모델로 문서 초안을 만든다. 이 수집 단계에서는 쓰기 도구를 제공하지 않는다.
- 일반 작업 완료: 실제 화면 검증과 완료 검토를 통과하면 `위키에 남길까요?`에서 초안 작성 또는 건너뛰기를 선택한다. 자동 저장하지 않는다.
- 작성 중 필요한 기준이 없으면 기존 `ask_user` 객관식과 자유 입력 폼을 사용한다. 이미 확인한 답변은 이어서 사용한다.
- 초안을 수정한 뒤 저장한다. 문서와 저장 완료 기록을 한 번의 local storage 쓰기로 반영한다.
- 저장한 문서는 새 대화에서 같은 제공자와 같은 사이트의 읽기 결과에 최대 3개를 검색해 첨부한다. 검색은 기존 MiniSearch를 재사용한다.
- ZIP의 `site.md`를 기존 외부 OpenWiki 문서 폴더에 넣을 수 있다. 외부 폴더에 자동 쓰거나 OpenWiki CLI를 실행하지 않는다.

## 문서의 근거

URL, 제목, 확인 시각, 화면 제목, 입력 항목의 이름/종류/필수 여부와 조작 라벨을 남긴다. 관찰 수집기는 값, raw DOM, ref, selector, 쿠키와 스크린샷을 보관하지 않는다. 작업 요약의 개별 값은 모델 작성 시 변수로 바꾸고 저장 전에 사용자가 검토한다. 문자열 필터를 완전한 개인정보 탐지라고 주장하지 않는다.

화면 관찰, 사용자 확인 업무 기준, 미확인 사실을 문서 안에서 구분한다. 필드 이름만 보고 FP 정의나 승인 규칙을 추정하지 않는다. 화면 확인은 내부 서버 구현, 저장 결과, 사이트 전체 구조를 증명하지 않는다.

문서는 출처/시각/버전을 유지한다. 조회에 실패한 경로와 30일 지난 자료는 자동 조회에서 제외하지만 삭제하지 않는다. 새 `/wiki` 확인과 검토 저장으로 갱신한다. 삭제/비활성화 시 revision을 올려 진행 중이던 예전 초안이 다시 저장되는 것을 막는다. 문서 내용은 현재 실행 증거나 권한이 아니며, 완료 검토에서 historical knowledge는 제외한다.

Crawl4AI/Firecrawl은 추출과 수집에 강점이 있지만 Python/서버 런타임과 별도 운영이 필요하다. Mem0/LangMem은 범용 기억에 유용하나 이번 문서 작성/검토 흐름의 대체재가 아니므로 의존성을 추가하지 않았다. 단순히 패키지를 늘리는 것보다 현재 확장 안에서 검증 가능한 문서 생성 흐름을 우선한다.

## 검증 범위

`tests/browser-knowledge.test.mjs`와 `tests/browser-wiki-browser.mjs`를 기준으로 범위 제한, 민감 URL 제외, 문서 검토/저장/재접속, 질문 이어가기, 새 대화 조회, 건너뛰기와 ZIP을 확인한다. 실제 Chrome의 합성 페이지와 모델 fixture 검증이며 회사망 Qwen 응답 품질 또는 사내 업무 기준의 정확성을 증명하지 않는다.

## 코드 형상 없이 정확도를 확보하는 기준

코드는 내부 동작을 확인하는 근거지만, 브라우저 사용 절차에서는 사용자 역할과 배포 버전의 실제 화면이 더 직접적인 근거일 수 있다. 두 자료를 동등하게 취급하지 않는다. 코드 없는 누비의 원본은 정규화한 화면 관찰 JSON이며, SHA-256으로 해당 관찰의 변경 여부를 비교한다. 이 해시는 서버 데이터, 전체 DOM 또는 모든 동작의 동일성을 보장하지 않는다. 관찰 범위나 표시 순서만 달라지면 문서를 무효화하지 않는다. 명시적인 필수 여부 충돌이나 수집 범위가 확인된 제목 전체 불일치를 변경 신호로 사용한다. 일부 변경을 놓칠 수 있으므로 이 검사는 화면 동일성 보증이 아니며 실행 전 재관찰을 유지한다.

- [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval): 문서 조각에서 빠진 문맥을 보완하는 패턴을 적용해 제목/사이트/경로와 문단을 함께 검색한다. Anthropic의 임베딩+BM25 전체 파이프라인이나 공개 성능 수치를 누비에 그대로 적용했다고 주장하지 않는다.
- [Anthropic Context Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): 문서를 모델 문맥 밖에 보관하고 관련 구간을 필요할 때 가져온다. 페이지 자료는 명령이 아닌 관찰 근거다.
- [OpenAI Retrieval](https://developers.openai.com/api/docs/guides/retrieval): 출처 속성 필터와 문서 조각의 검색을 참고한다. 현재는 원격 Vector Store 업로드 없이 origin/provider 필터와 로컬 MiniSearch를 적용한다. 임베딩/의미 검색은 미구현이다.
- [OpenCode Compaction](https://dev.opencode.ai/v2/docs/compaction/): 실행 대화의 요약과 원본 보관을 구분하는 방식을 참고한다. 누비의 작업 요약을 검토된 사이트 위키와 혼합하거나 요약을 새 실행의 완료 근거로 사용하지 않는다.

실제 적용: 관련 문단 최대 6개, 문단별 최대 900자 발췌에 URL/문서 버전/확인 시각/관찰 해시를 붙인다. 제목·필드 구조가 달라지면 해당 문서는 자동 검색에서 제외한다. 기존 문서를 변경할 때 새 관찰에서 다시 초안을 만들고 검토 저장한다. 문서 원문은 검색 발췌와 별도로 남긴다.

남은 개선: 문장별 원본 근거 연결과 정확성 평가, 동의한 업무 매뉴얼의 원문 발췌, 사내 용어 동의어 평가, 여러 화면 사이의 절차 그래프, 근거별 사용자 확인 이력. 현재 화면 라벨과 작업 요약만으로 이 기능들까지 구현했다고 보지 않는다. 추가 도입은 실제 사내 평가 세트에서 검색 정답률과 작업 성공률을 비교해 결정한다.

## 상시 도구로 활용

`search_site_wiki`와 `read_site_wiki`는 브라우저 작업의 기본 도구로 노출한다. 주 에이전트가 작업 시작, 반복 탐색 직전, 용어/입력 기준이 불명확할 때 조회한다. 도구는 요청에 묶인 실제 탭의 origin과 제공자 범위만 읽으며 다른 사이트 문서를 추측해서 읽지 않는다. 검색의 문서 버전을 읽기 때 다시 검사한다. 조회는 `metadata_only`/historical로 표시하며 실행 완료의 증거에서 제외한다.

첫 페이지 읽기에는 관련 문서 발췌를 자동 제공한다. 같은 URL/문서 버전/원본 해시 묶음을 같은 실행에서 반복 전달하지 않는다. 필요하면 명시적 읽기 도구로 다시 열 수 있다. 핵심은 검색 횟수를 늘리는 것이 아니라 탐색 → 검증 → 검토 저장 → 다음 탐색의 품질을 올리는 것이다. 오류/빈 결과/출처 충돌은 실페이지 확인, 외부 문서 조회, 사용자 질문으로 해결한다. 쓰기/승인 권한을 기억에서 가져오지 않는다.

측정할 기준: 올바른 메뉴/규칙 검색 비율, 출처와 답변의 일치, 반복 탐색 횟수, 실패 뒤 불필요한 재실행, 실제 과업 완료율, 추가 토큰/지연. 자동 테스트의 도구 계약 통과와 실모델 성능 향상은 별개다. 임베딩이나 다른 메모리 프레임워크는 이 기준의 비교 평가에서 필요성이 확인될 때 추가한다.


## 저장된 위키 자동 갱신 (beta30)

설정 → 사이트 위키 → 저장된 위키 자동 갱신. 기본은 꺼짐이며 사용자가 켜면 매번 HITL 없이 갱신한다. 새 페이지 자동 생성과 백그라운드 크롤링은 하지 않는다. 최종 검토 complete, verify_page passed인 현재 작업에서 확인한 마지막 페이지에만 적용한다. 추가 LLM 호출 없이 기존 documentObservedPage로 라벨/필수 여부/메뉴를 정규화한다. 입력값, 비밀번호, 원시 DOM, 인증값은 저장하지 않는다.

- 동일 origin/provider/URL의 기존 문서, 현재 revision/관찰 시점 문서 버전이 일치해야 한다. 삭제/설정 변경/수기 저장 이후 늦은 결과는 적용하지 않는다.
- 업무 규칙이 포함된 Markdown과 검토일은 유지한다. 관찰 내용이 바뀌거나 문서가 무효화되면 본문을 재확인 대상으로 표시한다. 관찰 갱신으로 30일 지난 본문이 다시 유효해지지 않는다.
- 최신 화면 구조와 과거 본문의 신선도를 분리한다. 검색/읽기는 최신 구조를 사용할 수 있지만 재확인 본문과 복원용 과거 버전은 모델에게 전달하지 않는다. 현재 실행 근거/권한은 여전히 실페이지에서 검증한다.
- 설정에서 최신 화면 정보를 펼쳐 볼 수 있고, 이전 관찰 한 버전을 되돌릴 수 있다. 복원도 새 버전을 부여해 열려 있던 초안의 덮어쓰기를 막는다. 원래 무효화된 버전은 복원해도 무효 상태를 유지한다.
- 전체 원문을 자동 재작성하는 기능은 아니다. 절차와 업무 규칙 변경은 기존 /wiki 작성/검토 경로를 사용한다. 부분 관찰에는 누락이 있으므로 전체 사이트 지도나 재사용 성공을 보장하지 않는다.

방법론: [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)의 필요한 정보만 회수하는 구조화 메모, [LangGraph memory](https://github.com/langchain-ai/langgraphjs/blob/main/docs/docs/concepts/memory.md)의 세션 상태와 장기 기억 분리/기억 갱신 패턴을 참고했다. 브라우저 확장에는 이미 로컬 영속 저장과 MiniSearch 7.2가 있으므로 LangGraph 서버/벡터 DB를 추가하지 않는다. 실제 사용하는 오픈소스는 기존 MiniSearch이며 새 메모리 프레임워크를 도입했다고 표현하지 않는다. 효과는 다음 작업의 메뉴 탐색 수, 관련 근거 검색률, 완료율을 실모델로 비교해야 한다.
