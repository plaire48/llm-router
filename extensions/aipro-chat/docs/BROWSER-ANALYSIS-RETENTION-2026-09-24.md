# 하위 분석 근거 보존과 완료 상태 재검증

2026-09-24. 긴 문서의 분할 조사와 독립 분석 결과 전달을 검토했다. 실행 중인 하위 작업만 근거를 보호하고, 완료했지만 아직 부모에게 전달하지 않은 작업은 보호하지 않는 문제가 있었다.

## 재현과 수정

수정 전에는 분석 하나가 `ev_1`을 읽고 완료한 뒤 부모가 다른 관찰 60개를 기록하면, 최초 수집 결과가 `status=complete`, findings 1개, evidence 0개, missing_evidence `[ev_1]`로 반환됐다. 이에 대한 미전달 근거 보존, 과거 결과 재조회, 미수집 결과 수 제한 검사 3개가 모두 실패했다.

- 하위 작업의 원문 근거는 실행 중뿐 아니라 결과를 전달할 때까지 보호한다. 이미지도 같은 보호 대상 집합을 사용한다. 보존된 화면 관찰의 stale 상태나 확인 시각을 갱신하지 않는다.
- 동시 실행 2개는 기존 p-limit을 유지한다. 실행 중/대기 중/완료 후 미수집 작업을 합해 최대 6개로 제한한다. 수집하면 새 작업을 받을 수 있으며 같은 작업의 중복 요청은 재실행하지 않는다. 사용자 전체 작업 횟수나 문서 구간 수의 제한이 아니다.
- 이미 전달한 과거 작업은 이후 일반 근거 정리 대상이 될 수 있다. 재조회 시 인용한 원문이 없으면 partial로 반환하고 해당 근거가 필요한 결론을 제외한다. 누락 ID, 남아 있는 근거와 재검토 안내를 함께 반환한다. 원래 미해결 항목은 하나도 삭제하지 않는다. 이전에 전달한 결과 객체는 바꾸지 않는다.
- 문서 구간을 읽었던 기록과 현재 원문을 다시 검토할 수 있는 상태를 구분한다. 원문 해제 후에도 역사적 읽기 범위는 유지하지만 `review_needed=true`로 표시한다. 보고서와 진행 이벤트의 상태를 일치시킨다.

이 저장소는 현재 실행의 메모리다. 질문/중지/실행 종료 때 기존 dispose로 정리하며, 영구 문서 저장이나 워커 재시작 복구 기능을 추가하지 않는다. 일반 48개 정리 기준은 보호되지 않은 근거에 적용하는 기준이며 보호 근거까지 포함한 절대 개수 한도라고 표현하지 않는다.

## 방법론과 오픈소스 판단

| 검토 대상 | 선택과 적용 |
| --- | --- |
| [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | **방법론 참고**. 요약만 남기면 원래 근거를 잃을 수 있으므로 필요한 식별자와 원문 조회를 유지한다. 압축/정리를 완료 판정과 분리한다. 장기 영구 메모리 서버를 도입한 것은 아니다. |
| [DeepAgents 하위 에이전트](https://docs.langchain.com/oss/javascript/deepagents/subagents), 기존 MIT 1.13.2 | **기존 문맥 격리 원칙 유지**. OpenWiki 위임은 기존 DeepAgents, 브라우저 독립 분석은 기존 Pi를 사용한다. 이번 결함은 호스트의 근거 수명에 있으므로 프레임워크를 통합 교체하지 않는다. |
| [p-limit](https://github.com/sindresorhus/p-limit), 설치 7.3.3, MIT | **기존 라이브러리 재사용**. 설치 소스의 activeCount/pendingCount와 큐 해제 동작을 확인했다. 실행 동시성 관리와 결과 수집 대기량은 다른 문제이므로 2개 실행 제한을 유지하고 누비가 미수집 결과 수를 별도 관리한다. |
| [lru-cache](https://github.com/isaacs/node-lru-cache), 현재 upstream BlueOak-1.0.0 | **후보 검토, 미도입**. 최근 사용 시각과 max/maxSize/TTL을 기준으로 한 정리만으로 누비의 결과 전달 상태를 알 수 없다. 이번에는 기존 Map에 작업 소유권/수집 상태를 반영하는 것이 작은 변경이다. 소스 복사나 신규 의존성 추가는 없다. |
| 기존 Pi Agent Core 0.86.1와 MiniSearch 7.2.0, MIT | **실제 재사용**. 동일 모델 호출과 읽기 전용 분석 루프, 관찰한 구간의 발췌 순위를 유지했다. 검색 엔진 업그레이드나 임베딩 도입은 이번 누락 원인의 해결책이 아니다. |

패키지 버전/라이선스는 설치된 manifest에서 확인했으며 lru-cache는 upstream 문서/라이선스를 기준으로 비교했다. 버전 일괄 변경은 하지 않았다.

## 검증 범위

- 단위 검사는 결과 미수집 상태에서 60개 추가 관찰, 전달 후 근거 해제, 6개 결과 수집 전 추가 위임 차단, 수집 후 새 작업, 중복 요청 재사용, 문서 읽기 기록과 재검토 상태를 확인한다.
- 신규 `analysis-retention-browser`는 임시 확장의 서비스 워커에 실제 소스를 번들해 6개 Pi 분석을 실행한다. 60개 새 관찰 뒤 원문 유지, 수집 후 추가 관찰에 따른 원문 해제, partial 재조회와 같은 Qwen 모델 ID 전달을 검사한다. 모델 응답은 합성이다.
- 확대 검사: **단위 690개, 디자인 검사, 후보 빌드, 브라우저 25회 통과**. 긴 첨부 문서 조회, 결과 전달, 문맥 압축, 진행 표시, 역할 분석, 복구와 최종 검토 8개 시나리오를 각각 3회, 신규 근거 보존 검사를 1회 실행했다. [확대 보고서](../verification/pre-release-2026-09-24T13-34-28-680Z/report.json)
- 추가 검토에서 근거 누락 안내가 기존 세 번째 미해결 항목을 대체할 수 있음을 별도 검사로 재현했다. 모든 원래 미해결 항목을 유지하고 안내는 요약/다음 단계로 전달하도록 보완했다.
- 최종 후보: **단위 691개, 디자인 검사, 빌드, 브라우저 7회 통과**. 문서 조회/하위 결과 전달을 각각 3회, 근거 보존 서비스 워커 검사를 1회 실행했다. [최종 보고서](../verification/pre-release-2026-09-24T13-37-32-669Z/report.json)
- [통합 기록](../verification/browser-analysis-retention-2026-09-24/report.json)에 수정 전 재현, 각 후보 해시, 서비스 워커 결과를 남겼다. 후보별 소스/dist 불변 검사도 통과했다. 확대 검사와 마지막 보완본은 다른 빌드이므로 32회를 동일 후보의 검사로 합산하지 않는다.

실제 모델의 이해 정확도, 사내 SSO, 전체 브라우저 매트릭스와 다른 Office/Desktop 호스트의 실행은 검증하지 않는다. 공유 실행기를 재사용하는 다른 호스트를 배포하거나 빌드하지 않는다. 기존 첨부 문서의 40,000자 수집 한도와 위키의 별도 수집 한도를 확대했다고 표시하지 않는다.
