# 내장 위키 후속 품질 개선

첫 개선 뒤 남은 Markdown 검색과 읽기 전환 문제를 재현하고 수정했다. Chrome 확장 내부의 사용자 검토 문서를 대상으로 하며 외부 OpenWiki 서버, Desktop과 Office는 변경하지 않았다.

## 재현과 수정

| 입력/흐름 | 이전 | 변경 |
| --- | --- | --- |
| `휴가 **신청**`, 인라인 코드를 포함한 휴가 신청 | `휴가신청`으로 찾지 못함 | Markdown 텍스트 노드로 검색하고 원본 서식과 위치는 발췌에 보존 |
| 링크 URL 또는 HTML 속성에만 있는 단어 | 본문 검색 결과로 반환 | 링크의 보이는 라벨만 색인. 링크 목적지/정의와 HTML 속성/블록은 본문에서 제외. 문서 자신의 메뉴 URL 검색은 유지 |
| 인용문 또는 목록 안의 긴 표 | 뒤쪽 행에 열 이름이 누락 | 중첩 트리를 탐색해 해당 표의 원문 머리글도 함께 반환 |
| 전체 검색 → 문서 한 건 집중 읽기 → 전체 검색 | 한 건 조회가 전체 파싱 캐시를 교체해 재검색에서 전체 문서를 다시 파싱 | 유효한 출처 집합은 유지하고 집중 조회의 후보만 요청 URL로 제한 |

문단, 표의 각 셀과 줄바꿈을 넘어 별개의 단어를 합치지 않는다. 본문 색인은 실제 발췌 범위 안으로 한정한다. 별도 문맥에는 원문 범위를 가진 제목과 표 머리글만 포함한다. 완전히 포함된 텍스트 노드는 서식/엔티티를 해석하며, 구간에 걸친 노드는 원문 교집합만 보수적으로 사용한다. 전체 제목 계층은 기존 최상위 Markdown 제목 기준이며 인용문 안의 제목을 바깥 문서 제목으로 승격하지 않는다.

기존 900자 본문, 600자 문맥, 문서당 64개 본문 구간과 전체 3개 문서/6개 근거 한도를 유지한다. 모든 원문 범위는 실제 Markdown의 UTF-16 반열린 범위다. 제공자/사이트/버전/만료 검사 후 색인을 사용하며, 집중 읽기에서도 다른 문서가 섞이지 않는다. 과거 문서는 현재 실행 증거나 승인으로 사용하지 않는다.

## 비교와 실제 적용

| 후보와 공식 소스 | 확인과 결정 |
| --- | --- |
| [mdast-util-to-string](https://github.com/syntax-tree/mdast-util-to-string), MIT 4.0.0 | **실제 적용**. 이미 설치된 Markdown 의존성을 직접 고정. 텍스트/인라인 코드/이미지 대체 텍스트를 원문 발췌와 별도로 색인한다. 전체 문서를 한 번에 문자열화하면 문단/셀이 붙으므로 노드별 범위와 문맥을 유지한다 |
| [unist-util-visit-parents](https://github.com/syntax-tree/unist-util-visit-parents), MIT 6.0.2 | **실제 적용**. 이미 설치된 의존성을 직접 고정. 부모 정보를 가진 재귀 탐색으로 중첩 표와 텍스트의 문단/셀 소속을 구한다. 브라우저 ESM과 기존 MV3 번들 경로 사용 |
| [MiniSearch API](https://lucaong.github.io/minisearch/classes/MiniSearch.MiniSearch.html), 기존 MIT 7.2.0 | **재사용**. 색인 입력과 토큰화 분리를 확인하고 기존 검색기에 정리된 텍스트를 전달한다. DOM/첨부 문서의 일반 검색 구현은 변경하지 않는다 |
| [LangChain ParentDocumentRetriever 소스](https://github.com/langchain-ai/langchain/blob/master/libs/langchain/langchain_classic/retrievers/parent_document_retriever.py), MIT | **방법론 참고**. 검색 구간과 원본 문서 저장을 분리하는 구조를 확인했다. 누비는 기존 원본 버전과 파싱 집합을 유지하면서 문서별 후보를 좁힌다. Python/벡터 저장소/별도 LangChain 실행기를 추가하지 않는다 |
| [FlexSearch CJK](https://github.com/nextapps-de/flexsearch/blob/master/src/charset/cjk.js), Apache-2.0 | **앞선 비교 재사용**. 이번 재현 원인은 Markdown 색인 입력과 조회 범위이므로 엔진 교체를 선택하지 않았다. 의미 검색이나 한국어 형태소 분석을 도입했다고 표현하지 않는다 |

새 원격 서비스, 추론 호출과 실행 권한은 추가하지 않았다. 설치된 하위 패키지 버전 변경 없이 직접 의존성 2개만 명시했고 배포 후보에 전체 라이선스와 버전을 포함한다. 공식 소스와 설치된 실제 구현을 함께 읽고 결정했다.

## 검증

수정 전 신규 5개 검사에서 1개 통과/4개 실패를 보존했다. 수정 후 같은 5개와 추가 원문 범위/코드 블록 검사 1개가 통과했다. 기존 위키 검사까지 포함한 집중 검사는 31개 통과다. 최종 후보는 단위 **631/631**, 디자인 검사, 후보 빌드와 관련 Chrome 검사 **20/20회** 통과다. 위키 검색/위키 작성/업무 지식/계획 모드/첨부 검색/문맥의 6개 스위트를 새 프로필로 각각 3회, CSP와 채팅을 1회 검사했다. 전체 브라우저 매트릭스가 아닌 관련 범위 검사다. 생산 의존성 audit은 취약점 0개다. [최종 후보 보고서](../verification/pre-release-2026-09-24T09-50-56-655Z/report.json)에 원본 로그와 ZIP 해시를 보존한다. 합성 사례가 실제 모델 판단 정확도나 사내 업무 성공률을 뜻하지 않는다.

9,029자 합성 문서 100개로 같은 Mac에서 한 번 측정했다. 전체 검색 → 집중 읽기 → 재검색은 기존 691/6/565ms, 변경 후 810/1/41ms였다. 첫 구조 파싱 비용은 남으며, 결과는 이 표본의 Node 실행 시간이다. 브라우저 지연 분포나 일반 성능 보장이 아니다. 원본은 `verification/wiki-followup-2026-09-24/baseline-timing.json`과 `final-timing.json`에 있다.

원본/변경과 실패 로그는 `verification/wiki-followup-2026-09-24/`에 보존한다. 실제 Qwen 3.8 27B/사내 계정 답변 정확도, 동의어, 문서 간 의미 관계와 대규모 첫 검색 최적화는 아직 검증하지 않았다. 후보 ZIP만 생성하고 기존 릴리즈를 교체하거나 업로드하지 않는다.
