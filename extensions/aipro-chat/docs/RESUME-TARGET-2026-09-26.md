# 재개 작업의 탭 연결

NQ-47. 중단된 작업의 연결 정보가 사라졌을 때 START_CHAT이 현재 활성 탭을 pageTarget으로 선택할 수 있었다. 브라우저 재시작 후 세션 저장소가 비워진 경우에도 원래 탭을 읽는다는 보장이 없었다. 미확정 쓰기 차단은 있었지만 다른 페이지를 조회 대상으로 잡는 문제는 별개다.

## 적용

- 이전 브라우저 관찰/동작, 저장한 페이지 또는 미확정 입력 영수증이 있는 작업은 기존 실행에 연결된 탭이나 사용자가 명시적으로 연결한 페이지를 요구한다.
- 연결이 없으면 모델 호출/새 요청 생성 전에 `resume_page_required`로 멈추고 페이지 연결을 안내한다. 원래 목표/계획/입력 영수증/대화를 그대로 보존한다.
- 같은 실행의 재개용 주소 힌트는 새 요청 준비 시 관찰 결과가 없다는 이유로 지우지 않는다. 주소 자체를 동일 문서/승인/쓰기 완료의 근거로 사용하지 않는다.
- 사용자 연결 후 기존 새 관찰→미확정 입력 비교→검증 경로를 유지한다. 자동 입력 재전송이나 취소 후 자동 재개는 추가하지 않는다.
- 문서/Wiki/MCP 조회만 한 작업은 브라우저 작업과 구분한다. 예전 제외 목록에 없던 ask_documents/ask_openwiki도 무관한 페이지 관찰을 유발하지 않는다.

## 재현과 검증

`resume-target-browser.mjs`는 실제 Chrome에서 이전 브라우저 작업의 체크포인트를 남기고 탭 연결이 없는 상태에서 다른 활성 페이지를 연다. 기존 후보는 재개를 허용해 `verification/resume-target-before.log`에서 실패했다. 수정 후보는 이를 거부하고 기록을 보존하며, 실제 CONNECT_PAGE 뒤 같은 목표와 영수증을 가진 요청을 준비한다. 두 입력란은 빈 값을 유지한다. 모델 호출 없이 START_CHAT과 실제 DOM 연결을 검증한 합성 인증 시험이다.

단위 검사는 브라우저/문서/Wiki/MCP 분류, 사라진 대상 거부와 원래 조건 보존을 다룬다. 기존 실제 worker 종료/Chrome 재시작 검사, 재개 후 새 관찰과 중복 쓰기 차단 회귀를 유지한다.

전체 worker 문맥/메모리 실행기 복원, 실계정 네이버 완주, 실제 서버 저장 성공은 이번 구현의 범위가 아니다. 대상 탭 확인은 곧 실행 완료가 아니다.

## 최종 결과

- `npm run verify:quality`의 **quality-baseline-v8 통과**. 단위 **987개**, 디자인 검사, 후보 빌드, 실제 Chrome 핵심 회귀 **107회**로 110단계 모두 통과했다. 반복 대상 29종은 각 3회, 재시작/진단 등을 포함한 20종은 각 1회다.
- 보고서: `verification/pre-release-2026-09-26T12-59-59-198Z/report.json`. 전체 배포 매트릭스가 아니라 고정 핵심 baseline이다.
- 검사 종료 후 소스/테스트/공유 입력, dist와 ZIP 해시를 다시 대조해 모두 일치했다. `quality:status`도 현재 소스의 핵심 검증으로 인정한다 (`verification/resume-target-quality-status.txt`).
- 후보 ZIP SHA-256: `e55d29289ddfcef32520a2542c6c5337d078d1ba3ae0e45b612ead14f3533a9f`.
- 실제 Chrome 연결, worker 종료와 브라우저 재시작을 검증했지만 모델 응답/인증은 합성이다. 실계정 네이버 완주율이나 실제 서버 저장 성공으로 계산하지 않는다. 릴리즈 ZIP 교체/외부 업로드/배포는 하지 않았다.

## 남은 순서

1. 선택한 실제 모델로 네이버 과제의 첫 계획 완료와 최종 요구사항 충족을 다시 측정한다.
2. 전체 worker 문맥 복원은 별도 설계/구현이 필요하다. 현재는 목표/계획/체크포인트와 미확정 입력을 보존하며 실행 메모리나 이전 DOM 핸들을 복원하지 않는다.
3. 회사망 Qwen, 서버 저장 영수증, Windows/Edge 실계정, 공식 WebArena 독립 평가의 외부 조건은 기존 목록에 유지한다.
