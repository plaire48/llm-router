# 0.16.7 초안 작성과 최종 반영 승인

요청한 글은 페이지 구조에 맞춰 작성하고 입력한 뒤 검증한다. 등록이나 배포 같은 최종 작업은 준비된 초안을 보여주고 채팅에서 승인을 받는다. 사용자가 같은 작성 요청을 반복할 필요가 없도록 시스템 지침과 도구 계약을 맞췄다.

- 승인 카드에는 실제 페이지에서 읽은 초안 미리보기, 연필, 최종 작업 버튼과 취소를 둔다. 자세한 내용은 접어 두고 기존 CX 컴포넌트와 폰트 크기를 사용한다.
- 연필은 실제 입력란 전체 값을 다시 읽어 편집한다. 제목 등 단일 입력은 한 줄로, 본문은 넓은 편집란으로 표시한다. 변경한 값만 새 사용자 요청으로 전달하고 누비가 페이지에 반영한 뒤 다시 검증하고 승인받는다. 잘린 미리보기로 원문을 덮어쓰지 않는다. 기존 채팅 입력 초안은 유지한다.
- 승인 도구는 완료된 초안의 `verify_page` 통과를 요구한다. 인식한 등록, 게시, 배포, 발송, 삭제, 결제, 최종 저장 컨트롤과 제출 키의 일반 동작에도 같은 가드를 적용한다. 시각 도구가 제공되면 화면 좌표로도 명시적인 최종 승인을 요청할 수 있다.
- 승인 대기에서 모델과 후속 도구 실행을 멈추고 자동화 연결을 종료한다. 채팅 새로고침 후에도 대기 상태를 복원한다. 취소에는 모델 호출이 없으며 페이지 초안은 유지된다.
- 실행 권한은 대화, 질문, 계정, 탭, 문서, 실제 DOM 노드, 입력 내용 해시와 10분 만료에 묶는다. 수정 요청은 기존 권한을 폐기한다. 승인한 실행은 먼저 권한을 소비하고 한 번만 시도한다. 결과가 불확실하면 자동 재실행하지 않고 현재 화면을 확인한다.
- 등록 이후에는 별도의 페이지 검증과 요구사항 검토를 거쳐 완료를 알린다. 승인을 눌렀다는 사실이나 클릭 성공을 등록 완료로 표시하지 않는다.

## 검증

- 단위 테스트 235개 통과. 최종 컨트롤 분류, 질문 식별과 중복 답변 거부, 승인 대기에서 후속 도구와 완료 검토 중지를 포함한다.
- `approval-browser` 11개 통과. 실제 Chromium 확장에서 초안 작성과 검증, 승인 대기, 새로고침 복원, 서로 다른 대화/질문/계정의 승인 거부, 단일 trusted 클릭, 취소, 검증 전 클릭 거부, 자연어 수정, 연필 편집과 재승인, 본문/iframe/버튼/문서/만료 변경 검사, 스크립트 우회 차단, 좌표 승인과 대상 이동 거부를 확인했다.
- 기존 `browser-agent-browser` 16개 통과. 기본 읽기, 새 탭, iframe과 Shadow DOM 입력, 일반 좌표 클릭, 스크립트 복구, 취소와 재진입을 확인했다.
- 기존 `script-recovery-browser` 6개 통과. 실패 원인 표시와 허용된 기본 도구를 통한 복구를 확인했다.
- `npm run design:check`와 `npm run build` 통과. 좁은 패널과 넓은 창의 승인 카드, 편집 모달을 확인했다. 기존 Vite 청크 크기 안내는 유지된다.

모델 응답과 업무 사이트는 합성 fixture이며 브라우저 입력은 실제 Chromium/Playwright로 실행했다. 실제 회사 사이트와 AI Pro/FabriX/ChatGPT 계정의 추론 성공을 검증한 결과는 아니다. 자동 감지는 DOM의 의미와 알려진 키에 의존한다. 임의 사이트의 숨은 부작용이나 자동 저장 전체를 차단하는 보안 장벽은 아니며, 일반 화면 작업과 구분하기 어려운 사용자 정의 컨트롤에는 모델의 명시적 승인 요청이 필요하다. 페이지 변동 이후에는 새 관찰과 새 승인을 요구한다. 테스트 hook과 확대 권한은 임시 설치본에만 추가했다.
