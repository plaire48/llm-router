# 하위 에이전트 진행과 결과 취합

## 흐름

독립 과제 분리 → 담당별 대기/분석 → 먼저 끝난 결과 전달 → 메인 취합/검증 → 완료 기록 접기.

- 기존 Pi 0.86.1 실행기를 유지한다. 독립된 자료 조사, 화면과 문서 비교, 요구사항별 검토, 실패 진단을 한 번에 배정하도록 계획/실행 지침을 보강했다. 간단한 조회나 앞 단계 결과에 의존하는 입력은 나누지 않는다.
- p-limit 7.3.3(MIT)의 FIFO 대기열로 최대 6개 미완료 과제를 접수하고 2개씩 실행한다. 공급자 부하를 무제한 늘리지 않으며 먼저 끝난 슬롯에 다음 과제를 자동 배정한다. 전체 사용자 업무의 과제 수를 6개로 제한하는 것이 아니다.
- 기존 `prepareNextTurn`에서 준비된 결과만 메인에 전달한다. 다음 판단에 필요할 때만 기다리고, 느린 담당 때문에 다른 완료 결과를 묶어 기다리지 않는다.
- 각 담당은 지정 근거와 작은 브리프만 받는다. 페이지 조작/질문/승인/최종 검증은 메인 실행기에 남는다. 다른 제공자와의 자동 분산이나 여러 브라우저 쓰기 실행기를 추가하지 않았다.

## 표시

진행 상황 안의 Subagents에 역할, 과제, 실제 실행 상태와 전달 여부를 모은다. 완료 결과는 기존 안전한 Markdown 렌더러로 표시한다. 대기 상태는 실행 중 스피너와 구분한다. 완료된 그룹은 기본으로 접고 다시 펼칠 수 있다. 사용자가 펼쳐 읽는 중에는 강제로 닫지 않는다.

하위 작업이 종료돼도 보고가 partial/blocked라면 일부 확인/확인 필요로 표시한다. 실패/취소를 완료 수에 포함하지 않는다. 메인 최종 검토가 완료된 경우에만 바깥 기록에 ‘메인 에이전트 완료’를 표시한다. 한 담당의 실패를 메인 최종 검토로 성공으로 바꾸지 않는다.

상태는 실행 이벤트에서 발생하며 시간 경과로 가짜 진행률을 만들지 않는다. 저장은 정리된 과제 제목과 최대 600자의 공개 결과 요약만 추가한다. 원문 대화나 비공개 추론/토큰은 표시 계약에 넣지 않는다. 새로고침은 저장된 기록을 복원하며 실행을 다시 시작하지 않는다. 실행 중 담당은 최근 32개 기록 제한으로 숨기지 않는다.

## 방법론과 선택

- [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system): 독립 과제, 명확한 목표/근거/완료 조건, 소규모 문맥과 비동기 결과 전달을 적용했다. 병렬화의 이점과 토큰 비용을 함께 고려한다.
- [OpenAI Agents SDK orchestration](https://openai.github.io/openai-agents-js/guides/multi-agent/): 메인 에이전트가 제어를 유지하며 전문 담당을 도구처럼 호출하는 방식을 참고했다. 이미 제공자 전송과 취소/승인을 통합한 Pi를 사용하므로 SDK를 중복 도입하지 않았다.
- [p-limit](https://github.com/sindresorhus/p-limit): 브라우저 번들 가능한 동시성 제한/대기열/취소를 재사용한다. p-limit와 간접 의존성 yocto-queue의 MIT 라이선스를 ZIP에 포함한다.

## 검증 범위

단위 테스트는 동시 실행, FIFO 슬롯 재사용, 6개 과제, 대기 취소, 전체 중지, 결과의 조기 전달, 실패 격리, 부분 결과 및 trace 정리를 확인한다. Chrome 통합 검사는 합성 Qwen 응답으로 실제 격리 분석/주 실행기 연결, 좁은/넓은 화면, 안전한 Markdown, 키보드 펼침, 새로고침과 모션 감소를 확인한다.

실제 Qwen의 분업 판단 정확도와 사내 API에서의 지연/총 토큰 개선은 이 합성 검사로 증명되지 않는다. 실제 모델 평가는 동일 목표/근거의 단일 실행과 병렬 실행을 비교하고, 정답 근거/완료 여부/첫 유효 결과까지 시간/전체 시간/총 토큰/중복 조회를 함께 측정해야 한다.
