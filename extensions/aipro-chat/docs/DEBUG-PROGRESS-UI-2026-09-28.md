# 계획 변경과 디버그 화면

사용자 요청에 따라 기본 화면은 현재 계획, 완료 수, 진행과 실패, 답변과 승인을 유지한다. 세부 실행 진단을 숨겨도 완료 판단과 복구 경로는 바꾸지 않는다. 일반 화면의 진행 상황에는 현재 작업, 오류/대기, 부분 실패와 결과 캡처만 남긴다. 완료한 도구 목록과 전체 펼치기는 디버그 모드로 제한한다. 완료 도구만 있으면 기록 껍데기도 숨기며 최종 답변과 계획 완료 수는 그대로 유지한다.

## 반영

- 계획 변경은 새 계획에 바로 반영한다. 변경 요약은 추가 `+`, 제외 `−`, 기준 수정 연필과 개수로 표시한다. 이유와 이전/새 항목은 눌러 펼친다. 접근성 이름과 title에 의미를 유지한다.
- 설정의 `디버그 모드`는 기본 꺼짐이다. 켰을 때만 실행 진단, 전체 진행 기록과 전체 계획 변경 이력을 표시한다.
- 설정은 Chrome local 저장소에 boolean으로 보존한다. 제공자 연결이나 실행 권한은 변경하지 않는다. 실행 중 긴 도구 호출과 독립적으로 표시 설정을 바꿀 수 있다.
- 꺼져 있을 때 기록 컴포넌트 자체를 만들지 않아 화면의 조회 요청도 발생하지 않는다. 기존 제한된 진단 저장 및 소유 실행 조회 계약은 유지한다.

## 방법론 선택

[OpenCode TUI의 details](https://opencode.ai/docs/tui/#details)는 도구 실행 상세 표시를 별도로 전환한다. 이를 참고해 실제 작업 진행과 상세 진단 표시를 분리했다. OpenCode 코드나 UI 패키지를 복사하지 않았다. 기존 React details와 CX Icon/CxCheckbox를 활용해 의존성을 추가하지 않았다.

[Anthropic 문맥 관리](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)의 필요한 정보만 단계적으로 노출하는 방법론을 화면에도 적용했다. 이는 화면 가독성 설계 근거이며 모델 품질 개선의 실측 증거는 아니다.

기존 HTML의 Noto Sans KR, 본문 14px, 블루와 배경 및 모션 토큰을 유지한다. 완료 수는 실제 저장된 계획에서 계산하며 화면을 3/3으로 강제 변경하지 않는다.

## 검증 범위

`tests/debug-plan-ui-browser.mjs`는 격리된 실제 Chrome에 합성 대화를 저장하여 기본 숨김, 조회 없음, 켜기와 끄기, 설정 재열기, 페이지 새로고침, 브라우저 재시작, 오류/질문 보존과 360/1100px 화면을 검사한다. 실모델 작업 성능 검사가 아니다. 기존 계획 완료/진단/저널 검사는 디버그 모드를 명시적으로 켜도록 갱신했다.

임시 UI 후보에서 전용 Chrome 시나리오 6개 통과, 관련 단위 22개 통과, 디자인 검사 및 Vite 빌드 통과. 스크린샷과 결과는 `verification/debug-plan-ui/`에 보존했다. 통합 후보의 전체 `verify:identity`는 별도 실행한다.
