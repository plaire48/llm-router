# 가독성과 의미 전달 기준 적용

브라우저 누비의 기존 HTML 아이덴티티를 유지하면서 안내의 핵심 구절과 상세를 구분했다. 글자를 줄이기보다 판단에 필요한 의미를 보존하는 것이 우선이다.

## 실제 반영

- `DeckGuidance`로 아이콘, 핵심 문장, 필요한 상세의 공통 구성을 만들었다. 기존 CX의 공개 Icon과 공통 토큰을 사용하며 별도 의존성은 추가하지 않았다.
- 본문은 Noto Sans KR 14/22px를 유지한다. 핵심 문장은 잉크색/400, 중요한 구절만 진한 블루/600, 상세는 읽을 수 있는 보조색/400이다.
- 녹화의 입력값 미저장, 예약의 Chrome 실행 조건, 위키의 승인 없는 갱신을 구체적으로 강조했다. 같은 사이트/최상위 화면 범위, 제출 승인, 업무 규칙 보존은 상세로 유지했다.
- 반복되는 예약 복구 안내를 실행 조건에 합쳤다. 세 조건을 목록으로 구분하고 320px 화면의 들여쓰기와 가로 넘침을 검사했다.
- 의미 전달을 돕는 목록/시계/갱신 아이콘을 재사용했다. 장식 이미지를 늘리거나 중요한 조건을 아이콘으로 대체하지 않았다. 장식 아이콘은 접근성 트리에서 중복 안내하지 않는다.
- DESIGN-SYSTEM.md, AGENTS.md와 [시각 기준](VISUAL-STANDARD.md)에 같은 원칙을 연결했다. 기존 자동 모달 검사에 핵심/상세의 색상, 굵기, 아이콘 중복 안내 검사를 추가했다.

## 선택 근거

[W3C 작성 지침](https://www.w3.org/WAI/tips/writing/)의 간결하고 이해하기 쉬운 내용과 [디자인 지침](https://www.w3.org/WAI/tips/designing/)의 대비, 색 이외의 의미 표시, 여백으로 내용을 구분하는 방법을 적용했다. 설치된 CX 0.5.4와 기존 Nubi 토큰으로 충족하므로 새 라이브러리나 원격 폰트를 도입하지 않았다. 문장의 의미 적합성과 강조 위치는 계산 스타일 검사와 별도로 실제 캡처에서 검토했다.

## 작업 계획 유지

브라우저 작업은 `agent-runtime.js`에서 실제 도구를 실행하기 전에 계획을 준비한다. `task-plan.js`의 계획 지침은 보통 2~5개 결과 중심 단계와 확인할 결과를 요구하며, `TaskPlan.jsx`가 채팅에 표시한다. 일반 대화와 명확화 질문은 이 계획을 시작하지 않는다. 계획과 최종 결과 검토는 이번 가독성 수정에서 변경하지 않았다.

## 검증

최종 `npm run verify:identity` 26단계 통과: 단위 787개, 디자인 검사, 후보 빌드와 실제 Chrome 검사 23종. 320px 실행 조건/위키와 360px 예약/녹화 캡처를 직접 검토했다. 검증 이후 소스/테스트/의존성 및 빌드 해시 일치도 재확인했다. 첫 검사 후 발견한 미정의 간격 토큰을 공통 16px 토큰으로 수정하고 전체 gate를 다시 실행했다.
