## 현재 추가 개발과 검증

NQ-43은 [재방문 거짓 진전과 반복 읽기 복구](READ-LOOP-RECOVERY-2026-09-26.md)다. 새 문서 ID를 새 정보로 세는 결함을 재현해 수정하고 반복 조회에 기존 복구 워커를 연결했다.

NQ-41/NQ-42는 [여러 출처의 후속 분석과 진단 보존](MULTISOURCE-DIAGNOSTICS-2026-09-26.md)으로 이어진다. 두 출처 이후 자동 위임 차단을 해소하고 원문 없는 검토/종료 기록을 재시작 뒤에도 조회한다. 실제 모델 완주율과 구분한다.

[2026-09-26 앱 재검증](APP-RETEST-2026-09-26.md)에서 추가 지시가 섞인 대기열 정렬 오류를 재현해 수정하고 폼 답변의 원문/질문 연결 검사를 보완했다. NQ-36에 추적한다. 아래 수치는 각 과거 후보의 이력이며 현재 소스 판정은 `quality:status`를 따른다.

[폼 사용성 점검](FORM-USABILITY-2026-09-25.md)에서 질문의 자동 높이/더 보기, 입력 안내, 녹화/예약 초안 분리와 입력별 오류, 스킬/Wiki 편집 보존을 반영했다. 최종 후보의 단위 853개와 Chrome 화면 30종, 공통 폼 DOM 31개가 통과했으며 검증 후 소스 해시가 일치했다. 릴리즈와 실모델 평가는 별도다.

후속 UI 작업은 [아이덴티티와 가독성 점검](IDENTITY-READABILITY-2026-09-25.md)에 기록했다. 일반 강조, Wiki 상태 크기, 아이콘 조작과 코드 포함 모달 검사를 보완했다. 단위 853개와 화면 26종을 동일 후보로 검증했고 현재 작업 폴더의 입력 해시도 일치한다. 이 UI gate를 전체 핵심 회귀나 배포 완료로 계산하지 않는다.

beta34 이후 하네스에서 이미지 여러 장 전달, 미해결 보고서의 완료 판정, 압축 후 조사 상태 보존, 진행 화면의 미해결 내용 표시를 보완했다. [공개 소스 비교·반영·검증](BROWSER-AGENT-BENCHMARK-FOLLOWUP-2026-09-25.md)에 정리했다. **고정 후보는 단위 853개, 핵심 Chrome 77회, 화면 26종과 이미지 전송 검사를 통과했다.** 원본 작업 폴더의 공통 질문 화면과 해당 테스트에는 별도 작업이 계속되고 있어 원본 전체를 검증 완료로 표시하지 않는다. `quality:status`의 현재 소스 판정을 따른다. 이번 변경의 배포는 아직 하지 않았다.

### beta34에서 완료한 기준과 이력

대형 첨부 분업, 역할별 진행 표시, 전체 이력과 최종 근거 검토를 구현했으며 같은 후보의 전체 Chrome 228회와 단위 836개가 통과했다. 중앙 목록은 **25개: 구현 16개, 외부 조건 대기 4개, 비채택 5개**다. 신규 NQ-18/NQ-19를 포함한 구현 항목은 동일 후보의 연결 검사로 확인했다. 실제 모델 정확도와 외부 조건은 완료로 표시하지 않는다. [순서별 문제·개선·검증 목록](MULTIAGENT-IMPLEMENTATION-2026-09-25.md)에 관리한다. 아래 기존 핵심 검증은 변경 전 이력이며 새 후보를 인증하지 않는다. 최종 근거는 [배포 검증](RELEASE-BETA34.md)과 [현재 작업표](verification/beta34-quality-work.md)에 기록한다.

현재 소스의 상태는 `npm run quality:status`로 다시 판정한다. 2026-09-26 현재 `browser-verification-plan.mjs`의 `quality-baseline-v5` 범위는 **25종 × 3회 + 12종 = Chrome 87회**, 단위/디자인/후보 빌드를 포함해 **90단계**다. 위 77회는 과거 후보의 이력이다. full 보고서도 같은 입력, 필수 기준, 모든 추가 단계의 정상 종료, 고유 단계와 선택 목록 일치, fullMatrix를 확인해야 인정한다. 서로 다른 보고서를 합산하지 않는다.

## 외부 조건과 보류 후보

기존 보류 개발 NQ-14(Pi 0.87.1 전환)는 이미 구현됐다. 외부 조건은 로컬 코드 재작성으로 검증 완료를 대신할 수 없다. 사용자에게 대표 업무/사이트가 없다는 답변도 유지한다.

- **NQ-02**: 회사망의 평가 전용 인증을 연결하고 8개 정답 과제를 각각 3회 실행해 실제 Qwen 결과를 채점
- **NQ-04**: 대표 사이트와 저장/등록 완료를 판정할 서버 영수증 계약 확보 후 검증
- **NQ-07**: Windows/Edge 환경과 각 제공자 실계정으로 로그인/모델 선택/설치 업데이트 검증
- **NQ-08**: 공식 WebArena Docker 환경과 평가 인증을 연결하고 독립 grader 실행

D01~D05는 미뤄둔 제품 기능이 아니라 대안 기술의 비채택 결정이다. 기존 실행/대화/스킬/계측이 담당하는 경계를 교체할 근거가 없으므로 유지했다. 새 요구나 재현 결함이 생기면 다시 검토한다. 파일 전송/알림 API/녹화/예약/조직 정책의 기존 구현을 다시 미구현으로 표시하지 않는다. 실제 OS 배너와 기업 배포는 별도다.

## 이전 검증과 현재 판정

[최종 요약](../verification/quality-ledger-2026-09-25/report.json), [동일 후보 원본](../verification/pre-release-2026-09-25T02-25-07-810Z/report.json): **단위 787/787, Chrome 71/71**. `quality-baseline-v4`, 21종 × 3회 + 8종, 디자인/후보 빌드 통과. 소스/검사/의존성/빌드 해시 불변. 연결한 단계 로그 모두 확인. 알려진 의존성 취약점 0건.

`npm run quality:status`는 현재 소스와 일치하는 단일 v6 핵심 보고서 또는 그 기준을 전부 포함한 정상 종료 full 보고서를 선택한다. 이전 v4 통과는 현재 소스를 인증하지 않는다. `npm run quality:report`는 작업표를 출력한다. JSON은 `npm run quality:status -- --json`으로 확인한다. 완료 표시만 있거나 일부 검사만 통과한 보고서를 합산하지 않는다. 각 항목에 연결한 검사는 핵심 회귀이며 모든 상세 기능이나 실제 모델의 의미 정확도를 입증하지 않는다.

직전 변경은 품질 판정/작업표 도구였으며 이번에는 검사 범위를 넓혔다. 제품 실행기와 새 의존성은 변경하지 않았다. 실제 모델 평가, 전체 배포 매트릭스, 공개 업로드/설치는 수행하지 않았다.

## 2026-09-26 첫 계획과 액션 보완
