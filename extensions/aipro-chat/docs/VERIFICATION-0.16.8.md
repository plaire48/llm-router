# 0.16.8 새 창에서 작업 이어가기

새 창에서 승인 대기 후 다시 시작하면 부모 창 정보가 사라져, 자식 창을 닫은 뒤 `browser_stale`로 멈추는 문제를 재현했다. 작업 창과 관찰한 부모 관계를 대화와 계정에 묶어 브라우저 세션에 보관하도록 수정했다.

- 새 탭과 별도 팝업에서 같은 작업을 이어가며, 창을 전환할 때 해당 창도 활성화한다. 빈 문서에서 늦게 이동하거나 기존 named 창을 다시 여는 경로를 유지한다.
- 채팅을 새로고침하거나 다른 탭을 연결한 뒤에도 연필 편집과 승인은 원래 초안의 창을 사용한다. 질문에 답하거나 중단한 작업을 재개할 때도 원래 목표와 작업 창을 복원한다.
- 작업 도중 자식 창이 닫히면 알려진 부모로 돌아가 다시 관찰한다. 중첩 팝업의 중간 창이 닫혔다면 남아 있는 상위 창을 찾는다. 임의의 활성 탭으로 바꾸지 않는다.
- 최종 승인은 원래 탭, 문서, DOM 노드와 초안 내용에 계속 묶는다. 닫힌 창의 승인을 다른 창에서 실행하거나 불확실한 클릭을 자동 재전송하지 않는다. 창이 닫혀 클릭 응답이 끊긴 경우는 결과를 확인한 뒤 이어간다.
- 저장하는 연결 정보는 탭 ID와 부모 관계뿐이다. DOM 참조는 다시 만들고 승인 대상은 다시 검증한다. 기존 취소, 디버거 연결 종료와 회사 인증 경계를 유지한다.

## 검증

- 단위 테스트 237개 통과. 승인 링크의 새 창 탐지와 질문 응답 후 작업 창 복원을 추가했다.
- `browser-popups-browser` 8개: 지연된 빈 팝업, 별도 창 목록, named 창 재사용, 연결 종료 후 부모 복귀, 지연된 새 탭, 연속 입력, 중첩 창의 상위 창 복귀, 팝업 대기 중 취소.
- `popup-approval-browser` 7개: 실제 확장 UI에서 별도 팝업과 `noopener` 탭 각각의 초안 작성, 승인 대기, 새로고침, 다른 탭 연결, 연필 수정, 재검증, 단일 승인 실행, 창 닫힘과 원래 페이지의 결과 검증. 도구 호출 사이에 창을 닫아도 `page_changed`로 멈추지 않는 경로도 확인했다.
- 기존 `approval-browser` 11개와 `browser-agent-browser` 16개 통과. 문서/초안 변경 거부, 중복 승인 차단, 취소와 프레임 입력을 포함한다.
- `npm run design:check`, `npm run build` 통과. 설치 ZIP과 SHA-256을 생성했다.

브라우저 조작은 실제 Chromium/Playwright에서 수행했고 업무 사이트와 모델 응답은 합성 fixture다. 실제 사내 사이트와 AI Pro/FabriX/ChatGPT 계정의 추론은 별도 확인이 필요하다. 브라우저가 차단한 팝업이나 여러 창 중 업무 대상을 구분할 근거가 없는 경우까지 자동 선택 성공을 보증하지 않는다. 기존 권한 범위를 유지하며 테스트 권한은 임시 설치본에만 부여했다.
