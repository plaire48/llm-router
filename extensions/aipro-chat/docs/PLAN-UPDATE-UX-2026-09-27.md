# 계획이 바뀌었을 때 이해할 수 있는 진행 화면

## 문제와 적용

기존 `update_plan`은 현재 배열을 덮어썼다. 이유와 이전 계획이 남지 않았고, 목록을 접으면 진행 중인 단계도 숨겨졌다. 화면 색상만 바꾸어서는 사용자가 변경을 이해할 수 없다.

1. 계획 목록이 접혀도 현재 작업을 한 줄로 표시한다. 펼쳐져 있을 때는 강조된 현재 단계를 사용해 같은 문장을 반복하지 않는다.
2. 단계 이름/구성/순서/완료 기준이 바뀌면 `계획 수정`과 변경 요약을 표시한다. 모델이 제공한 공개 사유는 한 문장으로 보인다. 세부 추가/제외와 완료 기준의 전후 차이는 펼친다.
3. 동일한 단계의 완료/진행 전환은 계획 수정과 구분한다. 추가된 단계에는 접근성 이름을 가진 작은 `+` 아이콘을 사용한다. 변경 감지를 위해 텍스트가 완전히 다른 단계를 같은 항목이라고 추정하지 않는다.
4. 저장이 끝난 실제 갱신만 버전/사유/이전/이후 계획으로 남긴다. 동일 계획 재전송은 기록하지 않는다. 최근 8회만 보관하고 이전 기록이 생략되면 표시한다.
5. 답변별 진행 상태에 기록을 붙여 다음 대화, 이력, 새로고침과 중단 후 재개에도 보존한다. 계획 수정 사유가 없으면 추측하지 않고 펼친 상세에서 미제공 상태를 알린다. 표시용 사유가 없다는 이유로 실제 업무를 중단하거나 승인 폼을 추가하지 않는다.
6. 기존 단계 검토, 미확정 쓰기 차단과 최종 요구사항 검토를 유지한다. 계획의 체크 표시 자체는 실제 업무 완료 증거가 아니다. 사용자가 접은 목록을 갱신마다 강제로 열거나 스크롤을 이동시키지 않는다.

## 검증 경계

단위 검사로 상태 전환과 구성 변경 구분, 중복 억제, 보관 한도, 직렬화, 사유 토큰 마스킹, 최종 검토 전 완료 차단을 확인한다. 실제 Chrome의 합성 모델 시험에서는 사유/추가/제외 표시, 접힌 상태 유지, 320/360px 폭, 새로고침과 이력 복원을 확인한다. 이는 실제 모델이 매번 정확한 사유를 생성하거나 실제 사이트 업무를 완주한다는 증거가 아니다.

## 과정의 연결과 가독성

사용자가 보는 현재 단계와 AI의 `Current user-visible task plan`은 같은 저장 계획을 사용한다. 단계의 `expected_outcome`을 상세의 완료 기준에 그대로 표시하며, 기준이 없으면 미정으로 알린다. 화면 설명을 AI에게 다시 입력하거나 별도 모델 호출로 진행 상황을 생성하지 않는다.

`단계 상세`는 현재 단계에 연결된 실제 최근 도구 이벤트와 다음 예정 단계를 보여준다. 도구 성공은 `도구 실행 완료`로 표시한다. 최종 업무 완료와 혼동하지 않으며, 질문/승인/중단 상태에서도 다음 항목은 실행 약속이 아닌 다음 계획이다. 기존 실행 기록의 캡처와 하위 작업 상세는 유지한다.

변경 사유를 추가/제외 상세보다 먼저 읽도록 배치했다. `+`/`−` 아이콘은 접근성 이름과 툴팁을 유지하고, 핵심 제목만 강조한다. 브랜드 블루와 본문/보조색을 사용하며 색만으로 구분하지 않는다. 모바일 폭에서는 단계 상세와 이력을 접어 정보량을 조절한다. 전체 런타임이나 추가 상태 관리 라이브러리보다 기존 React/CX와 실제 이벤트를 재사용하는 편이 저장/표시 불일치와 의존성 비용을 줄인다.

## 선택한 표현 방식

| 후보 | 판단 | 이유 |
| --- | --- | --- |
| 매 호출마다 긴 설명 생성 | 미채택 | 추가 지연과 반복 문장이 생기며 실제 실행 상태와 어긋날 수 있음 |
| 아이콘과 진행률만 표시 | 단독 사용하지 않음 | 무엇을 확인하고 왜 계획이 바뀌었는지 전달할 수 없음 |
| 실제 상태의 짧은 요약 + 펼칠 수 있는 근거 | 적용 | 현재 단계는 즉시 읽고 기준/실행/다음 단계는 필요할 때 확인 가능 |
| 계획 체크를 업무 성공으로 취급 | 미채택 | 단계 검증과 최종 요구사항 검토를 통과해야 업무 완료로 표시해야 함 |

이번 변경은 계획 이해도와 상태 일관성 개선이다. 실모델 업무 성공률 향상은 이 화면 검사만으로 주장하지 않는다. 변경 사유의 사실성, 완료 기준의 구체성, 반복 행동 감소와 최종 정답률은 실제 모델 평가에서 별도로 측정해야 한다.
