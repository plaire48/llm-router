## 공통 완료 계약

원래 요청의 조건을 줄이지 않고, 비어 있지 않은 계획 전체 완료 → 저장 readback → 최종 요구사항 검토 → 화면에 답변 표시 → 실제 결과 독립 대조를 통과해야 한다. 표시만 3/3으로 채우지 않는다. 질문/승인 대기는 정당한 사용자 입력 대기와 불필요한 중단으로 구분한다. 재시도나 작업 수 증가 자체는 진전이 아니다.

수정마다 재현 → 원인 확정 → 최소 수정 → 실패 회귀와 기존 성공 회귀 → 같은 후보 실제 평가 → 채택/보류 순서로 기록한다. 30개 최초 평가에서 실패한 회차를 지우지 않고 후속 후보의 재시험을 별도로 남긴다. 시간 한도 변경은 속도 개선으로 계산하지 않는다.

보고 수치는 실행 x/30, 독립 판정 x/30, 확인 통과 x/30, 잘못된 완료, 중복 쓰기, 불필요한 사용자 개입, 모델 호출/활성 시간, 사용자 대기다. 24/30은 파일럿 목표이며 일반 서비스 전체의 80% 보장은 아니다.

## 방법론과 오픈소스 활용

[Anthropic 결과 중심 평가](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)의 실행 기록과 실제 결과 구분, 능력 평가와 회귀 평가 분리를 적용한다. 판정 기준 자체가 틀리면 결과를 왜곡하므로 H-10처럼 조건과 근거가 다른 항목부터 검토한다.

[Anthropic 문맥 관리](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), 기존에 확인한 OpenCode MIT compaction과 Codex Apache-2.0 compact 소스를 활용해 원래 조건, 최근 결과, 인용 원문을 구분한다. 실제 코드 위치와 고정 커밋은 [30개 완주 재검증](FULL30-COMPLETION-2026-09-27.md)에 연결했다.

다운로드한 Claude 확장은 오류 반환과 권한 대기/실행 분리의 참고 근거다. 공개 라이선스가 확인되지 않은 실행 코드를 복사하지 않는다. Aside MIT 평가 소스도 전체 성공과 부분 조건 점수를 구분하는 근거로만 사용한다. [기존 분석](ASIDE-BENCHMARK-2026-09-27.md)을 재사용한다.

Pi, Playwright CRX, Readability/Turndown, MiniSearch, LangChain은 이미 있으므로 유지한다. 현 단계에서 검증되지 않은 검색 엔진/하네스 전면 교체나 워커 수 증가는 채택하지 않는다. 모델 능력과 하네스 연결 실패를 구분하려면 먼저 현재 사용자 선택 Luna의 동일 조건 실행을 확보해야 한다.
