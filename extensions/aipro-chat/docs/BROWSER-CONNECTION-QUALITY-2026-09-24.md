# 브라우저 누비 연결과 복구 재검증

2026-09-24. [앞선 확대 검사](BROWSER-QUALITY-BROAD-RECHECK-2026-09-24.md) 다음으로 로그인 수신, 제공자 전환, 저장 상태, 분석/스크립트 복구와 위키 연결 유지 경로를 확인했다.

## 재현한 문제와 수정

| 문제 | 반영 |
| --- | --- |
| 외부 OpenWiki의 401/403을 JSON 파싱보다 나중에 판정해, HTML이나 빈 응답이면 `project_invalid`로 오분류 | HTTP 401은 `project_expired`, 403은 `project_scope`로 본문과 독립적으로 판정한다. 읽지 않을 응답 스트림을 취소하고 본문 완료를 기다리지 않는다. |
| `ask_openwiki`의 스냅샷 경로는 401 후에도 연결이 connected 상태로 남음 | 기존 소스/위키 조회와 새 에이전트 스냅샷 경로의 오류 처리를 `projectReadFailure`로 통합했다. 현재 연결을 거부 상태로 저장해 같은 만료 연결에 대한 후속 네트워크 조회와 다음 요청의 도구 노출을 차단한다. |
| 취소 신호가 이미 설정되었거나 늦게 응답한 대체 fetch에서 성공 응답이 반환될 수 있음 | 요청 전과 응답 후 신호를 검사하고 사용자 취소를 `cancelled`로 보존한다. 12초 네트워크 제한과 사용자 취소를 구분한다. 실제 브라우저 fetch 외에 호스트가 공급하는 fetch에도 같은 계약을 적용한다. |
| 과거 연결의 실패가 새 연결 상태를 덮어쓸 가능성 | 거부 상태 저장 전에 현재 connectionId와 토큰이 해당 실패의 연결과 일치하는지 검사한다. 인증값을 모델/로그로 전달하지 않는다. |

수정 전 오류 주입 검사 4개가 실패했고, 수정 후에는 통과했다. 이후 이전 연결/새 연결 교체 검사 1개를 추가했다. 403은 연결 만료로 바꾸지 않는다. 서버가 거부한 자료를 페이지 HTML이나 다른 위키로 대체하지 않으며 자동 재로그인/페어링/재전송을 추가하지 않는다.

내장 위키, 선택한 폴더와 선택적 로컬 서버의 위키는 기존 모델 위임 구조를 유지한다. 변경은 외부 로컬 서버의 참조 조회와 공통 오류 처리에 한정한다. 서버의 자료 조회는 LLM 실행기가 아니며 현재 누비 모델은 기존 확장 실행기가 호출한다.

## 방법론과 오픈소스 판단

| 검토 대상 | 선택과 비선택 근거 |
| --- | --- |
| [HTTP RFC 9110의 401/403](https://www.rfc-editor.org/rfc/rfc9110.html#name-401-unauthorized), [Fetch 취소](https://fetch.spec.whatwg.org/#abort-fetch) | **표준 동작 적용**. 인증 거부 상태와 응답 본문 형식, 사용자 취소를 구분한다. 기존 `fetch`, `AbortSignal.any`, 응답 크기 제한을 재사용한다. |
| [Ky](https://github.com/sindresorhus/ky), MIT. [실제 Ky.ts](https://raw.githubusercontent.com/sindresorhus/ky/main/source/core/Ky.ts) | **방법론 참고, 패키지 미도입**. 사용자 취소를 네트워크 오류로 오인하지 않도록 분리하고 사용하지 않는 응답 본문을 취소하는 구현을 확인했다. 현재 요청은 고정 localhost 경로, 별도 인증, 엄격한 본문 크기 제한과 일회성 페어링 계약을 이미 갖추므로 HTTP 계층 전체 교체보다 필요한 동작을 보완했다. Ky 소스 복사나 새 런타임 의존성 추가는 없다. |
| [p-retry](https://github.com/sindresorhus/p-retry), 설치된 8.0.1, MIT | **기존 추론 복구 유지**. 설치 소스의 AbortError/shouldRetry 구분과 `model-recovery.js`의 401/403/취소 제외를 확인했다. 권한이 사라진 위키 조회는 반복 요청으로 복구되지 않으므로 참조 요청에 재시도 라이브러리를 추가하지 않았다. |
| [Playwright Chrome 확장 검사](https://playwright.dev/docs/chrome-extensions), 기존 1.62.1, Apache-2.0 | **실제 재사용**. 새로운 임시 프로필로 로그인/전환/복구 시나리오를 반복하고 HTTP 오류를 주입한다. 기존 실제 OpenWiki HTTP 핸들러 검사에 401/403 오류 구간과 재진입/재연결 검증을 추가했다. |
| [Chrome 서비스 워커 수명](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle) | **기존 설계 재확인**. 연결 상태는 session 저장소, 폴더 핸들은 기존 IndexedDB에 보관한다. 응답을 받았다는 이유만으로 철회된 연결을 복원하지 않는다. 새 장기 실행 프로세스나 영구적인 워커 유지 장치를 추가하지 않았다. |

기존 오픈소스 의존성을 재사용했으며 이번 문제를 해결하기 위해 패키지 버전을 올리거나 검색 엔진을 교체할 근거는 없었다. 버전 변경과 실서비스 성공을 개선의 대리 지표로 삼지 않는다.

## 검증

- 관련 단위 검사 `project-tools`/`login-lifecycle`: **86개 통과**. 정상 조회, 만료, JSON/HTML 오류, 대기 중인 본문 취소, 늦은 응답, 새 연결 보호를 포함한다.
- 최종 후보의 **단위 686개, 디자인 검사, 빌드와 브라우저 21회 모두 통과**했다. 로그인 수신 두 종류, 제공자 전환, 상태 동기화, 분석 복구, 스크립트 복구를 각각 3회, OpenWiki 에이전트/서버 연결/폴더 유지 검사를 각각 1회 실행했다. [원본 보고서](../verification/pre-release-2026-09-24T13-24-54-087Z/report.json), [통합 기록](../verification/browser-connection-quality-2026-09-24/report.json)
- 실제 확장의 401/403 처리, UI 새로고침 후 만료 유지, 만료 연결의 중복 조회 차단, 다음 요청의 도구 제거, 명시적 재연결 성공을 확인했다. 검사 전/후 소스 및 dist 해시 일치도 통과했다. 앞선 다른 빌드의 검사 횟수를 이번 후보 결과에 합산하지 않았다.
- 운영 의존성 `npm audit --omit=dev`는 검사 시점 알려진 취약점 **0건**이다. [npm audit 원본](../verification/browser-connection-quality-2026-09-24/npm-audit.json)을 보존한다. 전체 보안 감사나 알려지지 않은 취약점이 없다는 보장은 아니다.

실제 Chrome과 로컬 HTTP 서버를 사용하지만 모델 응답과 로그인 제공자는 합성이다. 사내 SSO, 실제 모델 정확도, 사용자 OS의 폴더 선택창은 이번 검증으로 입증하지 않는다. 전체 브라우저 매트릭스와 배포/설치/업로드는 수행하지 않는다.
