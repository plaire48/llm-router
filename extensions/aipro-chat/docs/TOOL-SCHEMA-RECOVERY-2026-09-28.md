# 반복 검증 호출의 형식 오류 복구

## 실측 원인

beta.36 후보 `b131cdd87611bf2b8fa1db3b1fa49d1fbda9ff1d83247d4b0a1d19e521c009ed`의 [E01 실행](../verification/naver-sso-luna-2026-09-27T20-35-49-034Z.json)은 286,688ms와 모델 호출 68회 뒤 최종 답변 없이 사용자 대기로 종료했다. 계획은 0/2이며 독립 평가 실패다.

`verify_page` 7회는 모두 실행 전 `tool_arguments_invalid`로 거절됐다. 공통 원인은 최상위 객체의 `additionalProperties`이고 실제 `verificationChecks`는 비어 있었다. 원래 잘못된 속성명은 진단에 저장하지 않았으므로 특정 속성 때문이라고 추정하지 않는다. 검색 입력과 페이지 이동은 실제 실행됐다. 이를 모든 브라우저 행동 실패로 해석하지 않는다.

실패 사이의 정상 `read_page`/`browser_snapshot`가 전역 오류 횟수를 0으로 돌려놓았다. 인자 값이나 확인 문구가 바뀌면 기존 결과 지문도 달라졌다. 그 결과 같은 형식 오류가 반복돼도 전용 복구 경계가 작동하지 않았다. 기존 오류 응답은 허용 속성이나 필수 속성을 알려주지 않아 다음 호출을 고치기 어려웠다.

## 변경

1. 기존 TypeBox 스키마 검증 결과에 선언된 객체 속성과 필수 속성 안내를 추가한다. 모델이 보낸 임의 키, 입력값, 원문 오류 메시지는 노출하지 않는다. 중첩 객체와 선택 분기를 구분하고 안내 크기를 제한한다. 잘못된 키를 자동 삭제하거나 검증을 우회하지 않는다.
2. 실행별 형식 오류 횟수를 도구와 스키마 오류 위치/종류에 연결한다. 다른 도구가 성공해도 초기화하지 않는다. 같은 도구의 유효한 인자 실행이나 새 사용자 입력만 해당 오류 상태를 해소한다. 실제 페이지 검증 결과는 별도로 유지한다.
3. 3회 교정에 실패하면 보존된 작업의 기술적 재시도/중지를 묻는다. 사용자 요구가 불명확하다고 오인해 다시 설명하도록 요청하거나 완료 처리하지 않는다.

## 선택 근거

[Anthropic의 도구 설계 방법론](https://www.anthropic.com/engineering/writing-tools-for-agents)은 입력 검증 오류에 구체적으로 교정할 수 있는 피드백을 제공하도록 권한다. 기존 [Claude 실제 배포 확장 분석](CLAUDE-HARNESS-STATIC-2026-09-26.md)의 도구 오류를 다음 모델 판단에 반환하는 방식과 일치한다. 공개 배포 Claude 코드를 복사하지 않고 기존 Pi 실행기와 MIT TypeBox를 확장한다. 추가 SDK 도입은 이 오류를 해결하지 않아 채택하지 않았다.

## 검증 범위

실패 사이에 서로 다른 성공 조회를 끼워 넣어도 같은 인자 오류가 3회에서 중단되는지, 유효한 인자를 받은 같은 도구만 오류 횟수를 해소하는지, 미실행 호출은 호스트에 도달하지 않는지 확인한다. 기술적 오류를 새로운 요구사항 질문으로 바꾸지 않는 것도 확인한다.

beta.36 평가는 고정한 빌드로 계속한다. 이 수정은 다음 후보에만 포함하며, 해당 후보의 E01 실측에서 최종 답변과 원문 정확성까지 확인하기 전에는 완주 문제 해결로 표시하지 않는다. 관찰 문맥량과 검토의 순위 조건 추가도 남은 진단 대상이다.

## 후보와 남은 문제

- 수정 후보: `1.0.0-beta.37`, Chrome `1.4.40`. 단위 1,308/1,308, 디자인/빌드와 선택 Chrome 44/44 통과했다. [고정 후보 보고서](../verification/pre-release-2026-09-27T20-44-27-841Z/report.json). 후보 SHA-256은 `6a851d87f52e569e56864062ce879902514f38b87c0127983f41c25c23d5834f`다.
- 직접 회귀: 실행기 33/33, 스키마 교정 12/12 통과. 전체 단위 검사와 실제 모델 성능은 별도다.
- beta.36 E04는 `page_content_pdf_unavailable/pdf_http_error` 뒤 계획 교정 대기로 종료했다. 네트워크 다운로드 복구와 선택 출처의 HTML 조건 추가는 이 형식 오류 수정으로 해결됐다고 표시하지 않는다.
- beta.36 후반 실행과 beta.37 로컬 검증이 일부 겹친다. 해당 실행 시간은 관찰값으로만 기록하고 단독 실행 성능 개선의 증거로 사용하지 않는다.
