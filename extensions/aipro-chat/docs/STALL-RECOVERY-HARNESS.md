# 진행 정체의 감지와 복구

## 확인한 결함과 수정

모델 전송에는 p-retry와 무진행/시도별 제한이 있었지만, 문서와 OpenWiki 읽기는 반환되지 않는 Promise가 공용 작업 대기열을 계속 점유할 수 있었다. 또한 하위 모델/조회 구현이 AbortSignal을 무시하면 cancel_analysis가 그 작업의 종료를 기다렸다. OpenWiki의 잘못된 응답 스트림에서는 reader.cancel() 자체를 기다리는 경로도 있었다.

- 순수 문서/프로젝트 읽기는 45초 안에 반환되지 않으면 `read_timeout`을 결과로 전달한다. 완료된 다른 결과는 보존하고 모델이 범위/검색어/자료를 바꾸어 다음 작업을 선택한다. 시간 초과를 성공이나 내용 부재로 해석하지 않는다.
- 사용자 중지는 직렬 큐 밖에서 해당 요청의 읽기를 취소한다. 취소를 무시하는 구현의 늦은 결과는 현재 작업의 근거/완료 상태에 반영하지 않는다.
- 하위 에이전트도 취소 시 종료 대기를 해제한다. 수집과 대기 슬롯을 반환하며, 늦은 모델 응답은 사용량/보고/완료 이벤트 처리 전에 차단한다.
- OpenWiki HTTP 조회에는 외부 취소 신호를 전달하고, 오류 스트림의 cancel 완료를 무한히 기다리지 않는다.
- 브라우저 클릭/입력/발송과 승인된 MCP 호출에는 이 읽기 제한을 적용하지 않는다. 시간 초과만으로 미실행을 가정해 쓰기를 재전송하지 않는다.

## 하네스 복구 기준

| 정체 유형 | 감지 | 복구 |
| --- | --- | --- |
| 모델 응답 없음 | 기존 실제 delta 기준 무진행 120초, 시도당 5분 | p-retry로 최대 3회 재시도. Retry-After 공유. 소진 시 상태를 남기고 중단 |
| 문서/프로젝트 조회가 끝나지 않음 | 신규 순수 읽기 완료 제한 45초 | 실패 결과를 Pi에 전달. 성공 근거 보존, 더 작은 범위나 다른 자료로 수정 |
| 같은 실패/결과 반복 | 기존 의미 기반 결과 비교 | 중간 검토로 접근 변경. 반복이 계속되면 필요한 정보만 질문 |
| 하위 담당이 중지에 응답하지 않음 | 신규 취소와 실행 Promise 경쟁 | 담당을 취소로 종료하고 늦은 결과 무시. 다른 담당 결과 유지 |
| 컨텍스트 초과 | 기존 입력 예산/실제 overflow | 원문/출처/미완료 범위를 보존한 요약과 제한된 재호출 |
| 쓰기 결과 불명확 | 기존 발행/수신 기록 | 재관찰 후 검증. 완료된 클릭이나 입력의 재전송 금지 |
| 질문/승인 대기 | 실제 대기 상태 | 자동 재개하지 않고 사용자 답변으로 진행 |
| worker/브라우저 종료 | 기존 lease/체크포인트 | 실행 상태 일시 중지. 새 실행에서 상태 확인 후 이어가기 |

재시도 횟수나 상태 표시 이벤트를 실제 진척으로 취급하지 않는다. 이 변경은 문서 읽기 병목을 해소하며, 모든 브라우저/스토리지/네이티브 장애를 복구한다는 보증은 아니다. UI 스레드나 worker의 동기 코드 자체가 멈추면 같은 이벤트 루프의 타이머도 실행될 수 없다. 파일 API처럼 취소를 지원하지 않는 연산은 대기만 해제하며 실제 내부 작업의 중단까지 보증하지 않는다.

## 공식 방법론과 오픈소스 선택

- [Anthropic: Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents): 작은 작업 단위, 진행 기록, 다음 실행을 위한 명확한 상태, 실제 결과 검증을 참고했다. 브라우저 작업에서는 Git 되돌리기를 쓰기 복구로 적용하지 않는다.
- [OpenAI Agents SDK: Running agents](https://openai.github.io/openai-agents-js/guides/running-agents/): 모델 오류와 도구 시간 초과를 구분하고 상태를 보존해 복구하는 원리를 반영했다. 기존 Pi에 SDK를 중복 추가하지 않았다.
- [p-timeout 공식 문서](https://github.com/sindresorhus/p-timeout): 문서가 권장하는 AbortSignal 기반 취소와 Promise 대기 해제를 조합했다. Chrome 125 대상의 네이티브 기능으로 가능하므로 새 의존성을 추가하지 않았다.
- 기존 Pi 0.86.1은 오류 결과를 다음 모델 판단에 전달하고, p-retry 8.0.1은 모델 통신 복구, p-limit 7.3.3은 하위 담당 동시 실행 수를 관리한다. 역할을 분리해 중첩 재시도 폭주를 피한다.

## 검증

`read-deadline.test.mjs`에서 반환되지 않는 조회, 무시된 취소, 늦은 응답, 다른 요청의 격리, 미완료 문서 구간 보존, 하위 모델 중지, 취소가 끝나지 않는 스트림을 검사한다.

`document-retrieval-browser.mjs`는 실제 Chrome 확장의 읽기를 고의로 끝나지 않게 만든다. 격리된 테스트 사본의 45초 제한만 1초로 줄이고, 오류를 받은 합성 Qwen이 다른 범위를 읽어 완료하는지 확인한다. 중지 후 추가 모델 호출/늦은 결과 반영이 없는지도 검사한다. 실계정 모델의 복구 판단 정확도와 실제 사내 OpenWiki 장애는 별도 검증 대상이다.
