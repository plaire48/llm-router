# Qwen 도구 작업 중 요청 거절 복구

사용자 증상: AI Pro의 `qwen3.8-27b_CLI`로 도구를 사용하던 중 “모델 ID 또는 요청 형식을 확인하세요.”가 표시되며 중단됐다. 실제 요청용 이름은 모델 목록의 `name`을 그대로 사용한다.

## 확인한 원인

출력 한도에 도달하면 `output-recovery.js`가 기존 system 메시지 앞에 별도의 system 메시지를 넣었다. [Qwen3.8 공식 템플릿](https://huggingface.co/Qwen/Qwen3.8-27B/blob/1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0/chat_template.jinja)은 첫 위치 이외의 system 메시지를 거절한다. 도구 호출 후 이어서 생성하는 요청으로 공식 템플릿을 실행해 `System message must be at the beginning.` 예외를 재현했다.

이것은 확인된 클라이언트 결함이다. 사용자 환경의 서버 오류 본문은 아직 받지 않았으므로 모든 실서비스 실패가 이 원인이라고 단정하지 않는다. 기존 구현은 HTTP 400/404/422를 같은 `invalid_model`로 표시해 원인을 구분할 수 없었다.

## 수정

- 복구 지침을 기존 첫 system 내용에 합친다. 원래 지침, 도구 호출/결과 쌍과 수행한 작업은 유지한다.
- 대화/도구 형식, 모델 거절, 이미지 입력, 컨텍스트 초과, 요청 주소와 기타 요청 거절을 구분한다.
- 명시적인 `stream_options` 거절에만 해당 선택 필드를 빼고 모델 요청을 한 번 다시 보낸다. 다른 모델로 임의 변경하거나 도구를 재실행하지 않는다. 각 요청은 usage 집계의 별도 라운드다.
- 거절 응답은 최대 64 KiB까지 읽고 고정 원인만 진단으로 남긴다. 서버 원문, 토큰, 프롬프트와 도구 인자는 진단에 저장하지 않는다. 진단 실패가 모델 호출을 막지 않는다.
- 출력이 계속 잘리더라도 사용자가 질문을 나눌 필요 없이 다음 작은 단계를 생성한다. 진행 없는 출력 오류, 인증/권한 거절이나 모르는 요청 오류는 무작정 재전송하지 않는다.

Qwen 공식 [Function Calling 문서](https://docs.qwencloud.com/developer-guides/tool-calling/function-calling)의 도구 결과를 문맥에 추가해 다음 요청으로 이어가는 계약을 기준으로 검증했다. 새 오픈소스 의존성 없이 기존 Pi와 출력 복구기를 수정했다.

## 검증 범위

공식 템플릿 전후 실행 기록, Qwen 형식의 도구 후속 요청 계약 검사, 출력 한도/422 이후 브라우저 작성 회귀를 사용한다. 새 Chrome 프로필에서 핵심 회귀를 세 번 반복하며 긴 본문의 각 절이 한 번만 입력되는지, 저장 상태 검증과 재진입이 유지되는지 확인한다.

최종 검사 기록은 `docs/evidence/beta-1.0.0-qwen-request/`에 보관한다. 실제 AI Pro 계정과 Qwen 추론 정확도는 합성 모델 응답을 사용하는 Chrome 검사와 별도이며 이번 환경에서는 실계정 검증을 하지 않았다.

추가 요청인 다중 제공자/역할별 병렬 실행은 [별도 설계안](PARALLEL-AGENT-DESIGN.md)에 정리했다. 이 오류 수정 배포에는 병렬 하위 에이전트가 포함되지 않는다.
