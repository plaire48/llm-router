## 실행 범위

일반 첨부와 Wiki는 같은 읽기 전용 조사 코어를 사용하지만 원문 종류와 소유권을 구분한다. 첨부 원문 스냅샷은 호스트와 조사 코어 사이에서만 사용하고 부모 모델에는 결과와 선택한 인용 근거를 돌려준다. 하위 분석 도구는 원문 읽기/검색만 사용하며 재귀 위임이나 브라우저 쓰기를 허용하지 않는다. 최종 브라우저 반영과 결과 확인은 주 실행기가 담당한다.

PDF/DOCX는 추출 텍스트를 조사한다. 그림, 서식과 OCR 지원으로 표현하지 않는다. 로컬 입력은 파일 8 MiB, 추출 400만 자/12 MiB, PDF 2,000쪽 한도가 있으며 이미지 입력은 기존 4 MiB 한도를 유지한다. 모델에 한 번에 넣는 첨부 본문은 최대 6,000자다. 큰 파일을 읽는 도구가 없는 연결에서는 목록만 보고 답하는 경로를 거부한다.

`ask_documents`는 브라우저 첨부용이다. Desktop의 기존 `analyze_documents` 계약과 구분해 공유 하네스의 기존 동작을 보존한다. 단위/합성 모델/실제 Chrome 성공은 실계정 모델의 분업 정확도나 비용 절감을 입증하지 않는다.

방법론과 라이선스 선택은 [멀티에이전트 진행 근거](MULTIAGENT-PROGRESS-2026-09-25.md)에 기록한다. 신규 실행기를 추가하지 않고 기존 Pi, DeepAgents, LangChain, MiniSearch와 idb를 재사용한다.

## 화면 검증

동일 후보의 단위 836개, 디자인 검사와 `verify:identity`의 Chrome 26개 시나리오가 통과했다. [화면 게이트](verification/beta34-identity.json). 대형 문서 검사는 고정 모델 응답으로 34개 조사 워커/동시 2개, 합성 13회, 최종 검토 1회, 저널 373건/8페이지를 확인했다. 실제 모델 답변 정확도는 미측정이다. 이후 같은 후보의 전체 Chrome 228회와 단위 836개가 통과했다. [전체 게이트](verification/beta34-browser.json).
