# 누비 1.4.0 스크립트 사전 검사와 복구

2026-09-22. 논의 후 남아 있던 브라우저 작업 품질 개선 중 사전 검사와 실패별 복구를 구현했다. 실제 모델의 자율 성공률과 절차 재사용은 별도 과제로 남긴다.

## 반영한 동작

- 실행 전 Acorn으로 문법, 정적으로 식별한 미지원 API, 직접 호출의 명백한 await 누락을 검사한다. 페이지 쓰기와 디버거 연결 전에 멈추고 오류 줄 위치와 현재 화면 관찰을 모델에 반환한다.
- 사전 검사에 실패한 경우에는 명령 0회임을 명시한다. 실행 중 실패한 경우에는 기존 명령별 기록과 현재 화면을 제공해 앞서 반영한 입력을 반복하지 않고 남은 동작을 수정한다.
- 대상 없음, 다중 일치, 다른 요소에 가림, 비활성, 숨김, 입력 불가와 노드 변경을 구분한다. 필요한 탭/프레임 확인, 가림 요소 처리, 필수 입력 확인 등 사유에 맞는 안내를 제공한다.
- 지연 생성/활성화되는 입력란은 정상적으로 기다린다. 숨김 노드에 대한 기존 보호와 최종 등록/발송 승인도 유지한다. 가림 요소와 비활성 상태를 force로 우회하지 않는다.
- 화면에는 기존 CX 작업 기록의 짧은 오류 이름과 검증 후 복구 상태를 사용한다. 별도 설정이나 상시 안내 문구는 추가하지 않는다.

대기와 동작 가능 여부 판정은 [Playwright actionability](https://playwright.dev/docs/actionability)를 기준으로 기존 실행기의 자동 대기를 유지한다. 새 분류는 예외 뒤 현재 대상의 존재/상태와 실행기 피드백을 확인한다. Acorn은 로컬 번들이며 MIT 라이선스를 설치본에 포함한다.

## 이전 버전 비교

같은 스크립트 `입력란 채우기 → 미지원 page.evaluate 호출`을 1.3.0 설치본의 샌드박스와 새 실행기로 비교했다. 1.3.0은 앞선 명령 1개가 실행된 뒤 실패했고, 1.4.0은 명령 0개에서 사전 검사를 반환했다. 이 비교는 실행기 동작 검사이며 모델의 코드 작성 성능 점수가 아니다.

## 검증 상태

단위 테스트 **285개**, CX 디자인 검사와 빌드가 통과했다. 변경 범위의 Chrome 스위트 **14개를 34회 실행**했다. 핵심 업무/관찰/코드 실행/새 창/승인/사전 검사/복구/하네스/AI Pro 로그인/ChatGPT 로그인 10개는 새 프로필로 각각 3회 검사했다. 디버거 수명, 승인, FabriX와 사이드 패널 4개는 각각 1회 검사했다. [최종 기록](evidence/1.4.0-report.json).

- 사전 검사 실패 때 쓰기/디버거 연결 0회, 오류 줄 위치와 현재 DOM 관찰.
- 일부 입력 후 대상 누락, 가림 요소와 비활성/읽기 전용 입력란 구분, 정상 지연 로딩 대기.
- 이미 작성한 값의 중복 입력 없이 수정한 스크립트 실행, 실제 값과 저장 상태 검증.
- 중복 이름, iframe/shadow DOM, 재렌더링, 여러 창/탭, 최종 승인과 수정, 실패 후 복구 표시 및 새로고침 유지.
- 하네스의 잘못된 완료 선언 차단, AI Pro/ChatGPT 합성 로그인에서 debugger 0회, FabriX 도구 변환과 사이드 패널.

전체 제품 전수 검사와 실제 계정 검증으로 확대 해석하지 않는다. [이전 버전 비교](evidence/1.4.0-preflight-before-after.json), [사전 검사/복구 실행 기록](evidence/1.4.0-script-preflight-browser.json), [오류 복구 UI 기록](evidence/1.4.0-script-recovery-browser.json).

## 확인 범위

실제 Chrome 확장을 합성 사이트에서 실행한다. 모델과 인증 응답은 테스트용으로 구성하며 실제 AI Pro/ChatGPT/FabriX 계정, 회사 사이트, Windows/Edge와 실제 모델의 자율 판단은 검증하지 않았다. 사이트 권한은 테스트 복사본에 미리 부여한다.

사전 검사는 보수적인 정적 분석이다. 동적으로 만든 메서드 이름, 가변 객체와 모든 JavaScript 제어 흐름의 성공을 보증하지 않는다. 실제 동작은 기존 격리 VM과 호스트 검사를 통과해야 한다. 스크립트 전체를 자동 재실행하지 않고 결과를 재관찰하며, 완료 판단은 실제 페이지의 입력값/저장 상태 검사와 요구사항 검토를 거친다.

일반 조작의 디버거 사용 자체를 없앤 변경은 아니다. 사전 검사 실패와 콘텐츠 스크립트의 DOM 조회에는 새 디버거 연결이 없고, 실제 Playwright 조작에는 기존 연결이 필요하다. 외부 게시나 웹 스토어 등록은 하지 않았다.
