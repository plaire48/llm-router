# Current-session context and clarification — beta30

Recorded execution evidence is selected from the active conversation. Reviewed site wiki remains separately reusable by origin/provider. Creator requests now receive up to 12 complete, sanitized current-session user statements under a 6,000-character text budget, with omitted count and chronology. They do not import other chats, assistant claims or attachment bodies. The active request still carries one-use approvals separately.

General execution, skill creation and wiki creation share the question policy: inspect available conversation/answers and relevant evidence first, prioritize latest user corrections, then ask one blocking question with 2–4 grounded choices and free text. If choices cannot be grounded, use a short text question instead. Reading instructions cannot guarantee that a live model always asks the best question.

Wiki creator retrieval is bound to its selected source URL, not an unrelated later task page. Existing Pi, MiniSearch and React/CX question UI are reused; no new runtime dependency is introduced. See [clarification flow and primary references](CLARIFICATION-FLOW.md).

Validation after the automatic wiki update: 585 unit tests, design check and candidate build passed. Six actual-Chrome suites ran three times each: wiki creation, workflow skill creation, clarification, question forms, document retrieval and conversations. These use synthetic model responses. The complete pre-release matrix and live-model evaluation were not rerun. The beta30 ZIP is a local candidate; the published beta29 release remains unchanged.


Opt-in saved-site-wiki observation refresh now runs only after verified task completion. No extra model writer, automatic new-document creation or per-update HITL is used. Authored Markdown and its original review date are preserved; changed/stale prose is excluded from retrieval while fresh structured observations remain queryable. Source revision/version checks and one-version undo prevent silent overwrites and permit recovery. MiniSearch is retained; no new dependency or extension permission was added. See BROWSER-SITE-WIKI.md.
