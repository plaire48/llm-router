# 누비가 완주하지 못하는 이유

후속 변경: [조사 근거와 단계 완료 연결](RESEARCH-COMPLETION-2026-09-26.md)에 자동 본문 확보, 단계/최종 평가 범위 분리, 위임 오류의 실제 근거 ID 피드백과 별도 검증 결과를 기록했다. 아래 표는 변경 전 실제 실패 기록이며 새 후보의 실모델 성공으로 갱신하지 않는다.

2026-09-26. 이번 판단은 Luna/ChatGPT SSO 실제 Naver v2 1번 과제 네 번, 모델 호출 없는 평가 준비 실패 한 번, 별도 실제 Chrome 재현과 Pi 회귀를 구분한다. 앞선 두 실측은 사용자 질문으로 멈췄고 세 번째는 계획 생성 실패로 행동 전에 끝났다. 최종 후보는 계속 행동했지만 첫 단계가 끝나지 않아 평가기의 8분 제한으로 중지했다. 모두 최종 답변이 없었다. Claude보다 정확하다거나 이번 후보가 실서비스를 완주한다고 판정하지 않는다.

실제 첫 시험의 접근 오류는 정확한 호스트 코드가 보존되지 않았다. 두 번째 시험은 browser_stale 1회와 verification_failed 2회만 확인됐고 page_permission 오류는 없었다. 동일한 오류를 두 시험의 원인으로 단정하지 않는다. HTTP 헤더 도착 시간은 전체 모델 생성 시간과 다르며, 종료 이벤트가 수집되지 않아 전체 모델 응답 지연은 미측정이다.

[세 번째 실측](../verification/naver-sso-luna-2026-09-26T07-13-15-152Z.json)은 18,974ms 후 plan_failed였다. 로그인 완료와 실제 모델 HTTP 응답을 확인했지만, 전체 실행의 인증 확인 플래그는 false이므로 인증 검증 완료 상태로 바꾸지 않는다. 이번 시험은 앞선 두 경로의 복구 성공/실패를 평가할 브라우저 단계까지 도달하지 못했다.

그 뒤 계획 복구를 처음 배포한 평가 준비는 워커 의존성 누락으로 시작하지 못했다. 모델 호출 0회인 setup_error이며 모델 성능 시험으로 합산하지 않는다. 파서를 번들 경로로 분리한 뒤 실제 Chrome 시작/RPC와 배포된 정적 ESM 87개를 확인했다. 이 수정 과정은 Node/빌드 성공과 실제 앱 시작을 분리해야 하는 이유이기도 하다.

[최종 후보 실측](../verification/naver-sso-luna-2026-09-26T07-34-09-964Z.json)은 모델 요청/HTTP 200 각각 55회, 오류 0회, 481.863초 후 평가 제한으로 중지했다. 앱 자체 오류와 질문은 없었다. 계획 0/3 완료, 답변 없음이며 정확도는 미측정이다. verify_page 4회 통과/1회 실패와 독립 검토 5회 완료는 실제 작업 완료가 아니다. 조건부 자동 recovery가 실제 시작됐다는 근거도 없다. 읽기/위임/검토의 연결을 더 강화해야 하며 단순히 워커 수나 시간 제한을 늘리는 것은 이 기록으로 정당화되지 않는다.

같은 최종 후보의 [core gate](../verification/pre-release-2026-09-26T07-33-05-839Z/report.json)는 단위 941개, 디자인, 후보 빌드와 Chrome 100회를 포함한 103개 단계 전부 통과했다. 입력 해시도 현재 소스와 일치하고 NQ-37은 current_core_passed다. 실측과 같은 후보 ZIP 해시를 대조했다. 이 로컬 회귀 통과를 실제 완주 성공으로 바꾸지 않는다.

필요한 실행 계약은 원래 요구사항 → 근거가 필요한 단계 → 한 행동 → 실제 결과 → 단계 검토 → 구체적인 보완 → 최종 요구사항 검토다. revise는 추가 작업, blocked는 실제 사용자 정보/권한/선택 대기다. 하위 에이전트 보고는 조언이며 주 실행기의 완료 근거가 아니다. 미확정 쓰기는 실제 영수증/문서에 연결한 검증 없이 재전송하지 않는다.

독립적인 읽기/문서 분할/원문 대조는 병렬 워커에 맡기고, 같은 탭의 이동/입력/검증은 한 주 실행기가 순차 처리한다. 워커를 늘리는 것만으로 순차 브라우저 행동이나 잘못된 완료 조건이 해결되지는 않는다. 기존 Pi/p-limit/Readability/MiniSearch/OpenWiki 분할 조회를 활용하며 새 CLI 의존성은 추가하지 않는다.

남은 검증은 순서대로 진행한다. 첫째, 최신 동일 후보의 전체 Chrome 회귀와 실제 선택 모델의 첫 단계/최종 결과를 따로 확인한다. 둘째, 요청에 이미 허용된 미확인 보고를 다시 허락받거나 페이지에서 읽을 사실을 사용자에게 묻는지 실제 질문 이유와 연결한다. 셋째, 이번에 변경하지 않은 최종 검토의 no-progress 분기와 긴 조사에서의 출처 범위를 확인한다. 넷째, 전체 모델 응답 종료와 독립 사실 채점을 수집한 뒤에만 지연/정확도 지표를 산출한다. 계획 복구나 워커 실행 자체를 성공률로 계산하지 않는다.
