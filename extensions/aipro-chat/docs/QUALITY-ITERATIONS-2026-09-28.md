구현 분모는 `quality-work.json`의 기존 선택 항목 **51개**다. 전체 56개 중 비선택 5개는 제외한다. 현재 구현 46개, 외부 검증 5개로 **46/51 = 90.2%**다. 최근 수정으로 같은 항목을 여러 번 완료 처리하거나 성공률처럼 표시하지 않는다. 범위를 추가하면 변경 전후 분모와 이유를 기록한다.

현재 소스의 전체 핵심 품질 기준을 충족한 보고서는 확인되지 않았다. 선택한 44종 통과를 기존 전체 핵심 회귀 통과로 대체하지 않는다. 실제 품질 개선 완료율은 정답 검증 전 확정하지 않는다.

## 최근 7개 개선의 검증 완료율

전체 구현 목록과 별도로 이번 실패/화면 개선 묶음의 완료 조건을 고정한다. 화면 항목은 실제 Chrome의 표시/설정 지속성을, 에이전트 항목은 수정 후보의 실제 모델 결과를 요구한다. 종류가 다른 검증을 하나의 모델 품질 점수로 해석하지 않는다.

| ID | 개선 | 최종 완료 조건 | 현재 상태 |
| --- | --- | --- | --- |
| R1 | 계획 변경 아이콘 | 추가/제외/수정과 현재 완료 수가 좁은 화면에서도 구분됨 | Chrome 검증 완료 |
| R2 | 디버그 설정 | 기본 숨김, 활성화/해제, 재열기와 재시작 지속성, 질문/오류 보존 | Chrome 검증 완료 |
| R3 | PDF 본문 읽기 | 실제 과제에서 원문과 읽은 범위를 정확히 인용하고 답변 전달 | 코드/회귀 완료, 새 후보 실모델 대기 |

beta.37의 같은 빌드에서 UI 재검증까지 마친 기준 **검증 완료 2/7 = 28.6%**다. R7은 전체 결과 기준으로 별도 유지하며 세부 기능 성공으로 자동 완료하지 않는다. beta.36의 실제 모델 과제로 나머지를 판정한다. 요구 밖의 OCR/인증 PDF/양식 편집과 외부 환경은 이 7개 분모에 임의 추가하지 않는다. 추가 범위는 별도 기록한다.

beta.36은 직전 품질 개선 소스를 새 버전으로 고정한 후보다. 버전 번호를 올린 것 자체를 추가 품질 개선으로 계산하지 않는다. 실제 배포 승인을 뜻하지 않는다.

최근 변경은 기존 항목에 연결했다. PDF 텍스트와 그림/범례 읽기, 실제 전달한 이미지의 최종 검토 연결, 검토 오류와 계획 오류 분리, 검색 입력의 사실/허용 판정 분리, 오래된 DOM 문맥 절감, 계획 변경 아이콘, 디버그 설정이다. 세부 근거는 각 항목의 `latestRevision.reference`와 [개선 기록](BROWSER-REPAIR-AND-UX-2026-09-28.md)을 따른다.

## 반복 절차

1. 실패 원인, 변경, 남은 제한을 기록한다. 소스 변경 뒤에는 후보 버전과 ZIP SHA-256을 고정한다.
2. 같은 후보의 단위/디자인/빌드와 영향받는 Chrome 회귀를 통과시킨다.
3. GPT-5.6 Luna와 ChatGPT SSO로 E01/E03/E04/E07/E08을 같은 순서로 실행한다. 과제당 600초, 최대 모델 호출 120회, 무활동 180초를 유지한다.
4. 실행 중에는 종료 수/5와 현재 단계를 표시한다. 계획 3/3만으로 성공 처리하지 않는다. 원문 비교와 사용자에게 전달된 결과를 독립 채점한다.
5. 같은 후보의 결과로만 비율을 계산한다. 새 후보에 옛 점수를 물려주거나 성공한 과제만 골라 합치지 않는다. 실패를 반영해 다음 후보를 만든다.
6. 집중 5개는 실패 회귀 집합이다. 이후 쉬운 10개 전체와 최종 30개 중 24개 이상이라는 별도 목표를 검증한다. 5개 결과를 전체 30개 성능으로 일반화하지 않는다.

[Anthropic 결과 중심 평가](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)의 실행 흔적과 실제 결과 구분을 기존 평가기에 적용한다. 별도 평가 프레임워크를 추가하지 않고 기존 `quality-status.mjs`, 고정 후보 실행기와 `score-browser-30.mjs`를 재사용한다.
