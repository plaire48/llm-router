# 0.13.3 FabriX 도구 응답 복구

검증일: 2026-09-21

## 원인과 변경

누비의 기존 fabrix_tool_protocol은 FabriX HTTP 응답을 받은 뒤 텍스트를 OpenAI tool_calls로 변환하는 단계에서 발생한다. 정상 JSON 전체를 감싼 Markdown 코드 블록도 거부했고, 형식 오류를 재요청하는 경로가 없었다. OpenWiki 사내 어댑터에는 해당 복구가 이미 반영되어 있었지만 확장에는 없었다. 기존 OpenWiki의 기본 오류 매핑은 로컬 형식 오류를 502로 노출할 수 있었으며, 누비 자체는 그 로컬 오류에 HTTP 502를 붙이지 않는다.

이전 코드에 회귀 테스트를 적용해 7개 중 6개 실패를 확인했다. 실제 사용자 응답 원문을 확보한 것은 아니므로 사용자 환경에서 어떤 형식이 실패했는지는 새 진단으로 구분한다.

- 전체 JSON 코드 블록만 정규화한다. 설명/추론 중간이나 여러 객체에서 실행할 JSON을 추출하지 않는다.
- 작업 결과의 문서 형식과 전송용 JSON 형식을 구분해 지시한다. 이전 OpenAI tool_calls와 다음 응답의 FabriX envelope를 혼동하지 않도록 안내한다.
- 형식 실패만 새 요청 ID로 한 번 교정한다. 원래 작업과 대화를 유지하며 실패 원문을 재전송하지 않는다. 두 번째 실패는 중단한다.
- 요청 ID, 도구 이름, 인자 객체, 호출 수를 확인하고 기존 Pi의 인자 스키마 검사를 유지한다. 실패한 응답의 도구는 실행하지 않는다.
- 실제 401/429/502, 취소, 필터, 출력 길이 제한은 형식 교정을 하지 않는다. SSE END의 종료 사유를 보존한다.
- 진단은 실패 사유, 교정 여부, 시도 번호와 실제 HTTP 상태만 기록한다. 모델 응답 원문, 인자, 키, 요청 ID는 기록하지 않는다.
- 교정 요청은 사용량을 별도로 집계한다. 사용량 미제공은 미집계로 유지하며 마지막 성공 응답의 컨텍스트에 이전 실패 토큰을 더하지 않는다.

## 검증

- npm test: 184개 통과. FabriX 관련 20개 포함.
- npm run design:check, npm run build 통과.
- tests/fabrix-browser.mjs: 격리한 Chrome 확장에서 실행. 모델 응답만 합성이며 페이지 조작은 실제 실행했다.
- 연결 테스트와 자동화 중 형식 실패를 각각 주입해 1회 복구 확인. JSON 코드 블록으로 감싼 도구/최종 응답 처리 확인.
- 도구 선택, DOM 읽기, 새 탭 이동, iframe 본문 입력, 초안 저장 클릭, 페이지 상태 검증까지 완료. 메일 보내기는 실행하지 않음.
- 실패한 인증 요청 1회와 측정 가능한 14회 요청을 합쳐 총 15회, 1,680토큰 기록. 실패한 형식 요청 두 건도 포함한다. 마지막 답변 컨텍스트는 120토큰으로 유지했다.
- 실제 HTTP 502 합성 응답은 한 번 호출 후 upstream/HTTP 502로 기록. HTTP 200 안의 잘못된 응답 두 건은 fabrix_format_failed/invalid_json/HTTP 200과 로컬 fabrix_tool_protocol로 기록했다.
- 새로고침 후 연결, 대화와 사용량 유지. 진단과 local 저장소에 인증키 및 실패 원문 없음.

로컬 결과: verification/fabrix-browser.json. 화면: verification/fabrix-tested.png, fabrix-agent-panel.png, fabrix-mail-draft.png, fabrix-usage.png, fabrix-protocol-error.png.

이번 검증은 변환 계층, 확장 실행과 합성 HTTP 응답 범위다. 작업 환경에 실제 FabriX 연결 설정/인증값이 없어 회사망 모델의 응답 품질과 실제 계정 호출은 검증하지 않았다. 신규 오픈소스 의존성이나 라우터 설치는 추가하지 않았다. 기존 Pi 실행기를 유지하고 프로젝트 OpenWiki 어댑터의 복구 방식을 확장에 적용했다.
