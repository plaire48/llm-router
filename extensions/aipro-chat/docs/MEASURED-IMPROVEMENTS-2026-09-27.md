## 검증 및 남은 순서

통합 검사 중 16k 모델의 정적 도구 설명이 대화 압축 뒤 입력 예산을 넘는 회귀를 발견했다. 모델 한도를 올리거나 사용자 조건을 삭제하지 않고 중복 설명을 줄였다. 실제 공개 프롬프트와 스키마를 사용하는 관련35개 회귀가 통과했다. 실패한 검사 기록도 보존한다.

후속 후보 `a83bc160fee0cfca0c3b9655fc4e640562845a283b228d35101f60a64cdbe740`는 단위1,189개, 디자인/후보 빌드, 선택한 Chrome23종을 모두 통과했다. [통합 기록](../verification/pre-release-2026-09-27T12-45-44-857Z/report.json)의 26개 단계가 통과했고 전체 Chrome 행렬 검사는 아니다. 위 실제10건은 실행 중 소스 변경을 섞지 않은 b4489e 결과다. 후속 후보의 실모델 품질은 미측정이며 배포하지 않았다.

1. 날씨처럼 여러 카드가 섞인 페이지에서는 관찰한 한 영역의 제목, 날짜, 항목, 값을 묶어 읽고 독립 대조해야 한다. 원래 모델 입력이 없어 E-07의 정보 누락과 해석 오류 비중은 확정하지 못했다.
2. PDF의 빈 DOM과 동일 캡처 반복에서 다른 읽기 경로로 전환하는 처리와 검토 범위 복구 반복이 남아 있다. E-08은 verify_page를 호출하지 않았으므로 새 기술 검증 부채 복구가 이 경로를 직접 해결하지 않는다. 최초 계획의 과도한 원문 요구, 범위 감사 형식 실패, 마지막 텍스트 후보의 전체 미완료 단계 검사 경로를 분리해야 한다. 마지막에 후속 기준을 검사했다는 이유만으로 검토 범위 누출을 확정하지 않는다. [E08 감사](../verification/browser-30/b4489e-e08-cause-audit.json)를 따른다.
3. 통합 검사를 통과한 후속 후보로 같은10개를 다시 독립 채점해야 한다. 구현 완료를 실모델 품질 향상으로 표시하지 않는다.

현재10건의 모델 호출은313회다. 호스트에서 시작/종료가 짝지어진 압축29회는361,153ms, 검토100회는431,312ms였다. 호출 시간의 합으로, 페이지 읽기만의 지연이나 전체 병렬 실행 벽시계 시간으로 해석하지 않는다. 반복 압축과 검토가 주요 비용이지만 이것만 제거하면 정확도가 오른다고 단정하지 않는다.
