# 기존 창 안의 누비 탭 그룹

새 작업은 원본 탭이 있는 일반 Chrome 창에 비활성 탭으로 열고 청록색 `누비` 그룹으로 묶는다. 새 브라우저 창을 만들지 않는다. 원본이 팝업이면 이미 열린 일반 창을 사용한다. 같은 프로필의 로그인은 공유하지만 미저장 입력은 복사하지 않는다.

설정은 **누비 탭에서 작업 / 현재 탭에서 작업**으로 표시한다. 현재 탭은 입력 중인 내용을 직접 수정할 때 사용한다. 폰트, 크기와 탭 컴포넌트는 기존 CX와 사용자 HTML 토큰을 유지한다.

대화별 그룹과 tabIds를 따로 기록한다. 그룹 이름과 그룹에 사용자가 넣은 탭은 실행 권한이 아니다. 새 팝업을 기록된 작업 그룹으로 옮기고, 닫힌 자식 탭은 기록된 부모로만 복귀한다. 작업 탭 전체가 닫히면 원본에 쓰기를 대신 실행하지 않는다. 누비 탭 보기 버튼으로 작업 위치를 명시적으로 열 수 있다.

저장된 설정과 승인/이어가기를 보존하기 위해 내부 `browserWorkMode: window` 키는 유지한다. `layout: tab-group`은 새 작업 배치 정보다. 이미 실행 중인 과거 전용 창의 초안은 자동으로 이동하지 않는다.

## 방법 선택

Chrome 공식 [Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs)와 [Tab Groups API](https://developer.chrome.com/docs/extensions/reference/api/tabGroups)를 사용한다. 기존 Playwright CRX의 실제 페이지 입력을 유지하며 별도 탭 관리 라이브러리는 추가하지 않는다. 창 생성 대신 지정된 창의 비활성 탭 생성과 기존 그룹 API로 충분하다.

Chrome의 active 탭과 OS의 focused 창은 구분한다. 누비 소유 탭을 선택한 동안에는 에이전트의 현재 페이지로 자동 전환한다. 사용자 탭을 선택하면 멈추고 소유 탭으로 돌아오면 다음 도구부터 재개한다. 다른 창에서 작업하면 누비 창 안의 탭만 선택하며 창 포커스/최소화 상태를 변경하지 않는다. 팝업이 새 탭을 선택하면 확인된 작업 탭에 한해 이전 선택을 복원하고, 사용자가 다른 기존 탭을 선택하면 이를 존중한다. 사이트 팝업의 순간적인 화면 전환이나 OS 전면 상태를 모든 환경에서 보장하지 않는다.

## 검사 기준

- 기존 창 수가 늘지 않고 원본과 같은 창에 이름이 누비인 그룹이 생성된다.
- 원본 미저장 초안과 선택 탭을 유지하며 작업 탭에만 입력/클릭/캡처한다.
- 서로 다른 대화는 그룹을 구분하고 수동으로 넣은 사용자 탭은 조회/조작 대상에서 제외한다.
- 새 탭/팝업 편입, 부모 복귀, 중단 후 재개와 종료 후 임의 대체 금지를 확인한다.
- 사이드 패널, 전체 화면의 승인/이어가기와 설정 UI를 함께 검사한다.

## 결과

단위 검사 497개, 관련 Chrome 회귀 24회(핵심 6개 흐름을 각 3회), 전체 UI 17개 시나리오를 통과했다. 두 실행의 빌드 내용이 일치하고 최종 ZIP의 manifest 1.4.18과 파일 무결성을 확인했다. 회사망 실모델 검증과 신규 GitHub 릴리스는 포함하지 않는다. [회귀 기록](../verification/pre-release-2026-09-23T15-18-34-207Z/report.json), [UI 기록](../verification/pre-release-2026-09-23T15-22-08-705Z/report.json).

초기에는 새 팝업 선택으로 사용자 탭이 바뀌는 문제가 재현되어 새 작업 탭에 한해 선택을 복원했다. 기존 전용 창을 전제로 한 검사와 모델 환경 설명도 새 탭 그룹 기준으로 함께 변경했다.
