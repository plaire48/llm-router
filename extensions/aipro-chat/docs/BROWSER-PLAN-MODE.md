# 실행 전 계획 검토

`/plan 업무 내용`은 현재 화면, 첨부 문서, 내장 사이트 위키와 연결된 OpenWiki를 읽어 절차와 필요한 입력, 검증 기준을 정리한다. 설명만으로 해결되지 않는 필수 결정은 기존 선택형 질문으로 확인한다.

Pi 런타임은 유지한다. 호스트가 도구 목록과 실행 진입점 양쪽에서 읽기 전용 목록을 적용한다. 입력/클릭/이동/스크립트/MCP/내보내기/최종 승인 실행은 불가능하다. 질문 응답, 재시도와 재개에도 모드를 보존하고 자동 위키 갱신을 하지 않는다. 계획이 끝난 뒤 별도 일반 요청으로 초안을 적용할 수 있으며 최종 등록은 기존 HITL 대상이다.

[OpenCode Plan agent](https://opencode.ai/docs/agents/)와 [Codex plan mode](https://github.com/openai/codex/blob/main/codex-rs/collaboration-mode-templates/templates/plan.md)의 조사와 실행 분리 방식을 참고했다. 새 프레임워크는 추가하지 않았다. Chrome의 읽기 도구는 대상 탭 생성/캡처 등 브라우저 관찰을 수반할 수 있으므로 운영체제 수준의 부작용 없는 샌드박스라는 의미는 아니다.

UI는 기존 명령어 목록과 대화/진행 컴포넌트를 쓴다. 테스트는 실제 Chrome에서 실행 경로 차단, 새로고침 후 질문 응답, 이어지는 일반 요청의 초안 입력과 검증을 합성 Qwen 응답으로 확인한다. 실모델 계획 품질은 별도 평가가 필요하다.
