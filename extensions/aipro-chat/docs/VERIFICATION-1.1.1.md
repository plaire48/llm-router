# 누비 1.1.1 OpenWiki 폴더

2026-09-22. 사용 흐름을 설정에서 폴더를 지정하고 필요할 때 참고하는 방식으로 바꿨다. GitHub 게시나 웹 스토어 배포는 하지 않았다.

## 반영한 흐름

1. 설정의 OpenWiki 폴더에서 `openwiki` 폴더 또는 그 폴더를 포함한 프로젝트를 선택한다.
2. 설정은 확장 IndexedDB에 저장한다. 브라우저가 권한을 다시 요청하면 같은 화면에서 읽기를 허용한다.
3. 누비는 질문에 필요한 문서를 검색/조회하고 결과를 바탕으로 현재 웹페이지에 초안을 작성하거나 입력한다.
4. 브라우저 결과를 다시 확인한다. 최종 등록/발행은 기존 승인 절차를 유지한다.

폴더 모드는 서버 실행, 주소 입력, 매번 프로젝트 연결 없이 동작한다. Markdown 문서를 읽으며 원본 소스 쓰기/빌드/명령 실행을 제공하지 않는다. 원본 소스 조회가 필요한 경우를 위해 기존 서버 연결은 설정의 접힌 선택 기능으로 남긴다.

CX의 기존 컴포넌트와 사용자 HTML 기반 토큰을 사용했다. 변경/해제/권한 복구는 아이콘으로, 오류는 짧은 문장으로 표시한다. 참고한 문서의 근거는 페이지 입력 이후에도 유지하고 최종 페이지 상태는 별도로 검증한다. 같은 문서를 다른 해시로 다시 읽으면 이전 근거를 대체한다.

## 검증 범위

**단위 테스트 267개, 관련 Chrome 스위트 15개의 25회 실행, CX 디자인 검사와 빌드가 통과했다.** [검증 결과](evidence/1.1.1-report.json)에 설치 ZIP의 해시와 범위를 기록했다. 5개 핵심 스위트는 새 프로필로 3회씩 실행했다. 설정 검사에서 같은 단계 제목과 하위 서버 설명을 혼동한 테스트 선택자를 수정한 뒤 남은 검사를 완료했다. 두 실행의 빌드 내용 해시가 동일하며 전체 기능의 전수 회귀나 한 번의 중단 없는 통과로 표현하지 않는다. 직전 후보는 연결 전환 저장 실패를 수정하기 위해 회귀 실행 도중 중단했으며 최종 후보의 결과로 합산하지 않는다.

- 폴더 선택/변경/해제, 권한 철회, 저장 실패 시 기존 설정 보존과 서버 자동 복귀 방지.
- 실제 Chrome DirectoryHandle의 IndexedDB 저장 및 서비스 워커 읽기, 현재 Markdown/해시 재조회.
- Wiki 검색/읽기 → 웹 폼 입력 → 앱이 보관한 초안/실제 필드/검증 결과 확인. 등록 버튼은 누르지 않음.
- 동일 프로필의 브라우저 종료/재시작 후 폴더 설정 복원, 해제 후 다시 살아나지 않음.
- 320/360/1100px 설정 화면, 글꼴/넘침과 오류 복구.
- 관련 브라우저 자동화/하네스/로그인/제공자 전환/대화/설정 회귀.

## 확인하지 않은 범위

파일 핸들 자동 테스트는 OPFS의 실제 Chrome 핸들을 사용한다. 네이티브 OS 폴더 선택 완료 및 실제 디스크 폴더의 재시작 후 권한 지속성은 별도 실사용 확인이 필요하다. OS 선택창이 열리는 것은 수동 탐색에서 확인했으나 선택 완료를 확인한 것으로 표현하지 않는다.

웹 폼과 확장 실행은 실제 Chrome에서 확인하지만 모델 응답은 합성이다. 회사 모델의 판단 성능, 사내 파일/계정, Windows/Edge 실환경, 배포 서비스의 등록 성공을 의미하지 않는다. 브라우저 사이트 권한과 폴더 읽기 권한은 별개다. 폴더 읽기에 디버거는 필요 없으며 브라우저 조작은 기존 도구 경로를 사용한다.
