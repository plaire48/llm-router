# 브라우저 작업 녹화 UX 재검토

## 사용자가 수행할 일

설정의 **작업 녹화·예약**에서 **녹화 시작** → 사이트에서 평소처럼 작업 → 누비 상단의 **끝내고 확인** → 기록을 검토하고 **이 작업 저장**. 저장한 작업은 같은 섹션의 **저장한 작업**에서 다시 실행한다. 기록은 자동 재생 명령이 아니며 재실행 때 대상 재관찰, 필요한 값 확인과 기존 승인 절차를 거친다.

| 이전 상태 | 인지 부담 | 바뀐 동작 |
| --- | --- | --- |
| 설정 안에 녹화가 한 단계 더 접혀 있음 | 기능 발견이 어려움 | 녹화 섹션을 첫 화면에 보이고 현재 단계별 주동작 하나를 제시 |
| 녹화 시작 후 채팅에서 상태가 보이지 않음 | 끝내는 위치를 기억해야 함 | 사이트와 기록된 동작 수, **끝내고 확인**을 누비 화면에 계속 표시 |
| 초안 단계 최대 100개를 저장 폼 앞에 전부 표시 | 저장까지 과도한 스크롤 | 처음 3단계만 먼저 표시하고 나머지는 펼침 |
| 이름/목표의 역할이 모호하고 저장은 아이콘만 있음 | 무엇을 써야 하는지 불명확 | **저장할 이름**, **다시 할 일**과 한 문장 예시, **이 작업 저장** 사용 |
| 새 녹화가 기존 초안을 덮어씀 | 미저장 기록 손실 | 같은 초안 ID를 확인한 명시적 교체만 허용하며 녹화가 끝날 때까지 기존 초안을 보존 |
| 저장 후 결과가 약함 | 성공과 다음 행동이 불명확 | 저장 완료 상태와 저장한 작업 목록을 표시하고 작업명 붙은 실행 버튼 제공 |

화면 문구는 각 단계의 행동과 결과만 남겼다. 입력값과 암호는 녹화하지 않는다는 사실은 시작 전 한 줄로 알린다. 단계/오류/저장 상태는 텍스트와 `role=status`로 전달하며 색에만 의존하지 않는다. 초안 교체는 별도 확인 선택을 요구한다.

## 근거와 채택 판단

- 적용: W3C WAI의 [Provide Feedback](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o4p10-status-feedback/)은 단계 상태와 완료 피드백을 요구한다. [WCAG 4.1.3 설명](https://www.w3.org/WAI/WCAG21/Understanding/status-messages)은 포커스 이동 없는 상태 알림을 설명한다. 녹화/저장 상태에 사용했다.
- 적용: W3C WAI의 [Labels or Instructions](https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions)는 입력 목적을 식별할 수 있어야 한다고 설명한다. 저장 폼의 이름과 목표 문구를 구체화했다.
- 적용: 로컬 `cognitive-accessibility:simplify` 지침의 짧은 문장, 한 상태의 주동작, 선택적인 세부 정보 원칙. 기존 CX 컴포넌트와 토큰을 재사용해 의존성을 늘리지 않았다.
- 비선택: 새 온보딩 라이브러리나 강제 투어. 현재 흐름은 네 단계이며 강제 안내는 실제 사이트 작업을 가린다. 기능 구현과 검증 없이 외부 패키지를 더하는 이점이 없다.
