# 포인터 유지와 누비 작업 탭 정리

## 확인한 원인

1. 읽기 전용 실행에는 표시를 설치하지 않았다. 첫 클릭 이전에는 포인터가 없었다.
2. 페이지 이탈에서 표시를 제거한 뒤 다음 입력까지 복원하지 않았다.
3. 클릭 완료 시 180ms 파동도 취소해 빠른 클릭에서는 효과가 거의 보이지 않았다.
4. `new_tab=yes`가 같은 URL에도 새 탭을 만들었고 종료 시 그룹을 정리하지 않았다.

## 적용

- 현재 작업 페이지를 읽을 때 휴지 위치에 포인터를 표시한다. 실제 입력 전 위치는 입력 증거가 아니다.
- 문서 로딩 완료와 10초 갱신에서 허용된 현재 소유 탭에 복원한다. 읽기 때문에 debugger를 붙이지 않는다. 표시 실패가 실제 작업 실패나 재시도를 만들지 않는다.
- 실제 이동을 160ms 보간한다. 클릭 전 호버 이동을 마친 뒤 기존 Playwright가 대상 위치/실행 가능 여부를 다시 확인한다. 사용자 입력은 대기 중 구독하지 않는다.
- 클릭 파동은 동작 완료 후에도 남은 180ms 수명까지 표시하고 다음 동작/중지에서는 정리한다. 입력은 필드 위치에 표시하며 내용은 복사하지 않는다. 모션 감소를 따른다.
- `✦ 누비` Chrome 탭 그룹을 사용한다. 일반 이동은 현재 작업 탭, 비교/초안 보존이 필요한 새 탭 요청은 정확한 주소의 기존 소유 탭을 먼저 재사용한다. 주소가 같아도 사용자 탭은 가져오지 않는다. query/hash와 이동 중 주소를 구분한다.
- 종료 시 비활성 소유 그룹만 접는다. 사용자가 보고 있는 그룹, 사용자가 수동으로 넣은 탭, 초안은 닫거나 숨기지 않는다. 결과 페이지를 다시 펼칠 수 있다.

## 방법론과 선택 근거

| 근거 | 적용 범위 |
| --- | --- |
| [rrweb replay cursor](https://github.com/rrweb-io/rrweb/blob/master/packages/rrweb/src/replay/styles/style.css), MIT | 실제 이벤트와 재사용 가능한 표시를 분리하는 기존 패턴 유지. 녹화 SDK/사용자 행동 수집은 추가하지 않았다. |
| [Playwright Mouse](https://playwright.dev/docs/api/class-mouse), Apache-2.0 | 기존 Playwright CRX와 정상 actionability를 재사용. 실제 입력 경로는 바꾸지 않고 표시만 보완했다. |
| [Chrome tabGroups](https://developer.chrome.com/docs/extensions/reference/api/tabGroups) | 공식 그룹 제목/접힘 API 사용. 그룹 이름을 소유권으로 사용하지 않는다. |

별도 마우스 자동화 라이브러리는 지연과 중복 입력 경로를 늘리므로 도입하지 않았다. 위 출처는 설계 패턴과 API 근거이며 Claude/Codex 비공개 커서 코드를 복사한 것이 아니다.

## 범위

Chrome의 실제 탭 그룹이다. 여러 사이트를 한 HTML iframe에 넣은 단일 탭은 아니다. 사이트가 여는 팝업과 비교에 필요한 서로 다른 탭은 같은 그룹에 남긴다. 브라우저 탐색 중 문서 교체, 캡처용 임시 숨김, 브라우저 자체 대화상자까지 단 한 프레임도 끊김 없이 표시한다고 보장하지 않는다. 표시 개선은 실모델의 목표 완주율 향상 증거가 아니다.

검증 결과는 이 문서에 별도로 기록한다. 현재 진행 중인 실계정 30과제 평가는 이전의 고정 후보이며 이 변경의 실모델 결과로 합산하지 않는다.

## 실제 Chrome 검증

- [최종 아이덴티티 검사](../verification/pre-release-2026-09-26T15-50-25-664Z/report.json): 단위 검사 1,013개, 디자인 검사, 후보 빌드와 UI Chrome 32개 스위트가 통과했다. 입력 소스와 빌드 해시의 일치도 확인했다. 전체 릴리스 매트릭스나 공개 배포는 수행하지 않았다.
- 후보 ZIP SHA-256: `e8021484c28bf8ce43a5c141b0ba6580bc356793c79b42d684b2cab3c5c8300b`.
- [포인터 23개 검사](../verification/pointer-browser.json): 읽기 시작/문서 복원, 대기 중 유지, 실제 클릭/입력/프레임/드래그/휠, 모션 감소, 캡처 제외, 중지와 고아 표시 만료를 통과했다. [동작 영상](../verification/pointer-demo.webm), [클릭 화면](../verification/pointer-click.png).
- [작업 공간 10개 검사](../verification/workspace-browser.json): 동일 URL 탭 재사용, 초안 보존, 별도 비교 탭, 소유권, 사용자 탭 선택 보존과 종료 후 접힘을 통과했다.
- 이 검사는 실제 headless Chrome과 합성 사이트를 사용한다. 실제 OS 전면 앱 전환, Windows/Edge, 실모델의 업무 완주 검증과 구분한다.
- 기존 좌표 검사는 애니메이션 중간 위치를 도착 위치로 취급해 실패했다. 이동 완료 후 hotspot을 확인하도록 수정했다. 표시 고장 주입은 Chrome의 MAIN-world 오류로 남는 문제가 있어 표시 계층 내부에서 예외를 격리했고 전체 포인터 검사를 다시 통과했다. 이전 실패 로그는 삭제하지 않았다.
