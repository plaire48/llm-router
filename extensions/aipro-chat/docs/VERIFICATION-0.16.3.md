# 0.16.3 긴 작업과 팝업 복구

검증일: 2026-09-21

## 변경

- 주 실행 응답 12회, 도구 16회, 요약 포함 모델 요청 64회, 스크립트 RPC 60회 및 실행 중 압축 6회 상한을 제거했다. 64회 이후의 사용량도 중복 없이 집계한다. 사용자 중지, 진행 없는 동일 결과 반복 중단, 10분 요청 시간, 스크립트 60초/CPU/메모리와 실제 모델 입력 한도는 유지한다. 잘못된 도구 응답의 크기/형식 검사는 작업 횟수 오류로 표시하지 않는다.
- 요약 프롬프트와 검증기의 필드/길이 계약을 일치시켰다. JSON 형식 오류나 잘린 요약은 원본을 이용해 한 번 다시 작성하며 모델 출력 예약 안에서 출력 예산을 늘린다. 자동 요약을 복구하지 못해도 원본이 입력 한도 안이면 계속한다. 같은 입력의 요약을 매 도구 실행마다 반복하지 않는다. 수동 압축 실패나 실제 입력 한도 초과는 숨기지 않는다. 저장에 실패한 요약으로 실행 중 경계를 앞당기지 않는다.
- 클릭 전에 대상 탭/창을 활성화하고 Chrome 탭 이벤트를 관찰한다. 별도 창의 about:blank 초기 문서, 지연된 새 탭, 기존 이름을 가진 팝업 재사용을 처리한다. 팝업 창도 탭 목록에 포함한다. 여러 창이 열리면 임의로 선택하지 않고 후보를 반환한다. 자식 창이 닫히면 기록한 부모로 돌아가 다시 관찰한다. 중지 시 관찰을 해제하고 사용자 창은 유지한다.

## 검증

- `npm test`: 216개 통과. 80회 에이전트 도구 실행, 71회 제공자 요청/사용량, 스크립트 RPC 100회, 실행 중 요약 10회, 요약 형식 복구/실패 시 원본 유지/취소/저장 실패를 확인했다.
- `npm run design:check`: 문제 없음.
- `npm run build`: 0.16.3 설치 폴더와 ZIP 생성. 기존 Vite 청크 크기 안내는 남아 있다.
- `browser-popups-browser`: 실제 Chromium에서 7개 시나리오 통과. 빈 팝업의 1.6초 후 탐색, 팝업 창 목록, 기존 창 재사용, 창 닫힘 후 부모 복귀, 다른 탭이 선택된 상태에서 1.4초 뒤 새 탭 열기, 65회 연속 입력 후 값 확인, 팝업 로딩 중 중지 후 추가 입력 차단을 검증했다.
- `browser-agent-browser`: 기존 자동화 14개 시나리오 통과. 메일 초안, shadow DOM/다른 출처 iframe 입력, 신뢰된 입력 이벤트, 코드 오류 후 수정, 화면 좌표 조작, 중지와 새로고침 후 보관을 확인했다. 모델 응답은 합성 데이터다.
- `context-browser`: 5개 시나리오 통과. 자동 요약과 사용량, 새로고침 후 기억 복원, 수동 압축 시 초안 유지, 실제 입력 체크포인트, 명시적 이어가기에서 이미 완료한 입력의 재실행 방지를 확인했다. 모델 응답은 합성 데이터다.

팝업 테스트는 실제 확장 실행기와 실제 브라우저 입력을 사용한 합성 사이트 검사다. 모델이 스스로 생성한 스크립트의 성공률이나 사용자의 회사 페이지에서의 성공을 검증한 결과는 아니다. 새 창 관찰 순서는 [Playwright의 페이지 전환 안내](https://playwright.dev/docs/pages#handling-new-pages)를 참고했으며 Chrome 확장 내부에서는 탭 이벤트로 실행한다.
