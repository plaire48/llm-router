# 블루 상태와 HTML 애니메이션

## 원인과 변경

초록색은 이전 HTML의 green/green-soft 성공 토큰과 bird-ink 제목/아이콘 연결에서 나왔다. 사용자는 제거 범위를 글자/아이콘/상태 표시로 확정했다. 이 범위의 성공 토큰, 완료 체크, 녹화 제목, 설정/답변 아이콘과 제공자 설명 글자를 메인 블루로 통일했다. 코드 구문에서 해당 토큰을 사용하던 강조도 같이 바뀐다. 배경과 캐릭터 자산은 그대로 유지한다. 완료 체크와 문구는 남아 색만으로 상태를 구분하지 않는다.

| 기준 HTML | 현재 적용 |
| --- | --- |
| floaty 6s / -11px | 환영 캐릭터 껍데기의 기존 회전/9px 대신 원본 수직 부유 |
| rise .55s / 18px / cubic-bezier(.22,.61,.36,1) | 메시지 등장 시간을 원본과 통일 |
| pop .4s / scale .88 / 8px | 컨텍스트 칩과 상태 표시에 원본 팝 비율 적용 |
| twinkle 3.2s | 기존 원본 반짝임 유지 |
| reduced motion | 장식/등장 애니메이션 비활성 유지 |

출처는 사용자 파일 `/Users/ganadi/Downloads/agentfactorysdkdeck.html`의 CSS다. 모달/토스트는 고정 위치와 가독성을 유지하기 위해 전체 팝 이동 대신 기존 표면 효과를 유지한다. 새 모션 라이브러리는 단순 CSS keyframe을 중복하므로 추가하지 않았다.

## Codex 참고 범위

[OpenAI 공식 앱 소개](https://openai.com/index/introducing-the-codex-app/)의 작업 진행과 결과 검토 흐름, [공개 TUI BottomPane](https://github.com/openai/codex/blob/main/codex-rs/tui/src/bottom_pane/mod.rs)의 composer 위 pending input 배치를 참고했다. 비공개 Desktop 구현을 읽었다고 주장하지 않는다. 누비에서는 입력창 위 독립 큐, 채팅/진행 기록 분리, 아이콘 우선 보조 조작을 유지한다. 화면 전체를 다른 브랜드로 바꾸지 않는다.

선행 아이콘 요청도 포함한다. 저장/다시 녹화는 툴팁이 있는 아이콘만, 녹화/실행/예약은 아이콘과 짧은 이름, 초안 폐기 확인은 결과를 명시하는 글자를 사용한다. 기존 CX Icon/ActionButton을 재사용한다.

## 검증

- 제목의 계산 색상과 성공 토큰은 #1B64DA다. 원래 배경 토큰은 유지했다.
- [실제 움직임 녹화](../verification/blue-motion/motion.webm), [설정 360px](../verification/blue-motion/settings-360.png), [측정](../verification/blue-motion/report.json).
- 선행 아이콘 후보 `05-55-41-753Z`는 과거 저장 텍스트 버튼 기대값에서 실패했다. 새로운 사용자 기준에 맞춰 아이콘 전용 여부와 툴팁 검사로 수정했고, 실제 저장/재녹화 회귀는 통과했다. 실패 보고서는 보존한다.
- 최종 [identity gate](../verification/pre-release-2026-09-26T06-25-47-835Z/report.json)는 단위 검사 909개, 디자인 검사, 후보 빌드와 실제 Chrome 30개 시험을 통과했다. 모든 모델/계정 응답은 합성이며 실모델 품질 근거가 아니다. 배포하지 않았다.


## 녹화 텍스트 배치 후속 수정

사용자가 녹화 영역의 배치를 다시 요청해 내부 중복 제목과 오른쪽에 붙은 순서 문구를 제거했다. 위에는 `사이트 작업 → 기록 확인 → 저장`을 기존 CX workflow/eye/save 아이콘과 짧은 이름으로 나란히 배치하고, 아래에는 현재 단계 안내와 시작 버튼을 둔다. 실제 recording 상태에서는 사이트 작업, draft 상태에서는 기록 확인에만 `aria-current="step"`과 블루 강조를 사용한다. 저장을 누르기 전에 완료 표시를 만들지 않는다. 저장/다시 녹화는 오른쪽 아이콘 한 줄을 유지한다.

[최종 녹화 안내 360px](../verification/readability/recording-360.png), [1100px](../verification/readability/recording-1100.png). 앞선 블루/모션 후보 `05-59-07-366Z` gate는 이 후속 배치를 반영하기 위해 종료했고, 최종 배치로 gate를 다시 실행한다. 해당 중간 후보를 통과로 표시하지 않는다.


### 단계 목록 여백

후속 지시로 `사이트 열기` 등 기록 단계 목록의 안쪽 여백을 보완했다. 최초 번호 목록 후보는 24px/12px 여백으로 검증했으나, 사용자가 번호 필요성을 재검토하도록 요청해 최종 화면에서는 번호를 제거했다. 기록 순서는 유지하고 사이트 열기/입력/클릭을 기존 CX 아이콘과 짧은 내용으로 표현한다. 좌우 12px, 위아래 8px 여백과 아이콘/내용 사이 8px 간격을 적용한다. 펼친 나머지 단계도 동일하다.

녹화 상태의 중간점은 제거하고 사이트와 동작 수를 줄바꿈으로 구분했다. 섹션 이름은 `녹화와 예약`으로 정리했다. 기존 순서 목록 의미와 접근성 이름은 유지하며 새 패키지를 추가하지 않았다. 최신 실제 Chrome 회귀에서 저장, 재녹화, 만료, 100단계 펼치기와 좁은 화면 검사가 통과했다.

번호가 있던 중간 후보 `06-09-22-694Z` identity gate는 통과했지만 최종 화면의 근거로 대체하지 않는다. 기존 `verification/readability/recording-inset-*.png`는 그 중간 후보의 합성 실패 복구 화면이다. 최신 검토 화면은 [녹화 기록 확인](../verification/browser-routines-review-360.png)을 따른다.

번호 제거 후보 `06-20-04-263Z`는 captures 시험의 프로필 재시작에서 Chrome launch 180초 시간 초과로 실패했다. 앞선 11개 캡처 검사는 통과했고 앱 assertion 오류는 없었다. 같은 소스를 단독 재실행했을 때 재시작과 이미지 보존을 포함해 통과했다. 일시적인 실행 환경 실패 가능성이 있으나 원인을 확정하지 않으며 실패 보고서는 보존한다. 전체 gate도 동일 소스의 `06-25-47-835Z`에서 통과했다.

앞선 배치 후보 `06-04-14-307Z` 검사는 이 여백 수정 요청을 반영하기 위해 종료했다. 중간 검사를 최종 소스 통과로 간주하지 않는다.
