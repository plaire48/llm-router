# 업무 절차

이 파일과 references의 `작성 필요` 항목을 조직 내부에서 채운 뒤 배포한다. 아직 작성되지 않은 규칙은 추정하지 않고 질문한다. 업무명이나 약어만으로 조직 규칙을 알 수 있다고 가정하지 않는다.

## 적용 범위

- 업무명: 작성 필요
- 사용할 때: 작성 필요
- 대상 사이트와 메뉴: 작성 필요
- 담당자와 문서 버전/확인일: 작성 필요

## 수행 순서

1. `read_page`로 현재 사이트와 화면을 확인하고 적용 범위와 비교한다. 화면이 다르거나 범위가 미정이면 `ask_user`로 확인한다.
2. `read_skill`로 `references/procedure.md`를 읽고 기존 `update_plan`에 짧은 단계와 확인 조건을 반영한다.
3. 약어, 메뉴 의미와 작성 기준은 `read_skill` query로 필요한 부분만 검색한다. 규칙 전체가 필요한 경우 해당 path를 읽는다.
4. `references/inputs.md`에 따라 누락된 정보를 기존 질문 폼으로 받는다. 확인된 선택지가 있으면 객관식과 직접 입력을 함께 제공한다. 예시와 사용자의 실제 값을 구분한다.
5. 현재 화면에서 확인한 요소에 초안을 작성한다. 가능한 경우 `fill_form` 등 의미 기반 도구를 사용한다. 메뉴가 바뀌면 관찰부터 다시 하고 미완료 단계만 수정한다.
6. `references/checks.md`의 기준과 사용자 요청을 `verify_page` 등 실제 관찰로 검사한다. 문서의 절차를 읽었다는 사실은 업무 완료 증거가 아니다.
7. 등록/발송/배포가 요청되었다면 먼저 검토 가능한 초안을 준비하고 기존 승인 절차를 사용한다. 승인 후에도 실제 저장 결과를 확인한다. 초안 요청은 승인이나 최종 처리를 유도하지 않고 초안에서 마친다.

업무 절차에는 계정 비밀번호, 토큰, 타 사용자의 실제 입력값을 넣지 않는다. 공유 파일은 절차와 자료의 복사본이며 받은 사람은 자신의 계정과 권한을 사용한다.
