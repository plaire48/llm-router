# 개발 기준

긴 웹 문서는 기존 read_page의 content 모드에서 Readability/Turndown으로 복제 DOM을 읽고 LangChain/MiniSearch로 필요한 구간만 반환한다. 화면 관찰/ref와 문서 근거를 구분하며 변경 해시를 섞거나 문서 조회로 불확실한 쓰기/클릭 실패를 해소하지 않는다. 텍스트 검증은 같은 가시성 필터의 출력 절단 전 결과를 대조한다. 선택과 범위는 docs/BROWSER-OPEN-SOURCE-QUALITY.md를 따른다.

도구 근거 없이 종료하는 답변은 완료 의도 검토로 일반 대화와 외부 작업을 구분한다. 작업이면 Pi followUp으로 관찰부터 이어가며, 계획/스킬 조회를 실행 근거로 삼지 않는다. 의도 검토는 최종 완료 증거가 아니다. 평가는 URL 검색 대신 대화/제공자/인증 시점에 묶인 실제 작업 탭을 읽고 별도 창 모드의 원본 보존도 확인한다. 근거와 한계는 docs/COMPLETION-QUALITY.md를 따른다.

모든 작업에서 관련 방법론, BP와 오픈소스의 활용 가능성을 MUST 검토한다. 공식 문서와 실제 구현을 확인하고 사용자 목표, 확장 실행 환경, 정확도/복구, 라이선스, 유지보수와 비용을 비교한다. 도움이 되는 패턴이나 라이브러리를 적용하며, 작은 단계의 실제 입력/결과를 보고 개선한다. 선택 근거와 검증 범위를 남기고 합성 검사와 실모델/실서비스 성능을 구분한다.

브라우저 코파일럿의 개발과 성능 평가 기준은 MUST Qwen 3.8 27B (`QWEN3.8-27B-FP8-256K`)로 둔다. 신규 AI Pro 연결의 기본 모델과 실모델 평가의 기본값을 공유하고, 사용자가 저장한 다른 모델 선택은 유지한다. 요구사항 파악 → 현재 화면 관찰 → 단계별 행동 → 결과 검증을 기본으로 하며 모호한 요구는 객관식/주관식 질문, 최종 트랜잭션은 HITL로 처리한다. 개선할 때 관련 공식 사례와 오픈소스를 비교하고 실제 적용/검증 근거를 기록한다. 합성 Qwen 응답 검사는 실제 모델 정확도 평가를 대신하지 않는다.

현재 제품 이름은 `nubi`, 표시 버전은 `Beta 1.0.0`이다. beta12는 로컬 검증 후보이며 공개 beta11과 구분한다. npm 패키지는 `nubi@1.0.0-beta.12`, ZIP은 `nubi-beta-1.0.0.zip`을 쓴다. Chrome 업데이트용 manifest.version은 기존 설치보다 큰 1.4.15로 두고 version_name을 표시 버전으로 사용한다. UI/진단/패키징은 표시 버전과 내부 업데이트 번호를 구분한다. 한글 누비 로고 오른쪽에 작은 beta 텍스트를 공통 보조 글꼴/색상으로 표시한다. 기존 unpacked 설치의 ID와 저장소 유지를 위해 폴더를 임의로 옮기지 않고 기존 경로의 파일을 갱신한다. 새 스킬 파일은 nubi-browser-skill로 내보내되 기존 aipro-browser-skill 가져오기를 지원한다. 제공자 AI Pro 이름과 기존 API/저장소 식별자는 제품 이름 변경으로 치환하지 않는다.

UI 작업에는 .agents/skills/cx-ui/SKILL.md의 CX UI 스킬을 적용한다. DESIGN-SYSTEM.md를 읽고 설치된 @e2e/cx-design-system의 manifest와 문서를 확인한다. 제공자 아이콘 탭은 사용자 HTML의 옅은 색면과 그림자를 사용하고 밑줄/테두리 대신 선택 배경이 부드럽게 이동한다. CX 역할/키보드/초점은 유지하고 모션 감소에서는 즉시 표시한다.

상단 로그인/로그아웃은 `…` 설정의 계정 행에 둔다. 상단은 이력/창 확대/사용량/설정을 유지하고 새 대화 연필은 제거한다. 새 대화는 대화 이력의 검색 옆 + 아이콘에 모으고 기존 로고 단축 동작은 유지한다. 전환 성공 뒤 입력창에 초점을 두며 닫기/Escape는 이력 아이콘으로 돌아간다. 계정 선택창 전환 시 설정을 닫고 돌아오면 상단 설정 버튼으로 초점을 복구한다. 모델 선택창의 새로고침/로그아웃/연결 편집은 오른쪽 아래 아이콘으로 모으며 수신/표시/전체/검색 개수 문구는 본문에 노출하지 않는다. 모델 선택창의 로그인/연결은 64px 타일과 32px 아이콘, 28% 반경, 상하 24px 여백으로 표현한다. 공통 ActionButton에 서비스 토큰을 적용하고 제공자별 옅은 색과 아이콘/툴팁을 유지한다.

검증: npm run design:check, npm run build. 변경 화면의 반응형과 동작도 브라우저에서 확인한다.

브라우저 작업 변경의 배포 전 검증은 npm run verify:browser로 실행한다. 후보 ZIP은 verification/candidate에 분리해 기존 releases ZIP을 덮어쓰지 않는다. 핵심 회귀는 새 프로필로 3회 반복하며 한 번이라도 실패하면 중단한다. 실제 모델 성능/실계정 확인은 합성 모델의 Chrome 회귀 결과와 구분하고 자동 업로드하지 않는다.

클릭의 화면 변화는 팝업 대기를 줄이는 힌트이며 완료 증거가 아니다. 빠른 반환 후에도 원래 제한 시간 동안 자식 창 이벤트를 감지하고 다음 도구 진입점에서 새 관찰을 반환하며 그 요청의 쓰기는 보류한다. 승인 문구는 실제 노드의 동작 이름을 사용하고 제출/신청을 등록으로 합치지 않는다. 분명한 양식 열기/내역 조회와 실제 form submit을 구분하며 일회성 승인 결합은 유지한다. 근거와 한계는 docs/CLICK-LATENCY-AND-APPROVAL.md를 따른다.

브라우저 작업은 기본적으로 대화별 누비 전용 Chrome 창에서 수행한다. 첫 도구 호출 때 원래 URL을 새 창으로 열며 기존 로그인은 공유하지만 미저장 DOM/폼은 복사하지 않는다. 설정의 현재 탭 모드는 명시적 예외다. 소유권은 session의 대화/제공자/인증 시점/windowId/tabId 목록에 묶으며 그룹 이름은 권한이 아니다. 탭 조회/전환/팝업/재개는 소유 탭에 한정하고 창이 닫히면 원래 사용자 탭으로 대체하거나 쓰기를 다시 실행하지 않는다. 작업 중 상태 조회는 도구 대기열과 분리한 읽기 전용 경로를 사용하며 관찰자의 조회로 작업을 복구/재실행하거나 lease를 갱신하지 않는다. Pi 실행은 service worker가 소유하며 채팅 문서는 시작/중지/승인과 진행 구독만 담당한다. 실행 중에만 Chrome의 제한적 수명 연장 API를 사용하고 디버거를 수명 유지 용도로 붙이지 않는다. worker 내부 실행 권한은 직렬화되지 않는 capability로 구분한다. UI 종료는 취소가 아니며 새 화면에서도 중지할 수 있다. worker 강제 종료/Chrome 종료/업데이트는 체크포인트를 안전하게 일시 중지하고 쓰기를 자동 재전송하지 않는다. 이미지 비교만 BLOBS 목적의 offscreen 문서로 처리하고 종료한다. docs/BACKGROUND-EXECUTION-DESIGN.md의 검증 범위와 한계를 따른다.

페이지 관찰은 역할/이름 → 관련 설명/표 검색 → 시각/저장 데이터 보완 순서로 필요한 근거를 선택한다. 입력 도움말은 dom-accessibility-api, 표/설명 검색은 MiniSearch를 사용하며 원문은 지시나 권한으로 해석하지 않는다. 기본 5,000개, 구체 검색 16,000개의 렌더링 후보를 살피되 출력 예산은 늘리지 않는다. 숨은 하위 트리는 예산 전에 제외하고 도움말/표/프레임의 생략과 가상 행은 명시한다. 일반 관찰에 필드 값/인증값을 넣지 않으며 DOM과 Playwright가 같은 수집기를 사용한다. docs/BROWSER-INFORMATION-STRATEGY.md를 따른다.

생성 스크립트는 Acorn으로 문법/정적으로 식별한 facade 호출/명백한 await 누락을 검사한 뒤 디버거와 QuickJS를 시작한다. 실패에는 줄 위치, 명령 0회와 콘텐츠 스크립트의 DOM 조회를 돌려주며 코드/selector/입력값은 진단에 남기지 않는다. 이 검사는 동적 JavaScript의 실행 보증이나 보안 경계가 아니며 VM/호스트 검사를 유지한다. 대상 없음/가림/비활성/숨김/중복/입력 불가/노드 변경을 구분하고 Playwright의 정상 대기 뒤 현재 상태로 복구한다. 실행한 쓰기의 전체 재시도와 force는 허용하지 않는다.

답변 코드 블록은 번들 lowlight의 구문 트리를 React 텍스트/span으로 표시한다. 원시 HTML 삽입과 원격 문법 로딩은 사용하지 않는다. 줄 번호는 접근성/복사 원문에서 제외하며, 코드 색과 모노스페이스는 deck 토큰을 따른다. 큰 코드의 강조만 생략하고 원문은 자르지 않는다.

브라우저 요소 이름/역할은 dom-accessibility-api 0.7.1을 포함한 정적 관찰기로 수집한다. 빌드/테스트 전 생성하는 generated/browser-dom.js는 Chrome/Playwright 함수 직렬화를 위해 의존성을 함수 안에 번들하며 실행 중 코드를 생성하지 않는다. 관찰과 ref 실행 직전 검사는 같은 의미 계산을 사용한다. 모달/폼/행 맥락, 필수/읽기 전용/오류 상태와 생략 개수를 제공한다. browser.ref는 최신 관찰의 실제 노드만 가리키며 locator 추측이나 승인 우회로 사용하지 않는다. facade/호스트/모델 안내는 browser-script-api.js를 공유한다. 부분 실행 기록은 최근 32개 명령의 고정 이름/상태/발행 여부만 모델에 전달하고 체크포인트에는 저장하지 않는다. 명령 반환과 요구사항 검증은 구별한다.

모달의 제목은 Noto Sans KR 16px, 본문/항목명/입력/버튼은 14px로 통일한다. 날짜/단위/버전만 12px로 표시하며 진단 기록도 본문 글꼴을 사용한다. 문구는 핵심 문장과 그에 필요한 설명만 남긴다. 접힌 화면뿐 아니라 펼친 본문/오류/삭제 확인도 검증한다.

진행 현황의 계획/단계명/도구 설명/상태/Markdown도 Noto Sans KR 14px/22px를 공유한다. 크기를 줄여 구분하지 않고 굵기와 HTML의 본문/보조색, 진행 블루와 오류색을 사용한다. 코드만 고정폭을 유지한다.

웹페이지 메일/게시글 작성은 내용과 서식을 함께 검토한다. 대상 편집기의 기본 글꼴/크기와 기존 초안을 보존하고 관찰한 도구 모음/단축키로 적용한다. editorState/selectText는 고정 관찰/선택 헬퍼이며 임의 HTML/CSS 주입을 허용하지 않는다. 요청한 서식은 verify_page text_style로 별도 검증하고 미리보기/저장 근거와 구분한다. 최종 승인 해시는 리치 초안의 구조/서식에도 묶는다. docs/RICH-TEXT-AUTHORING.md를 따른다.

모달을 포함한 모든 화면은 지금 필요한 선택과 동작만 보여준다. 사용량은 잔여 한도와 제공자별 한 줄 합계를 먼저 보여주고 토큰 상세는 펼친다. 컨텍스트 상세와 도움말 주제는 기본으로 접으며, 스킬 설명은 툴팁에 둔다. 로그인 전 모델 모달은 내용 높이에 맞춘다. 로고/선택 상태로 드러나는 이름과 상시 설명을 반복하지 않는다. 모델 선택은 이름과 선택 표시만 두고 한도는 툴팁/컨텍스트 상세로 보낸다. 검색은 7개 이상 목록에서 표시한다. 연결된 제공자의 모델 선택창에는 목록이 있어도 새로고침 아이콘을 유지한다. 새로고침과 로그아웃은 제공자 탭에서 분리하고 모델 선택 모달 하단 오른쪽에 둔다. AI Pro 선택창을 열 때 기존 목록을 유지하면서 최신 목록을 한 번 조회하며 자동 조회에는 완료 토스트를 표시하지 않는다. 아이콘 조작의 접근 가능한 이름과 필요한 오류 복구는 유지한다.

제품 소개는 AI Agent로 표현한다. 사용자 제공 `/Users/ganadi/Downloads/agentfactorysdkdeck.html`을 모든 기존/신규 화면과 요소의 지속적인 시각 기준으로 MUST 사용한다. 로그인, 채팅, 진행 현황, 설정, 모든 모달/탭/질문/HITL/첨부/토스트의 색감, 서체/크기/굵기/행간, 버튼/아이콘 비율, 간격/반경/그림자와 애니메이션까지 적용한다. 기본/호버/초점/선택/로딩/완료/오류 상태도 같은 공통 토큰을 MUST 사용하며 화면이나 제공자별 임의 스타일을 NEVER 추가한다. 변경 화면은 같은 역할의 기존 요소와 함께 좁은/넓은 창의 계산 스타일과 실제 움직임을 확인한다. 명세와 원본 해시는 `docs/VISUAL-STANDARD.md`, 공유 서비스 토큰은 `design/agent-deck.css`에 있다. 이 명시적 사용자 기준은 CX의 기본 색/반경보다 우선하며 CX 컴포넌트 동작과 로컬 Noto Sans KR는 유지한다. Codex는 대화 흐름과 피드백의 참고다. 원본 HTML을 읽을 수 없으면 기록된 기준을 사용하고 새 스타일을 임의로 만들지 않는다.

제품 캐릭터는 사용자가 선택한 부리 없는 청록색 데포르메 새다. `design/brand` 원본을 `scripts/icons.mjs`로 크기별 변환하며 제공자 공식 로고와 분리한다. 제품명은 누비(Nubi)로 확정했다. 제품 로고는 정갈한 한글 누비와 캐릭터 조합이며 영문 로고는 사용하지 않는다. 후속 지시에 따라 상단은 웹폰트 텍스트 대신 public/icons/nubi-wordmark.webp의 좌우 폭을 좁힌 한글 이미지 로고를 사용한다. 캐릭터 32px, 워드마크 42×24px와 4px 간격을 유지하며 alt는 누비다. 로고 뒤 배경/외곽선/그림자는 hover에서도 만들지 않고 키보드 초점만 표시한다. 로고 클릭은 기존 NEW_CHAT 경로로 이전 대화/초안을 보관하고 새 채팅을 연다. 실행/인증 중에는 전환을 막는다. 버전은 manifest에서 읽어 설정 모달 하단에만 작게 표시한다. 메인 제목은 “웹을 누비는 AI Agent, 누비” 전체를 같은 서체/크기/진한 청록 단색의 한 줄로 표시하고 설명은 “작은 뱁새가 웹을 누비며 / 탐색부터 입력과 실행까지 대신합니다.” 두 줄로 줄이되 캐릭터가 사용자를 돕는 이야기를 유지한다. 로그인 화면의 반복 질문은 생략한다. 색은 역할별로 사용한다. 제목/로고는 진한 청록, 설명은 차분한 회색, 동작/선택은 블루, 민트/아쿠아는 캐릭터와 후광에 쓴다. 빈 채팅의 질문에만 진한 청록에서 진한 블루의 절제된 그라데이션을 허용한다. 이전 워드마크는 이력으로만 남긴다. 시스템 프롬프트와 사용자 표면은 누비로 표현하며, AI Pro/ChatGPT/FabriX는 제공자 이름으로만 쓴다. 확장 툴바는 정적 PNG, 앱 내부는 부유/빠른 짧은 날갯짓/눈 깜빡임과 pending→done 때 4.2초 눈웃음을 사용한다. 대기 중에도 짧은 눈웃음을 넣고 20초 무활동이면 잠든 눈과 Z, 오류에는 별도 눈물 맺힌 표정과 두 번의 눈물 모션을 사용한다. 표정의 정적 가시성은 움직임과 분리하여 입력 포커스/모션 감소에서도 웃음과 오류 표정을 숨기지 않는다. 호버 인사는 1.8초 뒤 기본 동작으로 돌아온다. 숨김/모달/모션 감소 규칙은 모든 프레임에 적용하고 실패/중단에는 완료 표정을 표시하지 않는다.

복사/저장/모델 선택/페이지 연결은 실제 비동기 결과가 성공한 뒤 CX 토스트로 알린다. 모든 토스트는 화면 상단 중앙에 표시하며 작은 창에서도 같은 위치를 유지한다. 복사는 체크 아이콘을 잠시 보여주며 실패 시 버튼 옆 재시도 안내를 유지한다. 모달 안 알림은 모달의 키보드/스크린 리더 범위에 두고 완료 후 사용자의 현재 초점을 빼앗지 않는다. 선택 상태는 옅은 강조 배경, 작업 목록의 완료/진행 상태는 체크/스피너와 접근 가능한 설명으로 표현하고 반복 문구는 표시하지 않는다. 오류/취소처럼 구분과 대응이 필요한 상태는 짧은 문구를 유지한다.

도움말은 설정 헤더의 물음표에서 열고 같은 CX 모달 안에서 주제별로 펼친다. 닫기/Escape는 설정으로 돌아오며 초점을 도움말 아이콘에 복귀시킨다. 화면을 열기만 해서는 모델 요청이나 페이지 읽기를 실행하지 않는다. help-content.js가 사용자 안내의 단일 원본이며 빌드가 GUIDE.md와 ZIP의 오프라인 안내를 생성한다. 사용자 사용법은 GUIDE.md, 개발/연결 규격은 docs/DEVELOPMENT.md, 검증 명령은 TESTING.md로 구분한다. 기능이 바뀌면 해당 도움말 항목도 갱신한다.

AI Pro 로그인 후 GET /api/models를 Authorization: Bearer <token>으로 요청하여 modelList를 조회한다. 모델 목록 인증 계약 버전이 바뀌면 이전 세션 캐시를 다시 조회한다. modelList의 모델은 target과 is_agent에 관계없이 모두 표시한다. 유효한 name이 없는 항목과 중복 name만 제외하며 분류를 근거로 호출 경로를 바꾸지 않는다. sort_seq 순서를 유지한다. display_name은 화면 표시용, name은 요청용이다. QWEN3.8-27B-FP8-256K를 기본으로 선택하며 목록과 인증값은 session 저장소에 둔다. 설정 모달은 계정, OpenWiki 폴더, 연결 진단과 데이터 보관을 표시한다. AI Pro와 ChatGPT 연결 설정과 인증값 직접 입력은 UI에 노출하지 않는다. FabriX 키 입력은 전용 연결 모달에서만 제공한다. 로그인/로그아웃은 설정의 계정 행에 아이콘 하나로 제공한다. 로그인은 모델/연결 창을 열고 로그아웃은 초안을 저장한 뒤 선택한 제공자만 해제하고 같은 창을 연다. 만료/거절된 인증도 로그아웃할 수 있다. 실행 중에는 비활성화하며 연결 진단에 같은 조작을 중복 배치하지 않는다. 목록 진단은 HTTP 상태와 수신/표시/제외 사유별 개수만 보관하고 원문을 복사하지 않는다. 서버 빈 목록과 이름을 읽을 수 없는 목록을 다른 상태로 표시한다.

모델은 입력창에서 검색해 변경한다. 답변의 모델과 정규화한 usage는 대화와 함께 저장한다. 컨텍스트는 현재 모델의 마지막 완료 요청만 실측으로 표시하며 이전 턴의 usage를 합산하지 않는다. 초안, 모델 변경, 중단 및 usage 미제공은 추정으로 구분한다. context_length와 max_input_tokens를 혼동하거나 없는 한도를 만들지 않는다. 상세 수치는 컨텍스트 버튼에 접어 둔다.

AI Pro SSO는 /auth/cli/login?port=... → GET localhost /auth?code=...&status=00 → POST /auth/exchange 계약을 따른다. 로그인 전에 declarativeNetRequest 세션 규칙을 등록해 해당 탭·포트의 localhost/127.0.0.1/IPv6 최상위 GET /auth 탐색만 auth-return.html로 전환한다. MUST 모든 제공자 로그인/연결에 debugger/Network/Fetch 연결이나 실패 시 debugger 대체 경로를 사용하지 않는다. 로컬 소켓과 보조 프로그램은 없다. WAR은 auth-return.html 하나와 명시한 AI Pro/EP SSO/OpenAI/ChatGPT/loopback 출처로 제한한다. 다른 탭·포트·경로·iframe·XHR/POST 콜백은 처리하지 않는다.

콜백 문서는 URL의 일회용 query를 fragment에서 읽고 즉시 주소를 지운 뒤 runtime 메시지로 전달한다. worker는 extension id, 문서 URL, 최상위 frame, 로그인 tab과 attempt nonce, 만료/단계를 모두 검사한다. query JWT는 이전 탐색 계약과 호환하며 code는 URL-encoded code 필드로 한 번만 교환하고 JSON 루트 token의 JWT를 trusted session에 둔다. 교환 성공 전에는 로그인 완료로 표시하지 않는다. code/전체 콜백 URL/쿠키/이메일/원문은 MUST 진단이나 저장소에 남기지 않는다. User-Agent를 수동 설정하지 않는다.

대기 중인 v4 규칙과 시도는 worker 휴면 후에도 유지하되 코드 교환 중 재시작은 종료한다. 취소/만료/탭 닫힘/성공 시 탭과 규칙을 정리하고 이전 교환 응답을 적용하거나 같은 code를 자동 재전송하지 않는다. 구버전 debugger 시도는 시작 시 정리한다. 인증 진단은 단계와 교환 HTTP 상태/안전한 오류 코드만 남기며 로그인 페이지의 Network/본문 수집은 제거했다. 합성 Chrome 검증과 실제 회사망 SSO/API 성공은 구분한다. ChatGPT 로그인도 같은 v4 세션 규칙으로 정확한 localhost:1455/auth/callback만 수신한다. PKCE state/verifier는 attempt에 묶어 trusted session에만 대기 중 보관하고 교환 시작/취소/완료 때 제거한다. worker 대기 복원은 규칙과 PKCE를 함께 검사한다. FabriX는 HTTP 연결 테스트를 사용하며 debugger를 연결하지 않는다. debugger는 실제 브라우저 자동화에만 사용한다.

AI Pro 채팅은 Authorization: Bearer <token>을 사용한다. 사용자 제공 OpenAI 요청/응답을 기준으로 max_tokens는 최대 24576 안에서 모델 컨텍스트에 맞춰 예약하며 stream_options.include_usage를 사용한다. 시스템 지침과 실제 브라우저 environment는 요청 때 한 번 붙이고 대화 기록과 분리한다. CLI 도구/스킬/로컬 경로를 복사하거나 실행기가 없는 tools를 전송하지 않는다. reasoning은 단계 표시만 하고 원문을 저장하지 않는다. reasoning_tokens는 출력의 부분집합이며 중복 합산하지 않는다. length 종료는 요청별 usage를 기록하고 누비가 작은 다음 단계로 자동 복구한다. 잘린 tool call은 JSON이 파싱되더라도 실행하거나 인자를 이어 붙이지 않는다. 본문은 이어 생성하며 최근 꼬리만 재전달한다. 진행 없는 출력 실패가 3회 연속일 때만 중단하고 성공한 모델/도구 호출의 누적 횟수는 제한하지 않는다. HTTP/인증/필터/불확실한 네트워크 오류는 이 복구로 재시도하지 않는다. DONE 수신 시 EOF 없이 종료한다. 응답 대기 10분과 worker lease의 여유 시간을 함께 유지한다.

페이지 접근은 optional_host_permissions의 HTTP/HTTPS를 첫 요청의 사용자 제스처에서 허용받는다. 페이지 이동만으로 내용을 수집하지 않는다. 소스/구조/입력 제안 스킬과 저장소 읽기는 고정 ISOLATED 함수로 유지한다. 입력 제안은 미리보기 후 적용하며 문서/요소/값이 바뀌면 거부한다.

브라우저 작업과 Playwright 작업은 Pi agent core 0.86.1의 관찰 → 코드 생성 → 실행 → 오류 수정 → 결과 검증 루프로 동작한다. worker의 browser-agent.js가 @playwright-repl/playwright-crx 1.21.4의 실제 Playwright를 실행하고, 생성한 JS는 QuickJS 0.32.0 WASM VM 안에서만 평가한다. 모델 코드를 privileged realm의 eval/Function/scripting으로 실행하지 않는다. VM은 메모리 32MiB, CPU 연속 실행 1초와 총 60초를 유지하되 RPC 누적 횟수 상한을 두지 않는다. locator/탭/이동/입력/읽기 facade만 노출하며 Node, fetch, Chrome, cookies, evaluate, 파일 접근을 노출하지 않는다. 긴 본문은 한 절씩 작성한다. facade의 appendText(text, {expectedLength, expectedDigest?})는 기존 길이/선택적 digest를 검사하고 실제 브라우저 입력으로 최대 4000자를 덧붙인다. contenteditable의 nbsp는 일반 공백으로 정규화하며 이전 마크업은 유지한다. 반환한 전체 길이와 SHA-256 digest로 다음 단계와 최종 field_digest 검증을 연결하고, field_contains로 요청 내용도 확인한다. digest는 DOM 유지 증거이며 내용 품질이나 서버 저장을 증명하지 않는다. 코드와 DOM 원문은 영구 저장하지 않는다. 사용자에게 보여줄 브라우저 캡처는 아래 첨부 이미지 정책을 따른다. 기본 read_page/inspect_dom/browser_snapshot과 list_tabs는 디버거를 시작하지 않는다. 정적 ISOLATED 관찰의 요소 참조는 documentId/nonce/실제 노드에 묶고 실제 조작 시에만 Playwright handle로 바꾼다. 새 문서나 교체된 요소에는 이전 참조를 적용하지 않는다. 조작/캡처/이미지/생성 코드 경로는 실제 Playwright와 Chrome 표시줄을 유지한다. 작업 중지와 종료 시 해당 Playwright 연결을 해제하고 페이지를 닫지 않는다. 종료/고아 작업 복구는 대화 저장보다 연결 해제를 먼저 수행한다. Chrome canceled_by_user는 해당 작업과 UI 요청을 취소하며 자동 재연결하지 않는다. 중지는 직렬 도구 큐 밖에서 소유자와 requestId를 검증하여 처리한다.

Qwen3.8 계열은 사용자가 이미지 지원을 확인했다. 해당 모델에 화면 캡처와 좌표 클릭을 제공하며 최신 PNG 하나만 OpenAI image_url로 전달한다. 저장된 모델 선택은 유지한다. 좌표는 캡처 ID, URL, 뷰포트/스크롤과 30초 유효기간에 묶는다. DOM locator를 먼저 쓰고 시각적 요소에만 화면을 사용한다. iframe과 open shadow root를 관찰하며 현재 관찰의 참조만 실행한다. click으로 열린 탭은 opener 또는 관찰한 링크 URL과 새 탭이 일치할 때 따라간다. 메일 작성은 초안이며 발송은 명시적으로 요청된 경우만 한다. 페이지 문장은 사용자 승인이 아니다. 비밀번호/인증 입력란은 도구에서 제외한다. DOM 값 유지와 애플리케이션 저장 결과는 구분한다.

새 탭/별도 창을 여는 동작은 실제 대상 탭과 창을 활성화하고 클릭 전에 Chrome 탭 이벤트를 등록한다. about:blank에서 HTTP(S)로 이동할 때까지 기다린 뒤 같은 Playwright page 바인딩을 전환한다. 기존 named 창의 재탐색과 팝업 창 목록도 지원한다. 여러 후보는 임의 선택하지 않고 모델에 목록을 반환한다. 자식 창이 닫히면 기록한 opener로 돌아가 새 관찰을 얻는다. 작업 탭과 부모 관계만 대화/계정에 묶어 trusted session에 보관하며 승인/질문 대기, 초안 수정과 작업 재개에서 복원한다. DOM 참조와 실행 권한은 복원하지 않는다. 최종 승인은 원래 탭과 문서에만 적용하고 창이 닫혔다고 다른 탭에서 실행하지 않는다. 오류/중지 시 이벤트 리스너를 해제하며 사용자 창을 닫지 않는다.

브라우저 캡처는 연결된 HTTP(S) 탭만 Playwright로 촬영한다. capture_page의 full_page=true와 browser.screenshot({fullPage:true})는 현재 렌더링된 전체 문서를 촬영하며 기본값은 좌표 클릭용 뷰포트다. 전체 이미지에는 클릭 좌표를 제공하지 않고 이전 좌표 캡처도 무효화한다. 내부 스크롤/가상 목록/접힌 항목/미로딩 내용은 전체 문서 이미지의 범위 밖이므로 관찰 후 구간별 이동·캡처한다. 관찰의 스크롤 영역에는 최신 ref/크기를 제공하고 scroll_page/browser.scroll은 보이는 영역의 75%씩 실제 wheel을 발행해 이동/경계/막힘과 변경된 크기를 반환한다. 경계에서 wheel을 보내 부모로 전파하지 않으며 막힌 스크롤을 성공으로 표시하지 않는다. 캡처 coverage는 촬영 사각형, 내부 영역, 로딩/실패 이미지와 관찰 한계를 제공하며 경계 도착이나 전체 PNG를 전체 데이터 검증으로 승격하지 않는다. 큰 이미지 한도 초과와 실제 PNG 크기 불일치를 전체 캡처 성공으로 처리하지 않는다. 전체 이미지 확대는 폭 맞춤과 세로 스크롤을 기본으로 한다. 데스크톱/다른 앱 캡처 API와 권한은 추가하지 않는다. capture_page와 스크립트의 browser.screenshot() 모두 worker에서 실제 생성된 PNG를 답변 첨부로 저장한다. 이미지 바이트는 extension IndexedDB, 참조와 출처 호스트/크기/시각, 실행자가 생성한 실행 단계 UUID를 대화에 둔다. URL 쿼리/fragment/이미지 원문을 진단이나 체크포인트에 넣지 않는다. 보관 한도는 전체 80장/80MiB이며 한도 초과는 명시적으로 알리고 기존 이미지를 임의 삭제하지 않는다. 대화 삭제와 재시도에서 제거한 답변의 이미지를 삭제하고, worker 시작 시 제공자별 대화를 포함해 참조 없는 이미지를 정리한다. 캡처는 UUID로 해당 실행 단계 안에 연결하고 단계 문장을 누르면 펼친다. 연결 기록이 없는 과거 캡처는 실행 기록 안에서 보존하며 도구명/순서로 연결을 추측하지 않는다. 읽는 중인 캡처는 다음 단계나 완료 때 접지 않는다. CX 확대 모달, 원본/맞춤 보기와 PNG 다운로드를 유지한다. 다운로드 시작과 파일 저장 완료를 구분한다. 저장된 캡처를 다음 턴 모델 입력에 자동 재전송하지 않는다.

Pi가 대화 상태와 순차 도구 실행을 맡는다. 사용자 요청에 따라 모델/도구 누적 실행 횟수 상한을 두지 않는다. 어댑터는 동일 결과 3회 반복 중단, 인자 검증과 실패 피드백을 담당한다. 사용자 중지, 요청 시간 및 실제 컨텍스트 한도는 유지한다. 모델 usage는 마지막 API 요청 기준이다. 스킬은 지침과 명시적 capability를 공유한다. Markdown 코드 블록이나 도구 선언 자체에는 실행 권한을 부여하지 않는다.

자동화 하네스는 관찰/계획/검증과 select_tools를 먼저 광고하고 요청별로 허용된 도구 그룹을 동적으로 노출한다. 이미 허용된 도구의 직접 호출도 스키마 검증 후 해당 그룹을 활성화한다. 권한을 새로 부여하거나 외부 MCP를 설치하지 않는다. 동작 후 verify_page의 실제 페이지 검사 두 번이 연속 통과해야 완료할 수 있다. 모델의 근거 없는 완료 주장에는 최대 두 번 검증을 요청한다. 진행 중인 페이지 작업에는 누적 횟수 상한을 적용하지 않는다. worker도 검증 대기/실패 체크포인트의 FINISH_CHAT을 차단한다. 검증 이후 새 동작은 이전 증거를 무효화한다. Playwright의 읽기 전용 실행은 실제 실행기에서 actionIssued=false를 증명할 때만 검증 의무를 추가하지 않으며 이전 미검증 동작은 해소하지 않는다. 검증은 입력값 유지/가시적 안내/주소 확인 범위이고 서버 영속성이나 목표의 완전한 충족을 독립적으로 보증하지 않는다.

대화 이력은 local의 활성 chat, 비활성 chatHistory와 providerChats에 중복 없이 저장한다. 새 대화는 기존 메시지/초안/모델/스킬/요약/작업/이미지를 보관하며 삭제 RPC만 해당 세션을 제거한다. 전환은 하나의 local.set으로 커밋하고 저장 실패 시 기존 선택/이력을 유지한다. UI의 초안/시작/전환은 conversationId를 검사하고 진행 중인 응답이나 로그인 중에는 전환/삭제를 막는다. 대화 전환은 페이지 연결을 해제하고 다른 제공자면 session에서 해당 제공자의 연결을 복원한다. session 교체 저장 실패 시 기존 대화 선택을 복원한다. 로그인 없이 이력 읽기는 허용하되 전송은 같은 제공자의 인증이 있어야 한다. 브라우저 재시작은 마지막 대화를 복원하되 작업을 자동 실행하지 않는다. 이미지 정리는 활성/비활성 제공자/전체 이력의 참조를 모두 포함한다. 임의 이력 만료/자동 삭제와 계정 동기화는 없다.

새 채팅의 실행 소유권은 worker 내부 capability와 requestId에 묶인다. 화면의 GET_STATE/연결 수명은 실행 생존 조건이 아니다. 같은 대화의 재진입 UI는 진행 조회, 명시적 중지와 기존 입력 검토 답변만 허용하며 도구 실행/완료를 가장할 수 없다. 과거 START_CHAT 호환 경로만 documentId와 문서별 clientId를 검사한다. clientId는 새로고침 후 재사용하지 않는다.

기본 채팅은 스킬 선택 없이 browser-agent 도구를 제공한다. 키워드 규칙 대신 모델이 요청에 맞는 도구를 선택하며 첫 브라우저 도구에서만 페이지를 연결한다. 일반 대화는 페이지를 주입/조회하거나 URL/제목을 모델에 보내지 않고 브라우저 체크포인트도 만들지 않는다. 전송 시 대상 탭 ID를 lease에 고정하고 첫 도구에서 문서를 다시 연결하므로 이후 포커스 변경으로 다른 탭을 읽지 않는다. 전체 화면은 저장된 원래 웹 탭 ID를 사용하며 URL이 숨겨진 확장 탭을 웹 탭으로 오인하지 않는다. 사이트 권한 요청은 전송 제스처에서 수행하며 기본 채팅은 거절되어도 텍스트 응답을 계속할 수 있다. 권한 오류는 실제 페이지 도구가 반환한다. 링크 아이콘과 명시적으로 선택한 스킬의 capability, 문서 고정/입력 검토 방식을 유지한다. 모델 프롬프트에 링크 클릭이나 스킬 선택을 선행 조건으로 요구하지 않는다.

CX 0.5.4 CxSelect의 열린 native option에 aria-hidden을 붙이는 접근성 문제가 있으므로 재도입하지 않는다. 인증 방식 선택 UI는 0.9.1에서 제거했다. node_modules와 CX 원본은 수정하지 않는다.

브라우저 작업 스킬은 localStorage/sessionStorage 키 목록 조회 후 선택한 업무 키만 읽을 수 있다. 인증성 키/값은 필터링하며 쿠키와 extension 저장소를 페이지 도구로 노출하지 않는다. 저장소 기능은 allowStorage 스킬에만 광고하고 chat lease 도구 목록으로 검사한다. 입력 제안 스킬은 fill_form 적용 후 별도 verify_form 관찰을 수행하며 DOM 유지 결과와 서버 저장 여부를 구분한다. 실행 기록에는 고정 도구명과 상태만 저장한다. 스킬 공유는 버전 1 aipro-browser-skill JSON의 지침/기능 선언만 전달하며 가져오기는 편집 화면에서 저장해야 등록된다. Markdown 코드 블록은 실행하지 않는다. 외부 MCP/OpenCode 런타임 연결은 아직 없다.

0.12.0은 Pi Agent의 안정 API와 followUp을 실행 기반으로 유지한다. Nanobrowser의 실행/완료 판단 분리 패턴은 참고만 하며 코드나 패키지를 포함하지 않는다. 브라우저 도구 실행 후 같은 제공자/모델을 도구 없이 호출해 원래 요구와 실제 관찰 ID를 대조한다. 검토 출력 한도 실패는 같은 근거로 한 번 다시 검토하고 알려진 출력 예약 안에서 예산을 늘린다. 이 복구는 브라우저 작업을 재실행하지 않는다. 검토 실패/미완료는 완료로 표시하지 않으며 누락만 보완한다. 원문 검토/입력값은 체크포인트에 저장하지 않고 상태/개수만 남긴다. 검토 사용량은 합산하되 컨텍스트는 마지막 실행 요청 기준을 유지한다. 이어가기는 이전 검증 의무를 보존하고 새 결과 검증을 요구한다. 이 평가는 모델 판단이며 실제 회사 API 성능이나 서버 영속성을 보증하지 않는다. 근거와 범위는 docs/OPEN-SOURCE-HARNESS.md 및 docs/AGENT-HARNESS.md를 따른다.

Pi의 브라우저 번들은 background-runner.js를 통해 service worker에서 실행한다. CX 채팅 화면은 실행 상태를 구독한다. Node/Pi CLI 런타임이나 별도 LLM 제공자를 시작하지 않는다. Pi 패키지는 버전과 lockfile을 고정하고 라이선스를 ZIP에 포함한다. 공개 Pi CLI 후기와 통합판의 사내 모델 성능을 동일한 검증으로 표현하지 않는다.

생성 코드 실패는 script-feedback.js의 고정 원인/수정 지침으로 반환하며 원시 예외, selector와 입력값을 실행 이력에 저장하지 않는다. await 없이 남은 RPC가 있으면 실행 완료로 처리하지 않는다. 실패 후 이미 허용된 기본 입력/클릭/이동 도구를 광고하되 동작을 자동 재실행하지 않는다. 동일 인자/오류 반복은 새 관찰 ref와 무관하게 진행 없음으로 센다. 이력은 최근 32개와 고정 원인을 보관한다. UI는 최종 요구사항 검토와 요청 완료가 모두 확인된 경우에만 과거 오류를 복구됨으로 표시하고 원래 실패 기록은 유지한다.

ChatGPT 로그인은 OpenCode나 로컬 보조 프로세스 없이 확장 내부에서 처리한다. Pi AI 0.86.1의 공개 OAuth 계약을 Web Crypto PKCE로 구현하고 로그인 탭의 정확한 http://localhost:1455/auth/callback 탐색만 수신한다. code는 메모리에만 두며 저장하거나 재전송하지 않는다. state/verifier는 해당 로그인 대기 중에만 trusted session에 보관해 worker 휴면에서 복원하며 코드 교환 중 재시작은 종료한다. 토큰 교환과 갱신은 auth.openai.com/oauth/token에서 수행하고 access/refresh 토큰은 trusted session 저장소에만 둔다. 갱신은 취소 가능한 작업으로 큐 밖에서 실행하며 로그아웃 이후 결과를 반영하지 않는다.

ChatGPT 추론은 Pi의 openai-codex-responses SSE 어댑터를 확장 페이지에서 실행한다. SDK가 생성하는 헤더를 별도 클라이언트로 위장하지 않으며 쿠키와 redirect를 사용하지 않는다. SDK 모델 목록과 실제 계정 모델 권한을 구분한다. 공급자 전환은 대화/초안/모델을 분리하고 기존 페이지 연결을 해제한다. AI Pro 대화를 ChatGPT 입력으로 자동 전달하지 않는다. 시스템 지침과 도구는 Pi의 선행 system 메시지 toolsAdded로 전달한다. reasoning 원문/암호화 항목은 보관하지 않고 tool call_id만 재전송한다. 실제 ChatGPT 계정 로그인과 응답 성공은 합성 브라우저 검증과 별도로 보고한다. 이 경로는 기존 Python 라우터의 OpenCode 구현을 변경하지 않는다.

누적 사용량은 0.8.0 이후 각 모델 요청의 실제 usage를 제공자별 local ledger에 합산한다. chat lease 소유자와 라운드로 중복 집계를 막고 도구 후속 요청을 포함한다. 컨텍스트는 마지막 요청 기준을 유지한다. SDK 기본값 0을 실측으로 채택하지 않으며 미제공/중단 요청은 미집계로 남긴다. 기록 실패가 채팅을 중단시키거나 무기한 지연시키면 안 된다. 대화 삭제/로그아웃은 누적량을 지우지 않는다.

ChatGPT 계정 한도는 선택된 모델 제공자와 관계없이 연결된 ChatGPT 토큰으로 GET /backend-api/wham/usage를 읽는다. 기간/비율/초기화 시간과 제공된 크레딧/개인 한도만 계정별 session에 저장하며 성공 결과만 5분 캐시한다. 401은 토큰 갱신 후 한 번 재조회하고 오류/기간 초기화/구버전 캐시는 다음 열기에서 다시 조회한다. 사용량 모달 맨 위에 조회 상태와 한도 영역을 항상 표시한다. 쿠키/수동 User-Agent를 사용하지 않으며 한도 오류로 채팅 인증을 거부하지 않는다. 이전 계정의 비동기 결과는 적용하지 않는다. AI Pro 계정 한도 API는 미확인이므로 남은 토큰이나 비율을 추정하지 않는다. 실제 계정 조회와 합성 검증을 구분한다.

0.9.0은 Pi 공식 coding-agent compaction의 요약/최근 구간 유지 방식을 참고한 브라우저 컨텍스트 관리자를 사용한다. Node coding-agent를 번들하지 않는다. 원본 대화는 local에 유지하며 모델에 보낼 이전 턴만 구조화 요약으로 바꾼다. 요약 경계는 완료 메시지 ID로 검사하고 최근 두 사용자 턴을 유지한다. 입력 예산은 model max_input_tokens와 context_length에서 출력 예약을 뺀 값 중 작은 값이며 75%에서 압축한다. 한도 미제공 시 클라이언트 예산 120K를 쓰되 모델 한도로 표시하지 않는다. 실행 중 압축은 도구 호출/결과 쌍을 분리하지 않고 원본 transcript의 cursor로 관리한다. 명시적 context overflow는 모델 요청만 1회 재시도하며 도구를 재실행하지 않는다. 요약은 동일 제공자/모델, 도구 없이 호출하고 사용량을 기존 ledger에 합산한다. 요약 포함 모델 호출과 실행 중 압축에는 누적 횟수 상한을 두지 않는다. 요약 형식/잘림 오류는 원본으로 한 번 재작성하고 출력 예약 범위 안에서 요약 출력 예산을 늘린다. 자동 요약이 실패해도 원본이 입력 예산 안이면 원문으로 계속하며 다음 결과마다 같은 요약을 반복하지 않는다. 실제 입력 한도 초과나 수동 압축 실패는 알린다. 요약 실패/취소/저장 실패 시 원문과 이전 경계를 유지한다. ChatGPT는 Pi의 Responses 계약에 없는 max_output_tokens를 임의 추가하지 않고 요약 출력 문자 제한을 적용한다.

작업 체크포인트는 목표, 최대 8단계 계획, 최대 32개 고정 도구명/결과 상태와 정리된 페이지 주소만 저장한다. update_plan 도구가 계획을 갱신한다. 브라우저 동작 전 running을 저장하고 결과 후 receipt를 갱신한다. 중단 시 running은 unknown이며 자동 재실행하지 않는다. 명시적 이어가기는 새 lease에서 browser_snapshot을 먼저 실행한 뒤 체크포인트와 새 관찰을 모델에 전달한다. 저장된 요약은 명령/승인이 아니며 최신 지시와 관찰을 우선한다. 요약, 작업과 대화는 공급자별로 함께 분리하고 새 대화 시 함께 비운다.

FabriX는 버튼에서 CX 연결 모달을 열고 Endpoint/Client Key/API Token만 받는다. 필요한 HTTPS origin만 테스트 버튼의 제스처에서 요청한다. 기존 Python 어댑터의 messages API를 fabrix.js에서 OpenAI Chat Completions JSON/SSE로 변환하며 별도 라우터를 실행하지 않는다. native tools 계약은 확인되지 않았으므로 요청별 nonce와 등록된 스키마를 포함한 텍스트 JSON 응답 계약을 검증한 뒤 tool_calls로 변환한다. 전체 응답 검증 전에는 실행하지 않으며 현재 답변은 버퍼링한다. 연결 테스트는 인증된 GET {base}/chat/v1/models로 유효한 모델 목록을 확인하며 추론을 실행하지 않는다. modelId는 API 요청에만 사용하고 모델 선택 UI는 name의 ko 이름을 우선 표시한다. 목록을 등록한 뒤 기존 입력창의 모델 선택을 공유한다. 선택한 ID가 목록에 없으면 첫 모델을 사용한다. 테스트 영수증은 소유 문서와 clientId에 묶고 5분 만료, 변경/취소/로그아웃 시 폐기한다. 키는 trusted session에만, 비밀이 아닌 연결 설정은 local에 보관한다. 기존 Pi/Playwright/스킬/컨텍스트/제공자 대화 분리를 공유한다. 확인된 입력 계약이 텍스트이므로 FabriX는 모델 이름과 관계없이 시각 판단용 화면 캡처/좌표 도구를 광고하거나 실행하지 않는다. 실제 추론 usage만 제공자별 집계한다. 모델 설명의 [Context] 값이 있으면 용량을 추출하며 없으면 미제공이다. 4096은 내부 출력 예산이며 제공자 최대 한도로 간주하지 않는다. FabriX 계정 한도 API는 미확인이다.

페이지 이미지 다운로드는 find_images → 의미/시각 비교 → attach_images로 실행한다. 설명과 실제 후보가 명확하면 바로 첨부하며, 모호할 때만 ask_user의 image_refs로 실제 보관된 후보 2~4개를 제시한다. 근거 없는 선택지를 만들지 않고 후보가 없으면 짧은 자유 입력 질문을 사용한다. 질문은 대화에 보관하고 모델/도구 루프를 멈춘다. 선택은 해당 질문/대화에 검증하며 직접 입력도 가능하다. 새로고침 후 질문과 파일을 복원하고, 기존 초안을 선택 답변으로 지우지 않는다. 이미지 지원 모델의 inspect_images는 실제 파일을 확장 문서에서 번호 붙은 비교 PNG로 만들어 모델에만 전달한다. 원본 바이트는 모델/진단/체크포인트에 넣지 않으며 웹페이지 CSP에 기대어 썸네일을 만들지 않는다. SVG는 허용된 정적 도형과 로컬 참조/스타일만 내보내고 문서/도형 변경 시 관찰 ref를 거부한다.  정적 isolated-world observer가 DOM의 currentSrc/CSS 배경과 opaque ref를 수집하며 documentId/관찰 nonce/현재 src를 검증한다. 이미 로드한 브라우저 리소스 본문을 먼저 읽고 해당 문서 fetch로 보완한다. 임의 URL 다운로드나 모델 코드에 fetch/CDP를 제공하지 않는다. 원본 파일은 기존 캡처 IndexedDB/제공자별 대화 수명과 한도를 공유하며 한 파일은 20 MiB다. 모델에는 파일 바이트나 서명 URL을 전달하지 않는다. 시각 판단 기능과 분리하여 텍스트 모델에도 이미지 검색/첨부 도구를 제공한다. 카드에는 이미지/이름/오른쪽 다운로드만 표시한다. 호스트 주소, 파일 형식 배지, 중복 확대 아이콘, 다운로드 완료 체크는 넣지 않고 상세 정보는 확대 모달에 둔다.

FabriX의 로컬 tool protocol 오류를 HTTP 502로 표시하지 않는다. 전체 JSON 코드 블록만 정규화하고 형식 실패는 새 nonce로 한 번 교정한다. 실패 원문은 재전송/보관하지 않고 검증 전 도구를 실행하지 않는다. 실제 HTTP 오류, 필터, 길이 제한과 취소에는 교정 재시도를 하지 않는다. 진단은 허용된 사유/시도/상태만 기록하며 교정 호출은 별도 usage round로 집계한다. 최종 컨텍스트 토큰에 재시도 사용량을 합산하지 않는다.

OpenWiki의 기본 흐름은 설정의 폴더 선택 → 필요할 때 Wiki 검색/읽기 → 브라우저 작성/조작/검증이다. File System Access의 읽기 전용 폴더 핸들을 IndexedDB에 저장하며 프로젝트를 고르면 openwiki 하위로 좁힌다. 임시 선택 핸들은 clientId/만료를 검증한 worker의 직렬 큐에서 활성화한다. 매 도구 요청은 연결 ID와 현재 권한을 확인하며 재시작 후 필요할 때 사용자 제스처로 권한을 복구한다. 폴더 모드에는 원본 코드/쉘/쓰기 도구가 없다. 로컬 서버는 원본 소스 조회용 선택 기능이다. OpenWiki 읽기 연결은 docs/OPENWIKI-BROWSER-CONNECTION.md를 따른다. 기존 로컬 OpenWiki 서버를 직접 호출하며 별도 라우터는 없다. 프로젝트 도구는 worker lease/허용 도구 검사 뒤 페이지 연결 전에 실행하며 connectionId에 묶는다. UI에는 이름, 모델에는 이름/기능과 필요한 문서/소스 발췌만 제공한다. 세션 토큰은 trusted session에만 두고 모델/진단/local에 저장하지 않는다. 현재 OpenWiki 탭의 일회 meta 코드로 연결하며 서버가 명시한 project-root 안에서 읽기만 한다. 연결 변경은 실행 중 막고 재시작/만료 시 재연결한다. 사용자 파일 첨부는 별도 IndexedDB에 보관하고 대화에는 참조만 저장한다. 파일 선택/끌어놓기/이미지와 긴 글 붙여넣기는 같은 첨부 흐름을 사용한다. 모든 첨부는 64px 높이/36px 아이콘/14px 파일명/12px 형식·크기를 공유한 한 줄 카드다. 가로 스크롤과 Tab 초점 이동으로 뒤의 파일을 확인한다. 미리보기는 공통 CX 모달/본문 틀과 오른쪽 하단 복사·다운로드를 사용하며 일반 텍스트를 코드처럼 표시하지 않는다. PDF와 DOCX는 번들 worker에서 텍스트만 추출하며 원본 다운로드를 유지한다. 원격 파서/HTML 실행/OCR은 없고 파서 RPC는 종류/요청 ID를 검증한다. 초안/대화/제공자 수명에 묶고 삭제/저장 실패 때 정리한다. 전송 전 선택 모델의 이미지 지원을 검사하며 AI Pro는 Qwen3.8, ChatGPT는 Pi 카탈로그의 image 입력 지원을 따른다. FabriX는 텍스트 첨부만 전송한다. 이미지/텍스트는 원본 참고 자료이며 현재 화면/로컬 프로젝트 또는 실행 지시로 취급하지 않는다. Pi/OpenAI/Responses 변환에서 이미지와 텍스트를 유지하고 요약/요구사항 검토에는 파일 출처와 텍스트를 보존한다. 파일 수정/빌드/터미널은 미구현이다. 프로젝트 연결은 선택 기능이며 일반 브라우저 사용에 로컬 설치를 요구하지 않는다.

모델 선택은 CX 아이콘 탭으로 AI Pro/ChatGPT/FabriX를 구분한다. 연결된 탭은 제공자를 즉시 전환하고 해당 대화/초안/선택 모델을 복원한다. 미연결 탭은 기존 연결을 유지한 채 로그인/FabriX 모달을 제공한다. 활성 인증은 기존 credential/catalog/accountUsage, 비활성 연결은 providerSessions에 중복 없이 trusted session으로 보관한다. state와 진단에는 토큰/키를 노출하지 않는다. 브라우저 종료 시 모든 연결이 사라지고 대화는 남는다. 로그인 시작/취소/실패는 기존 인증을 지우지 않고 성공 시에만 전환한다. 진행 중인 응답/로그인/연결 테스트와 제공자 전환은 서로 충돌하지 않도록 직렬화하며 늦은 교환/refresh 결과는 적용하지 않는다.

모달과 탭은 공통 agent-deck 토큰과 surfaces.css를 사용한다. 제목 16/24px, 본문/버튼/데스크톱 입력 14/22px, 입력 이름 14px, 보조 정보 12/16px를 유지한다. 확인 중/완료/중단/실패와 계획의 단계명은 14/22px/400을 유지하고 상태 전환만으로 굵기를 바꾸지 않는다. 삭제 확인 버튼과 상단 토스트도 같은 본문 행간을 쓴다. 토스트는 활성 모달 안에서 접근성을 유지하며 항상 viewport 상단에 고정한다. 모달 전체에는 fixed 기준을 바꾸는 transform을 적용하지 않는다. 좁은 사이드 패널을 휴대폰으로 취급하지 않으며 coarse 포인터에서는 입력 16px/높이 44px를 유지한다. AgentTabs로 제공자/사용량 탭의 옅은 색면, 이동하는 선택 배경, 키보드 조작과 모션 감소를 공유한다.

최종 반영 HITL은 `request_approval`로 완성된 초안 검증 후 채팅에서 받는다. 등록/배포/발송 등으로 인식한 일반 클릭, 제출 키, 화면 클릭에도 같은 가드를 적용한다. 초안 작성/입력은 원래 요청 범위 안에서 자율 진행한다. 승인 대기 시 모델/도구 루프와 디버거 연결을 종료한다. 질문과 최대 4개 필드의 240자 미리보기는 대화 local에 보관하고, 실행 권한은 trusted session의 대화/계정/질문/탭/documentId/실제 DOM 노드/초안 해시/10분 만료에 묶는다. 승인 클릭만 1회 실행을 허용하며 실행 전 권한을 소모한다. 취소와 수정 요청은 기존 권한을 폐기한다. 불확실한 실행은 자동 재시도하지 않고 결과를 재관찰한다. 사이트 자동 저장이나 임의 이벤트 부작용 전체를 차단하는 보안 경계로 주장하지 않는다.

승인 카드의 연필은 실제 입력란 전체 값을 검증된 승인 대상에서 다시 읽어 CX 편집 모달을 연다. 변경한 필드만 사용자 작성 데이터로 새 요청에 전달하며 기존 채팅 초안을 지우지 않는다. 입력란 식별자와 계정/질문/초안 해시를 다시 검사하고 이전 실행 승인은 폐기한다. 에이전트는 수정 내용을 페이지에 적용하고 검증 후 새 승인을 요청한다. 잘린 미리보기로 원문을 덮어쓰지 않는다.

1.0.0 UI 공통 기준은 design/agent-deck.css와 src/surfaces.css로 유지한다. CX의 brand 토큰과 버튼용 cx-button-primary/color-*-primary 별칭을 함께 HTML 팔레트에 연결하며 포털의 실제 기본/호버 색을 확인한다. 반경은 조작 12px, 안쪽 면 16px, 화면 카드/모달 20px의 역할별 토큰을 쓴다. 카드 그림자는 입력란에 전파하지 않는다. 승인 카드도 같은 등장/글꼴/아이콘 규칙을 사용하며 최종 등록/발송 승인 문구는 유지한다. verify:browser는 기능/디자인 스위트(핵심 14개는 3회)를 실행한다. OpenWiki 검사는 packages/openwiki 빌드 뒤 실행하며 실제 로컬 서버와 임시 프로젝트를 사용한다. 검사한 후보 ZIP을 재빌드하지 않고 해시 검증 후 배포 파일로 승격한다. 사용자가 이번 작업에서 명시적으로 요청한 1.0.0 배포는 기존 저장소의 누비 확장 릴리스에 한정하고 다른 앱 버전은 바꾸지 않는다.


질문 UI는 승인과 공통 interaction-forms.css를 쓴다. ask_user는 실제 이미지 후보 또는 2~4개 텍스트 선택지와 text/long_text 입력을 지원한다. 선택지와 이미지 후보는 혼합하지 않고, 임의 후보/인증값 질문/최종 실행 승인은 이 도구로 만들지 않는다. QUESTION_DRAFT는 현재 제공자/대화/미응답 질문에 묶어 local에 보관하며, START_CHAT의 choice.text는 해당 질문에만 답하고 승인 권한이 되지 않는다. 답변은 일반 채팅 초안/첨부를 소비하지 않는다. HITL 편집창은 닫아도 화면 내 수정 내용을 유지하며 미반영 수정이 있으면 등록 대신 수정 계속을 표시한다. 페이지 반영 시에는 기존 실제 대상/해시 검증과 새 승인 절차를 유지한다.

CSP connect-src의 로컬 HTTP 대상은 localhost와 127.0.0.1만 사용한다. IPv6 리터럴은 CSP 문법에서 허용되지 않으며 이를 위해 http: 전체를 허용하지 않는다. OpenWiki 직접 연결 주소도 같은 범위를 검증한다. 로그인 IPv6 콜백은 별도 탐색 리다이렉트 규칙으로 유지한다. tests/csp-browser.mjs는 수정하지 않은 배포 manifest에서 CSP 파서 경고와 실제 로컬 요청을 검사한다.

진행 방법, 대상, 필수 정보가 불명확하면 추측 실행 전에 ask_user로 질문한다. 안전한 조회로 확인할 수 있으면 먼저 관찰하되 불명확하면 질문하고 답변을 기다린다. 질문 도구는 페이지 없는 텍스트 스킬과 읽기 전용 스킬에도 제공하되 실행 권한은 늘리지 않는다. 질문이 섞인 모델 응답에서는 질문 하나만 실행하고 같은 응답의 다른 도구는 실행하지 않는다. blocked 결과 검토는 180자 이내 질문으로 기존 질문 저장/대기 경로에 연결한다. 질문을 저장하지 못하면 후속 실행을 막는다. 질문 전 원래 목표를 보관하여 답변으로 대체하지 않고, 최종 실행 승인은 별도 request_approval로 유지한다.

페이지 분석은 수동 관찰을 우선한다. 본문은 인라인 순서를 유지하며 query는 관찰된 키워드의 주변 발췌로 좁힌다. 텍스트/URL 검증은 디버거 없이 최대 5초 대기하고, 비활성 필드의 읽기와 쓰기를 구분한다. 최종 script snapshot의 ref를 반환 직후 재관찰로 무효화하지 않는다. 실패한 도구와 같은 응답의 뒤쪽 호출은 실행하지 않고 다음 모델 판단을 받는다. 하네스는 연속 오류 2회 또는 브라우저 작업 도구 5회 이상 실행 뒤 다음 모델 판단 전에 같은 제공자/모델로 중간 요구사항 검토를 수행한다. 중간 검토 실패는 완료 증거로 쓰지 않고 기존 실행/최종 검증을 유지한다. 최종 보완은 새 근거로 진전이 있으면 계속하며, ref 변경만으로 진전을 인정하지 않는다. 동일 호출/결과 3회 반복은 질문으로 전환한다. 합성 제어 흐름 검사와 실제 모델 정확도 평가는 구분한다. eval:agent는 별도 프로필의 합성 페이지에 실제 AI Pro 모델을 호출하며 설정이 없으면 미실행으로 기록한다.

브라우저 작업은 채팅에 작업 계획을 먼저 저장한 뒤 실행한다. 모델이 계획 없이 도구를 요청하면 같은 제공자에서 짧은 계획만 먼저 생성하며 일반 대화나 선행 질문에는 계획을 강제하지 않는다. 단계 전환은 update_plan으로 하고 도구 기록은 실행 시작 시의 단계에 연결한다. 계획은 답변별 progress로 보관해 다음 턴/이력/새로고침에 남긴다. 완료 표시는 최종 요구사항 검토와 실제 task 완료에 따르며 질문/승인/중단의 미완료 단계는 유지한다. 진행률은 시간 추정 대신 완료 단계 수로 표시하고 실행 상세는 접는다.

실행 중에는 최근 도구와 짧은 공개 진행 설명을 채팅에서 펼쳐 보여주며 최종 답변 뒤에는 접는다. progress 메타데이터는 실제 도구 인자/중복 실행 판정/검증 근거에서 제외하고 표시 이름으로만 사용한다. 스피너/완료/실패는 실제 도구 이벤트에서 정하며 모델의 reasoning 필드는 기록하지 않는다. 활성 소유자만 중간 trace를 저장할 수 있고 FINISH_CHAT이 최종 기록을 확정한다.

브라우저 하네스는 Pi beforeToolCall에서 한 응답의 첫 실제 도구 결과 뒤 나머지 호출을 모델 재판단까지 보류한다. 앞선 update_plan/select_tools 메타데이터는 허용한다. 보류는 실패/실행 이력/진행 스피너로 표시하지 않으며 호출-결과 쌍은 모델 대화에 보존한다. Playwright 스크립트는 관찰된 입력란 묶음을 작성할 수 있지만 클릭/메뉴/선택/이동/탭 전환 뒤 추가 행동은 호스트 체크포인트에서 중단하고 최신 관찰을 반환한다. yielded/completed=false는 부분 실행이며 다음 모델 호출에서 이미 수행한 동작을 반복하지 않고 남은 작업을 선택한다. 읽기와 마지막 snapshot은 허용하고 승인/중지/팝업 대상 검증을 유지한다. 작업 누적 횟수 제한은 추가하지 않는다.

한 동작 뒤 재판단하는 규칙은 읽기 전용 스킬에도 적용하며 쓰기 권한을 늘리지 않는다. 다음 모델 요청은 직전 도구의 실제 입력/결과와 실패/부분 실행을 비교해 남은 행동을 고르도록 안내한다. 미검증 페이지 동작이 있으면 update_plan의 새 완료 표시는 보류하고 실제 verify_page 결과 뒤에만 허용한다. 실행 표시는 Pi 사전 검사를 통과한 호출에만 붙인다. 공개 진행 설명은 확인한 사실과 다음 행동만 담고 내부 reasoning이나 원시 입력/결과를 기록하지 않는다.

질문 복구는 planner/reviewer의 검증된 ask_user 형식을 공유한다. 같은 검토에서 새 근거가 없으면 질문만 가능한 호출로 필요한 한 가지를 묻고 대기하며, 답변 뒤 기존 목표를 재개한다. 링크의 관찰/참조/클릭은 browser-dom의 의미와 가시성 계산을 공유한다. display:contents 링크는 검증한 원래 노드 안의 보이는 비대화형 자식에 실제 입력을 보내고 force/DOM click/주소 우회는 쓰지 않는다. 세부 판단과 출처는 docs/BROWSER-LINK-RELIABILITY.md를 따른다. 링크의 여러 줄 hit area는 같은 노드에 도달하는 실제 지점을 골라 Playwright position에 넘긴다. 강제 클릭과 Enter/주소 우회는 하지 않는다. 호버 이벤트 후보를 관찰하고 aria-controls/owns의 메뉴를 제한 시간 안에서 기다린 뒤 최신 관찰로 모델에 반환한다. 스크립트 호버도 실행 기록/캡처 무효화에 포함하고 다음 행동은 재관찰 뒤 수행한다. docs/BROWSER-HOVER-LINKS.md를 따른다.

토글은 native checked와 aria-checked/pressed를 공유 관찰기로 읽고 원하는 상태를 지정한다. 이미 맞는 상태는 클릭하지 않으며 실제 label 연결만 사용한다. control_state/control_expanded 검증과 Qwen 캡처의 ref/화면 좌표를 함께 쓰고 data-state는 힌트로 구분한다. 대상 오류의 자동 캡처는 읽기이며 실행 재시도가 아니다. 모델 연결 복구는 p-retry의 추론 전용 재시도(일시 오류 최대 3회, 무응답 120초)로 처리한다. 완료한 브라우저 동작은 재실행하지 않고 사용자 취소/인증 거절/승인 대기는 유지한다. 전체 작업 시간 제한 대신 진행에 따라 갱신되는 무활동 감시와 요청 소유자의 lease 갱신을 사용한다. docs/BROWSER-CONTROL-RECOVERY.md를 따른다.

키보드 입력은 정확한 노드의 초점을 확인한 뒤 발행하며 초점 이동 시 남은 키를 중단한다. 자동완성의 controls/activeDescendant와 편집 상태를 관찰하고 일반 fill과 짧은 pressSequentially를 구분한다. 글자별 입력 후에는 모델 재판단을 요구하고 부분 입력은 재전송하지 않는다. 초점 변화만으로 실패 누적을 초기화하지 않는다. 범위와 근거는 docs/BROWSER-INPUT-QUALITY.md를 따른다.

이미지 입력이 포함된 요청은 현재 제공자의 인증된 목록에서 이미지 지원 모델로 자동 라우팅한다. AI Pro는 확인된 Qwen 3.8 계열 중 QWEN3.8-27B-FP8-256K를 우선하며 CLI 이름만 있으면 해당 반환 모델을 사용한다. 계정/제공자를 자동 변경하거나 목록에 없는 모델을 만들지 않는다. Pi의 같은 계획/도구 결과/대화를 유지하고 실제 이미지 요청에만 전환한다. 저장된 모델 선택은 유지하며 답변 모델명과 진행 내역은 실제 요청 모델을 반영한다. 공유 컨텍스트는 가능한 두 모델의 작은 한도에 맞추고 토큰은 두 요청 모두 기존 제공자 사용량에 합산한다. FabriX 이미지 전송은 어댑터 지원 전까지 비활성이다.

Qwen의 출력 한도 복구 지침은 기존 첫 system 메시지에 합친다. 두 번째 system 역할을 추가하면 Qwen3.8 템플릿이 요청을 거절한다. AI Pro HTTP 오류는 제한된 응답 본문에서 고정 사유만 분류하며 진단에는 원문을 저장하지 않는다. stream_options의 명시적인 거절만 필드를 빼고 모델 요청을 한 번 재시도하며, 실행된 도구/모델 선택/영수증은 유지한다. 도구 실행 후 출력 한도와 422 복구 회귀는 새 Chrome 프로필로 3회 검증한다.

역할별 분석은 기존 Pi 안에서 최대 두 개의 독립 문맥으로 실행한다. 전체 대화를 복제하지 않고 지정한 관찰 ID/작업/제약/완료 조건만 전달한다. 화면/검토/복구 담당은 지정 근거만, 문서 담당은 기존 연결의 읽기 도구만 사용한다. 시작과 결과 수집을 분리하고 Pi prepareNextTurn에서 완료된 요약/근거를 다음 판단에 한 번만 전달한다. 역할별 목표/제약/완료 조건/effort와 근거 ID 집합이 같은 작업은 재사용한다. effort는 quick 3회/16K자, standard 6회/32K자, deep 10회/48K자다. 긴 근거는 기존 MiniSearch로 원문 구간을 좁히고, 빈 조회/부분 검색을 확인 증거로 만들지 않는다. 보고에는 실제 읽은 구간의 최대 320자 발췌와 호스트의 성공/실패 상태를 붙인다. 복구 담당 외에는 실패 조회만으로 뒷받침한 사실을 완료 보고로 인정하지 않는다. 큰 주 문맥의 오래된 성공 읽기는 원본 전체가 실행 저장소에 있을 때만 재조회 가능한 참조로 바꾸고 최근 두 읽기/실패/이미지/쓰기는 유지한다. 역할별 마지막 호출은 확보한 발췌의 부분 결과 정리에 예약하며 전체 사용자 작업 횟수를 제한하지 않는다. 페이지 조작/HITL/최종 검증은 주 실행기에 남기며 분석 요약을 실행 증거로 사용하지 않는다. 현재 연결과 이미지 라우팅을 재사용하고 모든 요청 usage를 집계한다. 문맥 요약과 별도로 작업 레지스트리를 유지하되 현재 실행 종료/질문/승인/취소에서 자식도 종료한다. 다른 제공자 라우팅과 재시작 복원은 아직 없다. docs/ROLE-AGENTS-IMPLEMENTATION.md와 docs/ANTHROPIC-HARNESS-QUALITY.md를 따른다. 진행 설명과 짧은 표시명은 기존 안전한 Markdown 렌더러와 CX 토큰을 공유하고 실제 상태 아이콘은 유지한다. 진행 중인 담당은 최근 기록이 늘어나도 숨기지 않는다.

오류 복구는 추론 재시도와 도구 수정/결과 확인을 분리한다. p-retry의 지연 편차와 제공자 Retry-After를 적용하며 같은 실행의 분석 담당도 대기를 공유한다. 긴 서버 대기를 잘라 조기 재시도하지 않는다. 미등록 도구/인자 오류는 Pi 결과로 모델에 돌려주고, 쓰기 RPC 응답 유실은 최신 관찰 전 추가 쓰기/승인/완료를 막는다. 불완전한 SSE 도구 호출은 실행하지 않는다. 검토 JSON/근거 오류는 같은 증거로 한 번 교정하며 사용자 취소/인증 오류는 자동 재개하지 않는다. docs/ERROR-RECOVERY.md를 따른다. Pi 사전 검사와 실행 전 검사는 TypeBox 인터프리터로 원본 인자를 확인하고 값 없이 선언된 필드/규칙만 최대 네 개 반환한다. 성공한 verify_page는 해당 검증 복구 구간만 초기화하며 읽기/새 참조/추가 쓰기는 초기화하지 않는다. docs/HARNESS-REPAIR-QUALITY.md를 따른다.

HTTP 200 스트림의 오류는 고정 code/type으로 분류해 기존 추론 복구에 전달한다. 알려진 일시 오류만 재시도하며 할당량 소진/인증/알 수 없는 오류는 반복하지 않는다. 미완성 도구 호출은 폐기하고 이전 실행 영수증을 보존한다. HTTP 상태를 만들어내지 않으며 docs/STREAM-FAILURE-QUALITY.md를 따른다.

브라우저 복구는 같은 화면 재조회 성공이나 새 ref만으로 실패 기록을 초기화하지 않는다. 실행 중에만 프레임/관찰 대상/스크립트 토큰과 실제 결과 변화를 비교한다. 진전 없는 두 실패는 기존 중간 검토로 접근을 재판단하고, 실제 변화는 반복 구간을 초기화한다. 고정 작업 횟수 제한은 두지 않는다. 원인별 안내는 첫 system 메시지에 고정 문구만 합치며 페이지 원문/입력값/비교 키는 진단이나 진행에 기록하지 않는다. Browser Use 패턴과 기존 Pi/Playwright를 적용한 근거는 docs/BROWSER-OUTCOME-RECOVERY.md를 따른다.

화면 상태 조회는 TanStack Query Core 5.103.2(MIT)로 최초 포함 3회/요청별 8초만 대기하고, 소진 후 저장소 알림이나 타이머가 재시도를 다시 시작하지 못한다. 마지막 상태를 유지하며 CX 재연결 아이콘은 상태만 읽는다. 완료/숨긴 화면의 보조 polling을 멈추며, 작업 lease는 실제 소유자의 도구/모델 활동으로도 갱신한다. 조회 장애를 작업 재실행으로 복구하지 않는다. docs/STATE-SYNC-RECOVERY.md를 따른다.

DOM과 OpenWiki 폴더의 관련 근거는 번들 MiniSearch 7.2.0으로 조회한다. 검색 순위/coverage는 후보의 어휘 일치이며 확신이나 실행 권한이 아니다. 부분/잘린 결과에서 대상 부재를 단정하지 않고 영역/프레임/시각 근거를 보완한다. 압축 전 동일한 오래된 페이지 읽기만 정리하고, 실행 중 요약과 별도로 최근 사용자 조건/실행 상태/소스 provenance를 유지한다. 도구 쌍, 실제 검증, 승인과 원본 기록을 보호하는 기준은 docs/DOM-CONTEXT-RETRIEVAL.md를 따른다.

브라우저 하네스의 7단계 기준은 docs/BROWSER-HARNESS-SEVEN-STAGES.md를 따른다. 새 계획은 expected_outcome 완료 조건을 요청하고 상태만 변경해도 보존한다. 조건이 있는 단계의 완료 제안은 실제 검사와 별도 모델 검토를 통과해야 한다. 중간/단계 검토 성공은 최종 완료로 저장하지 않는다. 화면 동작/호버/스크롤 뒤 이전 캡처는 현재 판단 근거에서 제외하고 저장 파일의 존재만 역사적 결과로 남긴다. 드래그는 관찰한 같은 프레임의 두 ref로 실제 입력을 보내고 element_in 등으로 별도 검증한다. 최종 트랜잭션 드롭/프레임 간 드래그/OS 동작은 지원하지 않는다.

요구사항 검토의 입력 예산은 사용자 조건보다 오래된 화면과 Agent 설명을 먼저 줄인다. 무효화된 근거는 인용 불가 영수증으로 축약하고 동일한 과거 읽기만 제외하며 최신 두 읽기와 실제 상태 변화는 보존한다. 사용자 요구를 넣을 수 없으면 검토 실패로 두며 조건을 삭제해 완료시키지 않는다. 재조회 ID/초점 변화는 진전이 아니지만 다른 관찰 대상의 수정은 구분한다. 실행 권한과 원본 대화는 바꾸지 않으며 docs/HARNESS-CONTEXT-QUALITY.md를 따른다.

브라우저 포인터는 실제 Playwright 입력에만 연결되는 선택적 표시 계층이다. deck 토큰을 사용하며 입력/초점을 가로채거나 도구 결과를 변경하지 않는다. 표시 실패/무응답은 제한된 대기 후 실제 행동을 계속하고 중지/탭 전환/캡처에서 정리한다. 캡처에는 표시를 넣지 않는다. 클릭은 같은 노드에 호버한 뒤 Playwright가 위치를 다시 계산하며 강제 클릭이나 입력 재전송을 하지 않는다. docs/BROWSER-ACTION-POINTER.md를 따른다.

업무 스킬은 메타데이터만 카탈로그에 보내고 find_skills/read_skill로 필요한 절차와 자료를 읽는다. 등록 화면은 이름/사용 목적/지침만 받으며 새로 저장한 스킬은 toolMode: automatic으로 일반 채팅의 도구 선택과 필요한 시점의 페이지 연결을 사용한다. 기존 스킬은 편집 저장 전까지 기존 범위를 유지한다. 자동 연결 여부와 선택한 스킬 ID는 별개이며 중단/질문 뒤에도 원래 스킬을 복원한다. 브라우저 권한/탭 소유권/최종 행동 승인은 호스트에서 계속 검사한다. 요청 시작 시 ID/내용 해시를 고정하며 스킬 읽기는 브라우저 연결/추가 권한을 만들지 않는다. SKILL.md 폴더의 텍스트 자료와 JSON v2 공유를 지원하고 스크립트는 참고용이다. 스킬 지침은 완료 검증 근거에서 제외한다. OpenWiki 서버가 features.wiki_query를 광고하면 서버 라이브러리가 질문을 검색하고 제한된 근거 묶음을 반환한다. 폴더/구버전 서버는 기존 검색을 유지한다. 계약과 평가 기준은 docs/OPENWIKI-WORKFLOW-RETRIEVAL.md를 따른다.

첨부 문서 검색은 LangChain RecursiveCharacterTextSplitter 1.0.1과 MiniSearch 7.2.0을 사용한다. 6,000자 초과 첨부 원문은 기본 입력에서 참조로 대체하고 search_documents/read_document로 필요한 구간만 읽는다. 원문은 대화 소유 IndexedDB에 남고 요약 경계 이후에도 조회할 수 있다. 도구 권한은 시작 시 고정한 document ID/hash와 대화/제공자/인증 lease로 검사한다. Pi research 담당에는 배정된 document_ids만 제공하며 부모 대화/다른 문서/브라우저 쓰기 권한을 넘기지 않는다. 문서 근거는 페이지 동작으로 무효화하지 않지만 현재 화면 상태나 승인으로 취급하지 않는다. 검색 무결과는 부재의 증거가 아니며 전체 요약은 원문 범위의 누락을 확인한다. docs/DOCUMENT-RETRIEVAL-HARNESS.md의 선택 근거와 범위를 따른다.

- 누비 앱 간 작업 전달은 `packages/nubi-a2a`의 공식 A2A 1.0 SDK 전송과 수신자별 로컬 연결을 재사용한다. Desktop은 SQLite 작업/근거 조정 서버이며 Chrome/Office는 수신 클라이언트다. 가져온 요청은 기존 채팅에서 명시적으로 전송하고 기존 HITL을 유지한다. 소스/Wiki 버전이 바뀐 결과는 받지 않으며 A2A 완료를 실제 테스트 통과나 Office 저장 성공으로 취급하지 않는다. 미확정 결과는 Task/영수증을 조회하고 실행을 맹목 재전송하지 않는다. 인증은 모델에 전달하지 않는다. 상세 범위는 `packages/nubi-a2a/README.md`와 `packages/nubi-desktop/docs/A2A-COLLABORATION.md`를 따른다.

기본 JavaScript 확인창은 DOM 모달과 구분한다. Playwright context의 dialog에서 confirm/prompt/beforeunload는 취소를 시도하고 같은 실행의 후속 쓰기를 막아 기존 질문 폼으로 전환한다. 최종 승인 직후에도 추가 추론 전에 질문하며 원래 클릭을 재전송하거나 자동 수락하지 않는다. 메시지/기본 입력값은 기록하지 않고 실제 수락 도구는 아직 없다. docs/NATIVE-DIALOG-QUALITY.md를 따른다.

공유 Pi 분석 조정기는 Desktop이 명시한 observationSources의 Windows 근거를 읽기 전용으로 보관할 수 있다. 이 옵션은 하위 분석에 호스트 실행 도구를 추가하지 않으며 기본 Chrome/Office 동작은 바꾸지 않는다. 과거 캡처는 historical, 새 관찰 이전 근거는 stale로 표시하고 주 실행기의 현재 관찰/승인 검사를 유지한다.
