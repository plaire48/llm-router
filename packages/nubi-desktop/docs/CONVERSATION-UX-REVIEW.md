# 대화 중심 Desktop UX 검토

2026-09-25

후속 탭 탐색과 실행 중 대화 조회 정책은 [SESSION-NAVIGATION.md](SESSION-NAVIGATION.md)를 따른다. 아래 실행 중 전환 제한과 검증 수치는 당시 구현 기록이다.

사용자 요청: 본문의 새 작업 요소를 제거하고 다른 데스크톱 앱의 공개 구현에서 활용할 개선을 찾아 반영한다.

## 변경과 이유

| 이전 | 변경 | 이유 |
| --- | --- | --- |
| 요청 위의 새 작업 버튼 | 본문에서 제거. 이력 안의 접근성 이름을 가진 새 대화 아이콘으로 이동 | 작업 중에는 요청과 결과에 집중하고 별도 대화는 필요한 때만 연다. |
| 내부 REQ 번호 상시 노출 | 작업 도구 안에서 확인 | 사용자가 판단할 내용과 내부 식별자를 구분한다. |
| 답변 뒤에도 결과 검토 상태를 상시 표시 | 대기, 중지, 실행 등 행동에 필요한 상태만 표시 | 답변이 끝난 뒤 불필요한 상태 문구를 줄인다. |
| 이력 목록을 순서대로 탐색 | 요청 문구 검색과 현재 대화 표시 | 이전 작업을 찾는 단계를 줄인다. |
| 모든 대화가 하나의 입력 상태 공유 | 프로젝트와 대화별 초안 분리 | 미전송 문구가 다른 작업으로 섞이지 않는다. |
| 새 작업으로 이동하면 실행 중 화면과 제어를 놓칠 수 있음 | 실행 중 별도 대화 전환과 중복 전송 제한 | 실제 실행 상태를 계속 확인하고 원래 작업을 중지할 수 있다. |
| 코드 변경만 묻는 입력 안내 | 무엇을 도와드릴까요? | 코드 분석 외에 Wiki와 Windows 업무 요청도 받는 목적에 맞춘다. |

기존 HTML/CX 글꼴, 색상, 새 로고와 입력 외곽선을 유지한다. 질문과 승인, 중지 동작은 숨기지 않는다. 새로운 UX 패키지는 추가하지 않고 기존 React, CX의 DetailPanel, CxInput, ActionButton과 Deck 컴포넌트를 재사용한다.

## 내려받아 분석한 공개 소스

설치 EXE를 역분석한 것이 아니라 공식 저장소의 공개 소스와 라이선스를 내려받아 확인했다. 외부 설치 프로그램이나 받은 코드를 실행하지 않았다. 소스 출처와 SHA-256은 이 검증 폴더의 `sources.json`에 기록한다.

- [OpenCode](https://github.com/anomalyco/opencode): MIT. `packages/app/src/context/prompt.tsx`와 `components/prompt-input/submit.ts`를 커밋 `16c56fe5ecc3305028d1f0a9cff5806e51c9d480`에서 확인했다. 프로젝트/세션 범위의 입력 상태와 전송 처리를 분리하는 설계를 참고했다. Solid 기반 UI 코드를 React 앱에 복사하는 대신 기존 React 훅에 적용했다.
- [Goose](https://github.com/aaif-goose/goose): Apache-2.0. 기존 block/goose 경로에서 `ui/desktop/src/components/sessions/SessionListView.tsx`와 라이선스를 확인했다. 검색을 이력 화면 안에 배치하는 패턴을 참고했다. Goose의 서버 검색과 날짜 그룹화, 대량 목록 처리를 통째로 이식하지 않았다. 누비에서는 현재 제공되는 최대 50개 작업의 요청 문구를 검색한다.
- [Microsoft Command bar](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/command-bar): 주요 행동과 보조 명령을 분리하고 일관된 위치에 두는 공식 지침을 참고했다. WinUI 런타임이나 컨트롤을 Electron 앱 안에 추가하지 않았다.

코드는 복사하지 않았으므로 새 외부 소스 번들은 없다. 원래 라이선스와 선택 근거를 기록했다. Windows 설치 앱을 직접 실행해 비교한 것으로 표시하지 않는다.

## 초안과 실행 경계

초안은 같은 창의 `sessionStorage`와 메모리 캐시에 둔다. 키는 프로젝트 ID와 대화 ID를 JSON 배열로 구분하며, 아직 전송하지 않은 대화에는 별도 null ID를 쓴다. 렌더러 새로고침 후 같은 대화에서 복원되지만 앱/창 종료 뒤 영구 보존을 보장하지 않는다. 저장소 제한이 있으면 메모리에서만 유지한다.

미전송 초안을 모델에 보내거나 자동으로 실행하지 않는다. 후속 요청은 실행 요청이 수락된 후 비우며, 새 요청은 작업 기록 생성이 성공한 후 대화로 전환한다. 전환만으로 기존 작업을 중지하거나 승인을 넘기지 않는다. 실행 중에는 별도 대화를 여는 대신 현재 작업으로 돌아갈 수 있고 호스트 상태 조회를 유지한다.

## 검증

공유 UI 검사에서 버튼/내부 번호 제거, 이력 검색, 대화 사이 초안 분리, 같은 창 새로고침 복원, 실행 중 새 대화 제한을 확인한다. 실제 Theia 화면과 기존 질문/승인/저장/스킬 등록 검사는 별도로 수행한다. 합성 UI 모델 응답은 실제 모델의 의도 이해나 Windows 업무 성공 근거가 아니다.

검증 결과: Desktop 테스트 231개, Theia 화면 49개, 스킬 등록 화면 12개, 공유 UI 23개 통과. 개발 번들 빌드 통과. 전후 화면과 검사 기록은 `verification/conversation-ux-20260925/`에 보관했다. Windows 설치 파일은 다시 배포하지 않았다.
