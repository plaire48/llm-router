# 사용자 의도로 구성하는 작업

2026-09-25

사용자는 원하는 결과를 말한다. 누비는 요청과 후속 답변을 바탕으로 필요한 도구와 스킬을 선택하고, 기존 한 작업 화면에서 계획과 결과를 이어간다.

## 이번에 반영한 부분

1. **관련 스킬을 먼저 제시한다.** 첫 모델 요청에 프로젝트 카탈로그의 이름과 설명을 검색한 후보 8개를 제공한다. 기존의 이름순 20개 노출을 바꿨다. 최근 사용자 메시지와 원래 요청을 검색하며, 후보에 없는 스킬은 기존 검색 도구로 다시 찾는다. 본문과 스크립트는 이 단계에서 읽거나 실행하지 않는다.
2. **목표와 확인할 결과를 계획에 연결한다.** 첫 도구 실행 전 계획에는 원하는 결과, 유지할 조건, 관찰 가능한 예상 결과, 필요한 작업 종류와 스킬 경로가 들어간다. 여러 종류를 함께 선택할 수 있으며 사용자가 모드를 고를 필요가 없다. Ajv가 구조와 실제 카탈로그 범위를 검사한다.
3. **선택한 스킬을 실제로 읽는다.** 누비가 계획에서 선택한 스킬은 `use_skill`로 로드한다. 긴 본문은 연속된 구간을 끝까지 읽어야 프로젝트 작업을 진행한다. 본문 버전이 달라졌거나 문맥 압축으로 로드 상태가 해제되면 다시 확인한다. 스킬 선택은 설치, 실행, 변경 승인으로 사용하지 않는다.
4. **결과가 의도에 맞는지 검토한다.** 기존 독립 검토가 원래 요청과 사용자 조건을 우선 확인하고, 모델이 도출한 예상 결과와 보존 조건도 별도 항목으로 확인한다. 모델의 해석이 원래 요청을 대신하거나 완료 상태를 만들지 않는다.
5. **문맥 압축 시 중복을 줄인다.** 현재 목표, 사용자 답변과 최신 실행 기록은 보존한다. Desktop이 현재 기록으로 대체한 최초 호스트 스냅샷은 압축 문맥에서 제외한다. 공유 문맥 관리기의 선택적 콜백을 사용하며, 지정하지 않은 호스트의 동작은 그대로다.

예를 들어 “이 VOC 원인을 찾아서 문구를 수정하고 화면까지 확인해 줘”라면 VOC와 Wiki 조회, 소스 변경, 실행 환경과 화면 비교를 필요한 만큼 조합할 수 있다. 각 종류는 경로 안내일 뿐 고정 실행 순서나 권한이 아니다. 실제 선택 적절성은 모델 평가가 필요하다. 현재 JSM 자동 수집이나 A2A 위임을 지원한다고 표시하지 않는다.

| [Ajv](https://github.com/ajv-validator/ajv), MIT | 의도와 계획의 구조 검사 | 기존 8.20.0을 실제 적용. 존재하지 않는 작업 종류와 스킬 경로 거부 |

[Anthropic의 도구 검색 방법](https://www.anthropic.com/engineering/advanced-tool-use)에서 필요한 정보만 찾고 로드하는 원칙을 참고했다. 누비의 이번 변경은 스킬 메타데이터 검색과 본문 지연 로딩이다. Anthropic 전용 `defer_loading` API, 모든 도구 스키마의 동적 제거, Programmatic Tool Calling을 구현한 것으로 표시하지 않는다. 기존 제공자 공통 도구 계약을 유지한다.

신규 패키지는 추가하지 않았다. 기존 잠금 버전의 실제 라이선스를 확인했고, 참고 구현의 소스 코드를 복사하지 않았다. 모델에 추가되는 의도 해석은 기존 계획 호출 안에서 처리한다. 후보 목록과 검토 항목이 입력량을 늘릴 수 있으므로 기존 예산 검사와 압축을 유지한다. 스킬 해시 확인은 선택된 최대 4개에 한정한다.

## 검증과 남은 범위

`tests/intent-routing.test.mjs`는 실제 파일 카탈로그와 Pi 실행기에 지정 응답을 넣어 다음 계약을 검사한다.

- 이름순 뒤쪽의 관련 스킬 검색과 최근 요청 반영
- 여러 작업 종류 선택과 존재하지 않는 기능 거부
- 선택한 긴 스킬 본문을 끝까지 읽기 전 프로젝트 작업 차단
- 사용 중 스킬 변경 감지와 다음 작업 차단
- 의도가 없는 첫 계획의 실행 차단
- 압축 뒤 원래 의도 유지와 스킬 재조회

이는 실제 사용자 의도 분류 정확도나 사내 모델의 과제 성공률 측정이 아니다. 후속 실모델 평가는 단순 대화, 코드 조사, 수정과 검증, VOC와 Wiki 결합, 모호한 요청, 뒤늦은 제약 변경, 읽기 전용 요청, 설치 승인 대기를 포함해야 한다. 각 과제의 독립 정답과 실제 실행 결과, 잘못된 도구 선택, 불필요한 질문, 비용을 함께 평가한다. Windows 11 업무 앱 실사용과 설치 파일 재배포는 이번 검증 범위가 아니다.

최종 로컬 검증: Desktop 테스트 231개, 공통 문맥 검사 49개, 실제 Theia 화면 검사 49개 통과. TypeScript 컴파일과 브라우저 번들 빌드 통과. 결과와 소스 해시는 `verification/intent-driven-agent-20260925/`에 보관한다.
