# Source navigation, progress folding and saved projects

The source-opening preflight in Workbench omitted `projectId`, although `editorSource` requires an exact project identity. A valid citation therefore failed with `project_changed` before reaching the editor. Pass the selected project to that read and to the editor presentation check. Preserve the source hash and dirty-buffer checks. A real project switch or changed source remains a refusal with a Korean recovery message. Overview reads also reject results if their project/store changed while filesystem operations were pending.

A response in `review` or `completed` folds the shared plan and progress disclosures once, without deleting their records. The user can reopen them. The next run opens its own progress. Questions, approval waits and failures stay visible and are not promoted to completion. Existing shared TaskPlan and AgentTrace are reused without changing other hosts.

Successfully opened folders enter the Electron-owned `projects.json`. Folder/ZIP/Git opening, saved-project selection, alias changes and removal use the same project-opening boundary. Catalog writes are serialized and atomically replaced; damaged data is not silently overwritten. Only saved IDs can select a folder through the switch IPC. Legacy `last-project.json` migrates when opened. Removing a shortcut never deletes files or project databases; removing the active project first returns to personal chat.

The left sidebar groups the active project's conversations under its folder and lists other projects as collapsed rows. Names truncate instead of wrapping. Rename/remove actions use the existing horizontal popover, with common CX fields and confirmation. Folders can be added while AI is disconnected. On compact windows the project drawer and scrim sit above the auxiliary editor; the underlying editor stays mounted.

A single worker retains the current project. In-flight work and unsaved editor changes prevent switching. Conversation selection and drafts use the existing per-project storage; editor tabs and Monaco undo stacks remain in memory per project while the window stays open. Project catalog entries and aliases survive app restart. This is not simultaneous agent execution in multiple projects, nor a promise to persist Monaco undo or session drafts across app restart.

No new dependency was added. Reuse the existing project-scoped SQLite store, composer draft/session navigation helpers, source hash readback and shared CX controls. The catalog stores navigation metadata only and does not read another app's credentials.

Local verification: 635 supported tests passed, 197 existing disabled-feature skips, zero failures. The modal suite passed 33 checks; the scripted-model Electron agent passed 10 checks including automatic folding on response arrival. Native Electron source/navigation checks cover source opening, retained scope guard, two-project switching, drafts and tabs, dirty-buffer blocking, stale-source refusal, alias persistence, list-only removal, restart and compact menu hit testing. These use isolated files and a saved/scripted answer, not a live company account or model.
