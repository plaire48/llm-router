# 프로젝트 대화와 모델 선택

## 선택 근거

- [Codex 앱](https://openai.com/index/introducing-the-codex-app/)의 프로젝트별 스레드 구성은 작업 맥락을 찾는 기준으로 참고했다. Codex의 병렬 작업은 별도 worktree를 쓰므로 단순히 탭을 늘리는 것과 구분했다.
- [Claude Code Desktop](https://code.claude.com/docs/en/desktop)의 여러 세션, 프로젝트/상태 필터와 분할 화면은 탐색 기준으로 참고했다. 현재 누비는 작업 화면을 단순하게 유지하기 위해 분할 화면을 추가하지 않았다.
- [OpenCode](https://opencode.ai/docs/tui/)의 세션 전환과 프로젝트 경로 개념을 참고했다. 기존 React/CX 컴포넌트와 저장소로 충분하므로 새 탐색 패키지는 도입하지 않았다. OpenCode 구현을 복사하지 않았다.
- [Theia의 초기 레이아웃 지침](https://theia-ide.org/docs/frontend_application_contribution/)에 따라 누비 뷰는 저장된 사용자 IDE 배치를 덮어쓰지 않고 첫 레이아웃에서만 연다. 기존 Theia 확장을 유지하고 별도 IDE 프레임워크는 도입하지 않았다.

## 반영 범위

- 열린 대화는 왼쪽 프로젝트 사이드바에서 전환한다. 닫기는 대화를 삭제하지 않는다. 지난 대화는 사이드바에서 날짜별로 찾거나 검색 창에서 찾는다. 좁은 화면에서는 사이드바를 열어 선택하고, 선택 후 작업 화면으로 돌아온다.
- 입력창에는 현재 제공자와 모델을 표시한다. 선택하면 기존 누비 모델 모달이 열린다. Desktop의 제공자 탭에는 이름도 표시하며, 다른 누비 호스트의 공통 컴포넌트 기본 동작은 유지한다.
- 새 대화와 기존 대화의 미전송 초안은 기존 `useComposerDraft` 저장 경계를 유지한다. 프로젝트별 탭 선택은 로컬 저장소에 보관하고 존재하지 않는 작업 ID는 복원 시 버린다.
- 진행 중인 작업을 보면서 다른 대화를 열어 읽거나 초안을 수정할 수 있다. 기존 프로젝트 실행 소유권은 유지한다. 다른 대화의 전송과 실행은 현재 작업이 끝날 때까지 대기한다. 질문, 승인, 중지는 각 작업의 기존 경계를 따른다.
- 현재 이력은 실행기 `overview/state`가 제공하는 최근 50개 작업에 한정된다. 전체 보관 작업의 페이지 탐색과 서로 다른 프로젝트를 같은 창에서 동시에 실행하는 기능은 이 변경에 포함되지 않는다.

## 토큰과 모션

- 색, 폰트, 크기, 모달은 기준 HTML의 `deck` 토큰과 공통 CX 컴포넌트를 쓴다. 사이드바 너비, 표면, 선택 상태와 전환 시간은 누비 컴포넌트 토큰으로 모았다. CX에 없는 간격 변수는 사용하지 않는다.
- 좁은 화면에서 사이드바가 열릴 때만 기존 모션 토큰으로 짧게 표시한다. 데스크톱에서 너비를 연속 변경해 Monaco를 다시 배치하는 애니메이션은 사용하지 않는다. OS의 움직임 줄이기 설정은 전환 시간을 없앤다.
- 작업 중이거나 입력에 집중할 때 배경의 반복 움직임을 멈춘다. 창이 보이지 않을 때 작업 상태와 분석 이력의 화면 조회를 멈추고 다시 보이면 현재 상태를 읽는다. 백엔드 작업 자체는 계속 실행한다.
- 새 애니메이션·탭 라이브러리는 적용하지 않았다. 지금의 React, CX, Theia와 공유 누비 모션만으로 같은 기능을 제공한다. CPU 개선 수치는 측정 전이며 Windows 11 실사용 성능은 별도 검증이 필요하다.

## 검증

- 단위 검사: 프로젝트별 탭 복원, 오래된 ID 제거, 탭 닫기 후 작업 보존, 날짜 그룹.
- 브라우저 검사: 실행 중 다른 대화 조회와 초안 편집, 전송 차단, 사이드바 전환과 새로고침 후 초안 복원, 날짜별 이력, 모델 변경과 이름 표시, 좁은 화면 가로 넘침.
- 브라우저 검사는 합성 실행 상태다. 실제 Windows 11 설치나 실모델 병렬 실행을 입증하지 않는다.
