# 사용자 스킬 등록과 도구 호출

## 사용자 흐름

상단 `스킬 관리`에서 ZIP 또는 폴더를 선택한다. SKILL.md 한 개를 포함한 패키지를 현재 작업 공간의 `.agents/skills/<name>`에 등록한다. 작업별 Git worktree가 선택되어 있으면 그 작업 공간에 등록한다. 프로젝트 공용으로 쓰려면 새 작업 화면에서 등록한다.

폴더 안의 참조 문서, 스크립트, 템플릿과 중첩 폴더를 함께 복사한다. ZIP은 최상위 SKILL.md 또는 이를 감싼 폴더를 지원한다. 실제 저장 폴더명은 SKILL.md의 name을 사용한다. 이름과 설명만 먼저 목록에 표시하며 원본 지침은 에디터에서 수정할 수 있다. 기존 동일 이름은 덮어쓰지 않는다. 새 버전 자동 교체나 여러 스킬을 한 ZIP으로 묶는 등록은 이번 범위에 포함하지 않는다.

사용자는 문서 종류별 시작 버튼을 누르지 않고 평소처럼 요청한다. Pi 실행기가 다음 도구를 선택한다.

1. `discover_capabilities`: 등록된 스킬의 이름과 설명 검색.
2. `use_skill`: 정확한 경로와 해시로 스킬 활성화. 지침 첫 구간과 하위 리소스 경로 반환.
3. `list_skill_resources`: 100개씩 하위 자료 목록 조회. 다음 페이지는 목록 해시를 확인하고, 목록이 바뀌면 처음부터 조회.
4. `read_skill`: 남은 지침과 필요한 참조 문서만 구간 조회. 참조 문서는 최대 10MB이며 한 번에 8000자까지 읽는다. 이어 읽기는 이전 응답의 resourceHash로 같은 버전인지 확인한다.
5. `read_source`와 기존 작성/실행 도구: 현재 파일을 확인하고 변경이나 스크립트 실행 제안. 기존 반영/명령 승인과 결과 검증 유지.

스킬은 작업 지침이다. 등록 또는 활성화가 스크립트 실행, 문서 완성, 설치 승인으로 이어지지 않는다. 바이너리 템플릿은 원본 바이트로 보관하며 텍스트로 해석하지 않는다. 필요한 경우 실제 도구 지원과 의존성을 확인한 뒤 기존 명령 승인으로 활용한다. 모델 컨텍스트에는 스킬 이름과 설명을 우선 제공하고 본문은 도구로 읽는다. 압축 뒤에는 현재 해시로 다시 읽는다. 실행/반영 권한과 소스 관찰 권한을 확대하지 않는다.

## 방법론과 오픈소스 선택

- [Agent Skills 규격](https://agentskills.io/specification): SKILL.md와 scripts/references/assets 폴더를 쓰는 개방형 형식. 자체 보고서 전용 포맷을 만들지 않는다.
- [Agent Skills 클라이언트 구현](https://agentskills.io/client-implementation/adding-skills-support): 발견, 메타데이터 제공, 모델의 도구 호출에 의한 활성화, 필요한 리소스만 읽는 단계적 로딩 적용. 등록 UI와 모델 실행 권한은 분리한다.
- [Anthropic Agent Skills 설계](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills): 지침, 참조, 코드를 폴더로 조합하고 요청에 따라 필요한 부분을 읽는 설계 적용.
- [yauzl 3.4.0](https://github.com/thejoshwolfe/yauzl) (MIT): 이미 의존성 트리에 있던 Node ZIP 리더를 직접 의존성으로 고정한다. lazy entry와 스트림 크기 검증을 사용한다. 전체 압축 해제 후 필터링하는 방식은 채택하지 않는다. 실제 소스와 라이선스를 확인했다.
- 기존 Pi 0.86.1, YAML 2.9.0, MiniSearch 7.2.0을 재사용한다. 별도 에이전트 프레임워크, Python 런타임, 원격 스킬 저장소는 추가하지 않는다.

## 파일 처리

파일 선택은 Theia FileDialogService를 사용한다. 모델에 등록 RPC나 임의 외부 폴더 읽기 도구를 주지 않는다. 서비스는 크기와 파일 구조를 확인한 뒤 준비 폴더에 쓰고 해시 readback 후 카탈로그 위치로 옮긴다. 처리 중 프로젝트 변경이나 새 에이전트 실행을 막는다.

같은 패키지의 재등록은 저장된 모든 파일의 경로와 해시, 폴더 구성을 다시 읽어 일치할 때만 이미 등록된 상태로 반환한다. 호스트 재시작 뒤에도 같은 방식으로 확인하며 파일을 다시 쓰지 않는다. 사용자가 바꾼 자료나 추가 파일이 있으면 충돌을 표시하고 보존한다. 바이너리 자료 조회는 경로, 바이트 수와 해시만 반환한다. 텍스트로 변환하거나 내용을 추측하지 않는다.

단일 파일 10MB, 전체 20MB, 디렉터리 포함 1000개 항목, 깊이 20까지 지원한다. SKILL.md는 32KB까지다. 경로 이탈, 링크, 비밀 설정 파일, Windows 예약 이름/ADS, 대소문자 또는 Unicode 정규화 충돌, 중복 엔트리, 암호화, CRC 오류를 거부한다. macOS의 .DS_Store와 __MACOSX는 제외한다. 빈 하위 폴더와 한글 경로, 바이너리 파일은 보존한다. ZIP 생성 방식에 따라 빈 폴더 엔트리가 없으면 해당 빈 폴더를 재구성하지 않는다.

카탈로그는 스킬 폴더 120개, 탐색 항목 2000개까지 확인한다. `.pending-*` 준비 폴더는 스킬 수에 포함하지 않는다. 한도에 도달하면 새 패키지를 쓰기 전에 등록을 거부한다. 손상된 지침은 목록의 접힌 오류 안내에서 경로와 수정 방법을 표시한다. Windows 예약 이름은 파일 경로뿐 아니라 실제 저장 폴더가 되는 SKILL.md의 name에도 적용한다. COM¹처럼 특수 숫자가 포함된 장치명도 [Microsoft 파일 이름 규칙](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)에 따라 거부한다.

원본 선택은 로컬 데스크톱 호스트의 파일 선택이다. 원격 웹 서버로 업로드하는 API나 Office의 등록 저장소를 공유하는 기능은 아니다. A2A는 계속 보류한다.

## 검증

- `tests/skill-import.test.mjs`: 폴더와 ZIP, 하위 한글 경로, 빈 폴더, 바이너리 바이트, 중복/경로/CRC/용량 오류, 재열기, 동시 등록 제한 검증.
- 실제 Pi 도구 루프를 합성 모델로 구동하여 사용자 등록 패키지 검색 → use_skill → 하위 참조 읽기와 실행 권한 비확대를 검증.
- `scripts/check-skill-registration.mjs`: 실제 Theia 브라우저 UI, 파일 선택기, 로컬 worker RPC, 디스크 저장, 재진입과 에디터 열기를 검증.
- 실계정 모델의 문서 품질, 실제 Windows 11의 네이티브 파일 선택기와 이번 변경을 포함한 설치 파일은 별도 검증 대상이다. 기존 배포 파일에는 이 변경이 포함되지 않는다.

`tests/skill-quality.test.mjs`는 긴 참조 문서, 버전 변경, 바이너리, 동일 등록 재시도, Windows 예약 이름, 준비 폴더와 카탈로그 한도, 자료 목록 페이지를 검증한다. 실제 Pi 루프와 합성 모델로 등록 스킬 검색부터 활성화, 자료 조회, 변경 오류 후 다시 읽기까지 연결한다. 최종 재검증 결과와 증거 경계는 [품질 재검증 기록](QUALITY-RECHECK.md)을 따른다.
