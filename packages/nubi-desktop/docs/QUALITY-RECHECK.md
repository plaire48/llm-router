# 누비 Desktop 품질 재검증

2026-09-23. 최근 추가된 사용자 스킬 등록부터 Pi 도구 호출까지를 우선 점검하고, 전체 Desktop 회귀 검사로 기존 실행 흐름을 확인했다.

## 발견한 문제와 반영

| 문제 | 수정과 검증 |
| --- | --- |
| 긴 참조 파일을 등록해도 읽지 못하고 이어 읽기 중 수정된 버전을 섞을 수 있음 | 최대 10MB를 제한된 스트림으로 읽고 8000자씩 반환. 이후 페이지는 파일 해시 확인. UTF-16 문자 경계 보존. 바이너리는 바이트 수와 해시만 반환 |
| 등록 응답을 놓친 뒤 같은 패키지를 재등록하면 무조건 충돌 | 실제 저장된 파일 해시와 폴더 구성을 확인하고 같으면 변경 없이 응답. 사용자 수정과 추가 파일은 충돌로 보존. 호스트 재시작 뒤 같은 검사 |
| 자료가 100개보다 많으면 나머지 경로를 알 수 없음 | `list_skill_resources` 추가. 목록 해시와 다음 페이지 반환. 탐색 범위가 불완전하면 표시 |
| name이 Windows 예약 장치명이면 저장 경로가 부적합 | 실제 대상 폴더명까지 저장 전 확인. COM¹ 등의 예약 이름 검사 포함 |
| 준비 폴더가 정상 스킬 조회 한도를 소모하고 한도 초과 등록이 디스크에 남을 수 있음 | 준비 폴더를 스킬 수에서 제외. 120개 한도는 쓰기 전에 확인. 손상된 지침은 UI에서 경로와 복구 안내 표시 |
| Pi의 실제 도구 스키마가 문맥 계산에 전부 반영되지 않음 | 진행 설명 필드를 포함한 전송 스키마로 계산. 기존 14000 입력 토큰 예산의 회귀 검사 유지. 필요한 경우 완료된 과거 이력만 추가 압축하며 미응답 현재 요청은 보존 |

처음 다섯 문제는 회귀 테스트가 실패하는 것을 확인한 뒤 수정했다. 전체 회귀 검사 중 드러난 문맥 문제는 테스트 한도를 늘리지 않고 해결했다. 원문 보존, 사용자 답변, 모든 원래 완료 조건과 실제 호스트 기록도 검사한다.

## 방법론과 채택 판단

- [Agent Skills 클라이언트 구현](https://agentskills.io/client-implementation/adding-skills-support): 메타데이터 발견, 도구 기반 활성화, 필요한 참조만 읽는 단계적 로딩을 유지하고 자료 목록 조회를 보완했다.
- [yauzl](https://github.com/thejoshwolfe/yauzl): 기존 MIT ZIP 리더 3.4.0의 lazy entry와 스트림 크기 검사를 재사용했다. 전체 압축 해제나 별도 ZIP 런타임을 추가하지 않았다.
- [Microsoft 파일 이름 규칙](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file): macOS에서 등록해도 Windows에서 부적합한 저장 경로를 만들지 않도록 검증했다.
- Pi 0.86.1, YAML 2.9.0, MiniSearch 7.2.0과 공통 문맥 관리기를 재사용했다. 이번 문제는 프레임워크 교체보다 읽기 검증과 실제 도구 스키마 연결을 보완하는 편이 적합했다. 새 패키지나 모델 호출 프레임워크를 추가하지 않았다.

## 검증 경계

로컬 최종 결과: Desktop 자동 검사 206개, 공통 문맥 검사 40개, 실제 Theia 기존 화면 검사 46개와 스킬 등록 화면 검사 9개 통과. 개발 번들 빌드 성공. 좁은 화면의 실제 스크린샷도 확인했다.

최종 결과는 `verification/quality-recheck-tests.log`, `quality-shared-context.log`, `quality-recheck-build.log`, `quality-recheck-skills-ui.log`, `quality-recheck-ui.log`에 기록한다. npm audit은 이번 조회 시 보고된 취약점 0개였으며 알려지지 않은 취약점 부재를 증명하지 않는다.

Pi 도구 검사는 실제 실행기와 합성 모델을 사용했다. 화면 검사는 실제 Theia 브라우저 UI와 로컬 worker의 저장 결과를 확인한다. 실제 Windows 11 앱 조작, 설치 파일, 사내 모델의 문서 작성 정확도와 실계정 성공은 이번 검증에 포함하지 않는다. Windows CI에 새 스킬 회귀 검사를 추가했지만 원격 실행이나 배포는 하지 않았다. A2A 보류와 기존 HITL 경계를 유지한다.
