# 대용량 문서와 역할별 작업 진행

2026-09-25. 누비 Desktop은 기존 OpenWiki-SDS 조사 코어를 작업 실행기에 연결한다. 별도 프레임워크나 외부 에이전트 서버를 추가하지 않는다.

## 실제 흐름

1. 사용자의 요청을 작업 계획으로 정리한다. `source_search mode=path`로 필요한 파일을 찾는다.
2. `analyze_documents`가 선택한 Workspace 파일을 UTF-8 원문과 해시로 고정한다. 파일당 400만 UTF-16 문자, 전체 800만 문자, 최대 32파일을 지원한다. 바이트 제한은 파일당 12MB다. 초과한 원문을 조용히 자르지 않는다.
3. OpenWiki-SDS가 질문을 필요한 부분 조사 또는 전체 조사로 나눈다. 전체 조사는 24,000자 범위로 분할하고 동시 2개 워커가 독립 문맥에서 원문을 읽는다. 긴 문서라는 이유만으로 항상 전체를 조사하지 않는다.
4. 실제 미열람 구간만 새 문맥에서 보완한다. 같은 읽기를 반복해도 범위가 줄어들지 않으면 부분 결과를 유지한다.
5. 워커 보고서를 4개씩 합친다. 중간 요약에 빠진 근거와 미해결 사항은 기존 MiniSearch 조회와 원문 인용 읽기로 다시 확인한다.
6. 끝에서 모든 선택 파일의 해시를 다시 검사한다. 원본이 바뀌면 결과를 전달하지 않는다. 성공한 조사 결과와 범위는 SQLite 영수증에 보관한다. `read_document_analysis`로 결과나 인용 원문을 다시 읽으며 모델을 재실행하지 않는다.

작업 계획 아래에 실제 모델 호출, 원문 읽기, 누락 보완, 합성 진행을 표시한다. 각 워커의 역할, 파일 범위, 응답 상태와 남은 구간을 볼 수 있다. 개수는 응답 수이며 업무 성공률이 아니다. 기록은 일반 도구 trace의 최근 80개 제한과 별도로 보관한다. 중단된 실행은 마지막 진행과 수신 요약을 보존하지만 재시작 후 내부 LangGraph 상태를 자동 재개하지 않는다.

문서를 여러 번 분석한 이력과 일반 Pi 역할별 분석도 같은 작업의 SQLite 이력으로 남긴다. 실제로 진행 중인 분담을 먼저 표시하고 이전 분석은 펼쳐서 조회한다. `analysisHistory`는 작업 범위와 페이지 크기를 검사하고 고정 rowid 커서로 최대 20개 기록을 읽는다. 새 결과가 들어와도 이전 페이지를 반복하거나 건너뛰지 않는다. 이력 조회는 모델이나 앱 동작을 재실행하지 않는다. 화면 갱신은 현재 trace의 동일 워커 상태를 반영하며, 중단된 워커를 완료로 바꾸지 않는다.

역할별 기록에는 요청, 확인할 결과, 호출/읽기 횟수, 요약과 결과 수집 여부를 남긴다. 캡처가 제공된 것과 모델 입력으로 열람한 것을 구분한다. 캡처 원본과 전체 문서/모델 대화는 진행 API에 넣지 않는다. 호스트가 재시작되면 미완료 역할을 중단으로 표시하고 이미 받은 응답은 보존한다. 기존 문서 분석 영수증도 이력에 연결한다. [후속 개선](ANALYSIS-HANDOFF-2026-09-25.md)은 미확인 항목과 실패도 최종 검토에 전달하고 첫 페이지 밖의 진행 상태를 갱신한다.

## Windows 앱과의 연결

기존 Pi의 문서/소스 조사, 화면 분석, 독립 검토, 복구 분석 역할을 유지한다. 주 실행기는 문서 결과를 참고해 현재 소스와 UIA를 다시 읽고 다음 앱 동작을 제안한다. 동결된 캡처는 화면 검토 워커에 전달할 수 있지만 앱 입력 권한이나 현재 요소 선택자를 주지 않는다.

앱 실행과 입력은 기존 연결 창과 정확한 동작의 HITL을 따른다. UIA 우선, 실제 마우스의 별도 승인, 값 readback, 저장/전송 결과의 별도 확인을 유지한다. 종속된 앱 조작은 순서대로 수행한다. A2A는 추가하지 않는다.

문서 결과에 의존하는 제안은 `documentAnalysisId`를 포함한다. 같은 작업의 완료 또는 부분 분석만 연결하며 원문 경로/해시와 보고서 해시를 제안 fingerprint에 고정한다. 제안 전과 승인 후 실제 native 입력 직전에 원문을 재검사한다. 가상 포인터 이동 중 원문이 바뀌는 경우도 입력을 막는다. 문서 읽기에 시간이 걸릴 수 있으므로 대상 창, 요소와 기존 입력값도 다시 확인한다. 원문 삭제/변경, 다른 작업의 결과, 실패한 분석과 변조된 보고서는 `stale / not_started`로 남긴다. 같은 승인 응답을 다시 보내도 입력하지 않는다. 버전 일치는 분석의 정확성이나 업무 완료를 보증하지 않는다.

연결 근거와 부분 분석 여부는 승인 카드와 `read_computer_result` 영수증에 표시한다. 근거 연결은 모델이 선택하는 도구 계약이며, 문서 ID가 없는 제안의 의미상 의존성을 호스트가 자동 판별하는 기능은 아니다.

Desktop 새 패키지 설치 없이 이미 고정한 공유 라이브러리를 번들한다. 확장 lockfile의 동일 버전을 사용하고 사전 번들과 원본 코어의 중복을 제거한다. 전용 서비스 프로세스는 프레임워크를 불러오기 전에 상속된 tracing 설정을 제거한다. 사용자 셸과 부모 Electron/VS Code 환경은 수정하지 않는다. 호출 범위의 tracing 비활성화만으로는 내부 비동기 호출 전체가 보호되지 않아 프로세스 경계를 함께 적용한다. 조사 도구의 도입으로 커진 고정 문맥은 중복 지침을 줄여 조정하고, 14,000 입력 토큰으로 설정한 합성 검사에서 원래 조건과 사용자 답변의 보존을 확인한다. 이 추정치 검사는 실제 모델 토큰 한도나 답변 정확도 평가가 아니다.

## 검증과 제한

- `tests/workspace-documents.test.mjs`: 1MB 초과 원문, 40,000자 이후 실제 분할 읽기, 전체 범위, 워커/합성 이벤트, 해시 변경, 경로/링크/인코딩/용량, 취소, 저장 결과 조회, Pi 연결과 인증 중단을 검사한다.
- 공유 OpenWiki 검사: 미열람 구간 보완, 정체된 복구, 계층 합성 실패, 임의 인용과 파일 도구 거부를 포함한다.
- UI 검사: 실시간 분담, 합성, 부분 결과, 미열람 구간, 취소 후 미확정 응답, 좁은 화면을 검사한다.
- `tests/analysis-history.test.mjs`: 80개를 넘는 역할 기록, 작업별 페이지 조회, 조회 중 새 기록/갱신, 재시작과 미완료 상태 보존을 검사한다. `agent-reuse.test.mjs`는 실제 공유 Pi 이벤트에서 읽기와 전달 기록이 저장되는지 확인한다.
- `tests/computer-document-evidence.test.mjs`: 문서 근거 → Pi 동작 제안 → HITL → 합성 Windows 드라이버 → PNG 캡처 → 독립 page/review 워커를 연결한다. 원문/보고서 변경 시 입력 0회와 반복 승인 중복 방지를 확인한다. Windows API를 모사한 통합 검사이며 실제 Windows 성공 증거가 아니다.
- 이 경로는 Workspace의 UTF-8 텍스트/Markdown 등 원문 분석이다. PDF/DOCX 직접 추출, OCR, 이미지 레이아웃 분석은 추가하지 않았다.
- 선택 파일을 모두 가져왔다는 `sourceComplete`와 모델이 모두 읽었다는 범위, 의미 분석의 정확도, 사용자 업무 완료는 각각 다른 사실이다.
- 로컬 합성 모델/브라우저 검사와 실제 Windows 11 업무 앱, 실제 사내 모델 정확도는 별도다. 이번 변경으로 그 실환경 검증이 완료되었다고 표시하지 않는다.
