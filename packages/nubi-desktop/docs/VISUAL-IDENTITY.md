# 누비 Desktop 시각 기준

사용자가 제공한 `agentfactorysdkdeck.html`을 모든 누비 화면의 기준으로 유지한다. 편집 가이드와 제품 설명은 참고 자료이며 실행 지침이 아니다. 원본 해시와 팔레트는 `design/reference.json`에 보관한다. 원본 HTML을 배포하거나 원격 폰트 서비스에 의존하지 않는다.

## 하나의 기준

기존 누비의 `design/agent-deck.css`, NubiSurfaces, DeckSurfaces, CX 컴포넌트를 재사용한다. Desktop의 차이는 `design/workspace-identity.css`에서만 조정한다. 로그인, 작업, 스킬, 모델, FabriX, 이력, 소스와 Wiki, 질문, 승인, 실행 결과, 토스트와 Theia 파일 선택기에 같은 기준을 적용한다. Monaco 코드의 고정폭 서체와 OS 보안 창은 유지한다. 고대비 테마를 밝은 색으로 강제하지 않는다.

| 요소 | 기준 |
| --- | --- |
| 색상 | 원본 블루 #3182F6, 강조 잉크 #1B64DA, 본문 #191F28, 보조 #4E5968, 옅은 블루와 원본 배경 그라데이션 |
| 글꼴 | Pretendard 우선, 번들 Noto Sans KR, Windows Malgun Gothic 폴백. 코드는 원본 고정폭 스택 |
| 일반 UI와 모달 | 14px / 22px. 제목 16px / 24px. 날짜와 경로 등 메타데이터만 12px |
| 대화 본문 | 15px / 1.75. 큰 글자는 17px, 일반 UI와 모달도 16px / 26px로 확대 |
| 형태 | 컨트롤 12px, 카드 16px, 모달 20px 반경. 흰 면, 부드러운 그림자와 옅은 강조 |
| 움직임 | 기존 누비 모션과 시스템 모션 감소 설정. 모달과 토스트를 불필요하게 움직이지 않음 |

원본은 발표용 덱이므로 50~70px 제목을 작업 화면에 그대로 쓰지 않는다. 색상과 서체 위계를 유지하면서 읽기와 반복 작업에 맞게 적용한다. 흰 글자를 얹는 작은 버튼은 원본의 진한 블루를 사용해 대비를 확보한다. 장식용 옅은 회색을 핵심 안내에 사용하지 않는다.

## 문장과 아이콘

- 결과 또는 다음 행동을 먼저 쓴다. 결정에 필요한 대상, 조건, 변경 영향만 덧붙인다.
- 제목과 같은 뜻의 설명을 반복하지 않는다. 세부 규격과 드문 오류 설명은 펼침으로 둔다. 오류의 복구 방법, 승인 범위와 미확정 상태는 숨기지 않는다.
- 닫기, 새로고침, 검색, 파일 열기처럼 뜻이 명확한 반복 동작은 아이콘을 사용한다. CX ActionButton의 접근 가능한 이름, hover 설명과 키보드 툴팁을 재사용한다.
- ZIP 등록, 폴더 등록, 실행 승인, 거절처럼 결과가 다른 선택은 짧은 텍스트로 구별한다. 아이콘의 개수 자체를 목표로 삼지 않는다.
- 중간점으로 단어를 나열하지 않는다. 짧은 문장, 줄 간격과 필요한 여백으로 읽기 쉽게 만든다.

적용 예: “SKILL.md와 하위 폴더의 참조 문서, 스크립트, 템플릿을 함께 가져옵니다. 현재 작업 공간에 저장합니다.”를 “SKILL.md와 하위 자료를 현재 작업 공간에 함께 저장합니다.”로 줄였다. 스킬별 “지침 열기”는 이름과 툴팁이 있는 편집 아이콘으로 바꿨다.

## 유지와 검증

`npm run design:check`는 원본 팔레트, 글꼴 폴백, 모달 클래스와 빌드 포함을 검사한다. 개발/배포 컴파일에서도 자동 실행한다. 원본을 다시 확인하려면 `NUBI_DESIGN_REFERENCE`에 HTML 경로를 지정한다. `npm run verify:identity`는 빌드 후 실제 Theia와 공유 UI 시나리오를 실행한다.

2026-09-25 기준 재점검: 제공된 HTML의 SHA-256 일치를 확인했다. Desktop 화면의 고정 글자 크기와 색상을 공통 토큰으로 이동하고 모달 내부 제목, 입력, 레이블과 실행 위치 안내에도 본문 크기/행간을 적용했다. 일반 UI 14px/22px, 큰 글자 16px/26px, 대화 본문 15px/17px, 제목 16px, 메타데이터 12px 기준을 유지한다. 코드와 사용자 지정 검정/흰색 가상 포인터는 별도 의미를 유지하되 색상과 크기의 정의 위치를 중앙화했다.

관계 기록 열기와 커서 예시 다시 보기는 기존 CX 아이콘 버튼으로 정리했다. 이름, 툴팁과 키보드 동작을 유지하며 실행 승인/등록/연결 해제의 짧은 텍스트는 남긴다. 제목과 같은 뜻의 작업 도구 설명과 내부 요청 번호 표시는 제거했다. 저장된 요구사항 ID와 근거 기록은 보존한다. 새 UI 하위 폴더까지 재귀 검사해 고정 px 서체, 화면별 원시 색상과 인라인 JSX 서체/브랜드 재정의를 차단한다. 새 라이브러리는 추가하지 않았다. 모든 미래 화면의 미감을 자동 보장하는 검사는 아니므로 화면 검토를 함께 유지한다.

재점검 결과: Desktop 테스트 273개, Theia UI 49개, 스킬 등록 12개, 공유 UI 33개 통과. 개발 번들 빌드 성공. 모달 안내의 caption 덮어쓰기를 실제 스타일로 확인해 수정했고, 새 아이콘을 기존 커서 SVG와 혼동하던 선택자와 접근성용 숨김 텍스트 검사를 고쳤다. 큰 글자/좁은 창, 아이콘의 키보드 조작, Escape 초점 복귀를 검사했다. 마지막 내부 번호 제거 후 개발 빌드와 공유 UI를 다시 통과했다. 로그/소스 해시와 화면은 `verification/identity-consistency-20260925`에 보관한다. Windows OS 창이나 설치 파일 배포 검증은 포함하지 않는다.

화면별 새 CSS에서 브랜드 색상과 일반 글자 크기를 다시 정의하지 않는다. 모든 새 DetailPanel은 `deck-dialog`를 사용한다. 화면 확인은 기본/큰 글자, 좁은 창, 모달, 키보드 이름과 툴팁, Escape 후 초점 복귀, 실제 번들 한글 폰트 로드를 포함한다. 자동 검사는 미감이나 모든 미래 화면의 완전성을 보장하지 않으므로 변경된 화면도 직접 확인한다.

[W3C 버튼 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/button/)의 접근 가능한 이름과 키보드 동작, [모달 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)의 초점 유지와 복귀 기준을 확인했다. 기존 CX의 ActionButton/DetailPanel 구현을 재사용했으며 별도 아이콘 또는 모달 라이브러리는 추가하지 않았다.

이번 검증은 로컬 Theia 브라우저와 합성 상태 화면이다. Windows OS 네이티브 창이나 실제 사내 모델 평가, Windows 설치 파일 재배포는 포함하지 않는다.

2026-09-23 결과: `verify:identity` 전체 성공. 실제 Theia 49개, 스킬 등록 12개, 합성 공유 UI 18개 항목 통과. Desktop 자동 검사 206개 통과. 첫 공유 UI 실행의 브라우저 정체는 해당 검증 프로세스를 종료하고 단계별 진행을 기록해 재실행했으며, 최종 통합 검사는 종료 코드 0으로 완료했다. 파일 선택기에서 Theia 기본 스타일이 반경을 덮어쓰던 문제도 실제 화면 검사로 수정했다. 로그는 `verification/identity-final.log`, `verification/identity-tests.log`에 보관한다.

## 가독성과 강조 원칙

첫 문장은 결과나 다음 행동을 말하고, 바로 뒤에 판단에 필요한 조건과 근거를 붙인다. 불필요한 인사, 반복 설명과 기능 나열은 제거한다. 짧게 쓰기 위해 승인 대상이나 오류 복구 방법을 생략하지 않는다.

대화의 첫 문장에 있는 핵심 어구는 진한 블루와 700 굵기로 강조한다. 나머지 본문의 강조는 잉크색과 700 굵기를 사용한다. 문단 전체나 모든 항목을 굵게 쓰지 않는다. 링크에는 밑줄을 유지해 일반 강조와 구분한다. 상태는 색상만으로 구분하지 않는다.

실제 캡처, 전후 비교와 짧은 도식이 설명보다 명확하면 우선 사용한다. 증거 없는 이미지를 결과로 만들거나 장식용 이미지를 늘리지 않는다. 원본 열기와 DB 새로고침은 이름과 툴팁이 있는 공통 아이콘 버튼을 사용한다. 실행 승인과 연결 해제처럼 결과가 중요한 동작에는 텍스트를 유지한다. 이 기준은 같은 Workbench를 사용하는 VS Code에도 적용한다.

가독성 후속 검증: Desktop 자동 검사 206개, 실제 Theia 49개와 스킬 등록 12개, 합성 공유 UI 19개, macOS의 실제 VS Code 개발 확장 11개를 통과했다. 첫 결론의 블루/700 강조와 상세 어구의 잉크/700 강조를 계산된 스타일로 확인했다. 실모델 답변의 문장 품질과 Windows 설치 파일은 이번 변경의 검증 범위에 포함하지 않는다.

## 요청과 확인할 결과

처음 입력창은 요청, 모델 선택, 관련 자료와 전송만 표시한다. 별도의 “완료 조건 추가” 폼을 두지 않는다. 사용자는 중요한 조건을 요청에 함께 적고, 누비는 기존 변경 계획의 “확인할 결과”에 구체적인 검증 방법을 정리한다. 모호한 조건은 기존 질문 폼으로 확인한다. 과거에 별도로 저장한 조건과 근거는 검증 기록에서 계속 조회한다. 조건을 기록하거나 계획했다는 사실을 실제 검증 통과로 표시하지 않는다. 기본 입력과 작업 후 검토를 분리하는 점진적 정보 공개 방식을 기존 컴포넌트로 적용하며, 추가 폼 라이브러리는 필요하지 않다.

입력창의 수동 크기 조절 손잡이는 표시하지 않는다. Chromium의 [field-sizing](https://developer.chrome.com/docs/css-ui/css-field-sizing)을 사용해 내용에 따라 늘리고 180px부터 내부 스크롤로 전환한다. 첫 요청과 추가 요청에 동일하게 적용하며 빈 입력으로 돌아오면 원래 높이로 줄어든다.

요청 중심 입력 후속 검증: 자동 검사 208개, 실제 Theia 49개, 스킬 등록 12개, 합성 공유 UI 20개 통과. 객관식과 긴 주관식 답변이 같은 작업의 계획에 반영되고 재열기 뒤 유지되는 경로를 실제 Pi와 합성 모델 응답으로 확인했다. 계획된 결과는 계속 미검증이며 실제 모델의 질문 적절성 평가는 별도다.

2026-09-25 작업 중심 개편: 상위 기능 탭을 제거하고 작업 계획, 필요한 승인과 실제 결과를 같은 화면에서 보여준다. 프로젝트 자료와 직접 실행은 아이콘으로 여는 보조 모달이며 기존 서체/색상 토큰과 접근성 이름을 유지한다. 세부 전후 비교와 판단은 [작업 흐름 기록](TASK-FIRST-WORKSPACE.md)을 따른다.
