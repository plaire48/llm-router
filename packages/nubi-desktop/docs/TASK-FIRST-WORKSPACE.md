# 요청에서 결과까지 한 작업으로

2026-09-25 사용자 결정: 소스, Wiki, 실행, 비교는 누비가 필요에 따라 선택하는 수단이다. 사용자가 기능별 탭을 골라 작업을 연결하지 않는다.

## 바뀐 흐름

`요청 → 짧은 작업 계획 → 필요한 자료와 도구 선택 → 질문 또는 승인 → 결과 확인`

| 이전 | 변경 | 이유 |
| --- | --- | --- |
| 작업 / 소스와 Wiki / 실행과 비교 탭 | 하나의 작업 화면 | 사용자가 내부 도구 분류를 이해하거나 이동할 필요가 없다. |
| 수정 직전 변경 계획만 존재 | 첫 도구 실행 전에 작업 계획 저장과 표시 | 어떤 일을 어떤 결과까지 확인할지 먼저 알 수 있다. |
| 앱 연결과 수동 실행을 작업 도구 모달에 혼합 | 앱 연결은 대화 안의 요청 카드, 수동 실행은 프로젝트 자료의 펼침 | 일반 작업에 명령이나 URL 입력을 요구하지 않는다. |
| 실행과 비교 결과를 별도 탭에서 조회 | 승인 카드, 실행 출력과 캡처를 작업 안에 표시 | 결과가 생긴 작업에서 바로 확인한다. |
| 수동 주소 입력만으로 화면 비교 | 누비의 compare_local_pages 도구 | 요청 또는 읽은 자료에서 정확한 로컬 주소를 확인한 경우 기존 비교 실행기를 호출한다. |
| 변경 계획과 작업 계획의 구분이 어려움 | 작업 계획은 짧게, 변경 범위와 검증 방법은 펼침 | 진행 방향과 상세 코드 근거의 목적을 구별한다. |

인지 부하 관점에서 기존 화면은 기능 선택, 자료 탐색, 실행 결과 이동을 사용자가 기억해야 했다. 필수 선택은 요청과 실제 미해결 결정으로 줄였다. 단순한 대화와 먼저 물어야 하는 질문에는 불필요한 계획 호출을 넣지 않는다. 기존 새 로고, 글꼴, 색상, 모션과 CX 컴포넌트를 유지한다.

## 실제 실행 계약

Desktop의 첫 프로젝트 도구가 선택되면, 호출 전에 같은 모델이 1~5개 단계와 확인할 결과를 작성한다. 기존 공유 `task-plan.js`의 `normalizePlan`과 `initialPlan`, 설치된 Ajv를 재사용한다. 계획은 기존 Pi의 `update_plan` 경로로 저장하고 그 뒤 프로젝트 도구를 실행한다. 계획을 만들지 못하면 두 번 이내의 형식 확인 후 멈추며 계획 없이 읽기나 수정 제안으로 진행하지 않는다.

주 실행기는 새 근거에 따라 단계와 현재 진행 항목을 바꿀 수 있다. 계획의 번호나 진행 표시를 실제 검증 통과로 사용하지 않으며 `completed` 입력은 허용하지 않는다. 기존 변경 계획, 승인과 결과 검토가 실제 작업의 범위 및 검증 상태를 담당한다. 하위 에이전트에는 계획 변경 권한을 주지 않는다.

준비된 파일 변경안을 사용자가 모두 반영하면 같은 작업의 결과 검토를 이어간다. 남은 변경안이 있거나 질문 대기, 취소 상태라면 자동으로 시작하지 않는다. 답변을 마친 작업에 상시 이어서 진행 버튼을 표시하지 않는다.

재개할 때 원래 요청, 완료 조건, 사용자 답변, 기존 계획과 압축된 대화 문맥을 사용한다. 이전 계획은 이번 실행의 관찰이나 승인으로 승격하지 않는다. 계획은 SQLite에 남아 화면 새로고침 후에도 조회된다.

`compare_local_pages`는 현재 요청, 사용자 후속 메시지, 주 실행기의 소스 조회 또는 프로세스 기록에서 확인한 URL만 받는다. 실제 접속과 리소스는 기존 비교기의 loopback 제한을 따른다. Playwright 캡처와 pixelmatch 비교를 재사용하며 서버를 임의로 실행하거나 로그인 상태를 복제하지 않는다. 서버 준비는 기존 정확한 명령 승인 흐름으로 진행한다. 캡처됨과 픽셀 차이를 기능 성공이나 코드 버전 일치로 표시하지 않는다.

## 참고와 선택

- [Anthropic Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)의 작업 분해, 에이전트의 도구 선택, 환경 피드백, 필요한 지점의 사용자 확인을 적용했다. 단순 조합과 기존 실행기를 유지하며 별도 프레임워크는 추가하지 않았다.
- [OpenCode agents](https://opencode.ai/docs/agents/)의 주 실행기와 계획/분석 역할 구분을 검토했다. 누비에서는 사용자가 별도 Plan 모드를 고르지 않도록 같은 작업 안에서 필요한 순간 계획을 생성한다. OpenCode 런타임을 복제한 것은 아니다.
- 기존 CX의 아이콘 버튼, DetailPanel, DeckDisclosure, QuestionForm을 재사용했다. 화면 분리용 탭 라이브러리나 새 폼 라이브러리는 필요하지 않아 도입하지 않았다.
- `cognitive-accessibility:simplify`의 점진적 정보 공개, 한 화면의 핵심 행동, 불필요한 선택 제거를 적용했다. 한국어 문장의 읽기 등급이나 사용자 테스트 점수를 측정했다고 주장하지 않는다.

## 검증 범위

`tests/work-plan.test.mjs`에서 실제 Pi와 지정된 모델 응답으로 계획 저장 후 도구 실행, 계획 수정, 형식 실패, 취소, 질문 후 같은 작업 재개와 계획 원문 보존을 확인한다. localhost 비교는 실제 로컬 HTTP 서버와 브라우저 캡처를 사용한다. 잘못 추정한 URL은 캡처 전에 차단한다.

실제 Theia 및 공유 UI 검사에서 탭 제거, 계획 표시, 결과의 동일 화면 유지, 기존 승인, 자료 모달, 좁은 화면과 질문 초안 복원을 확인한다. 실제 사내 모델의 계획 적절성과 과제 성공률, Windows 11 업무 앱의 실사용 및 설치 파일 재배포는 별도다.

2026-09-25 검증: 런타임 테스트 225개, Theia 화면 검사 49개, 스킬 등록 화면 검사 12개, 공유 UI 검사 21개를 통과했다. 브라우저 번들 및 TypeScript 컴파일을 완료했다. 공유 UI의 계획과 답변은 지정 응답이며 실모델 성능의 증거가 아니다.

의도에 따른 스킬 선택과 결과 검토 확장은 [INTENT-DRIVEN-AGENT.md](INTENT-DRIVEN-AGENT.md)를 따른다.

## 앱 연결과 폼 개선 (2026-09-25)

- `작업 도구` 버튼과 혼합 모달을 제거했다. 대화에는 연결 질문만 표시한다. 수동 연결 관리는 프로젝트 자료에서만 연다. 직접 명령, 별도 worktree, 복구 설정과 URL 비교는 `프로젝트 자료 → 직접 실행과 기록 → 직접 실행과 비교`에 둔다. 요구사항 파일 저장도 같은 기록 펼침에 둔다.
- 주 실행기는 `request_computer_connection`으로 필요한 이유와 앱 힌트를 남긴다. 미연결 `observe_computer`도 반복 오류 대신 같은 연결 요청으로 전환한다. 요청 자체는 창 조회, 캡처, 앱 실행 또는 입력을 수행하지 않는다.
- 대화 안에서는 기존 공통 `QuestionForm`으로 질문 하나, 객관식 선택지, 하단 자유 입력을 표시한다. 사용자는 열린 창 선택 또는 앱 파일 선택을 고른다. 조회한 창도 객관식으로 표시하며 선택지는 4개씩 펼친다. 질문 대기 중 일반 대화 입력창은 숨겨 입력 위치를 하나로 유지한다. 연결 후 `연결한 앱으로 이어가기`를 눌러 같은 작업을 재개한다. 앱 이름 힌트를 HWND나 실행 파일 경로로 자동 해석하지 않는다. 창의 내용과 이미지 전달 범위, 별도 동작 승인을 연결 폼에 표시한다.
- `save_connection_draft`는 입력 초안을, `answer_connection`은 자유 답변을 같은 작업에 보존한다. 텍스트는 앱 선택이나 입력 승인이 아니며 모델 연결 실패 전에는 초안, 실행 이후에는 사용자 메시지와 답변 기록으로 남긴다.
- 요청은 작업과 요청 ID에 묶인다. 대기 중 일반 모델 재개와 자동 복구를 차단한다. 취소는 기존 작업 중지 상태를 사용하며, 사용자가 다시 요청하기 전 자동 재개하지 않는다. 재시작 시 연결 요청만 복구하고 창 권한은 다시 받는다.
- 전체 창 identity를 제공한 연결은 기존 비교를 유지한다. 일반 열린 창 목록은 HWND/프로세스/제목 요약이며 전체 identity snapshot이 아니다. 현재 창을 연결 시 확인하고 이어가기 직전 다시 대조한다. 이 경계를 실제 Windows 11 검증으로 표시하지 않는다.
- 실행 중인 계획 항목에만 `진행 중`을 표시한다. 종료한 계획에 완료 체크를 추정하지 않는다. 역할별 워커는 역할, 수행 내용, 응답과 남은 확인을 먼저 보여주고 호출 수와 진단 코드는 `분석 상세`에 접는다. 수집, 검토, 업무 완료는 별개다.

### 방법론과 재사용 판단

[OpenCode task 도구](https://github.com/anomalyco/opencode/blob/16c56fe5ecc3305028d1f0a9cff5806e51c9d480/packages/opencode/src/tool/task.ts)의 작업 식별자와 범위가 제한된 하위 세션, [Codex wait_agent](https://github.com/openai/codex/blob/aa380897f67b91e1a47d530d7286d497b6726d3f/codex-rs/core/src/tools/handlers/multi_agents_v2/wait.rs)의 실제 상태 기반 대기를 확인했다. 고정 소스/라이선스는 [기존 분석 기록](AGENT-BENCHMARK-2026-09-25.md)에 있다. 이는 설계 참고이며 해당 런타임을 새로 포함하지 않았다.

[Claude subagents](https://code.claude.com/docs/en/sub-agents)의 독립 문맥과 제한 도구, Anthropic의 단순 조합과 환경 피드백 원칙을 기존 Pi 실행기에 적용했다. Claude 데스크톱 내부 비공개 소스를 분석했다고 주장하지 않는다. 이미 도입한 Pi, OpenWiki-SDS DeepAgents, MiniSearch, p-limit, Ajv, CX 컴포넌트를 유지한다. 별도 에이전트/폼 프레임워크 추가는 권한과 상태 경로를 중복시키므로 선택하지 않았다.

### 검증 경계

`tests/computer-connection.test.mjs`는 실제 Pi 실행 경로와 합성 Windows 어댑터로 요청 대기, 같은 작업 연결과 재개, 잘못된 요청, identity 변경, 취소, 재시작과 자동 복구 차단을 확인한다. UI fixture에서는 대화 카드에서 연결, 명시 재개, 취소와 좁은 화면을 확인한다. 실제 Windows 11 창 조작, 사내 모델의 도구 선택 정확도, 설치 파일 배포는 이 검사의 범위가 아니다.

최종 폼 검증: 런타임 286개, 실제 Theia 49개, 스킬 등록 12개, 공유 UI 36개 통과. 객관식 아래 자유 입력, 연결 후 다른 앱 선택, 취소, 답변 보존, 대기 중 단일 입력창과 440px 화면을 확인했다. 기록은 `verification/simple-connection-form-20260925/`에 보존한다.
