# 창 전환과 편집 권한 (0.8.15)

Office 프로세스 안에서 앱별 `WindowWorkerSession` 하나가 Node 실행부를 보유한다. 각 `OfficePane`은 별도의 문서 창 핸들·COM 포트·질문·승인 상태를 가진다. 모델 로그인·선택·추론 설정과 런타임 대화 저장소는 실행부에 남으며 새 작업창이 별도 실행부를 시작하지 않는다. 새 문서를 Agent가 만든 경우 기존 대화 ID와 화면 상태를 전달한다. 사용자가 별도로 연 문서는 같은 모델 연결로 새 대화를 시작한다.

세션은 UI 스레드에서 하나의 실행 소유자를 지정한다. 문서 도구와 최종 응답은 해당 창으로만 전달하며, 모델 상태와 요청 ID가 있는 제어 응답은 연결된 화면에 전달한다. 다른 창은 실행 중 요청·모델 변경을 시작할 수 없다. 원래 창을 닫으면 그 실행을 취소하되 남은 창의 모델 연결은 유지한다. 마지막 작업창을 닫으면 실행부를 종료한다. Office 프로세스가 다르거나 Office를 재시작한 뒤에는 연결을 공유하지 않으며 자동 로그인하지 않는다.

권한은 사용자 화면의 명시적 선택으로 변경한다. 기본값은 `confirm`이며 현재 앱 세션에서 유지한다. 작업 중 변경은 차단하고 다음 실행 시작 때 네이티브 호스트가 권한을 확정한다. 모델 도구의 인자로 권한을 올릴 수 없다. WebView 새로고침과 새 창 연결 시 네이티브 상태를 다시 표시한다.

- `read`: 읽기·분석·미리보기만 허용한다. 문서 편집·생성·사용자 파일 저장은 네이티브 호출 전에 차단한다. 읽기에 필요한 임시 PDF/사본·미리보기와 계산 결과 읽기는 허용한다.
- `confirm`: 기존 변경안 확인 카드를 사용한다.
- `auto`: 요청한 일반 편집·새 문서 생성·문서 가져오기 계획을 자동 승인한다. 문서 일치·원본 비교·독립 결과 읽기는 그대로 수행한다. 복원과 외부 Markdown 저장은 확인받으며, 일반 문서 저장의 파일 경로 선택창도 유지한다.

불확실한 쓰기의 복구 확인은 권한 설정과 별개다. 과거 실행의 결과를 확인하지 못했다고 같은 변경을 재실행하지 않는다.

PowerPoint와 Word의 창 핸들은 기본 IDispatch의 PROPERTYGET으로 읽는다. Office 2016 호환 PIA의 HWND DISPID는 각각 2020과 39이며, 이 고정 조회는 네이티브 창 연결 코드에만 있다. 모델이 임의 DISPID를 호출할 수 없다. Office 전용 창 인터페이스 캐스팅과 HWND 이름 조회에 의존하지 않으며 창·문서 일치 검사는 유지한다.

Word·PowerPoint 편집이 가이드/읽기 단계에서만 끝나면 원본 GenOffice의 응답 검증 훅을 통해 한 번 보정한다. 비어 있는 마지막 응답은 실행 완료 콜백에서 같은 한도로 보정한다. 이미 시도한 편집·실패·거절·취소·설명 요청·읽기 전용에는 이 경로로 편집을 강요하지 않는다. 두 번째에도 준비만 수행하면 미완료로 보고하며 문서 성공으로 바꾸지 않는다.

테스트 증거는 `verification/session-permissions-0.8.15.json` 및 릴리즈 검증 파일을 참조한다. 실제 Windows Office 2016과 실계정 로그인 동작은 연결 환경이 없어 검증하지 않았다.
