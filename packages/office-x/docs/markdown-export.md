# 문서 전체를 Markdown으로 저장

Agent에게 `현재 통합문서를 바탕화면의 매출 분석.md로 저장해 줘`라고 요청합니다. 정확한 경로를 지정할 수도 있습니다. 가져온 파일은 파일 선택 창으로 고릅니다. Agent는 `export_markdown`으로 원문을 읽고, 추출 내용을 검증한 뒤 지정 위치에 저장합니다. 경로와 기존 파일 교체 여부는 대화 안의 승인 카드에서 확인합니다. 위치를 지정하지 않으면 Windows 저장 창을 사용합니다.

## 세 엔진의 역할

| 입력 | 읽기와 검증 |
| --- | --- |
| 현재 Excel | VSTO가 모든 시트의 실제 값·표시 값·수식·셀 주소·병합 범위를 읽습니다. 저장되지 않은 변경도 포함합니다. |
| 현재 Word | VSTO WordOpenXML → 원본 GenOffice DOCX 파서 → 제목·목록·표·머리글·바닥글·주석·각주·미주를 추출합니다. MarkItDown으로 보조 검증합니다. |
| 현재 PowerPoint | VSTO가 슬라이드의 텍스트·그룹·표·발표자 노트를 읽습니다. 슬라이드 번호를 유지합니다. |
| 가져온 DOCX/XLSX/PPTX | 원본 GenOffice 문서·통합문서·프레젠테이션 엔진과 파일 파서를 사용하고 MarkItDown으로 교차 확인합니다. 매크로 형식도 문서 데이터만 읽습니다. |
| PDF | GenOffice PDFium으로 전체 페이지와 원문 텍스트를 확인합니다. Docling이 읽기 순서·표 구조와 한국어 OCR을 분석합니다. |
| HTML/텍스트/CSV/Markdown | Microsoft MarkItDown으로 로컬 변환합니다. |

세 엔진을 매번 모두 실행하지 않고 입력에 맞게 사용합니다. 모델이 긴 본문을 재작성하거나 요약해 원문으로 대체하지 않습니다. 큰 문서의 본문 전체를 채팅 문맥에 넣지 않습니다. 결과의 짧은 미리보기, 구성 개수, 추출 확인 결과와 실제 저장 경로를 반환합니다.

## 저장과 품질

현재 문서를 읽을 때 `SaveCopyAs`, 체크포인트, 새 Office 창, 계산 명령을 사용하지 않습니다. 변환 후 문서 ID와 내용 해시를 다시 확인합니다. 문서가 바뀌었거나 다른 창으로 연결되면 저장 전에 다시 읽도록 합니다.

Markdown의 모든 원문 단위를 비교합니다. 구조 차이나 추가 원문이 발견되면 부록에 보존하고 확인 필요 상태를 반환합니다. JSON 구조는 누비의 내부 작업 폴더에 보존하며 지정 위치에는 요청한 Markdown만 저장합니다. Markdown은 시각 레이아웃을 완전히 보존하는 형식이 아닙니다. 이미지 기능은 추가하지 않았습니다.

OCR 신뢰도는 모델의 인식 점수이며 정확성 보증이 아닙니다. OCR을 사용한 결과는 원문 대조가 필요한 상태로 표시합니다. 분석되지 않은 페이지나 빈 추출을 완전한 변환으로 보고하지 않습니다. 변환 엔진을 준비하지 못하면 읽을 수 있는 PDF 원문 텍스트를 보존하고 표·OCR 미확인 사실을 알립니다. 스캔 PDF에서 텍스트를 읽지 못하면 빈 결과를 저장하지 않습니다.

지정 파일은 같은 폴더의 임시 파일에 UTF-8로 작성하고 해시를 확인한 뒤 교체합니다. 최종 경로를 다시 읽어 SHA-256이 일치할 때만 저장 완료로 보고합니다. 모델의 후속 응답이 실패해도 확인된 저장 결과를 유지하며 저장을 반복하지 않습니다.

## 실행 구성

설치 파일에는 작은 실행 준비 도구와 어댑터를 넣습니다. MarkItDown 0.1.8과 Docling 2.138.0은 처음 필요할 때 사용자 폴더의 분리된 Python 환경에 설치합니다. 버전과 의존성 해시는 잠금 파일로 고정했습니다. Docling은 CPU와 한국어 RapidOCR 모델을 사용합니다. 엔진·모델을 처음 준비할 때 인터넷이 필요하고 완료 후 캐시를 재사용합니다. 변환 과정에서 문서를 모델 서비스로 업로드하지 않습니다.

Windows 64비트에서는 Office 2016의 32비트·64비트 추가 기능과 별개로 변환 엔진을 실행합니다. 32비트 Windows 자체에서는 Python 변환 엔진이 지원되지 않으며 네이티브 문서 읽기와 GenOffice 경로를 사용합니다.

입력 파일은 최대 200MiB, 내보내기 결과는 최대 64MiB입니다. 네이티브 Excel은 한 번에 최대 200,000개 격자 셀, PDF는 최대 2,000페이지를 처리합니다. 제한을 넘으면 조용히 자르지 않고 제한을 보고합니다. 실제 Office 2016과 실계정 모델 검증은 Windows Office 호스트에서 별도로 수행해야 합니다.
