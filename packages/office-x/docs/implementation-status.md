# 0.8.3 변경

읽기 속성을 call로 보낸 경우 알려진 속성은 PROPERTYGET으로 정규화한다. Item/Range 등 안전한 접근자는 PROPERTYGET이 멤버 없음으로 거절될 때만 METHOD로 조회한다. Add/Delete/AutoFit 등 변경 작업은 inspect에서 실행되지 않는다.

member 및 target의 속성 경로는 전체 문법과 금지된 각 세그먼트를 먼저 검사한다. 중간 경로는 getter로 COM 개체만 얻으며 마지막 동작을 한 번 실행한다. 색상·글꼴 등의 쓰기는 기존 체크포인트와 독립적 읽기 검증을 유지한다. Application/Parent/스크립트/직접 파일 및 이미지 호출로 우회할 수 없다.

Word/PPT 생성·검증·창 활성화를 직접 IDispatch로 호출한다. 새 문서 COM 식별자를 확인한 뒤 연결을 교체하고, 연결 실패 시 이전 포트를 먼저 폐기하지 않는다. 이미 생성된 문서와 후속 연결 실패를 구분하며 불확실한 쓰기를 재실행하지 않는다.

로그인은 사용자 동작 이후에만 시작한다. 저장된 암호화 연결도 시작할 때는 캐시에 보관하며 자동 복원하지 않는다. 준비 중 또는 로그인 중 버튼과 모델 변경/보내기는 비활성화한다.

Claude 응답 형식은 엄격한 JSON으로 변환한 뒤 기존 도구 카탈로그 검증을 거친다. 형식 오류는 1회 복구하며, 검증된 변경 이후 복구 요청은 도구를 제거한다. 응답 텍스트는 성공한 응답에서만 전달한다.

Windows C++ COM 재현 객체는 고장 난 타입 라이브러리, 3개 앱의 새 문서 생성·읽기 확인·새 문서 연결, getter 별칭 및 중첩 속성 접근을 검증한다. 실제 Office 2016/VSTO 실행 및 로그인한 Claude 계정 작성은 현재 Windows 접근이 없어 미검증이다.
